# Changelog

All notable changes to this project are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/).

Versions are two-part and pre-1.0: breaking changes may land in any of them until 1.0, and each is marked **Breaking** below. But we intend to keep the configuration schema, the command-line interface of each script, and the format of the sidecar CSV files stable in each version.

## [Unreleased]

### Added

- **A `latex` target.** The LaTeX a PDF target builds from, as a master file that `\include`s a file per chapter, with the images beside them (an SVG made a PDF, as Pandoc's PDF route does, so its alt text holds), for an author to go on working in; `latexmk -lualatex` builds it. Read back as a LaTeX source, each chapter gives the page it was written from. Read back, 8 of GIAM's 10 chapters give the page they were written from. Reading LaTeX takes back what Pandoc's LaTeX writer adds and its reader drops or misreads (lines stacked in `\vtop` or broken in a minipage in a table's cell, the empty row a head-only table gets, the container's caption the reader gives a table in its cells, besides those below): an image inside `\pandocbounded`, a `longtable`'s one-row head (read as the table's header row) and its copy repeated for later pages (dropped), a `\multicolumn` spec holding `@{}` (which lost the whole table), and the PDF target's own link commands. [Formats](docs/formats.md#latex).
- **LaTeX as a source.** A book's master file, the one with `\documentclass` and `\begin{document}`, is read whole by Pandoc and cut into a page per `\include`-d file (one that includes none is one page), so the preamble's macros apply throughout and a reference into another chapter resolves; `latex.main` names the master when there are several, as with a textbook and a workbook made from the same chapters. With no `contents`, `contents-sample.yaml` gives the master's order with the roles its division commands give, and the title, authors, and language from its preamble. What Pandoc's reader (3.12) can't take is put right on a copy first, never in the author's files: ifthen's booleans, `\input` without braces, a table inside `\centerline`, `\cline`'s column range, an image named without its extension, alt text holding LaTeX, the `artifact` key, an author's header declaration for LaTeX's tagging (`\tagpdfsetup{table/header-rows={1}}`), which becomes the table's, and formulas texmath stops on (a size or text command inside `\mbox`, a length in millimeters or one set inside a formula, a rule with no width or height). A drawing (`picture`, `tikzpicture`, `pspicture`) is rendered by LaTeX with the book's own preamble and becomes an SVG in `rendered/`, keeping its figure's caption (a `tikzpicture` drawn as an `overlay` on every page is left alone), and a PDF or EPS image becomes an SVG; both need a LaTeX engine and `pdftocairo`. `latex-conversion-macros.tex` holds definitions read after the book's preamble, for a macro that draws what only a person can name, and the run writes `latex-conversion-macros-sample.tex` listing the book's macros whose formulas texmath still can't read, with a definition suggested where the drawing has one reading. A book whose own build hasn't made the files its master reaches stops the run before anything is converted, with the files named and any Makefile pointed to. Tested on the suite's book, on *A Gentle Introduction to the Art of Mathematics*, and on a set of calculus notes already tagged by their author. [LaTeX sources](docs/latex.md). A `source` target writes the book's `.tex` files back with each image's and drawing's alt text from the image-alt sidecar, as the `alt` or `artifact` key LaTeX's tagging reads; the copy still builds with the author's own `pdflatex`. With `tagging: "on"`, the copy is made to build with LaTeX's own tagging on LuaLaTeX: `\DocumentMetadata`, pdfTeX's option and settings out, and three constructs tagging can't take yet put the way it can; GIAM's builds with no tagging error and passes veraPDF's PDF/UA-2 profile. A LaTeX book's tables go through the header pre-pass, as an HTML page's do, and a tagged copy declares each header a person decided, `\tagpdfsetup{table/header-rows={1}}` in a group of its own before the table. The copy gets `latex-conversion-macros.tex` after its preamble too, unless `latex_definitions` is `"off"`.

### Fixed

- **A link to a chapter's own heading in an EPUB or a PDF.** The chapter's heading takes the page's id in a book, and a link to the id it had, a LaTeX chapter's `\label` say, went nowhere: epubcheck's RSC-012 on GIAM. Such links now go to the chapter.
- **Lists and quotations holding a formula, a table, or a rule, in a Word file.** Pandoc's writer gives a display formula's paragraph no numbering (jgm/pandoc#6638), Word can't put a table in a numbered paragraph, and Pandoc's reader takes its own rule only from a paragraph with no numbering; each ended the list when the file was read, and the rest came back as new lists, indented paragraphs, or quotations. A table in a quotation came back after it, and one whose cells hold a box came back a quotation per cell. A formula's paragraph in a list item, or in a quotation in one, now takes the item's level with no marker, as the item's other paragraphs do. A table or rule in a list item, at any depth, and a table in a quotation are recorded in the file, beside the map of ids, and put back on reading, the lists and quotations the reader began again joined to their own; a quotation's table cells are written as table cells, not as quoted text. On GIAM, read back from Word, lists or quotations differed from the HTML on 7 of 10 pages; now on none. A figure holding a table, which comes back as the table, is now reported (`figure-table` in `fidelity.csv`).
- **A rule with no height or no width, in a LaTeX source,** was read as a line across the page: `\rule{36pt}{0pt}`, a space between a table's columns, put a horizontal rule in a cell. It's a space now, and a rule with no width (a strut) is nothing.
- **A display formula inside emphasis, and a line break with no line to end, in a PDF.** A LaTeX source states a theorem as `\emph{\[ ... \]}`, which LaTeX's tagging couldn't place: the paragraph's content was left in the section's own structure, and veraPDF's PDF/UA-2 profile failed "Sect shall not contain content items" and "P shall not contain P" on GIAM. The formula now comes out of the emphasis, which keeps what's on either side. A line break at the start of a paragraph or right after a display formula, where LaTeX has no line to end and stops, is dropped. GIAM's PDF now passes the profile.
- **Figures a PDF couldn't hold as they were.** A figure inside a figure was written with an empty `\caption{}` of its own beside the outer one's, so the PDF numbered two captions in one figure; the inner one's content now stands in the outer figure, its caption, if any, a paragraph under it. A figure holding only a table lost its caption, since the writer writes the table, which can't float, and drops the figure; the caption is now the table's.
- **A table inside a table cell in a PDF.** Pandoc's LaTeX writer made each a longtable and LaTeX stopped on the inner one; the inner table is now written as lines of text, one a row, and the run says so. It's now a `tabular` inside the cell, its head ruled off and declared for tagging, which tags it as a table inside the cell's TD, a structure veraPDF's PDF/UA-2 profile raises nothing about (in a short test document); only one with a cell spanning rows is still written as lines of text.

## [0.8] - 2026-10-03

PDF and Word, mostly. A book can now be written as one tagged PDF, claiming PDF/UA-2 and Well-Tagged PDF (or PDF/UA-1, for checkers that know only that) and checked by veraPDF, and as Word files that Word's Accessibility Checker will run on and that read back as a source with what Pandoc alone would lose put back. A `source` target writes the run's decisions into an author's own Word or Markdown files. Math Word's editor got wrong is repaired, and math typed as text becomes equations. A page's title is now its own H1 in every output, and a title the source declares stands. The sidecars record who drafted each value and whether a person has reviewed it.

### Breaking

- **A page's title is its own H1 in every output, and a declared title stands.** A page whose only H1 is its title had that heading taken out of its body for the title block; every output now puts it back as the page's own heading, in its own words and with its id: a body `<h1>` in HTML with the title in `<title>` and no title block, a Heading 1 in Word with the title in the file's properties rather than a Title paragraph, a `#` heading in Markdown and AsciiDoc, and the chapter heading in the EPUB and PDF, a one-page book's included, which had lost it. `promote_h1_to_title` now defaults to `if-absent`: a declared title (Markdown's `title`, HTML's `<title>`, a Word Title paragraph) stands, and an H1 that says it, the same or one inside the other ("1.1 Definitions" under "Definitions", "A Web Page" under "A Web Page -- The Site"), is the page's title heading, shown once; one that says something else stays a heading of its own, the declared title shown above it. Saying the title is judged as a reader would: curly and straight quotes alike, dashes alike, case aside. `shorter` takes the H1 as the title when the declared one is it plus a site's name. The run says when pages keep a declared title without the section number their heading puts before it, as the OpenStax books' do, since their `<title>` and a cartridge's names for them then have none; `always` keeps it. A format source copy keeps the author's own title whatever the setting. `title_page` (`auto`, `on`, `off`) for an EPUB or PDF: `auto` gives a title page to a book of more than one top-level entry, or one page with more than one top-level heading or a byline before its title heading, and otherwise none, the title then in the file's metadata.
- **A `sidecars:` or `reports:` setting inside a target stops the run.** They're read once, for the whole book, from the first target, so in one target they applied to every target or to none, depending on the order. Set them under `defaults:`; the message says so. The schema marks such settings `book_level`, the counterpart of `target_only`, and the settings reference says it. [How values are settled](docs/configuration.md#how-values-are-settled).
- **A book written one file per chapter is guessed that way.** Without `project.contents`, a numbered file that is its chapter's only file (`01 BigPicture.md`) is now that chapter, rather than a page under a group heading made from its number ("Chapter 1"), and a page read as an appendix keeps that role. The EPUB, the cartridge, the HTML contents page, and the PDF all follow the guess, so each loses a level that wasn't in the book; a cartridge built this way and imported again has one module level fewer than the course it replaces. A chapter of several files is grouped as before.

### Added

**PDF**

- **A PDF target.** `format: pdf` writes one tagged PDF of the whole book: the pages assembled by `project.contents` as for the EPUB (the assembly now lives in `lib/bookassembly.py`, shared by both), then Pandoc's LaTeX writer and LuaLaTeX with LaTeX's tagging switched on by the declared standard (`pdf.standard`, PDF/UA-2 by default). What the writer can't be told, `bin/pdf-target.lua` adds: a declared header column tagged as row headers, a decorative image as an artifact, and every link's `/Contents` as its visible text followed by its description. Each formula carries MathML as structure elements and as an attached file. Latin Modern Math stands in for characters the template's fonts lack (Greek, and most mathematical symbols, written as text), which were otherwise blank. Any character still missing is named in one warning, since veraPDF catches it only when an OpenType font draws it blank, not when one of LaTeX's older math fonts drops it. A page's role is written as the division command it came from, the book opens in the front matter, and LaTeX numbers it. `pdf.metadata` names a file whose YAML goes to the writer, so a book set up for a Pandoc PDF build keeps its class, `header-includes`, and epigraphs. A LaTeX older than 2025-11-01 is refused before the build, saying which release was found, and a package LaTeX can't find is named with the `tlmgr` command that finds it. Measured on Pandoc 3.11, LaTeX 2026-06-01, and veraPDF 1.30.2: the suite's book and the whole economics textbook (431 pages, 1,141 formulas) pass PDF/UA-2, PDF/A-4f, and both WTPDF 1.0 profiles with no rule failed ([PDF](docs/formats.md#pdf); [installing LuaLaTeX](docs/installation.md#for-a-pdf-target-lualatex)).
- **PDF/UA-1, as PDF 1.7.** `pdf.standard: [ua-1]` now builds a file veraPDF's PDF/UA-1 profile passes, for checkers such as PAC that test only PDF/UA-1. Formulas carry LaTeX's TeX alternative text and their MathML as an attached file, since PDF 1.7 can't tag MathML, and a book with equations is warned; `pdf.ua1_math: office` adds the MathML as Microsoft Office's own attribute, as Word's PDFs carry it. LaTeX's own links get hyperref's description without overwriting the book's, and footnote marks aren't links ([PDF](docs/formats.md#pdf)).
- **veraPDF in the output check.** A PDF the run builds is checked as the audit checks one, and with veraPDF when it's installed (`VERAPDF`, or `verapdf` on the path): each rule it finds failed is a finding with the standard's clause, and a clean run drops the note that the file's claims are unverified. Both checks also report a figure whose alternative text is a file name, which is what LaTeX writes for an image with none, and which veraPDF accepts (`pdf-figure-alt-is-file-name`).
- **Figures stay in reading order in a PDF, and table captions are captions.** `pdf.figures` (`in_place`, the default; `section`; `float`) sets where figures go: LaTeX's tagging had gathered the tags of every figure that floats at the end of the document, 246 of the statistics textbook's 270, which a screen reader reached after everything else. `pdf.repair_captions` retags each captioned table's caption, which LaTeX writes as a first row of one spanning header cell, as the table's Caption, and takes out the empty repeated head LaTeX leaves inside the table; NVDA then read the caption as a caption and counted the table right, where it had read row 1 and counted four rows and six columns in a three-by-three table. Only tables the book captioned, matched in order, and only their first row. On the statistics textbook, 338 of 342 captions retagged, and veraPDF still passes. Needs `pikepdf` ([PDF](docs/formats.md#pdf)).
- **Empty paragraph elements removed from a PDF.** `pdf.remove_empty_paragraphs` (on by default, needs `pikepdf`) removes the paragraph structure elements LaTeX's tagging code leaves empty, which PDF4WCAG's WCAG 2.2 Machine profile reports and NVDA reads past. The contributed `util/contrib/fix-empty-paragraphs.py` is now `lib/pdfparagraphs.py`, run after the caption repair, with `util/fix-empty-paragraphs.py` for a PDF made some other way. On the economics textbook it removed 120 and on the statistics textbook 3,449, each book's page text and its tables, figures, formulas, and links unchanged, and veraPDF still passing ([PDF](docs/formats.md#pdf)).
- **DCIC as a PDF, and what it needed.** An HTML book built through the PDF target for the first time, from its WARC: 509 pages. Headings below a subsection now stand on their own line (Pandoc's `block-headings`, which a metadata file can turn off), since two run-in headings followed straight by a section had left LaTeX's paragraph tagging one paragraph short and stopped the build. A quotation inside a table cell is unwrapped for the PDF, since its structure can't hold a block quotation in a table cell; DCIC sets code side by side that way. Its 16 black-flag emoji stay undrawn and reported ([PDF](docs/formats.md#pdf)).
- **The security textbook as a PDF, and what it needed.** An AsciiDoc book built through the PDF target for the first time: 161 pages, veraPDF passing, its two captions retagged and 94 empty paragraph elements removed. Its code callouts are circled digits no Latin Modern font has, so DejaVu Sans, when installed, follows Latin Modern Math as a fallback font (58 characters had been drawn blank). Its SVG images need `rsvg-convert`, which Pandoc uses to make each a PDF before LaTeX, alt text kept; without it a PDF build of a book with an SVG now stops before LaTeX and says what to install, since the LaTeX writer's fallback, `\includesvg`, passes no alt text. The suite now checks what `pdf.figures: section` and `float` give LaTeX ([PDF](docs/formats.md#pdf)).

**Word**

- **A Word target.** `format: docx` writes a Word file per page, or per chapter with `merge: groups`: Pandoc's writer, then what it leaves out, in `lib/docxtarget.py`: compatibility mode 15, which accessibility guides for Word say its Accessibility Checker needs; a link's title as its ScreenTip; Word's marker on a decorative image; and the First Column flag on a table with a header column. A quotation's levels are indented, so a quote within a quote shows as one and reads back nested. Measured on four books from four source formats, every file valid against Word's schema; read back as books, the statistics book gives the same HTML on 167 of 169 pages, DCIC on 50 of 80, and the security textbook on 12 of 14, with no dead links in any. [Word output](docs/formats.md#word-output).
- **A Word file keeps only the bookmarks something uses.** `bookmarks: linked`, the default for a `docx` target, removes the heading and section bookmarks Pandoc writes that no link in the book goes to, keeping JAWS's table header bookmarks and those that carry a code block's language. NVDA had announced "bookmark" at every one, at the end of each section with Pandoc 3.12's placement, and at the heading when moved there; with them gone it announced none. `bookmarks: all` keeps every one ([Word output](docs/formats.md#word-output)).
- **Numbered and highlighted code through Word.** The Word target writes each line's number as text in Word's "Line Number" character style, so the numbers show in Word, and puts a code block's language in a hidden bookmark; reading the file back numbers the block again from its first number, and restores its language, so its highlighting. Two code blocks in a row are kept apart, which Pandoc's reader would join.
- **A report of what a target's files can't carry**, `fidelity.csv`: for a Word target, a figure with no caption, a layout table, a table's per-cell headers, and a code block's language when it can't be carried, a row per page, known before writing, with a line per target on the terminal. An EPUB target reports a frame, an image on another server, and a link to a local file, each of which it writes as a link or text, and a Word target a frame. Markdown and AsciiDoc targets report there too what their writing changes, such as an example list, which Pandoc's Markdown writer writes as a numbered list, a footnote of several paragraphs in AsciiDoc, or a root with an index. [Word output](docs/formats.md#word-output).
- **A Word table's headers declared with bookmarks.** A bookmark named `Title`, `ColumnTitle`, or `RowTitle` in a table, the convention [Freedom Scientific documents for JAWS](https://doccenter.freedomscientific.com/doccenter/archives/training/samplefiles/usethebookmarkfeatureinwordfortableheaders-oldertechnique.htm), is read as the table's declaration, supplier `source`, as an HTML table's `<th>` cells are, and the Word target writes the one each table's headers call for. A table the census would have guessed differently reads back as declared. What JAWS does with the bookmarks is from Freedom Scientific's documentation, which calls the method an older technique, and isn't tested here.
- **Word's decorative marker is read.** An image an author marked decorative in Word (Office 2019 and later) was treated as undescribed and reported; it's decorative now, in conversion and in the audit. Four images in the test corpus carry the marker.

**The author's own files**

- **`format: source`: the book's own files, remediated.** A Word source gets a copy in the target's folder with what a person decided in the sidecars written into it: table headers from the table-headers sidecar; a table's description from the table-captions sidecar, as a Caption paragraph above a table with no label or joined to a label paragraph; alt text and decorative marks from the image-alt sidecar; link titles and replacement addresses from the bare-links sidecar; and the book's language when the file declares none. Never a guess, since in the file it would read back as the author's own declaration: a first run changes no table, and says how many it left to their guess for adopting. Every part nothing decided is copied byte for byte; the compatibility mode is the author's unless `compatibility_mode` is `"15"`. A hand-maintained HTML page gets the same as text edits, the rest of it as written: header cells with `scope`, `alt`, a table's description from the table-captions sidecar as its `<caption>`, or joined to a label paragraph beside it, a bare link's title and replacement, and `lang` from the book's language. `util/remediate.py` does the same by hand. Markdown and AsciiDoc sources aren't written yet. [Source](docs/formats.md#source).
- **`format: source` for Markdown.** A Markdown source's copy gets the sidecars' decisions written where each element is, and nothing else changes, so every Pandoc Markdown construct survives as written: alt text and `.decorative`, a bare link's replacement and title, a `Table:` caption or a description joined to a label paragraph, and `lang`. Each element is found by rules that follow Pandoc's, and changed only when Pandoc's reading confirms it; anything unconfirmed is left and counted. On the author's own book, the copy's 30 bare links match the version fixed by other means, and every changed line is a link or an image. [Source](docs/formats.md#source).
- **`word.tracked_deletions` and `word.headings`: two repairs of Word sources as settings**, decided once for the book and applied both to what the conversion reads and to a `source` target's copy, so the book and the author's file agree. `strike` keeps text deleted with tracked changes, struck through; by default it's dropped, as before, but the run now names each file that has any. `from-toc` or a style map makes a book whose top level is styled `Title` read with headings. They're what `util/untrack-deletions.py` and `util/restyle-headings.py` do by hand, whose code is now shared (`lib/wordrepairs.py`). [Word](docs/formats.md#word).
- **`format: source` writes the math repairs into a Word file.** With `math.repair_equations` (on by default), the remediated copy of a Word source gets the repairs the pages do, as Word's equation structures: an upper limit holding a macron or an en dash becomes a bar (its base found by counting, since it can hold a subscript of its own), the micro sign mu, the increment sign Delta, an en dash a minus (except in an equation's normal text), the one-character y-hat a hat over y, and a subscript's slashed O a zero. With `math.from_text`, math typed as text becomes Word's equation where the filter made one in the page: the filter records each one's paragraph, the copy's paragraph with that text gets the equation Pandoc writes for the TeX, and a run it begins or ends inside is split with its formatting kept. Paragraphs that share a text are told apart by the filter's order, and anything that doesn't map exactly is left and counted. On the statistics textbook: 443 equations repaired and 1,613 made of text, 33 left; Pandoc reads none of the wrong characters back from the copies; read back as a book, 168 of 169 pages give the same HTML as the originals, the other differing in a table's guessed headers; in the four copies checked against Word's schema, the errors are exactly the originals'. `remediate.py --repair-equations` does the first by hand.

**Math**

- **Math repaired, and math typed as text made equations.** `bin/math-repair.lua` runs at the filter stage, so every target gets the result. Inside an equation it writes the character meant for one Word's equation editor let through: μ for the micro sign, Δ for the increment sign, a minus for an en dash, a bar for an en dash or macron set over a letter, a hatted y for the one-character ŷ, and 0 for the slashed O of H₀. Outside one it makes an equation of math typed as text, conservatively: a relation between operands with at least one italic or Greek variable, or a Greek letter or scripted italic letter standing alone; a plain letter, a lone italic letter, numbers alone, and an ordinal stay text. Measured on the statistics textbook: 444 equations repaired, 1,175 expressions and 457 symbols made equations, and in samples every one was math; on 771 files of six other books, five changes, all math. Each change is a row in `math-repaired.csv`, and `math.repair_equations` and `math.from_text` turn either off ([Math](docs/configuration.md#math)).
- **`math-keep.csv`: math kept as it was.** A row copied from `math-repaired.csv` (Kind, Page, Before; a blank Page for every page) keeps that equation unrepaired or that text as text, in the pages and in a Word source's remediated copy, where a kept equation is found by the TeX Pandoc reads from it. A row that keeps nothing in a run is warned about ([Sidecars](docs/sidecars.md#math-kept-as-it-was)).

**Sidecars**

- **Who drafted a sidecar value, and whether it's been reviewed.** Each report a person fills in, and so the sidecar its rows go into, ends with `Drafted by` and `Reviewed`: blank, `TI` for TextbookImprover's guess (every table's headers), or a model's name; and a reviewer's name or initials once a person has checked it. A drafted value is used whether or not it's reviewed, and the run says how many haven't been. Sidecars without the columns read as before, as a person's; for a `table-headers.csv` without them, whose rows are mostly the run's own guesses pasted in, the run writes `table-headers-sample.csv` with the columns added, `TI` on each row that matches today's guess. This prepares for drafts from a language model, on the roadmap for after 1.0.

### Changed

- **More of the math typed as text reaches a Word source's copy.** Several equations in one run of text now split it around each, its formatting kept on every piece, where the second had been refused; and a paragraph is matched with no-break and em spaces as text, as the filter sees them, where they had been taken for spaces and the paragraph not found. On the statistics textbook, 1,641 equations are written and 5 left, where 1,613 were and 33 left; the copies, read back, give the same pages as before.
- **A table-headers sidecar row that matches no table is a warning**, not an error that stops the run. Editing a table in its source changes its key, as when a Word file converted once is edited in Word and converted again. The row goes to `table-headers-unmatched.csv`, and `table-headers-sample.csv` is the sidecar without such rows, to adopt.

### Fixed

**PDF**

- **A one-page book's PDF is in its main matter.** The PDF writes `\frontmatter`, `\mainmatter`, and the rest where a book's roles change, between its entries, so a book of one page never reached the main matter: its pages were numbered i, ii in roman, and its chapter went unnumbered. Its one entry now starts its division.
- **A table cell spanning rows is tagged so in a PDF.** Pandoc sets it with `\multirow`, which LaTeX's tagging doesn't follow: the cell was tagged as one row's, and each row it covered got an empty cell of its own, which veraPDF didn't report. Each such cell now says `table/multirow`, so it has its `RowSpan` and the cells it covers aren't tagged; and since LaTeX's record of those covered cells outlived the table, so that the next table lost its cells at the same places, the build clears it at the start of each table. The statistics book's statistical tables have 79 such cells.
- **The audit crashed on a PDF when looking for veraPDF**, since veraPDF had never been registered as a validator, and it read veraPDF's text output, which names the file and the profile rather than the rule, so no rule would have been reported. It reads veraPDF's JSON report now.

**Word**

- **A quotation in a list item, and code in a quotation, stay whole through Word.** A list item's quotation came back one quotation a paragraph, and code in a quotation lost it inside a list item and came back one level deep in a quotation within a quotation. The Word target indents each by its depth and reading such a file nests it again; adjacent quotations are joined at every level; two quotations kept apart only by Divs, which Word doesn't keep, get a separator. DCIC read back from Word: 57 of 80 pages the same HTML, and the source's number of quotations on all but four.
- **Code with a language read back from Word has no zero-width space at its start.** The run that keeps the language's bookmark from merging with another was kept in the code's text.
- **A list inside a quotation stays in it through Word.** Pandoc's writer leaves a quoted list at the margin and its reader never puts a list in a quotation, so a Word target's quotation came back split around its list. The Word target now indents the list inside the quotation, which Word shows, and says so in a document variable; reading such a file puts the list back, at its depth. An author's own Word file, without the variable, is read as before, since its indented lists can mean something else. `list-in-quotation` is no longer a reported loss.
- **A decorative image in Word has no description or title at all.** The Word target and a remediated Word copy gave one Word's decorative mark beside Pandoc's empty description and title; Word, marking an image decorative, leaves neither, and so do they now. NVDA announces such an image as "graphic picture decorative" either way, in a file made in Word as in ours.
- **Pandoc 3.12's Word writer lost the Word target's marks and ids.** It names every bookmark with a leading underscore, which hides it in Word, and hashes any id holding anything but letters, digits, and underscores ([pandoc#11845](https://github.com/jgm/pandoc/issues/11845)). The marks the Word target finds its tables, images, code, and quotes by had hyphens, so none was found: no First Column flag, no JAWS bookmark, no decorative marker, no line numbers or language, no nested quote. The marks are letters and digits now and are found with or without the underscore, and the map that reads ids back holds both versions' names. The ScreenTips 3.12 writes itself are counted with the ones the target adds.
- **A paragraph's first bookmark was merged into the one before it** when a Word file was read, if the paragraph before ended with a bookmark and had a style or a bookmark's end, as Pandoc's writer makes a page's anchors. Pandoc's reader maps a bookmark that immediately follows another onto it, and the reading repair kept them apart only after a paragraph holding nothing but bookmarks. Read back from Word, the first solution on each of the statistics book's solutions pages lost its id: 14 dead links from exercises, now none. The book converted from its own Word files is unchanged.
- **A bookmark opening a paragraph was moved to the heading before it** when a Word source was read. The repair that moves a bookmark out of a heading matched from the heading on through later paragraphs, to the first that opened with a bookmark, and moved that one. On the statistics book, fixing it gives 32 pages figure captions they had lost (chapter 1.2 has all nine, where it had three), turns a title block left as stray text on 3 pages back into the page's title and author, and makes lists whole on 5.
- **A Word target could crash the run** reporting a list inside a quotation whose first item opened with another list; found converting DCIC.
- **A Word file read back lost every id Pandoc's writer renamed**, so a link from another page to it was dead: 475 links in DCIC's round trip, and every cross-reference into an Asciidoctor section, whose ids start with an underscore. Word's bookmark names start with a letter and run to 40 characters, and Pandoc names any other after a hash of the id. The Word target now records the names it hashed in a custom XML part of the file, and reading Word renames them back: no dead links in either book's round trip.
- **A term with no definition was lost as a description list** when a Word source was read: Pandoc's reader makes one only from a term followed by a definition, and a review question with no answer came back as a Div. A run of such terms is a description list again, one with the list beside it.
- **A list item's second paragraph, code block, or figure split its list** when a Word source was read. Pandoc's writer, and OpenStax's export with it, number such a paragraph with an invisible bullet to indent it under the item, and Pandoc's reader took it for an item of another list. It's folded into its item now. The statistics book had 102 such paragraphs in 20 files: 11 pages' lists are whole again, and a table inside a solution's item has its caption.
- **A captioned figure with a bookmark before it lost its caption** when a Word source was read. The repair that moves a body-level bookmark into the next paragraph put it beside the figure's drawing, and Pandoc's reader pairs a caption only with a paragraph holding the drawing alone; the bookmark goes into the caption now. Pandoc's own writer puts such a bookmark before every figure with an id.
- **`util/docx-compat.py` could write settings Word calls corrupt.** A new compatibility setting went before Word's legacy options in `w:compat`, where the schema puts it after them, and a new `w:compat` block went at the end of the settings, after elements the schema puts after it.

**Elsewhere**

- **A numbered book's long page titles are numbered.** The number went on a page's `<title>` and heading only when the writer had kept them on one line; a title long enough to wrap kept no number.
- **Captions and a focused table's outline were near invisible in dark mode** once Pandoc 3.12's stylesheet follows the reader's dark mode, with a `#1a1a1a` background: captions were `#555` there (2.33:1) and the outline `#1a1a1a` itself. Captions are `#b6b6b6` in dark mode (8.58:1) and the outline is the text's own color; a unit check computes each color's contrast against both backgrounds.
- **A `source` target wrote the schema's default language into the author's files** when the book declared none. A copy now gets the language only when `project.language` is set.
- **Python 3.13 warned in the middle of a run**, since two `re.split` calls passed `maxsplit` by position, which 3.13 deprecates. They name it now, and the portability test checks the source for those calls, since an older interpreter says nothing about them.

## [0.7] - 2026-09-25

New sources, mostly. A book can now arrive as HTML, AsciiDoc, or an EPUB; be captured from the web, as a browser's save, a WARC or WACZ, a Jekyll site's Markdown, or an EdTech Books archive; or be unpacked from a course's Common Cartridge. It goes out as HTML, an EPUB, Markdown, a new AsciiDoc target, and a cartridge, and converting the pipeline's own HTML changes nothing. Tables get title rows and bands, found in HTML as in Word. And links: bare links get a sidecar and shortDOIs, a link's title survives every route through the pipeline, and the project's first contribution to Pandoc, reading and writing Word's ScreenTips, was merged upstream.

### Breaking

- **An `.html` beside the sources is a source now, and a finished page goes in `_pt/`.** Before, an `.html` with no `.docx` behind it was a page someone wrote by hand and was copied as it stood. Such a page now lives in the pass-through directory (`_pt/`, or what `passthrough` in `project.yaml` names), where an `.html` is copied as it is. A book with `.docx` or `.md` sources and `.html` beside them says so on every run. See [HTML sources](docs/html.md).

### Added

**Sources**

- **HTML as a source.** An `.html` beside the sources is read, filtered, split, and rendered like any source, and converting the pipeline's own pages changes nothing. What Pandoc's HTML reader loses is repaired on the way in, from a copy (`lib/htmlrepair.py`) and in `html-source.lua`: ids on paragraphs, list items, cells, captions, and inline marks move to anchors the reader keeps; an id with whitespace is made valid, links following; `alt=""` stays decorative; `<details>` and `<summary>` are kept; `<section>` and `<header>` wrappers open so the split can cut inside them; a page's only `h1`, however deeply nested, is its title, and a `<title>` repeating the book's name loses it; empty headings, raw tag fragments, obsolete presentational attributes, and attributes whose names can't be names are dropped. [HTML sources](docs/html.md).
- **An HTML source's tables** go through the header pre-pass, into the same sidecar and reports as Word's: a page's own `<th>` cells are its declaration, a bold row (by `<b>` or by style) reads as bold to the guess, a header row written in `<tbody>` moves to the head, a column with nothing in it is dropped (code blocks count as something), and a row of `<th scope="col">` partway down splits the table there.
- **AsciiDoc as a source.** An `.adoc` file is a page; a file that `include::`s others is the book's order, written to `contents-sample.yaml`, along with its header's title, authors, and language. `imagesdir` is applied, a variant like `ch1.print.adoc` replaces `ch1` for its target, and `mailto:` links keep their scheme. [AsciiDoc](docs/asciidoc.md).
- **An EPUB as the source.** `unpack-epub.py` turns a publisher's EPUB into a book directory: a page per content document with its references moved and nothing else changed, the media where it sat, and a `project.yaml` with the package's metadata and its navigation as `contents`. `build-cartridge.py --toc` reads an EPUB through the same code. [An EPUB as the source](docs/epub-input.md).
- **A book saved from the web.** `unpack-site.py` takes a browser's "complete" saves, `.mhtml` files, a zip of either, or a WARC or WACZ from any archiving crawler (wget, ArchiveWeb.page, Browsertrix, Heritrix), and writes pages whose every reference is local: redirects and revisit records followed, gzip and chunked encodings decoded, a WARC recognized by its first bytes, an address with spaces found however it's encoded, and each image saved once. It recognizes generators (Scribble's layout tables become what they are), finds the book's order in its menus, parses with html5lib as a browser would, and keeps a site's MathJax formulas as math, 397 of them in DCIC. `convert.py` does the unpacking itself for a directory holding a WARC or WACZ. [A book saved from the web](docs/site-input.md).
- **EdTech Books, from a browser's archive.** The site draws every page by script, so its archive holds a shell and JSON records; the unpacker makes the book from the records: a cover with the contents, a page per chapter nested by its level, videos as players, the site's `h6` labels as labels, and headings starting at `h2`.
- **A Jekyll site's Markdown as a book.** `unpack-jekyll.py` flattens a just-the-docs source into a book directory, pages named as `unpack-site.py` names the same URLs and `contents` from the front matter.
- **Common Cartridge input.** `unpack-cartridge.py` turns a course cartridge (versions 1.0 to 1.3) into a book directory: its HTML pages and Word documents as sources, its other files where they sat, and its modules as `contents`, with Canvas's text headers as groups and link placeholders resolved. `--linked-documents` makes each Word, Markdown, AsciiDoc, or HTML file a page links to a page of its own. [Common Cartridge input](docs/cartridge-input.md).
- **`convert.py` extracts a plain `.zip` it finds alone**, as it does a WARC or a cartridge: wrapping folders dropped, macOS's litter left out, and an entry that would land outside the directory refused.
- **Raw HTML in a Markdown source is read as HTML and cleaned** the way an HTML source's is (`markdown-html.lua`), so `<sup>` is a superscript, `<img>` an image the run checks, and `<table>` a table the header sidecar reaches.

**Outputs**

- **An AsciiDoc target.** `format: asciidoc` writes the book as AsciiDoc to be read again as a source, with `merge: groups` as for Markdown. Pandoc's AsciiDoc writer and reader disagree in many places, so the target writes much of it itself: table markers, row-spanned and banded tables, images, figures, footnotes, and escapes for AsciiDoc's line-start characters. Round trips measured on four books from four source formats. [AsciiDoc](docs/asciidoc.md).
- **A menu for pages posted as a site.** `menu: on` on an HTML target gives every page the book's contents in a collapsed `<details>` inside a `<nav>`, the page's own entry marked `aria-current`, and links to the previous and next page.
- **Frames and remote media.** An `<iframe>` stays one in an HTML target, with a valid size, and becomes a link in the EPUB, named by its title; a video's link goes to the video's own page, not its player, keeping a start time and a playlist. A remote image stays an image in HTML and is a link in the EPUB, which can't hold it.
- **A page's links to local files are carried into each target.** A PDF or Word file a page links to is copied beside the page, as an image is. An EPUB can't link outside its pages, so there the link's text stays without the link, and the output check reports the file as `link-to-file-dropped`.

**Tables**

- **Title rows and bands, in HTML as in Word.** A merged row across the top becomes the caption, and merged rows partway down band the rows beneath, as does a `<tbody>` the page heads with one cell. `tables.bands` says what a banded table becomes per target: `split` (HTML, EPUB, and PDF by default) makes one table per band with the band in its caption, `group` (Markdown and AsciiDoc by default) keeps one table with a body per band, and `column`, for trying, puts the bands in a column of row-group headers. [Sidecars and reports](docs/sidecars.md).

**Links**

- **The bare-links sidecar, and shortDOIs.** Every link whose text is its own address is reported in `bare-links-new.csv`, one row per address with the citation before it. `bare-links.csv` replaces an address and its text (a shortDOI, which APA allows for a long DOI), or the text alone, or sets the link's title, or keeps it as it is. `util/shortdoi.py` fills in shortDOIs from the International DOI Foundation's service, a request a second. [Bare links](docs/bare-links.md) says why a screen-reader description couldn't do this: it fails WCAG 2.5.3 or, tested with NVDA, is read after the whole address.
- **A link's title survives from every source through every target.** Word's ScreenTips, which Pandoc 3.11's reader drops, are recovered on reading; a Markdown target writes a titled bare link in full rather than as an autolink; an AsciiDoc target writes every titled link with its title.
- **Upstream: Pandoc reads and writes Word's ScreenTips.** The project's report ([pandoc#11869](https://github.com/jgm/pandoc/issues/11869)) and patch ([pandoc#11890](https://github.com/jgm/pandoc/pull/11890), merged 2026-09-25) map a hyperlink's ScreenTip to the link's title in both directions, from Pandoc's first release after 3.11. Until the pipeline requires that release, it recovers ScreenTips itself.
- **Two output checks.** `link-label-without-text` finds a link whose `aria-label` doesn't contain its visible text, which fails WCAG 2.5.3, as 29 bare links labeled "DOI for …" did in one book. `image-alt-is-file-name` finds alt text that only repeats the file name, which is what Asciidoctor writes when an author gave none; it had hidden 49 undescribed images in one EPUB.

**Tools and documentation**

- **`adopt-pages.py`** writes a new book directory from a target's pages, for a book whose split pages should become its sources: pieces renamed, every reference following, and `contents` naming the pages as they are now.
- **When `contents` names a page the split cut**, the run writes `contents-sample.yaml` naming every piece, for anyone who means to arrange the pieces themselves.
- **`compare-output.py` compares lists and block quotes**: a quotation that became a paragraph, or a list that lost an item or a level, changes nothing it compared before.
- **`util/slim-corpus.py`** copies a corpus of Word books with nothing in each file but what the census reads; the nine-book test corpus came to 10.5 MB, with the same census totals.
- **A spelling check.** `tests/run-spelling-tests.py` fails on a UK spelling in any tracked text file, naming the file and line.
- **[Formats and packaging](docs/formats.md)**: every input, every way it can arrive, each output with how far it's tested and what it loses. And **[Worked examples](docs/examples.md)**: *Introductory Business Statistics 2e* from OpenStax's Word files and PDF to a cartridge, credited as OpenStax asks, with its bare links; and DCIC from a WARC to an EPUB and an HTML round trip, with the output each step printed.

### Changed

- **Table guessing.** `none` is guessed only with evidence (every filled cell a number or an amount, or a list laid out in columns); a table no rule recognizes is `unknown`, which asks a person to look. A banded table is guessed part by part everywhere, not only on the Word path. Two more shapes are recognized: a two-column box of labeled fields gets `first-column`, and a title row over a row of short labels gets `first-row` below the title. Across the nine-book test corpus, 39 tables that were guessed `none` are now guessed correctly.
- **The table census reads a table through a view**, not the OOXML, so the guess runs by the same rules on a table from HTML, an EPUB, or anything Pandoc reads. `table-census.py` takes directories and names each table's book, and `needs-word` is `needs-source`, since a table's headers may belong in HTML.

### Deprecated

- **`bookcontents.unrecognised_roles()` is `unrecognized_roles()`.** The old name still works, with a `DeprecationWarning`, until 1.0. No setting, option, environment variable, or report column had a UK spelling to change.

### Fixed

- **A linked image with no alt text was deleted, link and all**, by the rule that drops empty links. It's kept now, and the missing alt is reported.
- **Row headers are found by column, not by a row's first cell.** Under a cell spanning rows from above, a row's first cell is in the second column, and it was marked as the row's header.
- **A header row above the first band heads every part** when a table is split; unmarked, it had become a part of its own. And a band's non-breaking spaces stay out of its caption.
- **A declared page that the split cuts stands for its pieces** in the cartridge, the EPUB, and the contents page. Declaring a one-file book in `contents` had left every piece out.
- **A link into a split source from another page follows its target**, where only links between the pieces of one source had been rewritten.
- **A book's third run no longer stops because its own cartridge is there.** Once a directory has sources, no archive in it is read.
- **Pasting `table-headers-new.csv` in as the run says no longer warns**: the file has one row per key.
- **An image's alt text no longer describes another image that shares its name** but not its extension; an exact match is tried first.
- **Two images an HTML target would copy to one name, or two files that would be one page, stop the run**, both named, where one had silently replaced the other. So does an image that's really an HTML page, like a server's `403 Forbidden` saved under an image's name.
- **A Markdown image path written with a backslash no longer stops the run**; it's read with forward slashes, and a warning says so.
- **A page with no title is named by itself**, not by its intermediate's file name.
- **A finished page in `_pt/` no longer sends Pandoc to the network** for an iframe, and its `<footer>` or `<nav>` no longer reaches the EPUB as raw markup.
- **The packager looks for references only inside tags**, so a page quoting `<img src="/logo.png">` in its prose no longer stops the run.
- **A `pdf` or `docx` target says it's NOT YET IMPLEMENTED and is skipped**, where it had been read and filtered, then never written.
- **Reporting**: the output check counts a linked file on disk as present and a heading holding only a described image as not empty; `run-all.sh` lists the checks it skipped and why; an unpacker's notes are shown when it succeeds; the Nu checker's missing-validator note says how to provide it; `table-samples.py` shows the guess a conversion makes; and the sample document's compatibility note comes from what the sources declare.
- **The last UK-spelled names are US**, inside the filter and in its reports.

## [0.6] - 2026-09-20

Two tools and a round of what the books found. The audit is a fourth tool in the box: `audit.py` says what is wrong with a Word, Markdown, HTML, EPUB, or PDF file without converting it, in one findings format that names the standard each finding answers to, with a report a person can read and a cache that skips what hasn't changed. A markdown target can merge, so a book whose sources are one file per section comes back as one file per chapter. And *Clinical Nursing Skills* and a fresh Ubuntu each turned up things worth fixing: two table shapes the filter misread, a Pandoc package below this project's own floor, and the way the release archive is meant to be installed. Nothing here breaks a v0.5 directory.

### Added

- **`audit.py`: what is wrong with a file, without converting it.** Word and Markdown sources (read by Pandoc with no filter: alt text, table headers, bare-URL links, heading levels, raw HTML, and for Word what the census would guess), HTML pages and EPUBs (the output check and the validators), and PDFs (metadata, claims, tagging, structure tree, outline, scanned pages, fonts, with veraPDF when installed). One findings format for every check, `Where, Check, Detail, File, Kind, Severity, Standard, Tool, Fix`, whose first three columns are `output-check.csv`'s and which `output-check.csv` now uses too; a Markdown report with every input's SHA-256, so a stale report says so; a cache that skips an unchanged input. `convert.py --check-only` writes the conversion's reports and stops. Roadmap item 1. See [Auditing](docs/auditing.md).
- **A markdown target can merge.** `merge: groups` writes one file per top-level entry of the book's contents instead of one per page, so a book whose sources are one file per section comes back as one file per chapter (853 pages into 17 on the statistics book). Pages nest the way the book does, links between merged pages become links inside the file, and an id two pages shared is renamed with its page's links following it. Roadmap item 1. See [Merging sections into chapters](docs/markdown.md#merging-sections-into-chapters).
- `audit.py --report-html` and `--report-docx` write the report as a page and as a Word document (declared as the current Word format, so Word's own checker runs on it) beside the Markdown it always writes.
- With `numbering` on, each page's own heading and `<title>` carry the book's number (`16.1 Learning Objectives`), as the tables of contents and the EPUB's headings already did.

### Fixed

- A raw HTML comment in a source reached the HTML pages, where `--` inside one draws a warning from the Nu checker ("not mappable to XML 1.0") and would break an EPUB. The filter drops raw HTML comments for every target; the EPUB assembler's own removal stays for hand-written pages, which the filter doesn't see.
- Merging a book whose pages all come from one source wrote every file to the same name, so one survived. A file is named for its source only when it holds all of that source's pages; otherwise it takes its own entry's title, made unique.
- A markdown target copied media under the safe names the HTML targets use, so the Markdown it wrote (which keeps the author's paths, being source) referred to files that weren't there. Its copies keep the author's names.
- A link from one Markdown source to another by file name (`other.md#x`) now points at the page in whatever the target writes, instead of being left as a link to a file the output doesn't contain.
- [Installation](docs/installation.md) is written for a fresh Ubuntu, WSL included: how to get the tools (a release archive or a clone, with `$T` explained), what WSL is and where Microsoft's setup guide lives, `sudo apt update && sudo apt upgrade` first, the fact that Ubuntu 24.04's `pandoc` is 3.1.3 and below this project's floor (install the `.deb` from Pandoc's releases), `python3-pypdf` rather than `pip3 install pypdf` (which stops with `externally-managed-environment`, and on a fresh WSL install `pip3` isn't there), epubcheck 5.4.0, what `~/.bashrc` is and how to edit it, and a closing check that runs the suites.
- A one-cell layout table whose image the export wrapped in a bullet list stayed a table instead of becoming a figure, so the output check reported it as a data table with no headers. The scan that decides "this cell holds an image and nothing else" now looks inside list items, as it already did inside divs and block quotes. On *Clinical Nursing Skills* that is 18 of the 98 tables the check had flagged.
- Two headings with the same text on one page could come out with the same id, which no page may have: OpenStax names a bookmark for a repeated heading the way Pandoc numbers an auto id, so the reader's next candidate for the second heading was a name already taken. The filter makes every id on a page unique as its last step, renumbering the later element; an anchor keeps the name another file may link to, and links are left pointing where they pointed. Sixteen of them in *Clinical Nursing Skills*; epubcheck's matching errors go with them.

## [0.5] - 2026-09-19

The release where the pipeline stopped being a DOCX-to-HTML converter with extras. Every target in `conversion.yaml` is built from one set of intermediates, into a directory of its own: HTML pages, an EPUB, and now the book as Markdown source. Markdown is a source too, alongside Word, and a round trip through it holds: read back, *Introductory Business Statistics 2e* gives identical HTML on all 169 pages. A book's structure gained roles and numbering, footnotes learned to gather, editions can differ in a page or a passage without a second directory, and two things Word's export had always broken (cross-references and the anchors an index points at) land. Tested on seven books, two of them new this release: a 33-chapter Markdown textbook and *Clinical Nursing Skills* (379 files, an index of 2,045 entries). Two changes break a v0.4 directory; see [Upgrading from v0.4](docs/configuration.md#upgrading-from-v04).

### Breaking

- **Breaking: pages go into each target's directory, `html/` by default.** No target writes beside the sources any more; the content directory keeps the sources, the intermediates, the sidecars, and the reports. The packager reads the first HTML target's directory (`--pages`) and keeps its configuration, manifest, and archive in the content directory. Pages an earlier version left beside the sources are named on stderr and left alone. Set `output_dir: .` on a target to keep the old layout.
- **Breaking for names with spaces: a page is named after its source with spaces and other URI-special characters replaced** (`01 BigPicture.md` is the page `01-BigPicture`), and media a page refers to is copied under such a name with the reference rewritten to match. Percent-encoding the manifest's hrefs had been correct and not enough: Brightspace takes an href literally and found no page. Identifiers are XML names; an asset two pages share is in the archive once. A hand-written page with a space in its name is copied as is, with a warning, since its own links are the author's.
- **Breaking: `convert.sh` is gone.** It had been a one-line wrapper around `convert.py` since the driver moved to Python; `convert.py` takes the same arguments and does the same steps.

### Added

- **Multiple targets.** Every target in `conversion.yaml` is built, each into its own `output_dir`: several HTML renderings with different headers, footers, or options, and an EPUB, in one run. Targets whose filter-stage settings agree (the schema now marks each setting's `stage`) share one filtered intermediate; a target that differs gets its own under its output directory. A target away from the sources gets its media copied beside its pages. Reports and sidecars stay one per book. `tests/run-convert-tests.py`.
- **Markdown sources.** A `.md` beside the sources is a page, read into the same intermediate a `.docx` gets, filtered, split, and rendered by every target. `::: matrix` around a table (configurable through `tables.markers`) declares its headers; a link's `aria-label` carries through; images named by path are checked, copied beside the page in every HTML target, and packed into the EPUB, with a `%20` in a name decoded on the way to disk. Raw LaTeX passes through and is dropped by the HTML and EPUB writers. An `.md` with a same-named `.docx` is still the v0.1 leftover it always was. Tested on a 33-chapter Markdown textbook. See [Markdown sources](docs/markdown.md).
- **Markdown as a target.** `format: markdown` writes the book back as source in Pandoc's flavor, one file per source (or per page with a split), with every decision the pipeline made written as markup that reads back to it: `::: matrix` and `::: row-headers`, captions, alt text, `{.decorative}`, anchors, the author. Tables are pipe tables with Word's exact column widths carried as `widths` on the marker div; merged-cell tables and figures with ids go as fenced HTML and come back whole; a lone image is marked `[]{.inline}`. Read back, the statistics book's 169 pages give identical HTML; a second write is the fixed point. See [Markdown as a target](docs/markdown.md#markdown-as-a-target).
- **Editions from one directory.** `about.print.md` (or `.docx`, or a hand-written `.html`) replaces `about.md` for the target named `print`; a fenced div `::: {targets="epub print"}` or `{targets="!web"}` keeps a passage for some targets and drops it for the rest, resolved when each target renders. A source's opening page keeps the document's subtitle, date, and `include-before` as its title page; `title_block: off` on a target leaves them out. See [Editions](docs/configuration.md#editions).
- **Roles, numbering, and a generated contents page.** A `contents` entry can carry a `role` (`front`, `main`, `appendix`, `back`), inherited by a group's pages; `numbering: true` on the project (or `on`/`off` on a target) counts chapters, sections, and appendices the way a printed book does, in the EPUB's nav and headings, the cartridge organization, and the new contents page that `generate: toc` puts wherever it sits in `contents`. The guess reads `\frontmatter`, `\mainmatter`, `\appendix`, `\backmatter`, and `{.appendix}` from a Markdown source, so a book written for a Pandoc PDF build gets its parts right without a declaration. Additive: an existing configuration reads as before.
- **Footnote numbering and placement.** `notes.numbering` (`page` or `group`) and `notes.placement` (`page`, `group`, or `book`) rearrange footnotes after rendering, in every HTML target and in the EPUB: numbers continuing across a group's pages, notes gathered at the end of the group or on one Notes page with a heading per group. References and return links follow, the return links labelled for screen readers. Defaults are Pandoc's (per page).
- **Cross-references land.** A `.docx` is read through a repaired copy with each bookmark that stood between blocks moved into the block that follows, since Pandoc's reader drops the ones OpenStax places that way; a bookmark before a table is handed to the filter by the pre-pass and restored as an anchor ahead of the table, which a split table keeps. On *Introductory Business Statistics 2e* the 104 dead `#fs-id…` links become none. `lib/docxrepair.py`.
- **Bookmarks that only another file links to survive.** Pandoc's DOCX reader keeps a bookmark's anchor only when a link in the same document points at it (`removeOrphanAnchors`), so every index term and cross-chapter target was dropped. The repaired copy carries an invisible link to each unlinked bookmark, which the filter removes again; a bookmark before or inside a heading gets a paragraph of its own, since inside a heading Pandoc replaces its name with the heading's id. On *Clinical Nursing Skills* the dead cross-references fall from 338 to what the export itself omits: the table notes it dropped (their `*` markers remain) and a few anchors no file defines.
- **Publisher links become links here.** A link to a page of the book on the publisher's site (`https://openstax.org/books/<book>/pages/<page>#anchor`, the shape OpenStax's index and cross-references use) becomes a link to that page in every output, when the book has the page (`links.rewrite_publisher`, default on). On *Clinical Nursing Skills* that is 4,627 links, the whole index among them. Roadmap item 4, done.
- **Hand-written pages are in every output.** An `.html` beside the sources with no `.docx` behind it is copied into every HTML target with the local files it refers to, read into an intermediate so the EPUB carries it, packaged, and checked.
- The output check flags a data table outside the scroll wrapper; a unit test holds `page.css`'s colors to 4.5:1 and the caption color to 7:1.

### Changed

- **The driver is Python.** The driver is Python: the same steps, the same reports, the same output (checked page for page with `compare-output.py` on four books, which say `Runs agree`), with every comment that recorded what the shell script had learned carried over. `--quiet` turns off the command trace `set -x` used to give; unknown arguments still pass to the packager. `convert.sh` remains as a wrapper that runs it, for one release, so documented commands keep working.
- The unit tests call `convert.py`'s path helpers directly rather than reading the shell script's source; the check that the script's built-in defaults matched the schema is retired, since the Python reads the schema.

### Fixed

- A table is as wide as its content and no wider than the page, instead of stretched to the margins: `width: 100%` had come along with the rule that restores `display: table`.
- A piece cut from a source no longer inherits the source document's front matter (`subtitle`, `date`, `abstract`, `include-before`, `include-after`, `toc`); Pandoc's page template rendered it, so the first section of a Markdown book opened with the book's copyright line and epigraph. The source's own opening page keeps them: that is the title page.
- Alt text no longer carries the non-breaking space Pandoc's `smart` extension puts after an abbreviation ("vs.", "e.g."); there is no line to hold together in an attribute, and `--ascii` wrote it as `&nbsp;`.
- The guess's chapter branch (numbered file names) emitted front and back matter without their roles, so a glossary pinned last still counted as a chapter once numbering was on. Both branches now say what they know, and a `\\frontmatter`, `\\appendix`, or `\\backmatter` in a page that isn't split gives that page its role, as `{.appendix}` on its heading already did.
- The filename guess puts a page whose name holds a front-matter word (or starts with `_`) first and one with a back-matter word (`glossary`, `appendix`, …) last, in every branch, not only once numbered chapters were found. And the EPUB assembler seeds a source's title from its pieces when the source has no page of its own, as the packager already did; a chapter whose sections start right under its heading was named by its file.
- Footnotes in the EPUB had no number where they appeared: the writer's `aside` carries none, on the assumption of a reading system that pops notes up. Each note now opens with its number and ends with a return link, as Pandoc's HTML writer does.
- An EPUB page whose stem had a space got ids with a space in them, and a raw HTML comment holding `--` (a citation, say) was fatal in XHTML. The assembler makes ids from a sanitized stem and drops raw HTML comments; the output check flags an id with whitespace.
- An EPUB chapter whose heading held `<em>` or `<sup>` had them inside its `<title>`, which XHTML forbids (four chapters of the statistics book; epubcheck `RSC-005`). The chapter `<title>` is now set from the heading's text after the archive is written, since the writer offers no plain-text form of a chapter's heading.

## [0.4] - 2026-09-19

EPUB output, and pages that need not be files. ### Added

- **Output checking.** Every run ends by checking the pages it wrote and any EPUB built from them, and writes what it finds to `output-check.csv`: links and fragments that resolve to nothing, images with no alt attribute or an empty one without `role="presentation"`, headings that skip a level, duplicate ids, tables with neither header cells nor a caption, pages with no language or title, and an EPUB whose manifest, spine, and archive disagree or whose package document lacks the required metadata. Nothing but the standard library; the run isn't stopped by a finding. - `--toc` reads an EPUB as well as a PDF: the navigation document of an EPUB 3, or `toc.ncx` in an EPUB 2, gives the same `(depth, title)` outline the PDF's bookmarks do, and OpenStax publishes both. Nothing to install for the EPUB.
- **EPUB cover.** `epub.cover_image` names the image and `epub.cover_alt` what a screen reader says for it, defaulting to "Cover of" and the title. Pandoc's cover page is an SVG with no text alternative; the assembler gives it `role="img"`, an `aria-label`, and a `<title>`.

Pandoc's DOCX reader turns every `Title` paragraph after the first into a plain paragraph, so a book styled `Title` for its modules arrives with no modules; this is what fixes that before conversion. Empty paragraphs of a remapped style are dropped.
- **Page splitting.** `pages.split_level` cuts each source into one page per heading of that level or shallower, on the filtered intermediate, after the filter and before the render, so a book that arrived as one file per chapter gets one page per section in every output. The heading becomes the piece's title and stays as an anchor; body headings move up; links between pieces are rewritten and the EPUB assembler resolves them within the book. Pieces are named `<source>--<heading>` unless `page-names.csv` says otherwise, and each records its source and part in its metadata and `<head>`, which the packager and the assembler read to group the pieces under their source without a `contents` tree. New: `bin/split-pages.py`, the `page_names` sidecar, the `page_names_new` and `page_names_report` reports, `tests/run-split-tests.py`, and [Splitting pages](docs/splitting.md).
- **EPUB3 output.** A conversion target with `format: epub3` assembles every page in `project.contents` into one EPUB, built by the new `bin/build-epub.py` after the pages are rendered. The table of contents is the same tree the cartridge organization uses: a group is a heading over its pages, a page a heading at its depth, and a page's own headings continue below it, so the depth at which something appears is its rank in the book and not a fact about the file it came from. Each page is its own file, titled by its heading; ids are prefixed per page so two pages sharing one keep their links straight. The package document's accessibility claims (`accessMode`, `accessModeSufficient`, `accessibilityFeature`, `accessibilitySummary`) are computed from the build rather than asserted: `alternativeText` only when every image has it, `MathML` only when there are equations. See [Building an EPUB](docs/epub.md).
- Settings: `filename` on a target, an `epub:` section (`toc_depth`, `accessibility_summary`), and `project.authors`, recorded as the EPUB's creators.
- `read-conversion-config.py --format`, which is how `convert.sh` keeps the `html` target when an `epub3` one is declared beside it.

### Fixed

## [0.3] - 2026-09-18

The table-headers sidecar, complete: the sidecar, the key, and the report exist; the conversion applies the value in effect for every data table; a merged title row becomes the caption; and a table with grouping bands becomes one table per band. Output changes for tables declared or guessed to have a header column, an unmarked header row, no headers, a title row, or bands.

### Added

- `bin/table-headers.py`, a pre-pass `convert.sh` runs on the DOCX files before Pandoc. For every data table it computes a sidecar key, reads what `table-headers.csv` declares, asks the guess for the rest, and writes `table-headers-report.csv`. Tables with no sidecar row get a prefilled row in `table-headers-new.csv`, in the sidecar's own format, ready to paste in; that file is removed when there are none. A sidecar row whose key matches no table stops the run after writing the report, on the reasoning that a correction that silently fails to apply destroys work invisibly. Values this version doesn't act on (`manual`, `list`, `split-at`, `caption-rows`) are accepted and kept; a value it doesn't recognize is warned about once and read as blank.
- `lib/tablecensus.py`: the classification, the guess, and the key, moved out of `util/table-census.py` so the pre-pass and the census tool share one implementation. The key is a SHA-256 over every cell's text in row order, with edge whitespace stripped and nothing else normalized, plus the table's row count, column count, and per-row cell counts; a cell holding a nested table contributes that table's key. Computed on the source before any transformation, so it survives everything the pipeline does and changes only when the source table changes. Measured on a chapter Word had rewritten on save: all six tables kept their keys while every media part was renamed.
- Settings `sidecars.table_headers`, `reports.table_headers_new`, and `reports.table_headers_report`.
- `tests/run-headers-tests.py`, 23 checks over the pre-pass end to end, and 9 key checks in `tests/run-census-tests.py`.

- `util/table-census.py` reports a `Guess` column beside `Kind`: the value a table-headers sidecar would be prefilled with, for every data table. `Kind` is what the file says, `Guess` is what to declare, and a row where they differ is a row worth looking at. Across seven books (1,271 documents, 2,068 tables, 792 of them data tables) the guess gives 462 `both`, 264 `first-row`, 37 `none`, 28 `first-column`, and 1 `unknown`. The header mechanism it feeds behaves identically on Pandoc 3.1.3, 3.9, and 3.11, so this needs no version bump.
- `util/contrib/fix-empty-paragraphs.py`, contributed from another project and not wired in. It removes content-free paragraph structure elements from a tagged PDF, two sources of which are the longtable caption wrapper and Pandoc's minipage header cells. Needs `pikepdf`. See roadmap item 5.
- `tests/run-census-tests.py` checks that guess against thirteen table shapes built as OOXML directly, so each one carries exactly the formatting signals it means to and no table style decides the answer first. Registered in `tests/run-all.sh`.

- `util/table-samples.py` collects one real example of each table shape into a single Word document, copied out of the sources rather than rebuilt, so the style, table-look flags, merges, repeat-header rows, direct formatting, images, and links all come across. Each example is annotated with its census kind, its guessed value, the evidence read from the file, and which rule produced that value. Deterministic by default; `--random` or `--seed N` samples other examples of the same shapes.
- `util/docx-compat.py` reads, and optionally sets, the `compatibilityMode` compat setting that decides whether Word treats a document as current or opens it in Compatibility Mode, where it refuses to run its Accessibility Checker. Every other part of the package is copied through untouched, and legacy compat option elements are reported rather than cleared.

### Documentation

- The README is an overview and a quick start; everything else moved under `docs/`, one page per subject: installation, a first run, how it works, configuration, sidecars and reports, building the cartridge, Brightspace, testing, utilities, and troubleshooting with the known limits. The three settings references are generated from the schemas by `util/settings-reference.py`, so they can't describe a setting the tools don't have, and `run-all.sh` fails when a schema changes without them.

### Fixed

- `--toc` said nothing when it did nothing. It orders only pages the config doesn't place, so a `packaging.yaml` adopted from the first run's sample—which already places every page in a guessed order—left the outline with nothing to do, and the run gave no sign. It now warns, says what to do (remove the `contents` block and run again), and writes the same note into the sample. The README's walkthrough says to run `--toc` before adopting the sample and why.

### Changed

- **The conversion applies each table's header declaration.** The filter reads what the pre-pass resolved—the sidecar's value where one was declared, the guess otherwise—and sets `row_head_columns` and `scope="row"` for a header column, promotes an unmarked first row into the table head for `first-row` and `both`, and moves a reader-built head back into the body for `none` and `first-column`. A blank, `manual`, or `list` leaves the table as Pandoc gave it. Each resolved value is checked against the table's shape and first cell before it's applied, and refused with a warning on a mismatch, so a disagreement between the pre-pass's count of tables and the filter's can't put a declaration on the wrong table. Measured on *Introductory Business Statistics 2e* against the previous pipeline: 124 of 169 pages identical; on the 45 that differ, 228 tables gained row headers, 31 unmarked header rows were promoted, and one merged title row that had been a spanning header cell is no longer one (the caption it should be is step 3).
- **A merged title row becomes the caption.** `caption-rows=N,M` in the sidecar names rows to fold into the caption; the pre-pass infers `caption-rows=1` for a merged full-width first row and writes it into the prefilled row, so the decision is visible and a person can remove it. The row is taken out of the table and its content follows the label after a space, or an existing caption after a full stop; a bare label with a title row is no longer reported as missing a description. The row's inlines are carried, not its text, so an equation in a title row stays an equation. Measured on *Introductory Business Statistics 2e*: 11 tables change, on 2 pages; each loses a header cell spanning the table and gains the title in its caption; 11 rows leave `table-captions-missing.csv`; the page's count of equations is unchanged.
- **A table with grouping bands becomes one table per band.** `split-at=N,M` in the sidecar names the band rows; the pre-pass infers it for merged full-width rows below row 1 and writes it into the prefilled row. When row 1 is itself a band with bands below it, row 1 joins `split-at` rather than becoming `caption-rows=1`, since it's the first band and not a title. Each part gets the band as its caption composed onto the table's own—"Table 17.4: Year 2"—or a caption from `part-captions`; a copy of the table's marked header rows where it had any; and the header declaration applied on its own, so a table whose bands each cover their own header row splits into parts that each keep theirs. A split row with several cells can't be a caption, so it's the part's own header row and only its corner cell goes into the caption: a bold header row that repeats down the table with a group's name in its corner—Table 7.2 of *Introduction to Sociology 3e*, and two tables in *Economics 3e*—is inferred as a split and becomes one table per group, each headed by its repeat. The guess for a banded table is taken part by part, with the shared header rows in place, and the parts vote; read whole, the bands break every rule and such a table guessed `none`. Measured on *Principles of Economics 3e* against the previous step: 414 of 419 pages identical; the other 5 hold the book's four banded tables, which become fourteen.
- **Breaking.** `table-headers-missing.csv` is retired, and with it the `reports.table_headers_missing` setting; a configuration that still names that key is refused as unknown. A `packaging.yaml` adopted from a v0.2 sample is unaffected, since the sample never wrote the conversion `reports` settings; only a configuration that named the key by hand needs the line removed. What the report covered—tables with no header row—is answerable by a sidecar value wherever the header text exists, and where it doesn't, the report's `needs-word` status says so.
- Cell text now includes equations and respects line structure. A cell's content can be an OMML equation rather than runs of text, and 336 cells across the corpus looked empty to a `w:t`-only reader; paragraphs and line breaks inside a cell are separated rather than run together. Both matter for the guess and more for a key computed from cell text, where three tables in the statistics book hashed identically.
- The guess reads more shapes, each measured against the corpus: a numeric first column must be ordered to count as a key column, a blank corner with labels along both edges is a matrix whatever the body holds, a row of words over rows of numbers is a header row, values with their units written out (`$120 billion`) count as values, the values test is asked per column rather than over the whole body, an unlabeled trailing summary row is set aside, and one-column tables are no longer disqualified by tests written for merged rows.
- `guess()` is now a thin wrapper over `explain()`, which returns the value and the reason together, so the reason can't drift from the decision.
- A new `unknown` value covers a table whose header band the four values can't place—a claim about the guess rather than about the table, kept distinct from `none`.
- The vocabulary for header shapes is `first-row`, `first-column`, `both`, and `none`, naming the line that holds the headers. It previously used `col` for a header *row* and `row` for a header *column*, which is the opposite of how LaTeX's `table/header-rows` and `table/header-columns` read. No sidecar format has shipped with the old names, so there's nothing to migrate.

## [0.2] - 2026-09-12

Two major structural changes to prepare for future work: the conversion pipeline is now routed through JSON instead of Markdown, and the configuration is no longer described in three hand-maintained places. Both were prompted by the same discovery: settings and structure were being lost silently, in ways no report caught and no error announced. Converting *Introductory Business Statistics 2e* with v0.2 produces 169 of 169 pages semantically identical to v0.1, apart from the fixes below, and every one recovers something v0.1 dropped.

Three of the breaking changes need action before a first run with v0.2: split your configuration, rebuild your cartridge, and tell instructors how to re-import it. See [Upgrading](#upgrading-from-01).

### Added

- Pandoc's own document model, as JSON, is now the conversion intermediate. It's lossless where Markdown wasn't: Markdown has no syntax for a cell attribute or a header column, which are exactly what accessibility remediation produces.
- Every setting is declared in a schema with a type, a default, and a sentence of documentation. The readers, the validator, the sample writer, and the generated files all derive from it, so there's no second list to drift out of step with the first. 42 settings are now declared where 8 were reachable from the configuration file; the rest existed only as environment variables documented in a Lua comment.
- `bin/validate-manifest.py` checks the manifest against the Common Cartridge 1.1 schemas before an archive is built from it. The schemas are bundled in `schemas/cc11/`, unmodified and redistributed under their own terms, so validation needs no network. Full validation uses `lxml`, which is optional: without it the check falls back to well-formedness, identifier syntax, and unresolved references, and says which level ran.
- Chapters are wrapped in one module named after the book. An LMS never merges an imported structure with one already in the course; it appends. A re-import therefore always leaves a second copy, and this makes that one module to remove rather than one per chapter. `organization.wrap_in_module` turns it off, and `organization.module_title` is a template — `"{title} ({version})"` by default, because after a re-import two modules otherwise carry the same name and nothing tells them apart.
- `bin/media-extensions.lua` names extracted images by their real content type while they're still in memory, before anything is written.
- `util/compare-output.py` compares two conversion runs semantically, reporting what carries meaning rather than what changed byte for byte.
- `util/table-census.py` surveys table structure across a corpus of DOCX files.
- `util/migrate-config.py` splits a v0.1 configuration into the three v0.2 files, reporting where every setting lands and refusing to overwrite anything.
- `tests/` holds five suites, run together by `tests/run-all.sh`: a portability check over every Python file; twenty-two configuration conformance fixtures; a round-trip check that writing a configuration and reading it back changes nothing; unit checks over the functions that decide filenames and directory names, plus the places where one fact is written down twice; and filter tests that convert six small committed `.docx` fixtures and assert on the accessibility markup. Every filter bug fixed in this release was silent and was found by comparing two runs of a real book, which only works while the previous version is available; the fixtures make the same checks self-contained.
- `read-conversion-config.py --init` and `build-cartridge.py --init` each write a complete, documented configuration file. Between them there's a way to generate every one, which matters now that there's no example to copy.
- `--allow-unknown-keys` reports settings this version doesn't recognize instead of refusing them, and keeps them if the configuration is rewritten.
- `build-cartridge.py --target` selects which package to build when a configuration defines more than one, and `--no-validate` builds an archive from a manifest that didn't validate.
- `images.responsive` and `tables.wrap` are configurable, having been hardcoded.

### Changed

- **Breaking:** `imsmanifest.yaml` is replaced by three files, split by what a setting describes rather than which script reads it: `project.yaml` for the book, `conversion.yaml` for how it's rendered, `packaging.yaml` for how it's archived. Both halves stop with directions rather than ignoring an old configuration. Run `util/migrate-config.py`.
- **Breaking:** Every file in a package now sits inside one directory named after the book, so two books can't share a path. This relocates every file, so an instructor with an existing import gets a second copy rather than an update and has to remove the old module once — in an order that matters, since doing it backwards leaves a window with no content. `paths.prefix_content: false` restores the old behavior.
- **Breaking:** Pandoc 3.9 or later is required, up from 3, and checked before any work starts. Earlier versions accept most of the command line and quietly do something else: 3.6 and older write tables without cell spans, so a table with merged cells loses them with no warning at all. Upgrading to Pandoc 3.11 (current as of this date) should work best.
- **Breaking:** Python 3 is required rather than optional. It reads the configuration and inspects the conversion intermediates.
- **Breaking:** `build-cartridge.py --emit-conversion-config` is retired. `convert.sh` used to ask the packaging tool to parse its configuration, so a folder of documents couldn't be converted without it present. Both halves now use the shared library in `lib/` and neither uses the other.
- Reports are written to the book's directory rather than beside the scripts. In v0.1 those were the same place, because the scripts were copied into the content directory. From v0.2 the tools stay where they were cloned, so leaving the reports there would mean two books overwriting each other's.
- Sidecars default to the book's directory too, but that's only a default. They are read rather than written, and they hold the one thing in the pipeline no script can reproduce, so the directory you delete to rebuild is the wrong permanent home for them. `sidecars.table_captions` and `sidecars.image_alt` take a path: absolute, or relative to the book's directory, so corrections can live somewhere version-controlled. See [Sidecar files](docs/sidecars.md#sidecar-files).
- A configuration that can't be read stops the run. It was reported and then ignored, so a book would convert with the defaults while the user believed their settings had applied. A directory with no configuration still converts with the defaults, as before.
- A setting written twice in the same block is refused. PyYAML keeps the last and says nothing, which is a poor bargain when generated configuration files already contain every setting.
- A misplaced setting says where it belongs. `footer` at the top level (where v0.1 put it) now reports that it's a setting and belongs under `defaults:`, rather than reporting only that it was unexpected.
- `project.identifier` is checked as an XML name at load time rather than failing at import time. IMS types it as `xs:ID`, so it must start with a letter and contain no colons, which rules out both obvious ways of writing a globally unique identifier: a bare UUID usually starts with a digit, and `urn:uuid:` has colons.
- Generated configuration files include the settings that belong to a target: `format`, `output_dir`, `filename`, `includes`. They can't go in the defaults block, and were previously written only where a target overrode them, so five settings existed, were read, and were documented nowhere.
- A package's `filename` is derived on every run from the book's identifier and the format's extension rather than written into the file, so renaming the book renames the archive. Two packages of the same format are reported rather than left to overwrite each other.
- The tree is reorganized into `bin/`, `lib/`, `util/`, `tests/`, and `schemas/`, with the documentation at the root.
- Configuration errors print a message rather than a Python traceback.

### Fixed

- An absolute sidecar path in the configuration was silently ignored. `convert.sh` resolved every name as `$PWD/$name`, so `/srv/corrections/table-captions.csv` became `/book//srv/corrections/table-captions.csv`. The book converted, every correction in the file was discarded, the tables reappeared in the missing report as though nobody had written a caption, and the only trace was an instruction to append the work to a path that didn't exist. A path that the configuration names but the run can't read is now an error.
- A line of `lib/oerconfig.py` needed Python 3.12. An f-string replacement field spanned two lines, which PEP 701 permits and every earlier version rejects, so the file was a syntax error on anything older and took three of the four test suites with it. A syntax error is invisible to an interpreter new enough to accept it, so no suite could have caught this: `tests/run-portability-test.py` checks the source against Python 3.9 instead, and runs first.
- Every cartridge this project produced was invalid. The manifest carried a `lomimscc:version` element inside `lifeCycle`, where the CC 1.1 profile permits `contribute` alone and declares no `version` element anywhere. Every LMS accepted it, which is why it went unnoticed until the manifest was validated against the schema.
- Alt text could be applied to the wrong image. Converting a DOCX straight to HTML in one pass, the filter sees the raw mediabag path `media/rId26.so` rather than `1-3-foo/media/rId26.png`, because `--extract-media` rewrites the paths after filters run, so every document in a book collided on the same sidecar keys. Keys are now qualified by the source document. The two-step conversion `convert.sh` performs never had the collision, because step 1 has already rewritten the paths by the time the filter runs in step 2, which is why this needed a single-pass test to cover at all.
- Page language disagreed with package language. `convert.sh` hardcoded `-M lang=en` while the manifest read its own separate setting, so a book in any other language shipped pages contradicting the package describing them, and nothing checked.
- Blank worksheet tables were destroyed. Markdown's writer chose a layout whose empty rows read back as paragraph breaks, reducing a ten-row table to a single empty cell. Three tables across the three OpenStax books.
- Conditional-probability expressions containing `|` were lost, three per page in the statistics book.
- Twelve captions weren't being found. Word's list-paragraph style stores a bare label as a one-item list, which Markdown used to flatten.
- Two `<h1>` elements appeared on every page, and titles lost their section number. Pandoc's docx reader turns a paragraph styled `Title` into title metadata, and every OpenStax file has one (saying the same thing as the H1 without its section number). The existing title then blocked the filter's heading promotion.
- A visible "OpenStax" byline appeared under every page title, from an `Author`-styled paragraph read the same way. `author_byline` now keeps the metadata in the page head and suppresses the byline.
- A caption written against a generated position key stopped applying once the table's real label was found. The lookup now tries both, so no sidecar needs rewriting.
- The sample configuration writer dropped three settings (`captions`, `grouping`, and `manifest.modified`) from a file it described as complete and told the user to rename over their own. A round-trip test now asserts that nothing is lost.
- An explicitly empty setting was overruled by its default: `unsorted_title: ""` came out as `Unsorted`, and `back_matter: []` fell back to the built-in order.
- The built-in back-matter order and its documented default disagreed, the latter missing seven entries including `key-concepts-and-summary`.
- A reverse-DNS style identifier produced an archive with no extension. `org.example.book-2e` was read as a filename whose extension was `.book-2e`, so nothing was appended.
- Media that Word declares as `application/octet-stream` produced `.so` files, which Pandoc writes as `<embed>` rather than `<img>`—a page that validates yet shows nothing. Renaming now happens before anything is written, so the file and the reference can't disagree.
- Alt text kept leading whitespace, which a screen reader ignores but which counted against the length limit, so reported character counts disagreed with what a person counts. The trimmed text is now what gets written back as well, so the measured and the emitted value are the same string.
- `python3` was required but unchecked, so a machine without it failed part-way through a run with the intermediates already written.

### Removed

- The Markdown intermediate. Files left behind by v0.1 are named on stderr and otherwise ignored; nothing reads them, and the scripts won't delete files you may want.
- `conf/imsmanifest.example.yaml`. Sample configurations are generated from the schema, complete and documented, so a hand-maintained example is the second list that drifts.
- Roughly 160 lines of media repair in `convert.sh`, which walked the Markdown with `grep` and `sed` because by then it was the only option left. What remains is a check, kept because the failure it guards against is invisible.

### Upgrading from 0.1

```bash
python3 util/migrate-config.py -d . --dry-run   # see where everything goes
python3 util/migrate-config.py -d .
```

Sidecar files need no migration, and can now be moved out of the book's directory: see [Sidecar files](docs/sidecars.md#sidecar-files). If you tried an absolute path before and found it had no effect, that was the bug above rather than your CSV. For the cartridge, see [How Brightspace treats an imported cartridge](docs/brightspace.md), in particular the order in which instructors should import the new package and remove the old module, and which of Brightspace's two delete options is safe when. (We haven't tested on other LMS software.)
