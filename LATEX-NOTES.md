# LaTeX notes

What LaTeX, its packages, and LuaTeX do, as read from their source or established by test, for the questions this project keeps asking. Separate from PANDOC-NOTES.md because it's about LaTeX, not Pandoc, and from PROJECT-NOTES.md because it's not about us. Read this before answering a "what does LaTeX do when…" question, and read the source before running an experiment: TeX Live 2026's tree is in the working container under `/opt/ubuntu-tex/usr/share/texlive/texmf-dist/tex/` (Debian's packages, Ubuntu 26.10's snapshot of 2026-07-11: LaTeX 2026-06-01, l3kernel 2026-06-18, tagpdf 1.0c, luamml 0.9.2), and the wrappers in `/opt/tl2026/bin` run LuaLaTeX in that root by `chroot`, on files under `/opt/ubuntu-tex/tmp`, with `TMPDIR` there too. TinyTeX's bundle, brought up to date with `tlmgr update --self --all`, has later releases of some of these files (tagpdf 1.0g or 1.0h, latex-lab 2026-06-01a, l3kernel 2026-09-09), so each entry says which release a fact was read or measured at, and whether it was read from the source or measured. What TextbookImprover does about a fact is named at its end: the LaTeX a PDF from the pages gets is in `lib/latexbuild.py` (`PDF_MACROS`, `FIT_MACROS`, `PICTURE_PATHS`, `UA1_LINKS`, `CODE_SPACES`, `UM_ALIASES`, `FLOATS_HERE`), `bin/build-pdf.py`, `bin/pdf-target.lua`, and `bin/footnote-code.lua`, and what a LaTeX book's tagged copy gets is in `lib/texremediate.py`. Where a fact is Pandoc's output meeting LaTeX, the Pandoc half is in PANDOC-NOTES.md.

## Releases and resources

**A tagged build needs LaTeX 2026-06-01.** The tagging project describes tagging as usable in production from the release of 2025-11-01, for documents that keep to packages that support it ([its site](https://latex3.github.io/tagging-project/)), but measured with every suite on `main` at 01df4ec, Ubuntu 26.04's TeX Live 2025 (LaTeX 2025-11-01, tagpdf 0.99x, luamml 0.7.0) fails 14 checks where Debian's TeX Live 2026 (LaTeX 2026-06-01, tagpdf 1.0c, luamml 0.9.2) fails none. Two builds stop: a PDF/UA-1 book, whose `math/setup={mathml-AF,mathml-MS}` 2025-11-01 doesn't take ("The key '__tag/setup/math/__setup/mathml-MS' is unknown"), and a tagged document with enumitem's `leftmargin=*` ("Package block Error: Some keys specified on the itemize environment are unknown"). The rest build wrong: a table cell's formulas get no Formula and no MathML, and an `eqnarray*`'s rows are one Formula without a MathML file; figures' tags are gathered at the end of the document, `float/here` not existing yet; the enumerate package's labels repeat ("(a) First part (a) Second part") and a theorem's heading loses its period; and a source copy's `\begin{picture}[alt=…]` stops pdfLaTeX. Ubuntu 24.04's TeX Live 2023 (LaTeX 2023-11-01) failed 28, and no LaTeX release falls between 2025-11-01 and 2026-06-01. `latexbuild.MINIMUM_LATEX` is 2026-06-01, and `latexbuild.latex_problem` reads the release LuaLaTeX runs from `\fmtversion` and refuses an older one (CNX-NOTES, item 7, and TeX Live versions, measured).

**An older LaTeX can't open a tagged document at all.** Older releases load `pdfmanagement-testphase.sty` for `\DocumentMetadata`, where current ones load `pdfmanagement-init` (`documentmetadata-support.ltx`, read: its copy of 2026-06-15 requires `pdfmanagement-init`), and Ubuntu 24.04's packages (LaTeX 2023-11-01) stop on that file not found (`latexbuild.py`'s comment on `MINIMUM_LATEX`); Ubuntu's 2023 `lualatex` doesn't know `\DocumentMetadata`'s `tagging` key (PROJECT-NOTES' process notes). A TeX Live 2026 installed before its June update has LaTeX 2025-11-01 until `tlmgr update --self --all`, and TeX Live 2025's LaTeX stopped at 2025-11-01 (`docs/installation.md`).

**pdfLaTeX keeps a tagged document's structure in TeX's main memory, which a book outgrows.** GIAM with `\DocumentMetadata` doesn't build with `pdflatex`: TeX's main memory (5,000,000) runs out, so a tagged book is built with LuaLaTeX, a change to the author's build that Rob accepted (measured, 2026-10-05). Untagged, the same tree builds with pdfLaTeX. `texremediate` takes out what forces pdfTeX: the `pdftex` option of `\documentclass`, `\usepackage`, and `\RequirePackage`, and settings such as `\pdfcompresslevel=9`.

**LuaTeX grows its main memory as it goes.** A test that only grew the page never got "TeX capacity exceeded": LuaTeX grew until it was killed, and Pandoc's log ended without the error; a million names fill LuaTeX's strings in 5 s, and `\def\a{\a\relax}\a` fills the input stack (measured, 2026-10-05). A large tagged book can outgrow strings, hash, or memory, since tagging keeps every structure element (Prescott, TUGboat 47:2). `latexbuild.failure_advice` names the table that ran out and the variable that raises it (`max_strings`, `hash_extra`, and `extra_mem_top` and `extra_mem_bot` for pdfTeX's main memory, in `texmf.cnf` or the environment; [tex.stackexchange.com/a/741777](https://tex.stackexchange.com/a/741777/)), and calls an overflowing stack a macro that calls itself.

**Tagging costs time per pass, not passes.** GIAM takes 5 s a pass with pdfLaTeX, 7 s with LuaLaTeX, and 52 s tagged (2026-10-05); `latexmk -lualatex` ran LuaLaTeX four times on the tagged copy (235 s), as the author's Makefile runs pdfLaTeX four times. MathML adds more: with MathML as structure elements and attached files the copy built from clean in 481 s, with the attached files alone 257 s, and without MathML 226 s, so the structure elements cost most of it (2026-10-06). Bergmann's Java book: 11 s a pass untagged, 75 tagged.

**A LuaLaTeX run on a large book or chapter can take nearly 3 GB.** _Instrumental Analysis_'s PDF needs about 2.6 GB, and _College Algebra with Corequisite Support 2e_'s chapter 7 took 2.9 GB, against the container's limit of about 5.8 GB for the shell's commands. A run the kernel kills ("Memory cgroup out of memory") leaves its `.aux` cut off, and the next run stops at `\begin{document}` ("File ended while scanning use of \@newl@bel"), so a build that fails so is run again alone before it's taken for a fault of the code (PROJECT-NOTES' process notes, 2026-10-23 and 24).

**A class or package loaded inside a group stops LaTeX.** `\@fileswithoptions` raises "Loading a class or package in a group" when `\currentgrouplevel` is above zero (read in `latex.ltx`, 2026-06-01). _OpenIntro Statistics_' `style.tex` opens a brace on line 346 that nothing closes, so hyperref and biblatex, loaded at `\begin{document}`, stopped its build, a check releases before 2025 didn't make (PROJECT-NOTES, _OpenIntro Statistics_); `latexsource.brace_problems` names such a brace by file and line.

## LaTeX's tagging code

Read in TeX Live 2026's latex-lab (the block module 1.0c of 2026-06-10; enumitem's emulation 0.80f of 2026-04-21; the table module 0.85t, the graphic module 0.80i, the toc module 0.85k, and the footnote module 0.8p of 2026-04-28; the float module 0.81n of 2026-04-24; the math module 0.7e of 2026-05-27; firstaid 0.85x of 2026-06-08), tagpdf 1.0c (2026-05-17), and pdfmanagement 0.97c (2026-05-26), and measured with LaTeX 2026-06-01, unless an entry says otherwise.

### Lists and their labels

**An item's label waits in the tagging code's own box until the item's first paragraph begins, so a list's item that opens with highlighted code loses its number.** LaTeX's tagging code for lists (`latex-lab-testphase-block.sty`) keeps an item's label in `\g__block_labels_box`, not in `\@labels`, and sets it when the item's first paragraph begins (the `para/begin` hook, `\__block_item_everypar_std:`); `\item` adds its label to that box with `\hbox_gset:Nn`, unpacking what's there first. fancyvrb's list begins no paragraph: it sets `\@inlabel` false (`\FV@ListVSpace`) and puts `\@labels`, empty under tagging, beside its first line (`\FV@ListProcessLine@i`), and latex-lab's first aid for fancyvrb (`latex-lab-testphase-firstaid.sty`) keeps that. Pandoc writes an item that opens with highlighted code as `\item` and, on the next line, `\begin{Shaded}` around fancyvrb's `Highlighting`, `Shaded` empty unless the highlighting style has a background, when it's framed's `snugshade`, which isn't involved. In a tagged PDF the item's label waited, and the next `\item`, finding `\@inlabel` false, added its own to the same box, so both were set at the next paragraph, "2." over "3."; the structure had each label in its own item's Lbl. Untagged, `\@labels` holds the label and fancyvrb sets it in place, and an item that opens with code in no language, LaTeX's verbatim, which sets each line as a paragraph, has its number either way. Read in the block module 1.0c and fancyvrb 4.6a, and measured 2026-10-28 with Pandoc 3.13 and TeX Live 2026. `latexbuild.PDF_MACROS` moves a waiting label to `\@labels` before `\FV@ListVSpace` clears `\@inlabel` (`cmd/FV@ListVSpace/before`, added once fancyvrb is loaded), only where a label waits and only where the tagging code's box exists, so a fix of LaTeX's own isn't undone (CNX-NOTES, item 103); a LaTeX book's tagged copy doesn't get it, and no book here needs it. Not among the problems the tagging project's issue on fancyvrb lists ([latex3/tagging-project#741](https://github.com/latex3/tagging-project/issues/741)). A LaTeX file of 16 lines shows it with LuaLaTeX and pdfLaTeX, with LaTeX 2026-06-01 and with the latex-dev pre-release in this tree ("2026-11-01 pre-release-0 (develop 2026-10-24 branch)"), and the same hook in that file's preamble fixes it with both engines; LaTeX's own `verbatim` in its place keeps the number (measured 2026-10-28). A report for latex3/tagging-project is drafted for Rob to file, the file and the hook in it (Round 30, `fancyvrb-bug-report.md`); the tracker's own search isn't reachable from this container, and a web search found no report of it.

**An untagged build sets an item's label from `\everypar`.** A box's rule that cleared `\everypar` while a list's item, a quotation's, or a definition's label waited for the item's first paragraph stopped an untagged build ("perhaps a missing \item"), found by a review (CNX-NOTES, item 39). `\OERBoxRule` leaves `\everypar` alone while `@inlabel` is true.

**`\item`'s optional argument is read as keys when it holds an `=`.** The block module redefines `\item` at `begindocument/before` as `\RenewDocumentCommand{\item}{ ={label}o }`, so an argument with an `=` in it is a list of keys, and keys it doesn't know stop LaTeX: "Package block Error: Some keys specified on the \item command are unknown" (read in the block module 1.0c). A description list's term is `\item[term]`, so a term such as "x = 1" stopped the PDF until Pandoc 3.13 braced it (jgm/pandoc#11954); one whose `=` is in math, code, a link, or emphasis builds, its argument a command's (measured with 3.12.1, 3.13, and LaTeX 2026-06-01, 2026-10-26). `pdf-target.lua`'s `term_braces` braces such a term for an older Pandoc.

**Lists are laid out by an emulation of enumitem, which lacks most of enumitem's keys.** The block module replaces `enumitem.sty` with nothing (`\declare@file@substitution{enumitem.sty}{null}`) and loads `latex-lab-enumitem.sty` (0.80f, 2026-04-21), whose keys map to the block templates' own: `leftmargin` is `left-margin` and `labelwidth` is `label-width`, dimensions, so `leftmargin=*` and `labelwidth=*` stop LaTeX ("Missing number"), and `style`, `labelindent`, `widest`, `left`, `ref`, `label*`, `before`, `after`, and `series` aren't keys of it or of the block module's list template, so LaTeX stops on them as unknown ("Some keys specified on the itemize environment are unknown"). Read in TeX Live 2026's files; measured on FINC 308, whose 96 lists use `leftmargin=*` (2026-10-06). For a LaTeX book's tagged copy, `texremediate.ENUMITEM_KEYS` defines each missing key: a width to compute or a label's indent is left to the emulation's defaults, `resume` continues the numbering, `nolistsep` is `nosep`, and code around a list, a nested label, and `\ref`'s form are left out; it does nothing where enumitem itself is loaded.

**A description list's term can't be set unboxed under tagging.** The emulation doesn't take `style=unboxed`: `\setlist[description]{style=unboxed}` stops LaTeX with "Package block Error: Some keys specified on the description environment are unknown." So a term longer than a line, which LaTeX sets in a box, runs off the page: _Instrumental Analysis_'s chapter pages list their sections with the titles as terms. Read in TeX Live 2026's files and measured, 2026-10-18. Not worked around; `docs/formats.md` lists it among what the PDF can't do. A candidate for latex3/tagging-project.

**The enumerate package's label pattern is read as keys.** With tagging on, LaTeX's own lists take a list's optional argument as keys, and stopped on `(a)` at _OpenIntro Statistics_' first `\begin{enumerate}[(a)]` ("Some keys specified on the enumerate environment are unknown", 2026-10-07); with LaTeX 2025-11-01 the package's labels repeated instead. The tagging status list rates the package currently incompatible. `texremediate.SHIMS` makes `enumerate`, at `\begin{document}`, a wrapper around the tagging code's lists that reads an argument naming none of their keys as the package does, with the package's own loop (each `A`, `a`, `I`, `i`, or `1` outside braces the counter, the rest as written), and gives the result to them as `label`.

**`\newtheorem` defines a starred environment too, and amsthm isn't loaded.** The block module's `\newtheorem` (`s m o m o`) defines both `#2` and `#2*` with `\NewDocumentEnvironment`, so a book's `\newtheorem*{thm*}{Theorem}` after `\newtheorem{thm}` stops LaTeX ("Command \thm* already defined") with tagging on alone; and the module replaces `amsthm.sty` and `alltt.sty` with nothing and defines amsthm's commands itself (read in the block module 1.0c; measured on GIAM, 2026-10-05). `texremediate` defines such a starred theorem only where it isn't defined yet.

### Paragraphs and sections

**A display formula that opens a paragraph in `center`, `flushleft`, or `flushright` leaves a paragraph open.** `Text. \begin{center} \[ 1! = 1 \] \end{center} After.` is enough: tagpdf says "The number of automatic begin (3) and end (2) text para hooks differ!" (LaTeX 2026-06-01, measured 2026-10-05); in a list item the items after it nest in it (LI in LI), and in a table's cell, as in a paragraph column of a table in such an environment (FINC 308's boxes), it stops the build. A `quote` doesn't do it. `\leavevmode` before the formula opens the paragraph first, which `texremediate` writes (`BLOCK_FORMULA`). Not found in latex3/tagging-project's tracker (three searches, 2026-10-05): a candidate.

**A display formula inside `\emph` puts content straight into its section.** Two lines in a section reproduce it: veraPDF's PDF/UA-2 profile fails "Sect shall not contain content items", and the same formula outside the emphasis passes; in a definition, whose body Pandoc reads as emphasis, it's "P shall not contain P" (GIAM, which states each theorem as `\emph{\[ … \]}`, 2026-10-05). `pdf-target.lua` lifts a display formula out of emphasis, strong, underline, strikeout, small caps, or a span. A candidate for the tagging project.

**`\centerline` between paragraphs puts every later paragraph inside a P.** As an `\hbox` in vertical mode it gave GIAM 53 Parent-Child warnings (2026-10-05). `texremediate` redefines it after the preamble as a centered paragraph in vertical mode and as before inside a paragraph (`CENTERLINE_DEFINITION`), since GIAM also uses it inside a paragraph followed by `\newline`, where a centered paragraph stops LaTeX ("There's no line here to end").

**A sectioning command inside an environment opens a section that tagging can't close.** "The structure Sect can not be closed": measured in LaTeX alone, a sectioning command does it inside `itemize`, `enumerate`, `description`, `quote`, a `longtable`'s cell, a `figure`, and a `\footnote`, and the sections after it are tagged inside the environment, which veraPDF's PDF/UA-2 profile rejects (`L-Sect`, `LBody-LI`): 27 sections of _Principles of Marketing_, whose list items hold notes with titles. A footnote may hold no heading at all (`FENote-Hn`). `pdf-target.lua` sets such a heading as a paragraph tagged as the heading it is (`\tagpdfsetup{para/tag=H5}`, `H1` to `H6` by its level), bold and kept with what follows by `\nobreak`, and in a footnote as a bold paragraph (CNX-NOTES, item 26).

**A run-in heading followed straight by another heading leaves paragraph tagging one paragraph short.** The standard classes run a heading below a subsection in to the text after it, and where another heading follows instead, tagpdf's counts differ by one ("The number of automatic begin (7286) and end (7285)" in DCIC), which stopped its PDF. `build-pdf.py` sets Pandoc's `block-headings`, which puts each such heading on a line of its own.

**A heading's place to break a page comes after anything set just before it.** `\@startsection` adds the break with `\addpenalty\@secpenalty` (read in `latex.ltx`, 2026-06-01), so a box's rule above a heading that opens the box stayed at a page's foot, the box on the next page (_Introduction to Sociology 3e_'s "Big Picture" box). `\OERBoxRule` leaves LaTeX as a heading does (`\@afterheading`), so a heading after the rule adds no break and no space of its own (CNX-NOTES, item 39).

**The book class sets a running head in one line, however long, and in capitals.** `\ps@headings` defines `\chaptermark` and `\sectionmark` as `\markboth{\MakeUppercase{…}}` and `\markright{\MakeUppercase{…}}` (read in `book.cls`), and Pandoc's template doesn't touch them: a section titled with 85 characters ran past the page's edge (measured), and a link in a heading went into the head with its label in capitals ("PAGE-CH_DISTRIBUTIONS--CH_DISTRIBUTIONS undefined", _OpenIntro Statistics_' appendix of data sets). Every class's marks go through the kernel's `\markboth` and `\markright`, which insert the mark classes `2e-left`, `2e-right`, and, when the right mark isn't empty, `2e-right-nonempty` (`\mark_insert:nn`, read in `latex.ltx`, 2026-06-01). `build-pdf.py`'s `RUNNING_HEADS` wraps those two, copied with `\NewCommandCopy` since they're robust, to scale a head wider than the line less 3em down to fit, an empty mark left empty; `pdf-target.lua` gives a heading that holds a link the link's text.

**The standard classes leave a page number three digits' room in the contents.** `book.cls` sets `\@pnumwidth` to 1.55em and `\@tocrmarg` to 2.55em (read), and a fourth digit, or a roman number such as xxviii, is wider: 18 lines of _Introduction to Sociology 3e_'s contents stood 3.1 to 8.7 points past the text at 10 points, and 62 in 13.5-point type. `build-pdf.py`'s `PAGE_NUMBER_ROOM` sets 2.5em and 3.5em for the standard classes.

### Footnotes

**A verbatim block in a footnote stops LaTeX under tagging.** `latex-lab-footnotes.ltx` defines `\footnote` with `\DeclareDocumentCommand\footnote{o+m}`, taking the note's text as an argument, and puts its own `\@footnotetext` in place at `begindocument`, so a code block in a note ends LaTeX with "Paragraph ended before … was complete" (`\FV@BeginScanning` for highlighted code, fancyvrb's `Highlighting`), and fancyvrb's `\VerbatimFootnotes`, which Pandoc's template writes when a note holds code and which only replaces `\@footnotetext`, doesn't help. Measured 2026-10-12 with LaTeX 2026-06-01, and read again in the footnote module 0.8p and fancyvrb 4.6a. Pandoc's output for such a book can't be built with tagging on; `footnote-code.lua` writes each such block to a file from the preamble (`filecontents*`, highlighted as anywhere else, `oer-code-1.tex` and on, written where LaTeX runs, on each run) and reads it with `\input` where it stood (`\OERCodeFile`), so it's read line by line when the note is set.

**A footnote's mark and text given apart in a list's label stop LaTeX's tagging.** Pandoc gives a footnote in a definition list's term as `\footnotemark` in the term and `\footnotetext` after the list, and LaTeX 2026-06-01's tagging stops on the pair in a label, the counts of its paragraph hooks unequal. `pdf-target.lua` puts such a footnote at the head of the term's definition, where the writer gives it as a footnote.

**A tagged figure's caption is set twice, so a footnote mark in it is numbered twice.** The float module's `\@makecaption` sets the label and caption in a box with tagging suspended, to measure it, and then sets them again (read in the float module 0.81n); without tagging, the standard classes set a caption twice only when it's too long for its line, where the caption package isn't loaded. The mark stepped the footnote counter each time, so a book's first footnote, if it was a caption's, was numbered 2. `pdf-target.lua` opens such a caption with `\OERCaptionNotes` and a number of its own, which sets the counter back each time after the first (`PDF_MACROS`), and the list of figures takes the caption without it.

### Floats, captions, and graphics

**LaTeX's tagging gathers floats' tags at the end of the document unless told otherwise.** The float module keeps each float's structure in a container of its kind, placed at the end of the document or where `float/flush` puts it: `\g__tag_float_sect_bool` is true by default (`float/defer`), and `float/here`, its inverse, tags each float where its `\begin{figure}` or `\begin{table}` is, ending and restarting the paragraph around it, without moving it on the page (read in the float module 0.81n). veraPDF can't tell: 91 of GIAM's 195 figures, those in floats, were in two containers after everything else (2026-10-06), so were 246 of the statistics textbook's 270, and a floating table between two paragraphs of a book's first chapter was tagged after its second chapter (2026-10-22). The key came in latex-lab-float 0.81m (2025-12-04), after LaTeX 2025-11-01. `latexbuild.FLOATS_HERE` sets it where the key exists, for a book's PDF and, through `texremediate.FLOATS_HERE`, a LaTeX book's tagged copy (CNX-NOTES, item 53).

**A tagged figure's caption is LaTeX's own, which the caption package doesn't reach.** The float module redefines `\@makecaption` at `begindocument`: the label is the `caption/label` socket's, whose kernel plug is `#1:~`, between two tagging sockets, `caption/label/begin`, which switches paragraph tagging off and opens a Lbl, and `caption/label/end`, which closes it and switches paragraph tagging on (read in the float module 0.81n). So LaTeX labels every caption, and a book whose captions number themselves had two numbers ("Figure 1: Figure 1.1 The real number line"), each read by a screen reader. `\OERNoCaptionLabel` (`PDF_MACROS`) gives the label socket its `noop` plug and the two tagging sockets plugs that only switch paragraph tagging off and on, so the Caption holds its words and no empty Lbl; made `noop`, those two had left paragraph tagging one paragraph short at a caption too long to center. A longtable's caption, and an untagged figure's in a book with tables, is the caption package's, told to give none (CNX-NOTES, item 18).

**An image without alt text is tagged as a figure described by its file name.** With `\l__tag_graphic_alt_tl` empty, the graphic module's `alt` plug warns "Alternative text for graphic is missing. Using '…' instead." and makes the file name, made plain, the figure's `/Alt` (`alt-text-missing`, read in the graphic module 0.80i); a drawing gets `picture environment`. veraPDF accepts either, so the output check reports a figure so described (`pdf-figure-alt-is-file-name`), and `pdf-target.lua` marks a decorative image with the graphic module's `artifact` key, in a group (`\OERArtifactGraphics`); `alt={}` after `artifact` sets the image back to a figure.

**The graphic module keeps the alt key until it's set again.** It holds the key in `\l__tag_graphic_alt_tl` and clears nothing after an image, and `alt={}` is the state a graphic starts in, so `\setkeys{Gin}{alt={…}}` before a call of a book's own image macro and `\setkeys{Gin}{alt={}}` after it describe the image inside without a group, which would have ended a `\centering` in the macro before its paragraph did and restored `\@currentlabel` before a `\label` after the call (PROJECT-NOTES, 2026-10-06). But `\setkeys` in an argument LaTeX writes to a file or keeps to set elsewhere (a caption, `\captionof`'s and `\subcaption`'s too, a heading, either one's short form, `\index`, `\thanks`, `\title`, `\author`, `\markboth`, `\markright`, and `\addcontentsline`'s entry) stops the build, with pdfLaTeX and LuaLaTeX alike, and `\includegraphics`'s keys can't hold a paragraph break ("Paragraph ended before \Gin@ii was complete"; measured, `docs/latex.md`). `texremediate` writes the keys at each call and names each image it can't.

**graphicx defines `alt`, `actualtext`, and `artifact` itself, and older releases don't all know them.** graphicx 1.2e (TeX Live 2026's file is dated 2026-05-17) defines `alt` and `actualtext` as keys that do nothing and `artifact` as a boolean key, and the graphic module defines all three again at `package/graphicx/after` (read), so the keys build without `\DocumentMetadata` on LaTeX 2026-06-01. TeX Live 2023's graphicx stops at `artifact` ("artifact undefined"); `\picture` takes options first in LaTeX 2026-06-01, so `\begin{picture}[alt={…}]` stopped TeX Live 2025's pdfLaTeX; and a `tikzpicture`'s `alt` and `artifact` were defined only by the tagging code's TikZ module until pgf 3.1.12 (2026-08-01), which defines them as keys that do nothing, waiting for tagging to give them a use ("I do not know the key '/tikz/alt'" otherwise). `texremediate.KEYS_SKIPPED`, before a LaTeX book's `\begin{document}`, gives each missing key one that does nothing and leaves the kernel's `\picture` alone unless it's the one that takes no options; checked with TeX Live 2023, 2025, and 2026, with pdfLaTeX and tagged with LuaLaTeX (CNX-NOTES, item 8).

**The alt key is made plain with `\pdf_purify:nN`, which leaves the commands Pandoc's writer escapes as their names.** The graphic module's `alt` key runs `\pdf_purify:nN` (read in the graphic module 0.80i), which applies the purify equivalents and the `pdf/purify/setup` hook, hyperref's `\pdfstringdefPreHook` among it, and then `\text_purify:n` (read in pdfmanagement 0.97c). It turns `\&` and `\%` into their characters but has no equivalent for `\textquotesingle`, `\textbar`, `\textless`, `\textgreater`, `\textasciitilde`, or `\textbackslash`, which Pandoc's writer writes into an alt key, so the `/Alt` held their names ("E0\textquotesingle s lowest levels", 27 of _Instrumental Analysis_'s 500 figures; 96 of the 224 alt texts in _Prealgebra 2e_'s third chapter), takes `\^{}` for an accent, and keeps TeX's ligatures (`` ` ``, `''`, `--`, `---`) as typed, since only a font makes them characters (measured with LaTeX 2026-06-01, 2026-10-24 and 25). `latexbuild.PDF_MACROS` declares the six commands' characters as purify equivalents, wherever LaTeX makes text plain, and, for the alt key alone, makes `\^{}` a caret and the ligatures their characters before the graphic module reads the key: a wrapper around `\KV@Gin@alt`, set at `begindocument/before`, when graphicx has defined it, with `\regex_replace_all:nnN` for `\^{}`, since `\tl_replace_all:Nnn` can't match a brace group. A backquote, which the writer writes as itself, is a left quote there, as TeX sets it in the text (CNX-NOTES, item 70).

### Tables

**Header rows come from a longtable's head, and header columns only from a setting.** The table module's `tbl/longtable/finalize` plug sets a longtable's header rows from its first head (`\endfirsthead`) or its head (`\endhead`); under PDF 2.0 it tags the repeated head's rows as artifacts, and under PDF 1.x takes them out of the table's children (read in the table module 0.85t). Header columns come only from `\tagpdfsetup{table/header-columns=…}` before the table, and latex-lab's table tagging supports header rows and columns alone, so a table whose cells need a `Headers` list can't be tagged fully. Measured: a longtable's caption is tagged as a first row of one header cell spanning the table, and an empty copy of the repeated head stays inside the table ([latex3/tagging-project#1583](https://github.com/latex3/tagging-project/issues/1583)); NVDA in Acrobat read the caption as row 1, and counted four rows and six columns in a three-by-three table. `pdf-target.lua` declares a table's header column around it, and `lib/pdfretag.py` makes such a cell the table's Caption and takes the empty head out after LaTeX (`pdf.repair_captions`).

**LaTeX's tagging takes a longtable's head for header cells even in a division of paragraphs.** `table/tagging=div` clears the header rows and calls `\__tag_tbl_enable:`, which assigns the `tbl/longtable/finalize` plug a table gets, and that plug sets the header rows again from the longtable's head (`\g__tbl_LT@firsthead_rows_seq` or `\g__tbl_LT@head_rows_seq`) and retags their cells `table/headercell`: each a TH under a NonStruct in a Div, outside any TR. Read in `latex-lab-testphase-table.sty` of 2026-04-28 (0.85t, TeX Live 2026) and in the LaTeX team's development version (`latex-lab-table.dtx`, 2026-09-24, 0.85v, fetched 2026-10-16), which has it too; measured by the testing session on the Word corpus (veraPDF's PDF/UA-2 profile: ISO 32005's "Sect shall not contain TH", with tagpdf 1.0h) and here with a longtable of two rows, the first its `\endhead` (Debian's TeX Live 2026, tagpdf 1.0c: the two TH, not role mapped to a standard namespace, fail 8.2.4). Pandoc's writer puts a table's head in the longtable's head, so `figures-and-tables.lua` writes a layout table's head as rows like the others; a LaTeX book's own longtable with a head, declared `layout`, is tagged with the TH still. A candidate for latex3/tagging-project, drafted in PROJECT-NOTES (Reports drafted and not yet sent): under the division setting the finalize plug shouldn't set header rows, or the setting should give longtable one that doesn't. Not found by a web search; the tracker's own search isn't reachable from this container.

**`table/tagging=div` and `presentation` both tag a table's code, under other names.** Each calls `\__tag_tbl_enable:`, assigns `LayoutTable` plugs to `tbl/hmode/begin` and `tbl/vmode/begin`, and clears the header rows and columns; `div` gives the table, its rows, and its cells the `layouttable` structure names, which make it a division of paragraphs, a row's cells in turn, where `presentation` keeps Table, TR, and TD and adds the role presentation (read in the table module 0.85t). PDF/UA-2 says a role shall not contradict its structure element's meaning (ISO 14289-2, 8.2.6.4, as `docs/formats.md` reads it), which a Table "presentation" arguably does, so the PDF target and a LaTeX book's tagged copy tag a layout table and a box with `div`, in a group, since `\tagpdfsetup` holds until it's changed, and only where `\tagpdfsetup` is defined, since an untagged build stops on it. A data table inside such a division is a table again only with `table/tagging=on` and the two plugs set back to `Table` (`texremediate.DATA_OPEN`), which `table/tagging=on` alone doesn't do; veraPDF passes both, and the next table is a table.

**The tagging code doesn't follow `\multirow`, and a longtable doesn't clear its record of a span's cells.** Untold, the tagging code tags a cell spanning rows as its first row's alone and gives each row it covers an empty cell of its own; `table/multirow`, said inside the cell, gives it its RowSpan and records the cells it covers as untagged (`\g__tbl_untagged_cells_prop`). The kernel's `\tbl_init_cell_data_for_table:` clears that record through the `tbl/init/celldata` socket, and array's `\@array` calls it where longtable's `\LT@array` doesn't (read in `array.sty` 2.7b, `longtable.sty` 4.27, and `latex.ltx` 2026-06-01), so every longtable after one with spans lost its cells at the same places (measured). `pdf-target.lua` writes `table/multirow` in each such cell, and `PDF_MACROS` clears the record at `env/longtable/begin`. The tagging status list rates multirow currently incompatible.

**LaTeX's tagging reads a formula whole before setting it, so an `&` in it can end a table's cell.** In a table's cell TeX took a matrix's or an array's `&` for the end of the cell ("Forbidden control sequence found while scanning use of `\__math_grab_inline_delim:w`"), and in a caption for the table's while nameref read its title (_Elementary Algebra 2e_'s 5.2, 2026-10-15). `pdf-target.lua` sets such a formula in braces, and it's a Formula with its MathML file in its TD or its Caption (CNX-NOTES, item 19).

**A block quotation in a table's cell isn't allowed in a PDF's structure.** veraPDF reports a BlockQuote in a TD (ISO/TS 32005's TD-BlockQuote), and LaTeX's tagging tags a quotation in a cell as one; `pdf-target.lua` unwraps a quotation in a cell to what it holds.

**Two of PAC's errors on a tagged table are PAC's.** "Table header cell has no associated subcells": latex-lab sets `Scope` through an attribute class, and PAC doesn't resolve `/ClassMap` references, so the same value as an inline `/A` dictionary passes; the maintainers keep the class, which makes `TH-both` expressible for a cell heading both a row and a column ([tagging-project discussion #930](https://github.com/latex3/tagging-project/discussions/930)). "Invalid use of a TR structure element": PAC rejects `Artifact` as a child of `Table`, which is how a repeated longtable head is represented, and which ISO 32000-2's Annex L permits ([issue #1583](https://github.com/latex3/tagging-project/issues/1583)); it's reported to PAC, with no public ticket. Each was verified by building the diagnostic and watching the error go (`docs/troubleshooting.md`; PROJECT-NOTES, Provenance).

### Math

**luamml makes MathML only beside unicode-math or lua-unicode-math, unless it's forced.** With neither loaded, the math module warns "Neither unicode-math nor lua-unicode-math has been loaded" and loads no luamml, so a tagged LuaLaTeX build has no MathML; `\tagpdfsetup{math/mathml/luamml/load=true}` forces it with TeX's own fonts, and so does `math/setup` naming `mathml-SE`, `mathml-AF`, or `mathml-MS`, each of which sets luamml to load (read in the math module 0.7e): the calculus notes' own PDF, with `math/setup=mathml-SE` and no unicode-math, has MathML. With TeX's own fonts a symbol TeX builds from pieces comes out as the pieces (`\implies` "=" and "⇒", `\iff` two arrows, `\neq` "=" and U+0338, `\cong` and `\notin` nothing, `\longrightarrow` a minus and an arrow), dots as three periods, and capital Greek dropped, since luamml's OT1 table is commented out (read in `luamml-legacy-mappings.lua`, 0.9.2) and latex-lab registers only two of its three legacy tables, OML and OMS; luamml's own fixes for the arrows (`luamml-patches-kernel.sty`) are switched off under tagging. Forced on GIAM, 536 of 4,521 formulas differed from unicode-math's (2026-10-06). So a LaTeX book's tagged copy loads unicode-math, inside `\ifdefined\directlua` so pdfLaTeX builds as before (`texremediate.MATH_FONTS`), unless the book sets its fonts or math symbols with a package (`texremediate.OWN_FONTS`), whose formulas then get no MathML. An upstream candidate for luamml: OML slot 0x3F, cmmi's `\star`, maps to U+226D, not U+22C6 (read in `luamml-legacy-mappings.lua`).

**`math/setup` switches every form of MathML off before applying the ones it names.** It sets luamml not to load and turns off the TeX source's attached file, the MathML attached file, and the structure elements, then applies each value listed (read in the math module 0.7e), so the PDF target names both forms it wants (`math/setup={mathml-SE,mathml-AF}`) rather than leave either to defaults that could change. `latexbuild.MATH_SETUP` and `math_setup` choose the values by the standard the PDF claims (below).

**`\pmb` stops LuaTeX under tagging with MathML.** `\(\pmb{\hat{p}_1 - b}\)` in a document with `\DocumentMetadata{tagging=on}`, unicode-math, and `math/setup={mathml-SE,mathml-AF}` ends LuaTeX with "(nodes): trying to set an attribute fails, case 2", while `\pmb{\hat{p}_1}`, `\pmb{p_1 - b}`, `\pmb{\hat{p} - b}`, and `\boldsymbol{\hat{p}_1 - \hat{p}_2}` build. amsbsy's `\pmb` sets its argument three times in boxes, offset. Measured with TeX Live 2026, 2026-10-07 (_OpenIntro Statistics_' boxes have such headings). `pdf-target.lua` and the tagged copy write it as unicode-math's bold italic, `\symbfit`. A candidate for latex3/tagging-project, with the four lines above.

**`bm` and amsmath's `\boldsymbol` don't suit unicode-math's MathML.** Under unicode-math, `bm` draws a formula's letters from TeX's own bold font, which lacks them ("There is no 𝑥 (U+1D465) in font rm-lmbx10", a missing glyph that fails PDF/UA-2), and `\boldsymbol` puts the formula it makes bold inside the MathML's text, a `<math>` in an `<mtext>` (measured on GIAM's tagged copy; PROJECT-NOTES, GIAM). `texremediate` makes both `\symbfit` at `\AtBeginDocument`.

**amssymb loaded before unicode-math leaves some of its names drawn as control characters.** The names unicode-math has no command for (`\square`, `\blacksquare`, `\lozenge`, `\Box`, `\lhd`, `\leadsto`, and about 40 more) stay drawn from TeX's own symbol fonts, whose glyphs map to control characters: GIAM's `\square` read as U+0003, `\blacksquare` as U+0004, and `\lozenge` as U+0006, which a screen reader can't say and veraPDF passes. Pandoc's template loads amssymb before unicode-math, as most books do. `latexbuild.UM_ALIASES` makes each the character it is, at `\AtBeginDocument`, from the math font, or as a box from the text's fonts for the few Latin Modern Math lacks (`\Diamond`, `\blacklozenge`, the dashed arrows), and only where the name is still amssymb's or latexsym's, so a book's own definition stays.

**An empty line in a display formula stops LaTeX's tagging, which reads the formula's body as an argument.** "Paragraph ended before \environment equation* was complete" (_Calculus Volume 2_'s chapter 3, _Precalculus 2e_'s chapter 7), where LaTeX without tagging, and a formula in text, read on (measured in a bare `article` with TeX Live 2026); there the row is lost, since a `\\` before an alignment's end makes no row: an evaluation bar's upper limit sat 9.5 points above the formula's line and its lower one 28.5 below. texmath writes an `mtable`'s empty last row as such a line (PANDOC-NOTES); `pdf-target.lua` writes it as an empty group, `{}`, which makes the row, the limits 27.6 points above and 28.5 below (CNX-NOTES, item 55).

**amsmath numbers a row a final `\\` makes, and an `eqnarray` takes no `\tag`.** An `align` ending in `\\` numbers an empty last row (measured in LaTeX, 2026-10-07); an `eqnarray` stops on `\tag` ("\tag not allowed here"), and an `align` inside `\[ \]` stops amsmath ("Erroneous nesting of equation structures"). `pdf-target.lua` sets an `eqnarray`'s count before it, with the number's form, and puts the form back after.

### Links, bookmarks, and text made plain

**hyperref's `\pdfstringdef` makes dashes and inverted marks, as TeX's text does, and assigns its target globally.** It first replaces `\/` with a placeholder it empties after the substitutions, then replaces `---`, `--`, `` !` ``, and `` ?` `` with `\textemdash`, `\textendash`, `\textexclamdown`, and `\textquestiondown`, and nothing else of the kind, and defines its target with `\xdef` (read in hyperref.sty 7.01r). Tested: U+2013 for `--` and U+2014 for `---`, while `-{}-`, and Pandoc's `-\/-`, stay two hyphens (2026-10-23); so an address's `lang--en` was `lang–en` in a link's `/Contents`. `pdf-target.lua` writes an empty group after each hyphen and before each backtick of a link's description, `UA1_LINKS` does the same to an address with `\tl_replace_all:Nnn`, which doesn't reach inside a brace group, and `\OERLinkContentsReset` clears the description with `\tl_gclear:N`, since cleared locally in a group it came back at the group's end. hyperref's own default plug converts with `\pdf_purify:nN` and `\pdf_string_from_unicode:nVN`, which leave a string as written: offered as a cleaner way, not taken. And LuaLaTeX's ligatures print a lone backtick in a link's text as ‘.

**`\text_purify:n` keeps the arguments of a command it has no equivalent for, and expands a command that's neither protected nor robust.** So an `\href`'s address stays in the text, and hyperref's `\hyperlink`, a plain macro (`\def\hyperlink#1#2`, read in hyperref.sty 7.01r), stops LaTeX ("Missing number"), with or without an equivalent, wherever LaTeX purifies it. `\text_declare_purify_equivalent:Nn` says what a protected or robust command is, and the purify loop expands the replacement a step at a time, so a replacement can take arguments, one ending at a brace too (l3text-purify in `expl3-code.tex`; measured, 2026-10-23). A formula stays its TeX between dollar signs. `PDF_MACROS` declares equivalents: an `\href` its text (an optional argument before its address too, as hyperref's own `\HyPsd@href` takes it), a `\hyperref` its text in both its forms, Pandoc's `\citeproc` its text, `\OERLinkContents` nothing, `\oerlang` its words, and `\OERBlank` its underscores, hyperref's two at `package/hyperref/after`.

**A list entry's structure title is made by `\pdf_purify:nN`, which `\pdfstringdefDisableCommands` reaches.** The toc module titles an entry's structure element (`/TOCI`'s `/T`) with `\pdf_purify:nN` (read in the toc module 0.85k), which runs the purify equivalents and the `pdf/purify/setup` hook, where hyperref's `\pdfstringdefPreHook` is, before `\text_purify:n`, so `\pdfstringdefDisableCommands` reaches a list entry's title, but not a deck's frame title, which ltx-talk makes with `\text_purify:n` itself. A link in a caption had put its description and its target into its entry's title ("…a linked wordhttps://example.org/captiona linked word…"), and the equivalents above give its text alone (PROJECT-NOTES, _Instrumental Analysis_, 2026-10-23).

**An anchor or a passage in another language in a caption puts LaTeX's words into its entry's title.** hyperref defines `\phantomsection` as `\MakeLinkTarget[section]{}` (read in hyperref.sty 7.01r), which purify expands, since the list's file holds it without Pandoc's `\protect`, keeping "[section]" as text ("Eight: [section]anchored span with id."); and purify drops babel's `\foreignlanguage` but keeps both its arguments ("frenchmot"). Found by the review of round 9 (PROJECT-NOTES, _Instrumental Analysis_), not fixed: a purify equivalent for `\MakeLinkTarget` that drops its arguments, and one for `\foreignlanguage` whose first argument ends at the brace, would each fix one, the second tested by the review.

**The bookmarks follow LaTeX's `tocdepth` as it stands when each is written.** hyperref's `bookmarksdepth`, unset, is `\c@tocdepth` itself (`\let\Hy@bookmarksdepth\c@tocdepth`, read in hyperref.sty 7.01r), so where `tocdepth` is set only with the contents, a book with no contents page gets bookmarks as deep as the class's own depth, a subsection in the book class (measured, 2026-10-20). `build-pdf.py` sets `tocdepth` at the head of `header-includes` (PANDOC-NOTES, the LaTeX writer; CNX-NOTES, item 44).

### PDF/UA-1 against PDF/UA-2

**A PDF/UA-1 build is PDF 1.7, which has no MathML namespace.** MathML structure elements there are non-standard types that veraPDF rejects, so a formula keeps its MathML as an attached file and latex-lab gives it its TeX source as alternative text, which it switches on itself for PDF/UA-1 ("LaTeX formula starts" … "ends"); `mathml-MS` adds the MathML as Microsoft Office's own attribute on the formula (`/O /MSFT_Office /MSFT_MathML`), as Word writes it in the PDFs it saves. NVDA reads that attribute before the alternative text ([its Acrobat support](https://github.com/nvaccess/nvda/blob/release-2026.2/source/NVDAObjects/IAccessible/adobeAcrobat.py#L189-L234)): in Acrobat it read such a file's formulas as math, and without the attribute the TeX source as written. `latexbuild.MATH_SETUP` gives PDF/UA-2 `mathml-SE,mathml-AF` and PDF/UA-1 `mathml-AF,mathml-MS`, or `mathml-AF` alone with `pdf.ua1_math: alt`.

**PDF/UA-1 wants a `/Contents` on every link, LaTeX's own too.** hyperref's link `/Contents` sockets (`hyp/link/GoTo/Contents`, `hyp/link/URI/Contents`) are `noop` unless the PDF claims a PDF/UA standard that, as far as the code reads, requires a link's `/Contents`, when their default plugs write "Go to destination" and the destination's name, or the address (read in `hgeneric-testphase.def`, pdfmanagement 0.97c). `PDF_MACROS` gives each link the book's text makes its own (`\OERLinkContents`, set for the link and cleared after it) and assigns the two sockets `noop` at `begindocument`; for PDF/UA-1 (7.18.5, as the code's comment cites it), `UA1_LINKS` gives LaTeX's own links, a contents line or a cross-reference LaTeX makes, hyperref's text only where a link has none of its own, and `build-pdf.py` passes `hyperfootnotes=false`, so a footnote mark isn't a link. The security textbook built so passes veraPDF's PDF/UA-1 profile.

**PDF/UA-1 wants every change of language declared, and babel tags nothing.** `\foreignlanguage` and `otherlanguage`, which Pandoc's writer writes for a passage in another language, set its hyphenation, and the PDF had a `/Lang` in its catalog alone (ISO 14289-1, 7.2, as `docs/formats.md` cites it). `PDF_MACROS`' `\oerlang` tags a span or a link as a Span with its `/Lang`, opened in the paragraph, and `oerlanguage` gives a div's blocks theirs through `\tagpdfsetup{text/lang=…}`, babel's commands kept inside, so nothing on the page moves.

**PDF/UA-2 requires the PDF's title, which `\title` alone sets.** LaTeX's tagging puts `\title` in the PDF's metadata (`dc:title`), with no `\maketitle` to print it, and veraPDF's 8.11.1 failed FINC 308's 18 documents without one (measured, 2026-10-06). `texremediate` writes a `\title` where a LaTeX book names none, by `\title` or hyperref's `pdftitle`: the title its large type sets, or its file's name.

### Artifacts

**A page's head and foot are artifacts.** LaTeX's tagging marks the foot an artifact, outside the document's structure as a page number is, so a link there would be a link outside the structure, and a running head's size changes nothing a screen reader gets. `lib/pagefooter.py` writes the footer setting's link as its words and a picture as its alternative text.

**Tagging passes over a kern, and rules drawn in an artifact's marked content stay out of the structure.** A mutation that left a fill-in blank's kerns without the underscores' attributes, which the first version copied to them, broke nothing, since LaTeX's tagging passes over a kern, and the kerns carry none now (CNX-NOTES, item 33); `\OERBoxRule` draws its `\hrule` inside `\tag_mc_begin:n{artifact}`; latex-lab's firstaid module makes booktabs's rule in a longtable an artifact (below); and under PDF 2.0 a longtable's repeated head is tagged `Artifact` inside the table (above).

**Content no tagging attribute marks is an artifact.** Where a run of a page's nodes carries no marked-content attribute (`g__tag_mc_cnt_attr`), tagpdf's Lua code wraps it in an `/Artifact` marked content, when `tagunmarked` is true, its initial value (`activate/tagunmarked .initial:n = true` in `tagpdf.sty`, and the branch logging "this has not been tagged, using artifact" in `tagpdf.lua`, 1.0c, 2026-05-17, read). The arrow `FIT_MACROS` draws before a wrapped line's later part is a PDF literal in a box of no width that its Lua makes in `post_linebreak_filter`, which carries none of the marked-content attributes, so it's an artifact: the PDF suite reads each arrow inside `/Artifact` marked content, and the line's text and its structure as written, whether or not the code unsets tagging's three attributes on the box (`g__tag_mc_cnt_attr`, `g__tag_mc_type_attr`, `g__tag_structnum_attr`), which it did at first and doesn't now (a mutation, 2026-10-29; CNX-NOTES, item 109). It's the stroke's own attributes that count, not the box's: given the attributes of the glyph it's set before, the box alone, the arrow was still an artifact, and the stroke inside it, it was in the code's marked content (two mutations, 2026-10-29; CNX-NOTES, item 115).

## Packages tagging can't take

**longtable stops on a page of two columns.** "longtable not in 1-column mode" (`\if@twocolumn`, read in `longtable.sty` 4.27, 2026-01-28); measured with the class options `twocolumn` and `fleqn` in a book's metadata file and a page with one table (2026-10-21), and a book in two columns built where its table was of Pandoc's class `float`, a `tabular` in a `table` float (2026-10-22). ## Line breaking and fitting

**TeX names a line it can't fit by where its box came from, and by the file it's reading.** Its report of an overfull box (TeXbook, chapter 14: `\hbadness`, `\hfuzz`) says "in paragraph at lines", "in alignment at lines" for a table's row, or "detected at line" for a box made whole, a display formula. In the contents or a list of figures or tables, the line is the list's own file's (`book.toc`); a footnote's code is the file `footnote-code.lua` wrote it to, and a footnote's own paragraphs the line its text ends on. `PDF_MACROS` wraps `\@starttoc`, which the classes' lists go through, to mark in the log where each list is set, and `latexbuild.overfull_lines` reads the reports from Pandoc's `--log` (CNX-NOTES, items 34 and 92).

**TeX breaks a formula in text only after a relation or a binary operator outside braces.** (TeXbook, chapter 18: `\relpenalty` and `\binoppenalty`.) A script is part of its atom, so `Ag^+` doesn't break; `\left(` makes a group TeX sets apart; and an environment's lines (`gathered`, `aligned`) don't break at all. `pdf-target.lua` sets both penalties to 10000 in a worked example's steps' group, so a formula there is fitted, not broken (CNX-NOTES, item 52).

**A run of underscores can't break.** A question ending in a fill-in blank too long for what's left of its line ran into the margin (24.3 points, _Introduction to Sociology 3e_'s chapter 19 quiz), and Pandoc's template's `\emergencystretch` of 3em can't make room on a line of few spaces. `PDF_MACROS` marks a run of four or more underscores (`\OERBlank`) and draws one that runs past its line shorter once LaTeX has broken the paragraph (CNX-NOTES, item 33).

**In ragged lines a line holding only a label costs TeX nothing.** Its badness is 0 (`\tracingparagraphs`), so TeX broke the line after a label and set its long blank on the next. In text set flush to both margins, such a line, or one ending at a blank drawn at two thirds of its line, is too loose to take, and TeX keeps a label with a blank too long for its line itself, taking the line too wide as a last resort. With no way to break a line without an overfull box, TeX takes the last break it was still considering (artificial demerits), which split a label of two words from its blank where a no-break space joined them to it. `\linebreak[1]` is a penalty of −51 (`\@lowpenalty`, 51 in the standard classes, read in `book.cls`). `PDF_MACROS` draws a long blank at two thirds of its line while TeX breaks a ragged paragraph and asks for a break after it with that penalty (CNX-NOTES, items 60 and 62).

**`\emergencystretch` gives TeX a third pass, which decides where a justified paragraph breaks when no break is within `\tolerance`.** Pandoc's template sets it to 3em, so TeX gives each line that much more stretch and takes a line looser than `\tolerance` allows rather than one too wide: a label and its blank were a line of their own, underfull (badness 1184), where without it TeX's last resort was a line 3.64 points too wide, broken at a hyphen in the next label (measured in a LaTeX file of its own, 2026-10-24; PANDOC-NOTES, the LaTeX writer).

**In a ragged paragraph every line costs TeX the same, so a break's penalty decides; set flush to both margins, a loose line weighs against it.** A line's demerits are (`\linepenalty` + its badness) squared plus its break's penalty squared, `\linepenalty` 10 (TeXbook, chapter 14), and with a right skip whose stretch is infinite, as the PDF's ragged right is (`\@flushglue`), every line's badness is 0: a break at a penalty of 120 costs 14,400 more than a break at a space, more than 140 more lines would, so TeX takes it only where no break at a space fits, in a word longer than its line. Set flush to both margins, a line's badness counts too, and a penalty of 120 is cheaper than a line of badness above 110, a little looser than the font's stretch allows. Measured on a page of inline code (Pandoc 3.13, LaTeX 2026-06-01, 2026-10-28), a word of code of 40 characters after six or seven words, too long for what their line had left, in twelve placements: ragged, TeX put it whole on the next line in each, whichever of three rules the breaks inside a word had. ## Fonts

**fontspec keeps a family by a face's name and all its features, and a face set again with the same features keeps the size worked out first.** `\l__fontspec_fontid_tl` is the name and every feature, the defaults' among them, and `\g__fontspec_fontid_family_prop` maps it to the family made (read in `fontspec-luatex.sty` 2.9g); an empty option is no item of the list, so `[,RawFeature=…]` and `[RawFeature=…]` are the same features. ## Other packages

**pict2e draws picture mode as paths, where LaTeX draws it with fonts that map to no character.** LaTeX draws a `picture`'s lines, arrows, circles, and ovals with glyphs of its `line10` and `lcircle10` fonts, whose map to Unicode has only a space, and cancel (2.2) draws each stroke through a struck-out term with picture mode's `\line`, and `\cancelto`'s arrow with `\vector`: veraPDF failed _College Algebra 2e_'s first chapter on two of them (8.4.5.8, in PDF/UA-2 and both WTPDF profiles), and why it reports some of the font's glyphs and not others wasn't found. The fonts come in a few slopes and sizes: a circle asked for at 80 points is drawn at 40, the largest, with "size unavailable" in the log alone, and `\line(7,3)` stops LaTeX ("Bad \line or \vector argument"). cancel, given pict2e, asks for LaTeX's own commands (`\OriginalPictureCmds`), its comment saying pict2e removes the bounding box from `\line` and `\vector` (read in `cancel.sty` 2.2), which pict2e's `\line` has now; told to use pict2e's, it draws each stroke where it did (measured in text, in a script, and displayed). `latexbuild.PICTURE_PATHS` loads pict2e for every PDF at `begindocument/before` and makes `\OriginalPictureCmds` nothing where cancel is loaded; `picture_paths: off` (`PICTURE_FONTS`) keeps LaTeX's own drawing where cancel isn't loaded (CNX-NOTES, items 48 and 87).

**pict2e loaded late has names of its own that a document may have too.** pict2e (0.4b) loads trig and defines `\maxovalrad` with `\newcommand*` (read), so a document's own `\maxovalrad` stopped pict2e loading ("already defined"); loaded at `\begin{document}`, its drawing commands (`\arc`, `\Line`, `\polygon`, `\moveto`, `\buttcap`, and the rest) replaced a document's own `\arc`, on which LaTeX then stopped ("Missing number"), and stopped LaTeX on a `\newcommand` of one in the text ("already defined"). `PICTURE_PATHS` sets those names aside before pict2e loads and, at `\begin{document}`, gives them back as the document had them or takes them away, `\buttcap` given pict2e's own inside the group `\circle`, `\dot`, and `\oval` draw in, since taken away it stopped LaTeX at the first circle ("Undefined control sequence"); `\maxovalrad` is set aside and given back too. A `\maxovalrad` made in the text, and a command of one of trig's names (`\UseSin` and the rest), still stop LaTeX or are replaced (CNX-NOTES, items 48, 87, and 92).

**cancel and pict2e aren't in TinyTeX or TeX Live's medium scheme.** TeX Live's database puts cancel in collection-latexextra and pict2e in collection-pictures (the TinyTeX bundle of 2026-09 measured). A build that lacks both stops on `cancel.sty`, which Pandoc's template loads in the preamble, and once that's installed on `pict2e.sty`, loaded at `\begin{document}`, a file the book never names; `latexbuild.failure_advice` names both at once, and names `picture_paths: off` where the build stopped on `pict2e.sty` alone (CNX-NOTES, items 48 and 97).

**A standard class takes 10pt, 11pt, and 12pt alone, and takes its options in its own order.** The book class ignores another size, so `fontsize: 13.5pt` left the type at 10 points, and it matches an option letter for letter, so `12PT` did too; and the standard classes take their options in the order they declare them (`\ProcessOptions`), not the order they're given, so `fontsize: 12pt` with `classoption: [11pt]` sets 12-point type and `papersize: letter` with `classoption: [a4paper]` a Letter page, unless geometry is loaded, which takes the last paper option the class was given (measured, 2026-10-20). `build-pdf.py` lowercases a size, leaves out the default's `fontsize` or `papersize` where a metadata file's class option names one, and sets another size through scrextend (PANDOC-NOTES, the LaTeX writer).

**scrextend sets another type size for any class, and leaves the class's own spacing at its size.** With `fontsize=`, scrextend sets the class's other type sizes, the space around a display formula, a float, and a footnote, and its own list spacing, which gave a list 14 points more above and below it than a paragraph at 13.5 points, where parskip's lists have none but the space between paragraphs; it leaves a list's indents and its label's space (in ems in `book.cls`), `\topskip`, and a paragraph's indent as the class set them at the size it loaded with (measured, 2026-10-20). Its one check of another package, `\CheckCommand*\@footnotemark` (read in scrextend 3.49.2), is for an option of its own nothing here uses, and LaTeX's tagging changes `\@footnotemark`, so it would warn on every build. `build-pdf.py`'s `SIZE_PACKAGE` loads it with that check skipped and sets the rest again as the class and parskip set them at the new size.

**parskip sets the space between paragraphs from `\baselineskip` as it stands when parskip loads.** `\parskip=.5\baselineskip plus 2pt` (read in parskip 2.0h), and Pandoc's template loads parskip before `header-includes`, so a type size a package sets there leaves the space at the class's size: 6 points at 13.5 points, where half its line is 8.1 (measured, 2026-10-20). `SIZE_PACKAGE` sets it again.

**setspace sets a footnote single-spaced, and the caption package a caption.** Whatever `linestretch` says, a footnote is 1.2 times its type's size, and the caption package does the same to a caption in a book with a table; `\SetSinglespace{1.25}` gives them the text's spacing of 1.5 times their size (`docs/configuration.md`, the WCAG 1.4.8 page). geometry loaded again with options of its own stops LaTeX ("Option clash for package geometry"), and a spacing a metadata file's own LaTeX set was undone by the page's later `\setstretch`, so `build-pdf.py` leaves out the default's `geometry` or `linestretch` where the file's own LaTeX loads geometry or setspace or sets the spacing.

**xcolor loads its sets of named colors only when asked.** `dvipsnames`, `svgnames`, and `x11names` make xcolor input the set's `.def` file after the package (`\XC@declarenames`, read in xcolor 3.02), and xcolor takes them as class options too, so a formula naming `BrickRed` stops LaTeX where they aren't given, and a color a LaTeX book defines with `\definecolor` and a formula names stops it where the definition isn't there (_OpenIntro Statistics_). `build-pdf.py` passes a LaTeX book's sets as class options and writes its color definitions into the preamble.

**lua-ul draws its line as the line is made.** An underline, a strike-out, or a highlight lua-ul draws (`\ul`, `\st`, `\hl`) is drawn before `PDF_MACROS`' blank code could draw a blank shorter, so a blank inside one isn't marked (CNX-NOTES, item 33). luacolor and lua-ul are needed for struck-out, underlined, or highlighted text, and TinyTeX lacks them.

## TeX distributions

**TeX Live 2026 comes from tug.org's installer or as TinyTeX.** TinyTeX's bundle (`TinyTeX-linux-x86_64-v2026.09.tar.xz`) is what's tested here, a small TeX Live in the home folder that `tlmgr` adds to without `sudo`; TinyTeX's own install script installs a smaller one, TinyTeX-1, which lacks much a book is likely to load (the bundle the installation page names failed 5 of the LaTeX suite's checks for want of `luatex85` and `wasysym`, and TinyTeX-1 28, 2026-10-08). **`tlmgr` has three habits worth knowing.** It refuses to install once TeX Live has released a newer `tlmgr`, so `tlmgr update --self` comes first; its mirror chooser redirects, so on a network that allows only named hosts a fixed one is set first (`tlmgr option repository https://ctan.math.illinois.edu/systems/texlive/tlnet`); and for a TeX Live installed with `sudo`, `sudo tlmgr` isn't found, or runs a distribution's `tlmgr`, since `sudo` looks for programs in its own `secure_path`, while `sudo "$(which tlmgr)"` works, `tlmgr` putting its own folder first on the path of the programs it runs (`tlmgr.pl`'s BEGIN block). `latexbuild.tlmgr_command` adds `sudo` and `tlmgr`'s path to a suggested command where `kpsewhich -var-value=TEXMFROOT` names a tree the user can't write.

**Debian's and Ubuntu's texlive packages are a TeX Live of their own, with a `tlmgr` that installs nothing.** Ubuntu 24.04's is TeX Live 2023 (LaTeX 2023-11-01) and 22.04's 2021, too old to tag a book; their `tlmgr` runs in a user mode that isn't set up and installs nothing, so a package comes from `apt` (`apt-file search` finds it). `texlive-fonts-extra` has IBM Plex; Noto Sans is left to `fonts-noto-core`; `texlive-latex-extra` and `texlive-pictures` have cancel and pict2e; and a language's babel file and hyphenation patterns are one `texlive-lang-` package. **A language needs babel's file for it and its hyphenation patterns.** babel reads a language from a file of its name (`ngerman.ldf`, in `babel-german`), without which LuaLaTeX stops with "Unknown option 'polish'" (`errbabel.def`, read; measured on a page in Polish), and without the language's `hyphen-` package babel warns in the log (`\@nopatterns`) and uses the patterns preloaded for the format's first language (read in babel.sty 26.9).
