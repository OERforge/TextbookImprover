# Pandoc notes

What Pandoc does, as read from its source or established by test, for the questions this project keeps asking. Separate from PROJECT-NOTES.md because it's about Pandoc, not about us. Read this before answering a "what does Pandoc do when…" question, and read the source before running an experiment: a shallow clone of `jgm/pandoc` at the version in use lives in the working container (`~/pandoc-src` at 3.11, where most of this was read, `~/pandoc-src-3.12`, and `~/pandoc-src-3.12.1`, the reference from 2026-10-08; one that's missing is `git clone --depth 1 --branch <tag> https://github.com/jgm/pandoc` away), and the files below are where the answers are. Each entry says whether it was read from the source or measured. 3.12.1 (2026-10-07) changed the DOCX reader and writer, the Markdown reader and writer, and how the LaTeX writer writes alt text, and the entries those touch say so; it left the LaTeX and HTML readers, the EPUB reader and writer, `Chunks.hs`, the Lua engine, and `default.latex` as 3.12 had them (`diff -r` of the two tags' trees; the HTML writer's one change is reveal.js's address). Building Pandoc itself, which only an upstream patch needs, is in the section before Upstream.

- `src/Text/Pandoc/Writers/Markdown.hs` (and `Writers/Markdown/Table.hs`) — which table form is written, what becomes raw HTML, how figures are written.
- `src/Text/Pandoc/Readers/Markdown.hs` — raw HTML blocks, implicit figures, the `figure` div.
- `src/Text/Pandoc/Lua/Marshal/` — what a filter sees: `AttributeList`, `List`, the `Attr` constructor.
- `data/templates/default.epub3`, `data/epub.css`, `data/docx/` (the reference document).

What a slide's classes put among a frame's options is `frameoptions` in `Writers/LaTeX.hs`.

## The DOCX reader

**Bookmarks become anchors only when linked from the same document.** `parPartToInlines'` turns a bookmark into a `Span` with class `anchor`; `rewriteLinks` records every `#target` a link in the document uses in `docxAnchorSet`; `removeOrphanAnchors` then deletes every anchor span whose id is not in that set (`Readers/Docx.hs` 870–899). Consequence: a bookmark that only *another* file links to — every index term, every cross-chapter reference in an OpenStax export — is gone. Read from the source; measured on *Clinical Nursing Skills* (`term-00044`). Our repair adds an invisible link per unlinked bookmark so the set contains it.

**A bookmark inside a heading paragraph does not keep its name.** In a header, the reader records `bookmark → header id` in `docxAnchorMap` and rewrites same-file links to the header's auto id; the name itself never appears in the output (the `inHdrBool` branch of `parPartToInlines'`). So a bookmark that has to be addressable by name from another file cannot sit in a heading; our repair puts one before a heading into an empty paragraph of its own. Read from the source.

**Two bookmarks in a row collapse into one anchor.** `docxImmedPrevAnchor` holds the last bookmark seen until a non-bookmark part resets it; a bookmark seen while it is set is mapped to the previous name and dropped. The state carries across paragraphs. Read from the source (`parPartToInlines'`); measured on `term-00022`, which followed another bookmark. Our repair puts a zero-width run between adjacent bookmarks inside a paragraph, and at the start of a bookmark-only paragraph, and the filter removes the character.

**Body-level bookmarks are dropped.** `w:bookmarkStart` as a direct child of `w:body` (between blocks, which is where OpenStax puts one for a paragraph, list, heading, or table) is not a `ParPart` of any paragraph, so nothing makes an anchor of it. Measured (4,231 in one book); consistent with the parse. Our repair moves them into the following paragraph, or hands the ones before a table to the filter through the pre-pass.

**A link with no text is dropped before its target is recorded.** An empty hyperlink run yields no inlines and no `Link`; the anchor set never sees it. Measured. The keeper links carry a zero-width space.

**Metadata comes from `Title`/`Author`-styled paragraphs, not `docProps/core.xml`.** Measured on 3.11; open upstream as #3034. The first `Title` paragraph becomes the title, later ones plain paragraphs.

**The pipeline recovers ScreenTips on reading, for Pandoc before 3.12.** #11890, which makes the reader and writer do it, was merged into `main` on 2026-09-25 as c51b6a6 and released in 3.12 (2026-09-29); with 3.12 this changes nothing (a link that already has a title keeps it), and it can go once the pipeline requires 3.12. Until then: `docxrepair.apply_screentips` reads each `w:tooltip` from the package (the document, footnotes, and endnotes, with their relationships) after Pandoc has read the repaired copy, and gives each link Pandoc left without a title its ScreenTip, matched by target and text in document order, or by target alone when Pandoc merged a hyperlink's pieces and that target's ScreenTips agree. A link that already has a title keeps it, so a Pandoc with #11890 changes nothing. Measured on fixtures built from Pandoc's own output with `w:tooltip` added, internal links included.

**The DOCX reader pairs a caption only with a paragraph that holds a drawing and nothing else** (`Parse.hs`, `isCaptionable`), or with a table. A bookmark inside the picture's paragraph is enough to lose the figure. Pandoc's own writer puts a body-level bookmark before every figure with an id, so our reading repair, which moves body-level bookmarks into the paragraph after them, cost Pandoc's own figures their captions until it learned to put them in the caption instead. The caption styles it knows are named `Caption`, `Table Caption`, and `Image Caption`, case-insensitively, through the style hierarchy. A figure with no caption, which the writer styles `Figure`, isn't read back as a figure. Measured on the statistics book's Word target. The caption is the paragraph before the table or drawing, or the one after it when that one isn't kept with the next (`addCaptioned`): so a Caption paragraph reading only "Table 1.2" is the table's caption, a bare label, which the filter describes from the sidecar and a Word copy joins its description to, before the table or after it. Read at 3.12.1 and measured on a Word file Pandoc wrote from `Table: Table 1.2`, 2026-10-11.

**A numbered caption's label is stripped only from a simple field, and its separator never.** In a caption paragraph, `stripCaptionLabel` (`Parse.hs`) drops what comes before the first `w:fldSimple` whose instruction names `Figure` or `Table`, the label a `SEQ` field numbers, and the field. Through 3.12 it dropped bookmarks there too, so the bookmark our reading repair puts at a caption's start went with the label: a Word file Pandoc wrote with `+native_numbering`, put through `docxrepair.repaired_copy`, read back with the link to its figure dead on 3.12, and landing on 3.12.1, which keeps them (#11918, b7aa2db). On both, the separator after the number stays, so `Figure 1: A caption` reads back as `: A caption`: an upstream candidate. A complex field, Word's own (`w:fldChar` and `w:instrText` inside runs), isn't stripped at all, since the function looks only at the paragraph's own children: the same caption with its field made complex reads back `Figure 1: A caption`. Read from the source and measured on 3.12 and 3.12.1, 2026-10-08. And 3.12.1 reads `w:dstrike`, double strikethrough, as strikeout, where 3.12 read the text as plain; read in the source.

**The DOCX writer numbers a list item's continuation with an invisible bullet, and the reader splits the list there.** A second paragraph or a code block in an item is written with its own `w:num` whose level is a bullet with `lvlText` a single space, to indent it under the item's text; the reader takes it for an item of another list. OpenStax's export does the same, so its Word files have it too: 102 such paragraphs in the statistics book's 169. The reader does fold a numbered paragraph whose numbering it can't find into the item before it (`Lists.hs`, `handleListParagraphs`, via the `list-paragraph` class `Docx.hs` gives a `ListItem` with no level info), so our reading repair renumbers a blank-marker level's paragraphs with an id that has no definition.

**The DOCX writer styles every level of a block quote alike, and the reader nests quotes by indentation.** Every paragraph of a quote at any depth is `Block Text`, and a list or code inside one gets no style or indent to say so, so the file itself can't tell a quote within a quote from one. Given a deeper `w:ind`, the reader nests a paragraph (measured), but not code: a code paragraph in a quote comes back one level deep however far it's indented (measured at depths two and three). A numbered paragraph it never puts in a quote, however indented, so a list in a quote comes back outside it, and code a list item holds in a quote, numbered at a blank level to stay in the item, comes back in the item with no quote (tried by hand: a quote step of `w:ind` on it made no difference). A loose list's items in a quote are written `Block Text` like the quote's paragraphs, and the reader then wraps each item's content in a quote of its own. A `Div` with an id is written as a body-level bookmark range around its paragraphs, which is how our Word target marks each quote before writing and indents by depth afterward.

**The DOCX reader wraps each quote paragraph in a quote of its own, and joins adjacent quotes only where they sit.** A paragraph in a quote style, or indented beyond its style, is its own `BlockQuote`, doubled for a deeper indent; the block combining then joins adjacent quotes at their own level and no deeper, so an outer quote's paragraphs come back as one quote and a nested quote's as one quote each. A list item's paragraphs are read one at a time, so a quote inside an item comes back as one quote per paragraph, never joined. Two separate quotes in a row are joined too, and an empty paragraph between them doesn't help, since the reader drops it first; a paragraph holding only a bookmark isn't dropped (it comes back as an empty paragraph) and keeps them apart (measured). So our Word target writes one between two quotes in a row, and our reading repair takes it out again once the quotes are apart, after finishing the join inside quotes.

**A description-list term with no definition comes back as a `Div` of class `Definition-Term`.** The reader builds a `DefinitionList` only from a term paragraph followed by a definition one; a review question with an empty answer, written as a `Definition Term` paragraph alone, isn't one. Our reading repair makes a run of them a list again.

**The DOCX writer hashes an id that isn't a valid bookmark name.** In 3.11, `toBookmarkName` (`Writers/Docx/OpenXML.hs`) keeps an id that starts with a letter and is at most 40 characters, and otherwise writes `X` and the SHA-1 of the id with its first hex digit dropped, 40 characters in all; Python's `"X" + sha1(id).hexdigest()[1:]` reproduces it. In 3.12 (#11845) every name gets a leading `_`, which hides the bookmark in Word: `_` and the id when it's under 40 characters of letters, digits, and `_`, otherwise `_` and the same 39 hex digits, so an id with a hyphen, as most of Pandoc's are, is hashed. Python's `"_" + sha1(id).hexdigest()[1:]` reproduces it: checked against 3.12's output for `word-page`. A link within the page goes through the same function, so it still works; a link from another page is an external hyperlink naming the id itself, and after a round trip it's dead. Every Asciidoctor section id starts with an underscore, and DCIC's long ids ran past 40: 475 dead links read back. Our Word target records the hashed names in a custom XML part, and reading renames them back.

**What a DOCX round trip loses, measured on four books.** A list inside a block quote comes back outside it, splitting the quote (repaired since 0.8, below); a table's role is gone, since Word keeps no layout-table mark; a figure with no caption comes back as an image. With the repairs above, DCIC (from HTML) survives unchanged on 50 of 80 pages (57 once lists, code, and quotes inside quotes and list items were repaired, in 0.8), the statistics book (from Word) on 167 of 169, and the security textbook (from AsciiDoc) on 12 of 14, with no dead links in any.

**A hyperlink's ScreenTip (`w:tooltip`) is discarded** in both directions, in 3.11 and in `main` until c51b6a6 (#11890, merged 2026-09-25) fixed it. Measured; filed as #11869. Where: the two `w:hyperlink` cases of `elemToParPart'` in `Parse.hs` read `r:id` and `w:anchor` and nothing else, `parPartToInlines'` builds each `Link` with an empty title, and the writer's two `Link` cases in `OpenXML.hs` ignore the title. Read from the source. jgm replied on 2026-09-22: he treats a ScreenTip as the counterpart of HTML's `title` and would map it to the `Link` title in both directions, by default with no extension, and for internal links too if feasible. `w:hyperlinkRuby` and the question about contributing a patch drafted with Claude went unanswered. The patch series doing what he described was merged as #11890 (see Upstream). No file in the corpus has a ScreenTip: 25,017 `w:hyperlink` elements in the `document.xml` of 1,782 files, none with `w:tooltip`, and no `\o` switch or `w:hyperlinkRuby` anywhere; the full statistics files' footers add 169 hyperlinks, also without. Measured. So for these books the change brings nothing in; its value is for authors who write them.

**A `HYPERLINK` field's switches are all parsed, and only `\l` is used.** `hyperlink` in `Fields.hs` collects every switch; `\l` becomes the fragment, while `\o` (the field-code form of a ScreenTip), `\t`, `\m`, and `\n` are dropped. A quoted argument keeps `\"` as written, backslash included. Read from the source. The corpus's only field-code hyperlinks, seven in the BC files (BC-03, 10, 13, 14, and 15, pasted from the web), have no `\o`.

**Word saves a `HYPERLINK` field's `\o` as `w:tooltip`.** A hyperlink made with Ctrl+K, its field code then edited by hand to add `\o "…"`, was saved as a plain `w:hyperlink` carrying `w:tooltip`, with no field left. And an address typed as `https://example.org/guide.html#install` was saved as the relationship target `https://example.org/guide.html` with `w:anchor="install"`, which the reader joins back with a `#`, as Microsoft's notes say Word itself does. Measured on Word for Microsoft 365, Version 2609 (the fixture `test/docx/link_tooltips.docx` on the ScreenTip branch). So a Word-saved file has one form of ScreenTip, and reading `\o` was dropped from the patch.

**Word limits a ScreenTip to 260 characters.** [MS-OI29500 §2.1.521](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/df06e423-11a6-4a36-bfb3-82139e531781): the standard sets no limit on `w:tooltip`, Word restricts it to 260, and `anchor`, `docLocation`, and `tgtFrame` to 255. The same note says Word appends `#` and `w:anchor` to an `r:id` link's target, where the standard says to ignore the anchor. What Word does with a longer one isn't stated there. It opens the file without complaint, shows the first 260 characters, and cuts the ScreenTip to 260 when it saves. Read from Microsoft's documentation; the behavior measured on Word 2609 with `screentip-writer-check.docx`, written by the patched writer with ScreenTips of 260, 261, and 400 characters. So the writer writes a title whole: Word handles its own copy, and a round trip that never passes through Word keeps it.

**Adjacent links merge only when target and title both match.** `Combine.hs` treats a `Link` as a modifier and compares two by applying each to empty inlines, so a hyperlink Word split into two `w:hyperlink` elements comes back as one link, and two with different titles stay two. Read from the source.

**An image's title already goes both ways.** `getTitleAndAlt` reads `wp:docPr/@title` into the `Image`'s title and `@descr` into its alt text, and the writer writes both back to `wp:docPr`. It's the precedent for the ScreenTip. Read from the source.

**The reader finds `document.xml` only through `_rels/.rels`.** `getDocumentXmlPath` has no fallback, so a package without that part is a `DocxError`. Nothing else is required: `_rels/.rels` and `word/document.xml` alone read, with external links' targets empty for want of `document.xml.rels`. Read from the source; measured on all 1,782 slim corpus files once that part was added. But without `styles.xml` no paragraph has a style, since a paragraph's style ids are looked up in the styles' map and one that isn't there is dropped (`pStyle'` in `Readers/Docx/Parse.hs`), so nothing is a heading or a title: the slim corpus's BC-15 read with no heading, and with Pandoc's own `reference.docx` styles added, 59, since its paragraphs use the ids Word gives its built-in headings, `Heading1` and the rest, which Pandoc's reference document has too (OpenStax's export, being Pandoc's output, uses Pandoc's own). Read at 3.12.1 and measured, 2026-10-15.

**`w:tblHeader w:val="0"` read as a header row until 3.10.** Measured across versions.

**Heading ids are made unique against the anchor map's values, and a bookmark can hold the next candidate.** `makeHeaderAnchor'` computes a heading's id with `uniqueIdent`, checking each candidate (`base`, `base-1`, `base-2`, …) against `M.elems docxAnchorMap` (`Readers/Docx.hs` 589; `Shared.hs` 616). OpenStax names the bookmark for a repeated heading `site-selection-1`, which is exactly the candidate the second "Site Selection" heading is offered, so two headings got one id. Read from the source; measured on *Clinical Nursing Skills* (16 pages). Our filter renumbers duplicates as its last pass.

**A style based on `Heading N` is a heading.** `Heading2Grey` (OpenStax) becomes a level-2 `Header` with the style as a class. Measured.

**Row 1 is a header row whenever Word's table look says the table has one.** `splitHeaderRows (firstRowFormatting look)` in `Readers/Docx.hs`: with the first-row flag set in `w:tblLook`, row 1 is the head, and the rows after it join the head while they're marked to repeat (`w:tblHeader`) or continue a cell merged down from one; without the flag, only rows marked to repeat do, and when the first such row comes after unmarked ones, those are promoted with it so the order holds. So a header row can be declared by nothing but the table's style. The header pre-pass counts it as shared by every part of a banded table, as the filter copies it, and a declared `none` turns it back into ordinary cells: *Business Communication*'s Table 22.6 lost its header row that way until the per-part guess learned this. Read from the source (3.11).

**A quotation's style reaches its table's cells.** The writer gives every paragraph inside a quotation its Block Text style, a table's cell paragraphs among them; read back, a cell holding a minipage's div (GIAM's boxed aside in a proof) came back as a quotation of its own, the table gone. The Word target writes such a table's cells as `Compact`. Measured on GIAM's `proof2`, 2026-10-05.

**What the reader folds into a list item, and what ends a list.** `handleListParagraphs` (`Readers/Docx/Lists.hs`) folds a "list-paragraph" div, a paragraph numbered with an id that has no definition, into the list item before it, and nothing else: a table between an item's paragraphs ends the list. A rule is read from Pandoc's own form (`w:pict` holding a `v:rect`) only when the paragraph has nothing else, `w:pPr` included, and from a paragraph with a bottom border (`pBottomBorder`) as a rule appended after the paragraph's blocks, outside any list-paragraph div, so a bordered list paragraph still ends the list. Read from the source (`Readers/Docx/Parse.hs`, `elemToBodyPart`; `Readers/Docx.hs`, `bodyPartToBlocks`) and measured, 2026-10-05. The Word target records tables and rules in a top-level list item in its id-map part, and `docxrepair.apply_list_tables` puts them back.

**The reader reads Office math wherever a paragraph holds it**: an `m:oMath` in a `w:p` is `InlineMath`, an `m:oMathPara` `DisplayMath`, through texmath's OMML reader (`PlainOMath` and `OMathPara`, `Parse.hs` 900 and 1254, `Docx.hs` 474–477). PowerPoint keeps its equations in the same OMML (`a14:m` holding `m:oMath` or `m:oMathPara`), so the deck reader writes each deck's into a Word file of one paragraph each, after a paragraph naming it, and reads them back as TeX. Read from the source at 3.12; measured on OpenStax's 13 decks, whose 73 equations all read, 2026-10-15.

## The HTML reader

**A `<main>` is the whole document.** `extractMain` (`Readers/HTML.hs`, after `parseDoc`) finds every `Div` with `role="main"` (a `<main>` gets that role on read, unless it has a role of its own): when there's one, with no id and no class, the document is its contents; when there's one with an id or a class, or more than one, the document is those `Div`s, whole, and nothing outside them; when there's none, it's everything. Read from the source (3.12.1, 2026-10-17; this entry had said one main gives its contents and anything else everything); measured on 60 just-the-docs pages, where the site navigation is gone with no work from us, and on a page with WordPress's `<main id="main" class="site-main">`, which is a `Div` with the id, the class, and the role. A generator that marks its content with a `div` and a class gets no such help.

**A row of `th` partway down a `tbody` is read as a body row.** Pandoc has no header cells within a body, so the cells become ordinary cells, with the source's `scope="col"` left as an attribute, which the writer puts on a `td`. Measured on EdTech Books tables that repeat their header row; `html-source.lua` splits such a table at the row.

**A heading with no id gets one made from its text, the title-block `h1` included.** A page Pandoc wrote has `<header id="title-block-header"><h1 class="title">`, with no id, and when the title's text is also a section heading's, the generated id collides with the section's explicit one and the reader warns `Duplicate identifier`. On DCIC read back, 79 of 80 pages. Measured; `lib/htmlrepair.py` gives that `h1` an id first.

**`<nav>` and `<footer>` leave no trace of themselves.** `isDivLike` is `div`, `section`, `header`, `main`, `aside`; `section`, `header`, and `aside` become a `Div` with that class. A `<nav>`'s tags are skipped and its list is read as an ordinary `BulletList`, so a filter cannot tell a menu from content. Read from the source; measured (a page's own table of contents inside `<main>` arrives as a list of links). What has to go has to go from the DOM, before Pandoc.

**An `<iframe src>` is fetched over the network unless `raw_html` is on**, which it isn't by default for this reader: `pIframe` is guarded by `guardDisabled Ext_raw_html`, opens the URL, and reads what comes back into a `Div` with class `iframe`. With `-f html+raw_html` the tag is two `RawBlock`s and nothing is fetched. Read from the source and measured (the fetch attempt is logged as `Could not fetch resource`). The EPUB reader turns `raw_html` on itself.

**MathJax's rendering is skipped, its source is read.** Spans with class `mjx-chtml`, `MathJax_CHTML`, or `MathJax_Preview` are dropped (#10673), and `<script type="math/tex">` becomes `Math`, display when the type ends in `display`. Measured: 36 scripts, 36 `Math`, no duplicates. Not covered: MathJax 2's HTML-CSS output (class `MathJax`, with `mi`/`mo`/`mrow` spans), which is read as nested spans of text. A page saved as MHTML has no scripts, so there the TeX is gone and only that rendering is left. So a CommonHTML formula in an `.mhtml` save vanishes with no trace, and an SVG one leaves nothing to read. `lib/mathjax.py` replaces every MathJax rendering, of any version, before Pandoc reads the page.

**A `<th>` in every body row is a header column; the reader works it out.** `pTableBody` counts the leading `<th>` cells of each row and sets `RowHeadColumns` when every row agrees, 0 when they don't (`Readers/HTML/Table.hs`, citing #8984 and #8634); `scope` rides along as an attribute on the cell. A row of `<th>` alone at the top is the head even with no `<thead>`. Read from the source and measured. So the roadmap's old note that the reader "keeps the attribute but not the element" was wrong for the ordinary case, and what lost our own pages' row headers on reading them back was our filter, which sets `row_head_columns` to 0 on any table with no declaration, because a Word table never arrives with one. `html-source.lua` turns what the reader found into a declaration.

**Footnotes are read back into notes, keyed on the id of the element that holds the note.** A link with `role="doc-noteref"` (always) or `epub:type="noteref"` (with `epub_html_exts`) becomes a placeholder; inside an element with `role="doc-endnotes"` or `epub:type="footnotes"`, each child's content is filed under that child's own `id` (`eNoteref`, `eFootnotes`, `eFootnote`); `replaceNotes` joins them, and a reference with no match is an empty `Note` and a warning, `Reference not found`. So Pandoc's own endnotes round-trip, and anything that moves a note's id off its `<li>` empties every note on the page with the text gone. Read from the source; measured the hard way. The same block drops an element whose `epub:type` contains `titlepage`, with or without the extension.

**An id survives only where the AST has somewhere to put it**: div, section, span, heading, link, image, figure, table, code. `<p>`, `<li>`, `<dt>`, `<dd>`, `<td>`, `<th>`, `<caption>`, `<figcaption>`, `<blockquote>`, and the inline marks (`em`, `strong`, `sup`, …) lose theirs. Measured: a link to `<p id="deep">` was dead after reading. `lib/htmlrepair.py` moves those ids onto empty spans first.

**With `raw_html` on, a tag the reader has no element for is a fragment of raw markup**, opening and closing tags separately: `<footer>`, `<nav epub:type="toc">`, `<cite>`, and an unbalanced `</code>` the author never opened, which the writers then pass through. Measured: that last one made an EPUB that was not well-formed. `html-source.lua` drops the fragments and keeps what was between them, which is what the reader does with `raw_html` off.

**The HTML reader gives a heading an id from its text when it has none** (`auto_identifiers` is on for it), so an anchor inside a heading can't simply take the heading's place: it has one already. Measured.

**The EPUB writer builds each navigation entry from the heading's inlines**, attributes and all, so an empty `<span id>` inside a heading is an empty span inside `<nav>`, which epubcheck rejects. Measured on 11 headings. So is a span holding only a space, to epubcheck: an OpenStax heading's divider between its number and its words, `<span class="os-divider"> </span>`, was RSC-005, "Spans within nav elements must contain text" (*Anatomy and Physiology 2e*), measured with 3.12.1 and epubcheck 5.2.1, 2026-10-14.

**An id with whitespace in it is kept as it is**, from `<a name="section 15">` or `id="section 15"`, though neither HTML nor XHTML allows one; the writers then emit it, and epubcheck rejects each (RSC-005, 469 in DCIC). Measured. `html-source.lua` makes the whitespace a hyphen, in ids and in links' fragments.

**An empty alt and no alt read the same.** `<img alt="">` and `<img>` both become an `Image` with an empty caption, and the HTML writer writes that with no `alt` at all. In HTML an empty alt is the author saying the image is decorative, so without help every deliberately decorative image comes out undescribed, and a screen reader reads its file name. Measured. `lib/htmlrepair.py` gives such an image, and one with `role="presentation"` and no alt (Canvas's way), the class `decorative` before Pandoc reads the page, which the filter writes as `alt=""`.

**A paragraph keeps none of its attributes.** `pPara` builds a `Para` from the inlines and discards the tag's class and id. `<p class="subtitle">` and `<p class="date">` in Pandoc's own title block come back as bare paragraphs, and so does a web page's `<p class="caption">`. Read from the source and measured. Anything a paragraph's class has to say must be said before Pandoc reads it, or read out of the file.

**Pandoc's own title block is content to the reader**: `<header id="title-block-header">` becomes a `Div` with that id, while `<title>` and the `<meta name=…>` elements become metadata. Measured: reading our own page and writing it again gave two titles.

**An inline `<svg>` becomes an `Image` with a `data:` URI** (`pSvg`), including a twelve-pixel link icon inside a heading. Measured.

**The reader is lenient where an XML parser is not.** An EPUB content document with an unclosed `<br>` (Asciidoctor's, in one of our samples) reads without complaint; `xml.etree` refuses the file and epubcheck calls it fatal (RSC-016). Measured.

**`<details>` and `<summary>` have no element.** With `raw_html` they arrive as raw fragments, a tag at a time, and a summary's text between them becomes a `Para`, which is invalid inside `<summary>` once written back. Without `raw_html` the tags are dropped and the answer they hid sits open on the page. Measured; the Markdown reader does the same.

**Pandoc's own math markup doesn't read back as math.** `<span class="math inline">\(k^2\)</span>`, which the HTML writer produces for MathJax, is read as a `Span` with those classes holding the literal text `\(k^2\)`. Measured. What does read as math is `<script type="math/tex">` (MathJax 2's markup), or the delimiters themselves with `tex_math_single_backslash`, next.

**`tex_math_single_backslash` finds math inside `<code>`.** `<code>\(not math\)</code>` comes back as `Math InlineMath "not math"`. Measured. So the extension is unsafe for a programming book; `unpack-site.py` converts MathJax's delimiters itself, outside code, into `<script type="math/tex">`. Candidate upstream report.

**A table grouped by `<tbody>` keeps its groups.** Each `<tbody>` whose first row holds a `<th>` becomes a table body with that row as its own head row, and the HTML writer writes it back as a `<tbody>` with the row as `<th>` cells, attributes kept (`scope="rowgroup"`). So HTML to HTML preserves row groups exactly. Measured.

**Bold or italic written as a style isn't read as bold or italic.** `<span style="font-weight: bold">` is a `Span` keeping its `style` attribute, not `Strong`, which is how Scribble and many exporters write a header row. Measured; `html-source.lua` makes it `Strong` and `Emph`.

**A heading's generated id avoids only earlier headings' ids, and a div's first heading gives up an id the div has.** The HTML and Markdown readers record an id only in `registerHeader` (`Parsing/General.hs`), which a heading's generated id is checked against, so a table's, a div's, or a span's explicit id is never among them, before the heading or after: `<h1>Money</h1>` and a `<table id="money">`, in either order, or `# Costs` and a table captioned `{#costs}`, both have the id. The one exception is a `div` or `section` (any element `isDivLike` names) whose first block is a heading with its id, generated or written: `pDiv` (`Readers/HTML.hs`) clears the heading's, so `<section id="costs"><h2>Costs</h2></section>` reads with the section's id alone, and `<div id="other"><h2>Costs</h2></div>` keeps both. Read at 3.12.1 and measured, 2026-10-14. So `htmlrepair.py` marks an HTML page's heading that has no id of its own, and `figures-and-tables.lua`'s `make_ids_unique` renames such a heading wherever another element has its id, and reports every other rename (`ids-renamed.csv`).

**`<dfn>` is a `Span` with class `dfn`, and `<strong class="…">` loses its class**, `Strong` having no attributes. Measured with 3.12.1, 2026-10-14.

**`<code>` is inline wherever it stands, and only `<pre>` makes a code block.** A `<code>` is a `Code` of its text (`formatCode`), its spaces run together, a `<br>` in it a `LineBreak` between two, and a `<strong>` in it `Strong` around a `Code`. A `<pre>` whose first child is `<code>` is a `CodeBlock` of the text alone, a `<br>` a line end and any other element's formatting lost, with the two tags' attributes together, `pre`'s winning where both have one (`pCodeBlock`, `toAttr` keeping the first of a repeated attribute), so `<pre class="x"><code class="language-python">` loses its language; `language-` is taken off a class. A `<pre>` without one is preformatted paragraphs, no-break spaces and `LineBreak`s with the formatting kept (`pPreBlock`); 3.9, TI's minimum, makes it a `CodeBlock` (`plain` and an indented `two` one block of two lines), and gives a `<pre>` with any attribute of its own none of its `<code>`'s (`<pre id="p2"><code class="python">` is a code block with the id and no class, so no language, where 3.12.1 gives it both), since its `pCodeBlock` reads the code's attributes only when the `pre` has none. Read at 3.12.1 and measured there and with 3.9's release binary, 2026-10-14.

**MathML is read with texmath, presentation MathML only, after every tag's prefix is dropped.** An element texmath doesn't know, content MathML's `apply`, `ci`, `cn`, and the rest, fails the whole formula, which the reader keeps as its text in a `Span` of class `math`: `<apply><plus/><ci>a</ci><cn>1</cn></apply>` is the text `a1`. A formula carrying a TeX annotation (`encoding="application/x-tex"`) is read from that instead (`pMath`), and content MathML inside `semantics`, as `annotation-xml`, is harmless; OpenStax's sources have both, and a few formulas wholly content. `readHtmlWithDepth` strips each tag's namespace prefix before anything reads it (`stripPrefixes`), so `<m:math>` holding `<m:mi>` is MathML as `<math>` is, its namespace declared or not (3.12.1 and 3.1.3 alike). Read at 3.12.1 and measured, 2026-10-14.

**Some MathML is read as TeX texmath can't read back**, so the HTML writer shows the formula as its TeX ("Could not convert TeX math", the output check's `formula-shown-as-tex`): a straight or a closing curly double quote in an `mo`, `mi`, or `mn`, written `"` (`x."` from `<mo>.</mo><mo>"</mo>`), and an `mtext` in bold italic or bold sans serif, which becomes `\textit{\textbf{x}}` or `\textbf{\textsf{x}}`, a text command inside another, which texmath's TeX reader stops at (the `\text` entry in the LaTeX reader's section). An em space or em quad inside an `mtext` with words becomes `\quad` in `\text`, written back as U+2000, an en quad, half as wide and not in NFC (the `\mbox` entry there); an `mtext` holding the space alone is `\quad` between the parts, written as an `mspace` of 1em. An under- or overbrace written with U+FE38 or U+FE37, the brace for vertical CJK text, as MathType writes it, is `\underset{︸}{…}`, a glyph math fonts lack; with U+23DF or U+23DE it's `\underbrace{…}`. Found converting OpenStax's books from their source (*College Algebra* 5 of the quotes and *Prealgebra* 3, *Calculus Volume 1* 17 of the bold italic, *College Algebra* 18 of the Nu checker's NFC warnings, 128 braces of the first kind) and measured with 3.12.1, 2026-10-14. Candidates for texmath reports; the CNX unpacker writes such a quote as `mtext`, such a letter as the `mi` it is, and the brace that reads.

**texmath drops a forced line break, and writes a word as one italic identifier a letter.** An `<mspace linebreak="newline"/>` is read as a space, so a formula's lines run together; an `mtable` is read as `\begin{array}`, its `columnalign` kept, which every writer sets as rows. An `mi` of more than one character is a group, `{Value}`, which the MathML writer writes as an `mi` for each letter, each italic (`<mi>V</mi><mi>a</mi>…`), and `mathvariant="normal"` on it is lost on the way; a name texmath knows stays whole and upright (`sin`, `log`, `max`, and the rest of LaTeX's named operators; not `sech`, `cis`, or the Polish books' `tg`). An `mtext` is `\text{…}`, and an `mo` of letters `\operatorname{…}`, each kept whole, the second with a function application after it. Measured with 3.12.1, 2026-10-17: *Principles of Marketing*'s "Value = Benefits/Price" over "(V = B/P)" ran together, and in 16 of OpenStax's math and physics books and *Marketing*, 5,374 identifiers of Latin letters are split so (and some hundreds more of other letters, `µF` and `kΩ`), in 4,296 of 222,241 formulas, units most of them (`cm` 964, `kg` 567, `nm` 508, `eV` 359), most in the Polish physics books. The CNX unpacker makes a formula's forced line breaks the rows of a one-column `mtable`; whether it writes such an `mi` as an `mtext` is Rob's to decide (CNX-NOTES).

## The EPUB reader

**The spine is concatenated into one document**, each file preceded by an empty `Span` whose id is the file's name, and non-linear items are dropped (`parseSpine`). Only `dc:` elements become metadata: no `meta property=` (so none of the `schema:accessibility*` claims), and each file's own `<title>` and `lang` are lost. Read from the source.

**Every id is rewritten to `<file>_<id>`, but only on `Div`, `Header`, `CodeBlock`, `Span`, `Code`, and `Link`** (`fixBlockIRs`, `fixInlineIRs`), while every internal link is rewritten to `#<file>_<fragment>`. A `Figure`, `Table`, or `Image` keeps its bare id, so a link to a figure or a table is dead after reading. Read from the source; measured on a Pressbooks EPUB (117 figure ids and 6 table ids unprefixed). Candidate upstream report; tracker not searched yet.

**Every `epub:` attribute is removed** (`removeEPUBAttrs`), so `epub:type="footnote"`, `noteref`, and the landmarks leave nothing. Read from the source.

**The navigation document is not read** unless the spine lists it, and then it is content.

## The DOCX writer

**Drops a table's `id`.** Measured. **Wrote `w:styleId` before `w:type`** in `styles.xml` through 3.12, the reverse of Word's order; 3.12.1's XML library keeps the reference document's order (6e6b47d), `w:type` first. Parse attributes by name. Measured on 3.11, 3.12, and 3.12.1. **The bundled `reference.docx` declares no `compatibilityMode`**, so every `.docx` Pandoc writes opens in Word's Compatibility Mode; deliberate (#5645, #5358). Saving one in Word 2609 warns that it will be "upgraded to the newest file format", and the saved copy declares `compatibilityMode` 15. Measured.

**An internal link doesn't come back to its own target** (3.12; fixed in 3.12.1). `toBookmarkName` gives every bookmark the writer makes a leading `_`, which hides it in Word's interface (an id of 40 characters or more, or with anything but letters, digits, and `_`, becomes a SHA-1 instead), and the link's `w:anchor` the same name, so `[x](#methods)` reads back as `[x](#_methods)`. Measured on `main` (f0a20d437) and again on 3.12, where the round trip of a Markdown file with three headings reads each heading back with an id made from its text and each link to one with the hidden name, `#_costs` or `#_` and a hash: dead backward and forward alike. 3.11 kept both, since its bookmark name was the id. The cause, read and then measured: the writer's `makeSectionsWithOffsets` (`Writers/Docx.hs`) moves each heading's id to its section `Div`, and the `Div` case of `blockToOpenXML'` (`Writers/Docx/OpenXML.hs`) wraps the whole section in the bookmark, at body level, outside any paragraph; the reader parses a bookmark only inside a paragraph (`elemToParPart'`, `Readers/Docx/Parse.hs`), so it never reads a heading's, the heading gets an id from its text, and `rewriteLinks` has nothing to map the link through. 3.11 worked only where the id was the one the reader derives from the heading's text: `# Costs {#price}` with a link to `#price` read back dead in 3.11 too. Moving each bookmark into its heading's paragraph by hand in 3.12's output made every link read back to its heading (`{#price}`'s link to `#costs`, the heading's new id). That placement is also what #11845 asks for (a screen reader announces the bookmark at the section's last line) and what #8825 proposes for Word's cross-references. A one-clause writer change doing it was merged as #11917 (62bfc1f, 2026-09-30) and released in 3.12.1 (see Upstream), where the three-heading round trip reads every link back to its heading (measured, 2026-10-08). The reader still drops a heading bookmark's name, so `# Costs {#price}` and its link come back as a heading `costs` and a link to `#costs`, which lands; and `toBookmarkName` still adds the `_`. The Word target's own marks, which it finds again in the writer's XML by bookmark name, are letters and digits for this reason, and are looked for with and without the `_`.

**The DOCX writer flattens a table's bodies into one.** A body's head row becomes an ordinary row, and a head row that is one cell spanning the table becomes a merged cell (`w:gridSpan`): Word's own form for a band. Read back, it's one body with that row as a spanning `<td>`, which is the shape the header pre-pass infers bands from. So a grouped table survives a trip through Word in meaning, not in markup. Measured.

**A table inside an aligned table's cell has two alignments in each of its cells.** A cell's blocks are written inside `withParaProp` with the column's `w:jc` (`ooxmlCellToOpenXML`, `Writers/Docx/Table.hs`), and `withParaProp` (`Writers/Docx/Types.hs`) puts a property before those already set (`EnvProps`'s `<>` appends the lists; only the style is chosen, the inner one), so a cell of the inner table has its own `w:jc` and then the outer cell's, where the schema allows one (`CT_PPrBase`). Read from the source; measured on 3.12 and 3.12.1 with an HTML table in such a cell, and on GIAM's Word files on 3.12.1: 113 doubled `w:jc` in 3 of 11 files, the only schema errors. `docxtarget.single_alignment` keeps the first, the cell's own; then all 11 files validate, and read back the same. An upstream candidate.

**A display formula in a list item ends the list on reading.** `getParaProps` (`Writers/Docx/OpenXML.hs`, 3.12) writes no `w:numPr` at all for a paragraph whose one inline is display math (`not displayMathPara`), where the item's other continuation paragraphs get `w:numId` 1000, the numbering with no marker (`baseListId`); a paragraph mixing text and display formulas is first cut into paragraphs by `fixDisplayMath` (`Writers/Shared.hs`), so a formula in the middle of an item's text is affected too. The reader then ends the list at the formula, and the rest of the item and the list come back as new lists or indented paragraphs. Measured on GIAM's exercises and a one-item case. Filed long ago as #6638 (open, 2020); #11900 (closed 2026-09-25) changed the indent of such continuations, not this. The Word target marks each such formula and gives its paragraph the item's level and numbering 1000 (`docxtarget.list_math`).

**A display formula in a span with anything else is written in the line.** `fixDisplayMath` (`Writers/Shared.hs`), which the Word writer applies first, cuts a paragraph into paragraphs at a display formula alone or in a span alone (`isDisplayMath`); a numbered formula's span, holding its anchors and its number as well, isn't, so Word would set the formula among the paragraph's words. `docxtarget.py` unwraps the span before writing, the number after the formula on a line of its own. And of seven empty spans with ids beside such formulas, the writer (3.12) made bookmarks of the five a link targets. Measured, 2026-10-07.

## The Markdown reader and writer

**The reader keeps duplicate ids and warns.** `[WARNING] Duplicate identifier 'x' at file.md line N` on stderr; both elements keep the id. Measured on a merged file with 733 of them. Relevant because Pandoc's HTML writer then emits invalid HTML without complaint.

**The Markdown writer drops a bare link's title.** A link whose text is its own address is written as an autolink, `<https://…>`, whatever its title, so `[https://x](https://x "t")` comes back without `t`; a link with other text keeps its title. Measured on 3.11 and again on 3.12.1. The Markdown target writes such a link in full.

**A plain raw HTML block is read one tag at a time.** `<table>…</table>` written as bare HTML comes back as dozens of `RawBlock`s (125 on one page). A fenced raw block (` ```{=html} `) is one `RawBlock`. Measured. Our Markdown target writes with `-raw_html` so every raw block is fenced.

**The writer dropped cell spans silently, measured on 3.11.** A table with `colspan`/`rowspan` was written as a grid table with the spans removed and no warning (48 on one page, to none); `Writers/Markdown/Table.hs` has no span handling. Our target writes such a table as HTML. With 3.12.1 a grid table keeps a cell's spans, across columns and rows (`gridTable`, `Writers/Shared.hs`), and reads back with them, written with the target's options too (`markdown-simple_tables-multiline_tables-raw_html`), and `gfm` writes such a table as HTML: measured on a small table, 2026-10-14. The Markdown writer has handled spans in grid tables since 3.7, its changelog says, so what dropped them in the 3.11 measurement isn't known.

**The writer flattens a table's bodies.** A table of several bodies, each headed by its own row, as the HTML reader reads a `<tbody>` that opens with a row of `<th>`, is written by the `markdown` and `gfm` writers as one table, each head an ordinary row and the bodies one, so the groups and which rows headed them are gone. Measured with 3.12.1, 2026-10-14. The Markdown target writes such a table as HTML (`markdown-source.lua`, `has_body_heads`).

**A figure with attributes is written as a div.** `Writers/Markdown.hs` writes a `Figure` whose `Attr` is non-null as `::: {#id .figure}` holding the image and a `::: caption` div; the reader returns that as a `Div` around a `Figure`, not as the figure. Read from the source and measured. Our reading filter folds it back.

**A tight list item holds a `Plain`, and reads back loose.** A one-item list in a grid cell written as `- ![…]` comes back as a `Para` in the item, and a lone image in a `Para` is a figure. Measured. Our not-a-figure mark goes on `Plain` as well as `Para`.

**A lone image is a figure on read (`implicit_figures`).** The documented way to say "not a figure" is a non-breaking space after it (`\ `), which becomes a hard line break when a grid cell wraps at it. Measured. Our target writes an empty `[]{.inline}` span instead; an empty span with no attributes is not written at all.

**`smart` puts a non-breaking space after an abbreviation** ("vs.", "e.g."), including inside image alt text. Measured. The filter plainifies alt text.

**A wide pipe table is read with relative widths** (a row longer than `--columns`), and a table with widths is written as a grid table whose dashes round the width to a character, drifting by one per write. Measured. Our target carries widths as an attribute and writes pipe tables.

**Math ending in `\ ` doesn't survive the writer.** `Math InlineMath "a\\ "` is written `$a\$`, its space trimmed, and that reads back as the text `$a$`; the reader takes `$a\ $` itself as math. Measured on 3.11, 3.12, and 3.12.1.

**3.12.1's reader trims a display formula's TeX and keeps a formula's groups and comments whole** (`mathDisplay` and `mathInline`, `Parsing/Math.hs`, #11887, c248f88). `$$`, a line end, `E = mc^2`, a line end, and `$$` is `Math DisplayMath "E = mc^2"`, where 3.12 kept the line ends, so a page's display formula is written back as `$$E = mc^2$$` on one line; and a `$` inside a brace group or after a `%` no longer closes a formula: `$\colorbox{aqua}{$x$}$` is one formula, which 3.12 cut into three pieces, and `$a % c $`, a line end, and `b$` one, which 3.12 read as text (`$\text{a $b$ c}$` was one formula on both). Measured on 3.12 and 3.12.1. Also in 3.12.1's Markdown writer, read in its changelog: a destination with spaces is written in `<…>`, list markers after a line break are escaped (#11863), and a table with only a head isn't written as a multiline table (#11939); its reader keeps the spaces at the edges of a bracketed span.

**Raw TeX is cut at each command the reader knows, with the arguments it expects.** `\vskip 6pt plus 2pt` alone on a line is one `RawBlock`, but `\vskip 0.5\baselineskip plus 2pt` is a paragraph of two `RawInline`s, `\vskip 0.5` and `\baselineskip `, and the text "plus 2pt", which a writer that drops raw TeX, the PowerPoint writer among them, shows as text; LaTeX, given all three, puts them back together. A line that opens with a block command and goes on with text, `\vspace{1ex} Words here.`, is a `RawBlock` and a paragraph; `Words \vspace{2em}` keeps the command in the paragraph as a `RawInline`; and `\vspace{1em}\bigskip` on a line is one `RawBlock`. Measured on 3.12.1, 2026-10-12.

**A macro defined in a YAML `header-includes` is expanded as the document is read.** With `latex_macros`, on by default for Markdown, the reader records a definition it meets in raw TeX, the metadata's included, and expands it in later raw TeX: a deck whose `header-includes` had `\providecommand{\deckmark}{...}` and used `\deckmark` in its body reached the LaTeX writer with the macro already expanded and its definition gone, so a check for the macro in the PDF found nothing. A test that wants to see its `header-includes` kept has to use a command the reader leaves alone (`\hypersetup{pdfsubject=...}`, read back from the PDF's metadata). Measured on 3.12.1, 2026-10-12.

**Table attributes** are written and read on the caption line (`: Caption {#id}`) and, for us, on a wrapping div. The caption line is `Table:`, `table:`, or `:` not followed by punctuation, after up to three spaces, and the attributes end it and are taken off the caption (`tableCaption`, `Readers/Markdown.hs`): `Table: Table 1.3 {#tbl:x}` is the caption "Table 1.3" and the table's id `tbl:x`. So a Markdown copy that adds words to a caption puts them before the attributes. Read at 3.12.1 and measured, 2026-10-11.

**The writer leaves out a heading's id when it's the one the reader would make.** `blockToMarkdown'` (`Writers/Markdown.hs` 536–542) works out the id the reader would give the heading's text, `uniqueIdent` over the ids written so far, and writes no `{#id}` when the heading's own is that one and has no classes or attributes. So the deck reader gives each heading the id Pandoc's reader would (`pptxsource.identifier`, a port of `uniqueIdent` and `textToIdentifier` in `Shared.hs`), and a deck's Markdown carries none of its own: lowercased, its letters, numbers, `_`, `-`, and `.` kept, its words joined by `-`, what's before its first letter dropped, `section` for none, and `-1`, `-2` after one used. Read from the source at 3.12, and the port measured against the reader on seven titles (`½ cup` is `cup`, `2026` is `section`), 2026-10-15.

**A numbered list in a list's item that starts past its first number is read as text, since 3.10.1, and the writer still writes one.** The reader takes an ordered list inside an item only when it starts at 1 or its equivalent, `a` or `i` (`orderedList`, `guard (start == 1)` in `ListItemState`, `Readers/Markdown.hs`; #11735, "as with commonmark", the manual says), while the writer writes a nested list's own start (`5.`, then `b.` under it, then `i.` under that). So the item `5.` with its list under it reads back as the item and the text `b. … i. … ii. …` as one more paragraph of it, its lists' items joined; after a blank line too, where `b.` is a paragraph and what's under it a code block. A list that isn't in an item may still start where it likes, but the reader reads a definition as an item (a list starting at 3 directly in one is text), and a quotation or a div inside an item keeps the rule, while a list at the top of a footnote, a table's cell, or a quotation or div that isn't in an item starts where it likes (measured on 3.12.1). Measured on 3.10, 3.10.1, 3.11, and 3.12.1, 2026-10-15: 3.10 reads such a list back as written, as 3.1.3 does, and 3.10.1, whose changelog lists the rule, is the first that doesn't. The reader is stricter than CommonMark, whose rule the manual cites: CommonMark (0.31.2, 5.2, the first exception) asks a start of 1 only of a list that interrupts a paragraph, so after a blank line `-f commonmark` reads `3.` under an item as a list and `-f markdown` doesn't; and the commonmark writer writes such a list tight, under the item's text, which its own reader reads as text too. Measured on 3.12.1. The Markdown target writes such a list from its first number, its start an empty span at its first item, `1.  []{start="3"}` (`markdown-source.lua`, for every list's items and every definition, in a footnote or a cell too), which `figures-and-tables.lua` puts back; an item that opens with code has the span as a paragraph before it, so that list reads back loose. Found on a deck whose slides continue a list, `B.` repeated and its sublist numbered on from `3.`.

**`smart` round-trips a quotation inside a quotation in the same marks, and four periods, wrongly.** The writer writes curly double quotes as straight ones, and the reader pairs straight quotes its own way, so `“a or “b” c”` comes back as the quotation `“a or”` and `b”` after it, the space before the inner quote gone; and `Wait....` is written `Wait\....`, which reads back as a period and an ellipsis (`Wait.…`). Measured on 3.12.1, 2026-10-15, on text a PowerPoint deck held.

**The reader parses `<span>` and `<div>` and keeps every other tag raw, one tag at a time.** `x<sup>2</sup>` is a raw `<sup>`, `Str "2"`, and a raw `</sup>`; `<span href="…" rel="…">` is a `Span` whose `href` is an ordinary attribute, which the HTML writer then passes through where XHTML forbids it. Measured. `markdown-html.lua` reassembles the tags and reads each element with the HTML reader.

**The reader's time grows steeply with how deeply bracketed spans nest.** `[[[x]{.a}]{.a}]{.a}`, nested: 9 ms at depth 4, 144 ms at 8, 1.8 s at 12, and a real page never finished. That page was HTML holding a formula as MathJax 2 draws it (eleven spans deep, each with a style), which the Markdown writer wrote faithfully and the reader couldn't read back. Measured on 3.11; 3.12.1 is no faster (depth 12: 1.7 s on 3.12 and 2.0 s on 3.12.1, two runs each on a busy machine, 2026-10-08). Candidate upstream report. Our side: `lib/mathjax.py` rebuilds a MathJax rendering as MathML before Pandoc reads the page, so the spans never reach the writer.

## The AsciiDoc reader

The reader is the `asciidoc` library (jgm/asciidoc-hs), not part of Pandoc's tree, so everything here is measured on 3.11 against a real Asciidoctor book (Computer Systems Security) rather than read from source. 3.12 took the library from 0.1.0.5 to 0.1.1, which changed several entries here and in the next section, each marked where it was measured again on 3.12 and 3.12.1 (2026-10-08); 3.12.1's 0.1.1.1 only adds a test file to its package.

**`include::` is followed**, each included file wrapped in a `Div` with class `included`. **But through a master file, an included chapter's `= Title` is lost**: it's neither a heading nor metadata. Read on its own, a chapter's title is its metadata and its `==` sections are level 1. So `convert.py` reads each included file as a source and takes the master only for its order and header.

**`:leveloffset:` is ignored**, **`:imagesdir:` is kept as metadata and not applied** to image paths, and the document's other attributes (`toc`, `icons`, `stylesheet`, `sectnums`) arrive as metadata too.

**A cross-reference by title isn't resolved.** `<<Unix File Permissions>>` and `<<Malware>>` are links whose fragment is the title itself; Asciidoctor resolves them to the section's id or the chapter. 54 in one book.

**`mailto:someone@example.org[Name]` loses its scheme**: a link to a file called `someone@example.org`. **A code span holding a URL scheme** (`` `ftp://` ``) becomes a link to `ftp://` around the code.

**A block's layout attributes become element attributes.** `[width=300, float=right]` on an image, a listing, or a table, and a diagram's `target=`, arrive as attributes of the block, and the HTML writer writes `width` and `target` as they are, on `<figure>`, `<pre>`, `<div>`, and `<table>`, where XHTML allows neither: epubcheck's RSC-005, 43 times in the security textbook's EPUB. Measured; `asciidoc-source.lua` moves a block's size to its image and drops the rest. Other names (`float`, `format`, `wrapper`, `link`, `align`) are written as `data-` attributes, which are valid.

## The AsciiDoc writer, against the AsciiDoc reader

**A rule doesn't read back, and in a list ends it.** The writer writes a horizontal rule as five single quotes, `'''''`, and in a list item puts a blank line between the item's `+` and it; the reader takes a rule only as three, `'''`, so it reads five as a paragraph of closing quotes (U+2019 five times), and the blank line ends the list. Three quotes attached right after the `+` read back as a rule in the item. Measured, Pandoc 3.12, 2026-10-05; the AsciiDoc target writes `'''` raw. Inline code is the other: the writer's constrained `` `+...+` `` doesn't close before a word character, so code right beside a `latexmath:[...]` macro reads as plain text and the formula goes with it; `` ``+...+`` `` reads back, though not around a `+` (`` ``+x+y+`` `` reads as "+x+y+"). And `latexmath:[...]` is read on one line only, so a formula whose TeX holds a newline, as a LaTeX source's do, is lost. A bracket in a link's text: the writer escapes it as `++[++`, which the reader takes for a span's role, losing the text; `\]` the reader takes as a backslash and the end of the text; `&#91;` and `&#93;` read back as the brackets, so the AsciiDoc target writes those.

Measured on 3.11 by writing each case with Pandoc's `asciidoc` writer and reading it back, for the AsciiDoc target. The writer is Pandoc's; the reader is `jgm/asciidoc-hs`, so its entries are candidates there. Asciidoctor's behavior is from its documentation, not run here. What the target does about each is in `docs/asciidoc.md`.

**The writer and the reader disagree.** Each of these is written by the writer and misread by the reader:

- A footnote after a word is joined to it (`notefootnote:[…]`), which the reader didn't take for the macro in the case first measured. In a minimal case (`A note[^1] here`, and after a parenthesis) 3.11, 3.12, and 3.12.1 all read it back as the note (2026-10-08), so that case needs finding again before this is filed.
- An empty span with an id (an anchor) is `[#id]##`, which reads back as a highlighted span holding `id]`.
- An image's alt is the macro's first value, unquoted: a comma splits it and an `=` makes it a named attribute. With no alt, the file name less its extension is written as the alt.
- A table with no header row is written with no `noheader`, and 3.11's reader took row 1 for a header whenever `noheader` was absent. From 3.12 it takes one only when a blank line follows the row, as Asciidoctor does, so this disagreement is gone (measured on 3.11, 3.12, and 3.12.1, 2026-10-08).
- A heading one level below the document title is `===`, skipping `==`; the reader then numbers it 1, and `====` 3.
- A figure caption with a line break is a block title over two lines; the second starts a paragraph, which takes the image macro in as inline text.
- Display math inside a description list is indented with the definition, delimiters and all, and an indented `++++` isn't a delimiter.
- Text that means something at the start of a line isn't escaped: a leading `.` (a block title; in a list item the whole file fails to read), `=`, `//`, `----`, `NOTE:`, `:name:`. Nor are Asciidoctor's replacements other than `->`: `'`, `--`, `...`, `(C)`, `(R)`, `(TM)`, `=>`, `<=`, `<-`.

**The writer drops:** every link's title, bare or named (the reader reads `link:…[text,title="…"]`, with the title as a link attribute rather than in the title slot), a `Div` (its content stays), a raw HTML block, a footnote of several paragraphs (replaced by the words "[multiblock footnote omitted]"), a table's header column (it could write `cols="1h,…"`, which the reader doesn't read either), a row span, a table's groups, and the `subtitle` field. The standalone template writes `include-before` as plain blocks at the top.

**The reader:**

- 3.11 made a description list of any line holding `::`, anywhere and with nothing after it: `std::cout`, `3::4`, an address with `::`. Asciidoctor wants a space or the line's end after it. `:{empty}:` prevents it in text; in an address nothing does, since `{empty}` isn't expanded there, and `link:++…++[]` is split too. From 3.12, `std::cout`, `3::4`, and `link:++http://example.org/a::b++[the page]` read as written and `Term::` at a line's end still starts a list, but `http://[::1]/` is still misread, now as a link to `http://` with the text `::1` (measured on 3.11, 3.12, and 3.12.1, 2026-10-08).
- Ends `latexmath:[…]` and `footnote:[…]` at the first `]`, escaped or not; `\]` makes a footnote unrecognized. `{startsb}` and `{endsb}` work in a footnote; `\lbrack` and `\rbrack` in math. Measured again on 3.11 and 3.12.1 (2026-10-08), more narrowly: brackets in pairs read (`footnote:[see [1] here]`, `latexmath:[[0,1]]`), and so does a `\]` in a footnote's text; what fails is a `\]` in a formula, Asciidoctor's own form for a root's index (`latexmath:[\sqrt[3\]{x}]` is text, its backslashes gone), and a footnote holding such a formula, which is lost.
- Drops `latexmath:[…]` inside constrained italics (`_…_`), not inside `__…__` or bold. Measured again on 3.11, 3.12, and 3.12.1 (2026-10-08), more narrowly: a formula holding `_` there ends the italics, which are left as underscores in the text, the formula kept; one without reads, in the italics.
- Applies Asciidoctor's replacements to text and to inline code, and splits inline code at its spaces into several `Code` elements. `` `+…+` `` keeps code literal but is still split.
- Reads `link:x.html[9.1 Null and]` with the text "9"; `{empty}9.1` or quoting keeps it.
- Expands `{empty}` before deciding a line is a comment, so `{empty}//` is still one; `++//++` isn't.
- Reads no inline passthrough (`pass:[…]`), though `++…++` works in text. Not reproduced in a minimal case: 3.11 and 3.12.1 read `pass:[*x*]` as the text `*x*` (2026-10-08).
- Loses an open block (`--`) when a blank line comes before its closing delimiter after another delimited block inside it.
- Fails on a block anchor (`[[id]]` alone on a line) with no block after it.
- Puts a block image's id, alt, size, and `link` on a `Div` marked `wrapper="1"` around the figure, and an inline image's `alt=` and `link=` in its attributes rather than its caption and a `Link`.
- Honors no escaped quote in an attribute value, and doesn't take single quotes as quotes, so an alt with a double quote can't be written.
- Reads an attribute entry anywhere, header or body, as metadata; so a document can say something to a filter.
- Doesn't read `\root n \of`; neither does Pandoc's TeX reader, so a root with an index has no bracket-free form.
- Ends a constrained span (`#…#`) at a `#` inside it, a link's fragment included; the unconstrained `##…##` holds one. 3.11 read `[.a.b]` as one class, `a b`; 3.12 reads two. Reads an empty span, `[.x]####`, as text.
- 3.11 hangs, rather than failing, on a listing whose delimiter is never closed: a table cell whose listing holds a `|` breaks the cell there and leaves one. The process had to be killed. From 3.12 a listing never closed is read to the end of the file as code; the cell is still broken at the `|` (measured on 3.11, 3.12, and 3.12.1, 2026-10-08).
- Strips a non-breaking space at the end of a text element as trailing space; `{nbsp}` stays.
- Reads a nested quotation written with a longer delimiter (`______` around `____`).

**The writer, again:** it writes a `Div`'s blocks with blank lines between them, so inside a list item every block after the first falls out of the item; it nests a quotation in a quotation by wrapping the inner in an open block, which the reader loses (the blank line before `--`); it writes nested spans with the same delimiter, which is ambiguous; and a span that starts a line is `[.role]#…#`, which the reader takes for a block attribute line.

**Open, not traced:** in a Markdown source, raw HTML holding a table whose cell has a `<pre>` listing with a line starting `  |` lost the listing on reading, from Markdown as a source and before any target. Seen once, in a test; the cause isn't established.

## The EPUB writer

**A link to a figure in another chapter file keeps its bare `#fragment`.** `fixInternalReferences` (`src/Text/Pandoc/Chunks.hs`) gives a link the path of the chunk its target is in, from a map of each chunk's ids that `getBlockIdent` and `getInlineIdent` collect: a `Div`'s, a `Header`'s, a `Table`'s, or one in raw HTML, and a `Span`'s, a `Link`'s, or an `Image`'s. **The navigation document's manifest item never has `mathml`.** A chapter's item gets `mathml` and `svg` from what it holds (`props`, `Writers/EPUB.hs`), but the nav's is written with `properties="nav"` alone, so a formula in a heading, which the nav repeats, is epubcheck's OPF-014. Read from 3.12 and `main` at eaf3404; measured on OpenIntro. `build-epub.py` adds the property when the nav holds `<math`.

**An image the EPUB writer can't fetch is written with `../` before its source**, as if it were a path relative to the chapter's directory: `../https://example.invalid/badge.png`. Measured. ## The HTML writer

**reveal.js output names its library by a version range, and lazy-loads its images.** The writer's default `revealjs-url` is `https://unpkg.com/reveal.js@^6` (`Writers/HTML.hs`), and the Nu checker rejects the `^` in each address the template builds from it (`$revealjs-url$/dist/reveal.css` and the rest); setting `revealjs-url` replaces it. ## The PowerPoint reader

## The beamer writer, for ltx-talk

ltx-talk 0.6.9 (2026-10-06) takes most of what Pandoc's beamer writer writes. ## The Lua filter environment

**Within one filter table, every inline is walked before any block.** So a `Div`/`Span` handler pair that renames ids sees every span before every heading; a handler that must see elements in document order has to walk the blocks itself. Measured (`figures-and-tables.lua`, `make_ids_unique`).

**`AttributeList` is not a plain table**: `next()` on it errors; iterate with `pairs`. Measured. **A filter's table of attributes is iterated in hash order**, so build an `Attr` from a list of pairs for stable output. Measured. **Filters in a returned list run in order**, each over the whole document; a handler returning `{}` removes the element, `nil` leaves it. **`pandoc.read(text, 'html')`** reads MathML into `Math` and `<thead>` into head rows; **`pandoc.write(doc, 'html', {html_math_method = 'mathml'})`** writes math as MathML. Measured.

**A metadata value has no `.t` in Pandoc 3.** A `MetaBlocks` field arrives in a filter as a `Blocks` list and a `MetaInlines` one as `Inlines`, so `value.t == 'MetaBlocks'` is never true and code testing it silently does nothing; `pandoc.utils.type(value)` says `Blocks`, `Inlines`, `List`, `string`, or `boolean`. Measured, the hard way (`include-before` in the AsciiDoc target).

**`pandoc.utils.stringify` gives math as its TeX source.** A caption holding `$Q=100 \sqrt{LK}$` stringifies to `Selected values for Q=100 \sqrt{LK}`, which is where a table region's `aria-label` came from. The plain-text writer does better but not always: it renders `MC=\Delta {TC} / \Delta Q` as `MC = ΔTC/ΔQ`, and gives up on `\sqrt{LK}`, warning `Could not convert TeX math` and writing the TeX between dollar signs. Measured with 3.11.

**`pandoc.utils.stringify` runs a cell's blocks together, and Lua's `%s` is ASCII.** A cell of paragraphs, `Message Outline`, a no-break space alone, `Interested`, and `Our details`, stringifies to `Message Outline`, U+00A0, `InterestedOur details`, with nothing between blocks, where the Python pre-pass, joining the paragraphs' text with spaces and splitting it, has `Message Outline Interested Our details`. And `%s` doesn't match U+00A0, which Python's `str.split()` takes as a space, and `string.sub` counts bytes, not characters. So a filter comparing text with what the pre-pass computed has to normalize both sides alike. `matches_entry` in `figures-and-tables.lua` compares the first 20 bytes after collapsing `%s+`, and four tables of the slim corpus never match their pre-pass entries for a U+00A0 there, that cell's among them, and three more for a formula, which the pre-pass reads as its text and `stringify` as its TeX (the entry above; PROJECT-NOTES). Measured with 3.12.1, 2026-10-15. `figures-and-tables.lua`'s `cell_words` now reads a cell as the pre-pass does, a block at a time joined by spaces, every space Python's `str.split()` takes for one made a space first (U+00A0, U+2000 to U+200A, U+3000, and the rest, as UTF-8 patterns), and only the words before a formula, which are compared alone (`layout-tables.mbox`, 2026-10-16).

**A table's head and bodies are copies when read.** `tbl.head.rows = …` changes a copy and leaves the table as it was; the head has to be read, changed, and assigned back (`local head = tbl.head; head.rows = …; tbl.head = head`), as the bodies do. A body's own head rows (`body.head`) come along with a cloned body, and the reader puts a table's first `th` row there when the source has no `thead`. Measured, splitting a table in `html-source.lua`.

**Inline handlers run before block handlers, so a block handler sees what the inline ones made.** A `Table` handler that writes its table as HTML with `pandoc.write` loses every raw AsciiDoc inline the inline pass put in its cells, since the HTML writer drops raw content of another format. A filter file can return two filters that run in turn; the AsciiDoc target writes those tables in the first. Measured.

**A filter file that returns a table of filters ignores its global functions.** `target-blocks.lua` ends `return { {Div = …}, {Meta = …} }`, so a global `function Image` added to it never ran, and nothing said so. Measured, the hard way. A handler has to be in the returned table.

**A handler that returns `nil` keeps the element as it was, including changes made to it in place.** `html-source.lua`'s `Table` dropped empty columns from the table it was given and then returned `nil` when it had no headers to declare, and the columns came back. Return the element whenever it was changed.

## Upstream candidates from the Word round trip

Each is a workaround the pipeline carries because Pandoc's DOCX reader or writer does something that loses information on a round trip through Word. Noted to raise with jgm in October 2026, with the evidence gathered here; each workaround stays small, labeled in the code, and removable when Pandoc changes, as the ScreenTip recovery is.

- **The reader splits a list at its own writer's continuation paragraphs.** The writer numbers a list item's second paragraph or code block with an invisible bullet (a `lvlText` of one space); the reader takes it for an item of another list. OpenStax's export does the same. Workaround: `docxrepair.join_continuations`. Evidence: the statistics book's 102 such paragraphs, 11 pages' lists whole again.
- **The writer gives every level of a block quote the same style and indent**, so Word shows, and the reader reads, a quote within a quote as one. Workaround: `docxtarget.indent_quotes`, by bookmark ranges.
- **The reader joins adjacent quotes only at their own level**, and joins two separate quotes in a row. Workarounds: `docxrepair.join_nested_quotes`, and a bookmark-only paragraph between two quotes, which the reader keeps.
- **The reader never puts a numbered paragraph in a quote**, so a list in a quote, and code a list item holds in a quote, come back outside it. Workaround: `docxtarget.indent_quotes` indents them by depth and writes the document variable `TextbookImproverQuotedLists`; reading a file with it, `docxrepair.mark_quoted_lists` marks them, and `join_quoted_lists` and `apply_quoted_code` put them back. Gated on the variable, since an author's own file indents lists for other reasons.
- **The reader quotes code once, however deep**, and **reads a list item's quote one quote a paragraph**. Workarounds: `apply_quoted_code` for the code, and `nest_item_quotes` with the join at every level for the paragraphs.
- **The writer styles a quoted list's own paragraphs `Block Text`**, which the reader then quotes again, item by item. Workaround: `indent_quotes` writes them `Body Text` with the quote's indent.
- **A `Div` writes no paragraph, so two quotes in sibling Divs come out adjacent** and the reader joins them. Workaround: the separator paragraph between them too (`docxtarget._edge`).
- **The reader drops a description-list term with no definition** into a `Div` of class `Definition-Term`. Workaround: `docxrepair.join_definition_terms`.
- **The writer puts a table's caption before the table without keep with next, and the reader pairs such a caption with the table before.** A table with no caption takes the next one's. Workaround: `docxtarget.keep_captions`.
- **The reader joins adjacent code paragraphs into one code block**, as it joins adjacent quotes, so two code blocks in a row come back as one. Workaround: a separator paragraph between them. A paragraph holding only a bookmark isn't a dependable separator: read directly by Pandoc, one such paragraph between two code blocks came back as an empty paragraph and another in the same file was dropped, its blocks joined (measured, cause not traced). A zero-width space beside the bookmark keeps it.
- **The writer drops a code block's classes**: its numbering (`numberLines`, `startFrom`) and its language. Workarounds: `docxtarget.number_lines` writes the numbers as text in Word's Line Number style, a hidden `_tiqCode_<language>_<n>` bookmark carries the language, and `docxrepair.apply_number_lines` restores both, matching blocks by their text.
- **The writer hashes an id that isn't a valid bookmark name, and nothing maps it back.** A link from another page to it is dead after a round trip. Workaround: the id map in a custom XML part (`docxtarget.id_map`, `docxrepair.apply_id_map`).
- **The writer gives a table in an aligned table's cell two alignments**, its own and the outer cell's, which the schema doesn't allow; not a loss on reading, but a file Word's schema rejects. Workaround: `docxtarget.single_alignment`. Evidence: GIAM's 113, in 3 of its 11 Word files.

## The LaTeX reader

Read at the 3.12 tag (its image code is unchanged on `main` at 8f949db, 2026-10-02) and measured on 3.12 and 3.11, which agree on everything here. 3.12.1's reader is 3.12's.

**An unknown command or environment** (`blockCommand`, `rawEnv`, `rawVerbEnv`): without `raw_tex`, which the LaTeX reader doesn't enable by default, a command is dropped with its arguments and reported only as an INFO message under `--verbose`; with it, it's a `RawBlock` or `RawInline`. An unknown environment's contents are kept, in a `Div` classed with its name. `tikzpicture` and `tikzcd` are verbatim environments, dropped whole or kept raw, and any `alt` key goes with them. A command whose argument holds a figure takes the figure with it: `\marginalia{…}` (the `marginalia` package) took five figures, captions and all, from a section of APEX Calculus. Measured.

**The preamble** (`preamble`) is discarded, `raw_tex` or not, except macro definitions and what sets metadata (`\title`, `\author`, and the like). `\usepackage{x}` makes the reader look for `x.sty` on `TEXINPUTS` and in the working directory and read it if it's there; otherwise an INFO message, "Could not load include file". Read from the source; measured.

**`\DocumentMetadata`** comes before `\documentclass`, so it's an unknown block command: dropped, or with `raw_tex` a `RawBlock` at the start of the body, which the writer with `-s` puts after `\begin{document}`, where LaTeX stops ("Can be used only in preamble"; measured with LaTeX 2026-06-01). Neither its `lang` nor its `pdfstandard` is read: `lang` comes only from polyglossia's `\setdefaultlanguage` and `\setmainlanguage` (`Lang.hs`). **`\tagpdfsetup`** in the preamble is always lost; in the body it's dropped, or raw. latex-lab's `\tagstructbegin`, `\tagmcbegin`, and their ends are dropped and what's between them kept. Measured.

**Images** (`mkImage`). Of `\includegraphics`'s options only `width` and `height` are kept (relative to `\textwidth`, `\linewidth`, or `\textheight`, as percentages); `page`, `trim`, and `clip`, which the writer reads from attributes, are not. The `alt` key becomes the description, as the raw text of its tokens in one `Str` (`keyval` untokenizes the value): macros are expanded and nothing else is interpreted, so `$f(x)=x^2$` and `50\%` in an alt reach HTML as typed, and the writer then escapes them again (`\$f(x)=x\^{}2\$`, `50\textbackslash\%`). So alt text the writer wrote itself doesn't survive a round trip if it holds a character LaTeX escapes. With no `alt` key the description is the word "image", and so it is for `artifact` and `actualtext`, which aren't read: `alt="image"` in HTML, and `alt={image}` through the writer, which turns a decorative image into a figure described as "image". `alt={}` gives `[Str ""]`: `alt=""` in HTML, `alt={}` in LaTeX. Alt reading came in 3.1.4 (#8743). Read from the source; measured. A line end in the value stays in the `Str` too (`Str "Short\nalt"`), and the HTML writer writes it into `alt`, which matters now that 3.12.1's writer wraps an alt key's words (below); `latex-source.lua` makes a run of whitespace in an alt one space, as LaTeX reads it. Measured on 3.12 and 3.12.1.

**Pandoc's own standalone LaTeX loses its images on reading.** The template defines `\pandocbounded` with `\newcommand*`; `latex_macros` records the definition and expands it in the body, where `\sbox`, `\Gscale@div`, and `\ifdim` leave no `Image` and two `RawInline`s, even without `raw_tex`. The reader's own handler (`("pandocbounded", tok)`, added in 3.8.1 for #11140), which would give the image, is overridden by the definition. A fragment written without `-s` reads back fine, and so does the standalone file with `-f latex-latex_macros`. Measured on 3.11 and 3.12 with a one-image Markdown file.

**A macro written in expl3 leaks into the text.** 3.12 reads `\NewDocumentCommand` definitions (#7540), so one in the preamble is expanded where it's used, and an expl3 body (`\cs_if_exist:NT`, `\pdfannot_dict_put:nne`) is partly skipped and partly read as text: the PDF target's `\OERLinkContents` left stray "Contents ()" text around every link. Measured.

**A macro can stop the whole read.** With `latex_macros` a macro is expanded wherever it's used, so one whose body holds something the reader can't parse fails the document, not just the macro: APEX's `\printexercises`, which `\immediate\write`s, gave "unexpected \write" and exit 64. An empty redefinition in a driver file read the rest. Measured.

**#11695**, read in full (closed unmerged in July 2026; Rob supplied the thread): nothing about alt text. Its author withdrew the LaTeX reader fixes (`\csname` expansion, `\includesvg` and `\svgpath` resolution, macros in `\input` file names) and moved the ODT writer fixes to #11746. jgm declined extracting a `tikzpicture`'s images as a list or a table: an obvious omission is better than a figure that looks translated and isn't, and the way to get the figure is a Lua filter that renders the whole picture with LaTeX. The filter he posted takes `RawBlock`s, so it needs `raw_tex`, runs LuaLaTeX on a `standalone` document and `pdftocairo -svg`, and takes alt text from a comment of his own, `% alt="…"`, rather than latex-lab's `alt` key.

**`\rule` with a width is a horizontal rule**, whatever its height (`rule`, `Readers/LaTeX.hs`: the width is read, the height skipped), so `\rule{36pt}{0pt}`, a space, puts a line across the page, in a table's cell on GIAM. latexsource.py makes a rule with no height `\hspace` and one with no width nothing. Read from the source; measured.

**More that stops or garbles a read** (measured on 3.12, on the Bergmann and GIAM books, each from the source where it says so):

- **`\input file`**, TeX's own form without braces, stops the whole read ("unexpected figs"): `include` takes the name with `braced` (`Readers/LaTeX.hs`).
- **`\centerline{…}`** is read as `para . trimInlines <$> tok`, its argument as inlines, so a `tabular` inside it stops the read ("unexpected \begin"). A preamble `\renewcommand{\centerline}[1]{\begin{center}#1\end{center}}` wins over the built-in, as `\pandocbounded`'s definition does.
- **`\cline{2-2}`** is consumed as a rule by `hline` (`Readers/LaTeX/Table.hs`), which takes no braced argument, so `2-2` becomes the next cell's text; `\cmidrule(lr){2-3}` likewise loses only the parenthesized part. #7442 (closed 2021) was about `\cline`; 3.12 still does this.
- **ifthen** (`\newboolean`, `\setboolean`, `\ifthenelse`) isn't read: `\ifthenelse` is skipped with both branches. etoolbox's `\newtoggle`, `\toggletrue`, and `\iftoggle` are (`ifToggle`), so the one rewrites to the other. Requested in #11008 (open) and #8255 (closed).
- **A package file in the working directory** is read by `\usepackage` and can stop the read: DraTex.sty's catcode tricks did ("unexpected ()"). So can a macro defined in the book's own format that holds `#1` outside a TeX definition: DraTex's `\Define \Var(3){…#1…}`.

**What a course's notes needed** (measured on 3.12 with FINC 308's topics, 2026-10-06, each read in the source):

- **Size commands are ignored** (`isFontSizeCommand`, `Readers/LaTeX/Parsing.hs`): `{\LARGE Topic 1: ...}` is a plain `Span`, so a title set as large type is a paragraph like the course's name above it, and nothing in the AST says which was the title. `latexsource.visual_title` finds it in the source.
- **A `\chapter` moves every heading** (`parseLaTeX`'s `adjustHeaders`: when any heading's level is below 1, all are shifted so the lowest is 1), so a `\chapter*` written in for a title would push each `\section` down a level and change the numbers `\ref` gives sections. The copy writes the title as a `\section*` after a marker paragraph instead, and the shift is done on the page's blocks.
- **`\newcolumntype` isn't known.** A table using a type it defines has its column specification read as text (`p2.3inR2.3in` in the first cell) and falls apart into a div of paragraphs; a `\newcolumntype` in the body stops the read ("unexpected #1"); in the preamble it's dropped. `>{...}` and `<{...}` are skipped, so `>{\raggedleft\arraybackslash}p{2in}` is a left-aligned column.
- **A `\label` on an `\item` isn't registered**, so a `\ref` to it is written as the label's name in brackets (`[Topic2Q1]`); LaTeX gives the item's number (`1b`).
- **An unknown environment is a `Div` classed with its name**, its contents read as blocks, which is how the copy marks a box (`TextbookImproverBox`, renamed `box` by `latex-source.lua`).

**What a book made its own way needed** (measured on 3.12 with *OpenIntro Statistics*, fee2509, 2026-10-07, each read in the source and reduced to a few lines):

- **An environment's opening command called alone opens a group nothing closes.** `newenvironment` (`Readers/LaTeX/Macro.hs`) defines the macro named after the environment as `\bgroup` followed by the opening code, and `end<name>` as the closing code followed by `\egroup`; `doMacros'` (`Parsing.hs`) expands `\begin{name}` and `\end{name}` through them. In LaTeX `\name` is the opening code alone and `\begin` adds the group, so `\var{height}` (OpenIntro calls `\var`, `\resp`, `\data`, and `\eoce` about 1,700 times) is legal; here it leaves a `\bgroup` open, and the next `}` the book closes is "unexpected }". `newDocumentEnvironment` does the same.
- **`\bgroup` and `\begingroup` after other content in a block are dropped, while `\egroup` and `\endgroup` close a group.** `block` tries `blockCommand` for any control sequence before `grouped block`, and `blockCommand`'s `rawMaybeBlock` takes an unknown command, `\begingroup` among them, as a raw block it drops when a blank line follows; `egroup` accepts `\egroup` and `\endgroup` as `}` anywhere. `{\Large \begingroup Hello\par \endgroup}` fails ("unexpected }": the `\endgroup` closed the braces); `{\begingroup Hello\par \endgroup}` reads, since `grouped` first tries a group at the group's start ("{{a,b}} should be parsed the same as {a,b}"). The same drop hits an environment's own `\bgroup` after a command: `{\raggedright\begin{parts}\item A\end{parts}}`, `parts` defined to open `enumerate`, fails; and `{\begin{parts}\item A\end{parts}<newline>}` fails where the same without the line end reads, which an `\input`-ed file's last line end makes of `{\input{file}}`. latexsource.py writes the book's environments as `\name` and `\endname` commands, as LaTeX defines them, and a paired `\begingroup`/`\endgroup` as braces.
- **`\titleformat` takes its arguments only on one line.** `getRawCommand`'s case for it is `braced`, `skipopts`, then `count 4 braced`, and `braced` doesn't skip spaces, so the arguments on lines of their own, as titlesec's documentation sets them and OpenIntro does, fail ("unexpected {"); its fifth, optional argument isn't taken, so `[]` is left as text. Any other unknown command takes `many braced` the same way, so `\titlespacing{\chapter}` followed by `{0pt}% left` on the next lines prints "0pt0pt". latexsource.py drops titlesec's commands with their arguments, found as TeX finds them.
- **`\nameref` isn't known**: dropped with its argument, so OpenIntro's `\section{\nameref{ch_intro_to_data}}` is an empty heading. `\hyperref[label]{text}` is a link to `#label` with the text. latexsource.py writes the one as the other with a mark for the text, and convert.py gives it what LaTeX prints: a figure's or a table's caption for its label, a heading's title for one in or after the heading (the reader leaves `\section{A\label{a}}`'s label an empty span in the heading, the heading keeping its own automatic id), and otherwise the section's title.
- **`\subfigure`**, the obsolete subfigure package's command, isn't known: dropped, its optional caption with it, and a `\label` in its argument doesn't reach the figure, so a reference to it goes nowhere. subcaption's `subfigure` environment (`("subfigure", env "subfigure" $ skipopts *> tok *> figure')`) is a figure of its own whose label is its id; a `\label` there without a `\caption` also gives a `Span` of the same id, so the page has the id twice.
- **`\textcolor{name}`** gives a span whose style is `color: name` (`coloredInline`), the name as written, so a color the book defines with `\definecolor` isn't a CSS color (785 Nu checker errors on OpenIntro's pages); `skipopts` drops a model (`\textcolor[rgb]{.5,.5,.5}`) and keeps its values as the color. `\color` is dropped. convert.py makes a book color's name CSS in the read document, so a formula, a drawing, and a macro either uses keep it for LaTeX (the PDF route defines the book's colors); a model is written as CSS in the copy, outside those.
- **A label's key is the id as written**: `\label{US Airports}` is `id="US Airports"`, and `\label{edwardSatBelow\edwardsat{}}` expands the macro and keeps the `{}` in the id and the `\ref`'s fragment. The reader matches a `\ref` to its label by the key as written, through the book's own macros too (`\secref{US Airports}` for `Section~\ref{#1}`), so convert.py writes the keys as ids in the read document, after that matching; writing them in the copy broke a reference through a macro, which the review found. A `\ref` to a label in a paragraph, where LaTeX prints the section's number, is `[key]`: the reader numbers only a heading, a figure, a table, or an equation.
- **Every braced group after an unknown command is its argument, and a number its dimension.** `getRawCommand`'s default case (`Parsing.hs`) is `skipopts`, `option "" (try dimenarg)`, then `void $ many braced`; the command and all it took are dropped (or kept as raw TeX). So `\hspace{2mm}{\small text}` loses the group, which LaTeX sets as text after the space: OpenIntro's `\eocesol` writes every exercise's solution so, and its appendix of solutions read as numbers and nothing else. Measured losing a following group: about 70 of the commonest LaTeX commands, `\hspace`, `\vspace`, `\noindent`, `\centering`, `\bigskip`, `\clearpage`, `\selectfont`, `\fontfamily`, `\setlength`, `\setcounter`, `\index`, `\hypersetup`, `\color`, `\makebox`, `\raisebox`, `\phantom`, and `\pageref` among them (`\mbox`, `\label`, `\textsuperscript`, and `\ref` take only their own). `dimenarg` takes a number right after the command, a unit or not, past spaces, comments, and one line end: `\selectfont 1.1` loses the 1.1, and `\noindent 3 apples` the 3. The tokenizer puts the spaces after a control word in its token, as TeX does, so `\noindent {A}` loses the group too, while a space after an argument, `\vspace{1em} {B}`, ends the arguments. latexsource.py puts `\/` (an italic correction, `pure mempty` in `Inline.hs`) before such a group or number for the commands it knows; texmath doesn't read `\/`, so not in a formula, nor in a macro a formula uses.
- **Boxes are dropped with what they hold**: `\fbox`, `\framebox`, `\makebox`, `\raisebox`, `\smash`, `\fcolorbox`, `\scalebox`, `\resizebox`, `\rotatebox`, fancybox's `\shadowbox`, `\ovalbox`, and `\doublebox`, and `\boxed` and `\text` in running text, each an unknown command taking its arguments (measured, 2026-10-07); `\mbox`, `\hbox`, `\vbox`, `\colorbox`, and `\parbox` keep theirs. A table in `\resizebox{\textwidth}{!}{...}`, as books fit a wide one, is lost whole. latexsource.py unwraps them.
- **Counters aren't counted.** `\arabic{x}`, `\thesection`, and `\refstepcounter` are dropped, and a key made of counters is kept as written: OpenIntro's `\label{eoce_\arabic{chapter}_\arabic{eoce}}` gives every exercise the same id, and `\ref{eoce_sol_\arabic{chapter}_\arabic{eoce}}` a link to nothing, shown as `[eoce_sol_\arabic{chapter}_\arabic{eoce}]`, a backslash the Nu checker and epubcheck reject in a fragment. A `\ref` to a `\label` in running text is `[key]`; Pandoc numbers only headings, figures, tables, and theorems. latexsource.py marks the book's counter commands with empty `\hyperref` links the reader keeps in place through macro expansion, and counts them after the reading.
- **A numbered display formula keeps its environment, and its number is nobody's.** `mathEnvWith` (`Readers/LaTeX/Math.hs`, 3.11 and 3.12) reads `equation`, `align`, `gather`, `multline`, `eqnarray`, `alignat`, `flalign`, and their starred forms with the environment as its own inner one, so a display formula's TeX is `\begin{align}...\end{align}` whole, starred or not; `subequations` is read as a math environment with no inner one, so only its content is kept, a `\label` and the inner `align`. `\eqref{k}` is a `Link` with `reference-type="eqref"` and the text `[k]`, and `resolveRefs` (`Readers/LaTeX.hs`) gives a text only to a `ref`-type link (`ref+label` too, by `takeWhile (/='+')`, "TODO special treatment of ref+label") whose label it registered, a heading's, a figure's, or a table's: an equation's `\label` stays in the formula's TeX and registers nothing. texmath leaves `\label`, `\tag`, `\nonumber`, and `\notag` out of the MathML without a warning. So a formula had no number on the pages, and a reference to it read `[eq:energy]`. latexsource.py numbers them after the reading, a row at a time as amsmath does (a last `\\` makes a row: measured in LaTeX, an `align` ending in `\\` numbers an empty one), with a mark in the copy before each `subequations`. The LaTeX writer writes such a formula as it is (`isMathEnv`'s list has `subequations` too), so a PDF from the pages numbered it with LaTeX's own count, which isn't the book's for a book of documents or one with `\numberwithin`; each numbered row gets its number as a `\tag`. Measured on 3.12, 2026-10-07.
- **`minipage` is dropped, and an unknown environment is a `Div`, with a heading inside it inside it**: OpenIntro's chapter titles in its `chapterpage` (mdframed in a minipage) were `Div [Div [Header 1 ...]]`, which the H1-to-title promotion and the EPUB writer's chapters (`makeSections`, top-level headings only) don't see. latexsource.py takes a heading out of any division after the reading.
- **An `\include` inside an environment the reader keeps as a division** (the appendix package's `appendices`) puts the file's content, and latexsource.py's marker before it, inside the `Div`, where cutting the book into pages at top-level markers didn't find it: the file ran on in the page before, the marker shown as text. latexsource.py gives up such a division before the cut. Measured on 3.12, 2026-10-07.
- **A title holding a formula is written as its TeX** in the HTML writer's `<title>` (`pagetitle` defaults to `stringify` of the title, and `stringify` of `Math` is its TeX: `\pmb{t}-Probability Table`), and in anything else that stringifies the title. The plain writer gives the formula in Unicode where it can (`t`, `x²`), which `figures-and-tables.lua` uses for a page's title. Measured on 3.12.
- **texmath stops on `\begingroup` and `\bgroup`** ("unexpected control sequence \begingroup"), which Pandoc's macro expansion puts in a formula from a book's macro; braces read. Measured on 3.12.
- **Space a command sets between words is dropped in text.** `A\hspace{1cm}B`, `A\quad B`, `A\qquad B`, `A\enspace B`, `A\hfill B`, and `A\hspace*{\fill}B` are each the one `Str` `AB`, the words run together, while `A \quad B`, with a space before the command, is two; `\,` is U+2006, `\ ` a no-break space, and `\kern1em` and `\hskip1em` keep the space after their dimension. Measured on 3.12, 2026-10-08, after the calculus notes' example labels read "ExCalculating", 111 times (`\fbox{...}\hspace{2mm}` before each title). latexsource.py puts a space before such a command where there's none, unless the space is under 2pt, a sliver inside a name (OpenIntro's `sex\_\hspace{0.3mm}male`), or less than none.
- **A comment eats no line end.** `a%<newline>b` is `a`, a soft break, `b`: the tokenizer makes the comment one token and the line end another (TeX ignores the line end after a comment), so a comment can't join two words, as TeX authors use it, and `text%<newline>\footnote{...}` or a superscript citation after it has a space before its mark that LaTeX doesn't set. Measured again on 3.12, 2026-10-07. Counted in the corpus, the cases where the space shows are few (most are in definitions, or start a line LaTeX starts a paragraph with), so the copy doesn't join the lines.
- **A brace the book never closes** reads to the end of the book: "Error at main.tex (line 255, column 2): unexpected end of input", the position the end of the master, not the brace (`style.tex`, line 346).

**What the reader numbers, names, and cites, against what LaTeX prints** (read at 3.12 and measured, 2026-10-07, on GIAM, OpenIntro, and scratch books whose output LaTeX 2026-06-01 printed):

- **A heading's number is its depth's count and nothing else.** `section` (`Readers/LaTeX.hs`) numbers each heading that isn't starred with `incrementDottedNum` on one running number, the level moved down one once a `\chapter` has been read (`sHasChapters`). `\frontmatter`, `\mainmatter`, and `\appendix` aren't known and are dropped, so a numbered chapter in the front matter counts, and an appendix is numbered on from the chapters, not lettered. A `\part` is level −1, which `incrementDottedNum` makes an empty number (`take 0` of the levels), so a `\ref` to a part is empty and the chapters after each part start again at 1. `secnumdepth` isn't read, so a book class's subsubsection, which LaTeX doesn't number, has a number, and a label after it gets that.
- **A float counts only if it has a label.** `figure'` and `addTableCaption` (`Readers/LaTeX/Table.hs`) call `getNextNumber` only when `sLastLabel` is set, so each figure or table after an unlabeled one in its chapter is one less than LaTeX's. subcaption's `subfigure`, read through `figure'`, counts as a figure. `\caption*` is read as `\caption` (a command's star is tried and then dropped), so an unnumbered caption is a figure's caption like any other.
- **A theorem is numbered within its chapter, whatever `\newtheorem` says.** `newtheorem` (`Readers/LaTeX/Math.hs`) reads the `[within]` argument into `theoremSyncTo`, which nothing reads; `theoremEnvironment` numbers by `getNextNumber`, within the chapter when the book has one and alone when not. A shared counter (`\newtheorem{lem}[thm]{Lemma}`, `theoremSeries`) is honored. So GIAM's `\newtheorem{thm}{Theorem}[section]` gave Theorem 1.1 for LaTeX's 1.4.1, in the theorem's title and in each `\ref`. And `\newtheorem*{remark}{Remark}` is numbered ("Remark 1.1"): `blockCommand` takes the star (`star <- option "" ("*" <$ symbol '*' <* sp)`, `Readers/LaTeX.hs`) and looks up `newtheorem*`, then `newtheorem`, whose own check for a star then finds none. Measured.
- **`\autoref`, `\cref`, and `\Cref` get the bare number.** `doref` (`Readers/LaTeX/Inline.hs`) gives them the reference types `ref+label` and `ref+Label`, and `resolveRefs` cuts the type at its `+` ("TODO special treatment of ref+label"), so the name LaTeX prints before the number (Figure, fig., Equation) is never written. `\cref{a,b}` is one link to `#a,b` whose text stays `[a,b]`. cleveref's `\crefrange`, `\namecref`, and `\labelcref` aren't known: dropped with their arguments, so "See \labelcref{f:b}," is "See ,".
- **A citation is a `Cite` whose text is the raw `\cite`** (`citationWith`, `Readers/LaTeX/Citation.hs`: `cite c (rawInline "latex" ...)`), which only the LaTeX writer prints, so without citeproc a `\cite` is nothing in HTML, EPUB, or Word: GIAM's "a finite projective plane of order 10[10]" read "order 10". `\bibliography{a,b}`, and biblatex's `\addbibresource`, are the metadata field `bibliography`, each name given the extension `.bib` (`splitBibs`); `\bibliographystyle` and `\printbibliography` are dropped, so citeproc can make a bibliography, in its own style and not the book's, at the end of the document and not where the book prints it. `thebibliography` isn't known: a `Div` of what it holds, `\bibitem` an unknown command taking every braced group after it, so the entries run together in one paragraph without their labels, an entry losing a `{\em title}` set right after its key.
- **A caption outside a `figure` or a `table` is lost.** caption's `\captionof` and subfig's `\subfloat` aren't known and are dropped with their arguments, the `\subfloat`'s image too. wrapfig's `wrapfigure` and `wraptable` are unknown environments, `Div`s whose arguments (`{r}{0.4\textwidth}`) are read as text, "r 0.4", and the `\caption` inside them sets a caption nothing takes. And a `table` float holding no `tabular`, an image, say, drops its caption: `addTableCaption` puts it only on a `Table` it finds. It finds every one, by `walkM`, so a float holding two tables gives each the caption and the label, two ids alike, and a table in a table's cell takes its container's: GIAM's rules of inference, whose `\ref`s then went to the inner table, which a PDF from the pages writes as a `tabular` with no label ("Hyper reference undefined"). subcaption's `subtable` isn't known: a `Div` whose table gets the float's caption too, its own caption giving way.
- **A `\label` inside a `\caption` names two elements.** `\caption{X\label{y}}` gives the figure (or table) the id `y` and keeps the label in the caption as an empty `Span` with the id `y` and `data-label="y"`, so the HTML writer writes the id twice on one page, which HTML doesn't allow; nothing reads the span. Measured on 3.12, a figure and a subcaption `subfigure` alike. A candidate upstream report. figures-and-tables.lua drops a caption's empty span whose id is its float's before it makes the page's ids unique, which had renumbered the float (`y-1`).
- **floatrow's boxes are unknown commands**: `\ffigbox{...}{...}`, `\ttabbox`, and `\fcapside` are dropped with both arguments (`getRawCommand`'s `many braced`), the `\caption` and `\label` with them, so a `\ref` to one reads `[label]`, and a `floatrow` environment is a `Div` holding nothing. Measured on 3.12; latexsource.py writes each box as a minipage of what it holds, which `split_floats` makes a float of. floatrow takes both arguments into the box and finds the caption in either, whatever its manual's order.
- **An unknown environment's arguments are read as text.** `\begin{multicols}{2}` is a `Div` whose first paragraph opens with a `Span` holding `2`, and multicols's preface, `[Head]`, is the text `[Head]`; setspace's `spacing` and `Spacing`, changepage's `adjustwidth`, paracol's and parcolumns's column counts, boxedminipage's width, and beamer's `column` print theirs too, and KOMA's `addmargin` its mandatory one (its optional one is dropped). `tcolorbox`'s and `mdframed`'s options, enumitem's, and `minipage`'s are skipped. Measured on 3.12, 2026-10-07; latexsource.py begins each of these without its arguments, and sets multicols's preface before it.
- **`\protect` isn't known**, so it takes the group after it, as any unknown command does: `Christian \protect{G}oldbach`, a title in GIAM's database and so in the `.bbl` BibTeX writes from it, reads "Christian oldbach". Measured.

## The LaTeX writer, for a tagged PDF

Read at the 3.11 tag, and measured where it says so, with LaTeX 2026-06-01 (TinyTeX v2026.09, updated). Rechecked at 3.12: the `MetaString` class, the image code, the folded row heads, and `has-frontmatter` are as below; the template no longer loads `footnotehyper`, since the writer now writes notes in a `longtable` itself (#11857). 3.12.1 changes only how an image's alt is written (below).

**`pdfstandard`** is processed by `processPdfStandard` (`Writers/LaTeX.hs`): the accepted names are PDF/A (not `a-1a`), PDF/X, and `ua-1`/`ua-2`; `ua-1`, `ua-2`, `a-2a`, and `a-3a` switch `tagging=on`; a version is inferred where a standard needs one below 2.0. WTPDF isn't a name it knows. The `document-metadata.latex` partial writes `\DocumentMetadata` with those and the language, and has no slot for `tagging-setup`, so tagging options go in `header-includes` as `\tagpdfsetup`.

**The class decides chapters by its text, and a `MetaString` has none.** The writer's class for its own decisions is `lookupContext "documentclass" (writerVariables …)` or else `stringify <$> lookupMeta "documentclass" meta`, and `stringify` (`Shared.hs`) collects text from inlines, so `stringify (MetaString "book")` is empty. The template still writes `\documentclass{book}` from the context, where a `MetaString` renders fine. Measured: `-M documentclass=book` (a `MetaString`) gives a level-1 heading as `\section`; the same class as YAML metadata (`MetaInlines`) or `-V documentclass=book` gives `\chapter`. An upstream candidate: see Upstream, below.

**Images** (`inlineToLaTeX (Image …)`): the `alt` key comes from an `alt` attribute when there is one, even empty, which writes `alt={}`; otherwise from the description; an SVG gets none either way. **Tables** (`Writers/LaTeX/Table.hs`): `bodyRowCells` joins a row's head cells to its other cells, so `row_head_columns` changes nothing in LaTeX. The head goes in `longtable`'s `\endfirsthead` and `\endhead`, which latex-lab tags as header rows. Measured: latex-lab tags the caption as a header row spanning the table, and the repeated head as an artifact.

**A table it doesn't number can't have a caption with the caption package.** A table of class `unnumbered` with a caption is written `{\def\LTcaptype{none} … \caption{…}`, and the caption package, which Pandoc's own template loads, looks for the list such a caption goes in (`\ext@none`) and stops LaTeX: "No float type 'none' defined". **A table with an id and no caption is given an empty one, which LaTeX numbers.** `tableToLaTeX` (`Writers/LaTeX/Table.hs`, 3.12.1) writes a caption unless the caption is empty and the table is `unnumbered` or has no id (`Caption Nothing [] | unnumbered || T.null ident -> pure mempty`), so a table with an id and no caption is `\caption{}\label{id}`, its `\label`'s only home, and LaTeX numbers that caption: "Table 1" over a table nobody numbered, an HTML page's `<table id>` without a `<caption>`, say. A table of class `unnumbered` with no caption gets neither, so its id is nowhere in the LaTeX, and a link to it is "Hyper reference undefined". Read at 3.12.1 and measured, 2026-10-15 and 16. `pdf-target.lua` makes such an id a `Div`'s, which the writer writes `\protect\phantomsection\label{id}` before the table. A candidate upstream report: such an id could be the anchor a `Div`'s is, the table uncaptioned.

**A table whose columns have no widths and whose cells are each a paragraph is set in columns that don't wrap.** `colDescriptors` gives each column `l`, `c`, or `r`, by its alignment, when every column's width is `ColWidthDefault` and the table `isSimpleTable`: every cell, head and foot included, is one `Para` or `Plain` without a `LineBreak`, or empty. Any other table without widths gets `p` columns of equal width, which wrap, and one with widths `p` columns of those widths. An HTML table without a `<colgroup>` has no widths, so one whose cells, side by side, are longer than a line runs past the page's edge: 25 tables in *Prealgebra 2e*'s third chapter, unpacked from CNXML, by 6.7 to 258 points (LuaLaTeX's overfull alignments, its second pass), a worked example's steps most of them. A Word table has widths from its grid, and Pandoc's Markdown reader gives a pipe table relative widths when a row is longer than `--columns`. And a cell that runs past its body's row-head columns loses its span, as in every writer (the HTML writer's entry). Read at 3.12.1 and measured, 2026-10-16. `pdf-target.lua` gives such a table wider than a line widths in proportion to its columns' longest cells. A candidate upstream report: the writer could do as the Markdown reader does.

**LaTeX's tagging takes a longtable's head for header cells even in a division of paragraphs** (LaTeX's, not Pandoc's). `table/tagging=div` clears the header rows and calls `\__tag_tbl_enable:`, which assigns the `tbl/longtable/finalize` plug a table gets, and that plug sets the header rows again from the longtable's head (`\g__tbl_LT@firsthead_rows_seq` or `\g__tbl_LT@head_rows_seq`) and retags their cells `table/headercell`: each a TH under a NonStruct in a Div, outside any TR. Read in `latex-lab-testphase-table.sty` of 2026-04-28 (0.85t, TeX Live 2026) and in the LaTeX team's development version (`latex-lab-table.dtx`, 2026-09-24, 0.85v, fetched 2026-10-16), which has it too; measured by the testing session on the Word corpus (veraPDF's PDF/UA-2 profile: ISO 32005's "Sect shall not contain TH", with tagpdf 1.0h) and here with a longtable of two rows, the first its `\endhead` (Debian's TeX Live 2026: the two TH, `SENonStandard`, fail 8.2.4, the namespaces). **The template brackets the title and contents** with `\frontmatter` … `\mainmatter`, and puts `\backmatter` after the body, when `has-frontmatter` is set, which the writer does with `defField` for the classes in `frontmatterClasses`. `defField` leaves a field the metadata already set, so `has-frontmatter: false` in the metadata turns all three off.

**Running LaTeX** (`PDF.hs`): up to four runs, another whenever the log has a warning containing both `Warning:` and `Rerun`, and always while a table of contents exists (#10308). Images are copied into the temporary directory LaTeX runs in, and their paths in the AST rewritten, so a raw `\includegraphics` a filter writes wouldn't find its file; a filter that wants to change how an image is written has to leave it an `Image`.

**Missing characters** (`PDF.hs`, `missingCharacterWarnings`): after a successful run Pandoc reports each `Missing character:` line of LaTeX's log as a warning, one per occurrence, with the code point added. Measured: a character missing from an OpenType font (Latin Modern Roman, the template's default under LuaLaTeX, with or without a luaotfload fallback) is logged and drawn as `.notdef`, which veraPDF's PDF/UA-2 profile reports (clause 8.4.5.9); one missing from a legacy Type 1 math font (`lmmi10`, which an equation falls back to for a character unicode-math doesn't map, such as U+00B5) is logged and dropped, and veraPDF finds nothing.

**Math environments** (`isMathEnv`, `Writers/LaTeX.hs`, 3.12): a `Math` whose text opens with one of the listed environments is written as it is, anything else in `\(` `\)` or `\[` `\]` (#9711). The list has `eqnarray` but not `eqnarray*`, which the reader keeps in a display formula as written (`Readers/LaTeX/Math.hs` reads both), so `\[\begin{eqnarray*}...\end{eqnarray*}\]` stops LaTeX ("Missing \endgroup inserted"). Measured on OpenIntro Statistics through the PDF target's pages route; `pdf-target.lua` writes such a formula as raw LaTeX, and LaTeX's tagging gives it MathML. A one-word upstream fix; still missing in 3.12.1.

**`\pmb` stops LuaTeX under tagging with MathML** (not Pandoc's; LaTeX's tagging, TeX Live 2026, measured 2026-10-07): `\(\pmb{\hat{p}_1 - b}\)` in a document with `\DocumentMetadata{tagging=on}`, unicode-math, and `math/setup={mathml-SE,mathml-AF}` ends LuaTeX with "(nodes): trying to set an attribute fails, case 2", while `\pmb{\hat{p}_1}`, `\pmb{p_1 - b}`, `\pmb{\hat{p} - b}`, and `\boldsymbol{\hat{p}_1 - \hat{p}_2}` build. amsbsy's `\pmb` sets its argument three times in boxes, offset. `pdf-target.lua` and the tagged copy write it as `\symbfit`. A candidate for latex3/tagging-project, with the four lines above.

**A span's id in a heading is a `\hypertarget`, and an internal link is `\hyperref`**, which finds only a `\label` (`Writers/LaTeX.hs`, 3.12): `Span ("sec:spread",[],[]) []` in a `Header` is written `\protect\hypertarget{sec:spread}{}` in the heading's `\texorpdfstring`, while the same span in a paragraph is `\protect\phantomsection\label{sec:spread}{}`, and a link to `#sec:spread` is `\hyperref[sec:spread]{...}`: "Hyper reference `sec:spread' undefined", and the link goes nowhere. **Metadata is rendered in the body's state, before the body.** `pandocToLaTeX` (`Writers/LaTeX.hs`) calls `metaToContext` with `blockListToLaTeX` before it writes the body, in the same state, so a code block in `header-includes` is highlighted as one in the body is and sets `stHighlighting`, which gives the template `highlighting-macros` (the `Shaded` environment and the token macros) though the body has no code; and `highlighting-macros` is set with `defField`, so a metadata field of that name wins over the writer's. `footnote-code.lua` relies on the first, putting a footnote's code block in `header-includes`, and `deck-pdf.lua` on the second, giving a deck whose only highlighted code is in a section's footnote, which it writes apart from the deck, the macros the writer didn't. Read at 3.12.1 and measured, 2026-10-12.

**A verbatim block in a footnote stops LaTeX under tagging** (LaTeX's, not Pandoc's, 2026-06-01, measured 2026-10-12): latex-lab-footnotes.ltx defines `\footnote` with `\DeclareDocumentCommand\footnote{o+m}`, taking the note's text as an argument, and resets `\@footnotetext` at the start of the document, so a code block in a note ends LaTeX with "Paragraph ended before … was complete" (`\FV@BeginScanning` for highlighted code, fancyvrb's `Highlighting`), and fancyvrb's `\VerbatimFootnotes`, which Pandoc's template writes when a note holds code, doesn't help. Pandoc's output for such a book can't be built with tagging on; `footnote-code.lua` writes each such block to a file from the preamble and reads it with `\input` where it stood.

**Partials** (`Templates.hs`, `getTemplate`): a partial is looked for beside the template, then in the user data directory's `templates/`, then among the built-in files. So a one-line wrapper, `$default.latex()$`, is Pandoc's default template unless a file of a partial's name sits beside it or in the user data directory.

**How many LaTeX runs `-t pdf` makes.** `makePDF` (`src/Text/Pandoc/PDF.hs`, 3.12 and main at 8f949db) runs the engine again while the log has a line holding both `Warning:` and `Rerun`, or a `.toc` file exists, and at most four times. A book with a table of contents is therefore always run four times, though the comment above the check says three (#10308). A warning without the word, as tagpdf's "Destination ... has no related structure" is, never asks for another run by itself. `latexmk` decides differently: it runs again while a file the last run wrote and the next reads (`.aux`, `.toc`, `.idx`, `.bbl`) changed, at most five times (`$max_repeat`), and runs BibTeX and makeindex when their inputs change. Read from both sources, 2026-10-05; on GIAM's tagged copy, latexmk ran LuaLaTeX four times. Nor does `makePDF` look at the exit status before running again: a run that fails is run again while the `.toc` exists, so a pages-route build that fails, whose LaTeX always has `\tableofcontents`, runs LaTeX four times before Pandoc reports the error (2026-10-09: a one-page tagged book failing at once took four runs of about 3.2 s; three million `\csname`s, which fill LuaTeX's strings, four of about 8 s). Worth an issue upstream; until then a build that has to fail fast, as the convert suite's capacity case does, uses a stand-in engine.

**The template's layout variables** (`pandoc -D latex`, 3.12; used for a LaTeX book's own layout in a PDF from its pages, 2026-10-07): `fontsize` (`11pt`) and `papersize`, to which the template adds `paper` (`letter` is `letterpaper`), go to `\documentclass`'s options with each `classoption`; `geometry` is a list, each item an option of `\usepackage[...]{geometry}` (`\geometry{...}` under beamer); `linestretch` is setspace's `\setstretch`; and without `indent` the template loads parskip (or sets `\parindent` to zero and `\parskip` to 6pt, without it; a KOMA class gets `parskip=half`), so a book's indented paragraphs need `indent: true`. A field the metadata file sets later replaces ours, since `build-pdf.py` updates the metadata with it after. Measured on FINC 308's whole book: `fontsize: 11pt` and `geometry: [margin=1in]` give 10.91 bp type from 72 to 540 bp, as the author's article class does.

**xcolor's sets of named colors come only with `colorlinks`.** The template passes `dvipsnames,svgnames,x11names` to xcolor (`\PassOptionsToPackage`, before `\documentclass`) only when `colorlinks` is set, which also colors every link; xcolor takes the three as class options too, which `classoption` gives. A formula keeps its TeX, so one naming `BrickRed` in a book that loads `[dvipsnames]{xcolor}` stops LaTeX in a PDF from the pages without them. `build-pdf.py` gets them from the book's layout as class options. Read in `pandoc -D latex` and xcolor.sty (`\XC@declarenames`, which inputs the set's `.def` file after the package), 2026-10-07.

**Running heads** aren't the writer's: the book class sets `\chaptermark` and `\sectionmark` in `\ps@headings`, one line however long, and Pandoc's template doesn't touch them. Measured: a section titled with 85 characters ran past the page's edge. `build-pdf.py` wraps the kernel's `\markboth` and `\markright`, which every class's marks go through (`latex.ltx`, 2026-06-01: `\mark_insert:nn` for `2e-left`, `2e-right`, and, when the right mark isn't empty, `2e-right-nonempty`).

## Possible Pandoc enhancements

Not workarounds the pipeline carries: losses it reports (`fidelity.csv`) and doesn't repair, where a change in Pandoc would let a Word file carry more.

- **A list inside a block quote.** The writer doesn't indent a list inside a quote at all, so Word shows it outside; and the reader's rule that makes an indented paragraph a quote explicitly excludes numbered paragraphs (`not (numbered pPr)` in `paragraphStyleToTransform`). Two changes: the writer indents a list by its quote's depth; the reader compares a numbered paragraph's indent with its numbering level's own, not its style's, which needs care, since lists are indented by design. A crude search of the tracker (2026-09-25) found no issue.
- **A figure with no caption.** The writer styles its paragraph `Figure`; the reader doesn't read that style back as a figure.
- **The Markdown writer writes an example list as a numbered list** (measured, Pandoc 3.11). `(@)` items come out `(1)`, `(2)`, and a later example list `(3)`, which reads back as ordinary numbered lists starting where written, style `Decimal`, not `Example`: the numbers shown survive, the running numbering doesn't, and a reference to a labeled example, `(@good)`, is already written as the text `(1)`. Writing `(@)` for an `Example`-style list would round-trip. The Markdown target reports it in `fidelity.csv`.
