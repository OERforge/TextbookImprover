# Checking the output

Every run ends by checking what it wrote: each page of the run, and each EPUB and PDF built from them, and in a slides run each PowerPoint file it wrote, a deck's copy or a `pptx` target's file, checked as a deck is ([Slides](slides.md#whats-checked)), and each reveal.js presentation, as a page is. The findings go to `output-check.csv` beside the other reports, in the [findings format](auditing.md#the-findings-format) every check in this project shares (`Where, Check, Detail` first, then the file, its kind, a severity, the standard, the tool, and where the fix lives), and a summary goes to the terminal. The check never stops the run: the output exists, and the report is the list to work through. For the same checks on files that didn't come from a run, and for Word, Markdown, PowerPoint, and PDF as well, see [Auditing](auditing.md).

```bash
python3 bin/check-output.py *.html --epub epub/book.epub --report output-check.csv
```

runs the same check by hand, on whatever you point it at. `--pdf` and `--pptx` add a PDF or a PowerPoint file the same way, each as often as you like, `--quick` leaves the validators out, `--wcag` adds veraPDF's WCAG 2.2 checks to a PDF's ([below](#verapdfs-wcag-22-checks)), as `convert.py --wcag` does to a run's, and `--documents` names a JSON file giving each page's document (`{"html/deck.html": "deck"}`), within which one alt text on different images is looked for.

## What it looks for

The checks are the class of defect that has reached this project's output before: structure that's well-formed and wrong, which nobody notices by looking at a page.

| Check | What it means |
|---|---|
| `link-to-missing-file` | A link names a page or file that isn't in the set being checked. |
| `link-to-missing-fragment` | A link's `#fragment` matches no `id` in the page it points at, as written or decoded, as a browser looks for it. In a reveal.js presentation, `#/id`, reveal.js's route to the slide holding the id, is read as `#id`. |
| `link-to-file-dropped` | An EPUB's link to a local file, a PDF or a Word file a page offers, which an EPUB can't carry, so its text stays without the link. |
| `link-label-without-text` | A link whose `aria-label` doesn't contain its visible text, which fails [WCAG 2.5.3](https://www.w3.org/WAI/WCAG21/Understanding/label-in-name.html) (Label in Name): a speech-input user follows a link by saying the words on it. Text used as a symbol, with no letter or digit in it, isn't a visible label to the criterion, so a note's way back, `↩︎` labeled "Back to reference 3", isn't reported. |
| `image-without-alt` | An `img` has no `alt` attribute, so a screen reader announces the file name. |
| `image-empty-alt-not-decorative` | `alt=""` without `aria-hidden="true"`: the image was neither described nor declared decorative. In an EPUB this is the usual form of a missing description, since Pandoc's writer gives every image an `alt`. |
| `image-alt-is-file-name` | The `alt` is the image's file name (`db locked` for `db-locked.png`, as Asciidoctor writes one the author didn't give), or holds a file name or extension. |
| `image-alt-placeholder`, `image-alt-auto-generated`, `image-alt-page-title`, `image-alt-credit` | The `alt` says nothing about the image (a word such as "image", a camera's or tool's name for a file, a shape's default name, a clip-art id, punctuation alone), is a description Office generated, looks copied from a web page with the picture, or is only a credit (who made the picture, its license, or where it's from), by the rules a deck's pictures are judged by ([Slides](slides.md#whats-checked)). The project's own `images.alt_placeholders` are read for a book's `image-alt-missing.csv`, not here. |
| `image-alt-shared` | A note: one `alt` on different images of a book's pages, a deck's in a run of decks (its pieces and its presentation), or an EPUB, case and closing punctuation aside, that no other check names (`check-output.py` on its own takes the pages it's given as one document, as a book's run does, unless `--documents` names each one's, as a run of decks does). Images are told apart by their files' content, so the same picture in two files isn't named. It may be a description copied to a picture it doesn't fit, or the same picture in two files of different sizes ([Slides](slides.md#whats-checked) says how often each was so in OpenStax's books). |
| `heading-skips-level` | A heading is more than one level below the one before it. The run lifts such a heading in the pages it writes, unless `heading_levels` is `source` ([Configuration](configuration.md#headings-that-skip-a-level)), so it's found in a hand-written page, in pages `check-output.py` reads on its own, or with `source`. |
| `formula-lost` | A formula a saved page held only as MathJax drew it, with nothing left to read it from, marked `[formula]` ([HTML sources](html.md)). |
| `formula-shown-as-tex` | A formula Pandoc couldn't convert to MathML, so the page shows its TeX (`$r_{s} = \left( …$`) and a screen reader reads that out. Pandoc says so only in a warning among the run's output; the detail is the formula, to find it in the source. A page with a script is skipped, since a script there may be what renders the TeX. |
| `formula-kept-as-text` | A formula Pandoc couldn't read from its MathML, which its HTML reader keeps as its text in a span of class `math`, the parts of a fraction or a script run together (`x2` for *x*²), and says nothing of, not even in a warning: texmath rejects a script or a fraction of the wrong number of parts, and an element it doesn't know, such as content MathML's `apply` ([the Pandoc notes](../PANDOC-NOTES.md)). The detail is the text, to find it in the source. A page with a script is skipped, as for `formula-shown-as-tex`. |
| `empty-heading` | A heading with no text. |
| `invalid-id` | An `id` containing whitespace, which no `id` may. |
| `duplicate-id` | An `id` used more than once in one document, so links to it are ambiguous. |
| `vnu:error`, `vnu:warning`, `epubcheck:<ID>` | What the full validators reported, when installed; see below. |
| `table-not-in-scroll-region` | A data table on an HTML page outside the focusable wrapper the filter puts around every data table (WCAG 1.4.10). The filter's own invariant, checked on the output. A layout table, `role="presentation"` or `role="none"`, has none: its cells stack on a narrow screen instead. |
| `table-without-headers-or-caption` | A table with no `th` and no `caption`, and not marked as a layout table, `role="presentation"` or `role="none"`. A data grid with no relationships to encode conforms with a caption alone; without one it's unidentifiable. |
| `table-without-data-cells` | A data table whose every cell is a header (`th`), none of them data (`td`), so the table has no body, which an accessibility checker reports as a table missing its body. A page's `<thead>` holding every row made such tables until the repaired copy gave them a body ([HTML sources](html.md)). |
| `table-header-is-formula` | A note: a header cell (`th`) holding only a formula. The table is right as it stands, but NVDA reads the formula in the header row and announces no header on moving into its column, since it takes a header from the cell's text in its buffer, where a formula is a single space ([its browser support](https://github.com/nvaccess/nvda/blob/release-2026.2/nvdaHelper/vbufBackends/gecko_ia2/gecko_ia2.cpp#L849-L856), [the header's text](https://github.com/nvaccess/nvda/blob/release-2026.2/source/virtualBuffers/__init__.py#L416-L437)). Words beside the formula it announces ("Quantity demanded, q_d" is announced as its words). Heard so with NVDA in Chrome or Firefox and in Acrobat. The detail is the table's number on the page and the formula's TeX. |
| `no-lang`, `no-title` | The `html` element declares no language, or the page has no title. |
| `title-is-file-name` | The page's title is its file's name (`ch_intro_to_data`), as a page with no heading of its own gets: a name with an underscore, a hyphen, a dot, or a capital inside a word. |
| `not-well-formed` | An EPUB content document that isn't XML. |

For an EPUB it also checks the container: `mimetype` first and uncompressed, a package document the container points at, every manifest item present in the archive and every file in the archive present in the manifest, spine entries that exist, a navigation document, the `dc:title`, `dc:identifier`, and `dc:language` every EPUB needs, and the accessibility metadata this project writes.

Each finding says where (the page or archive member), which check, and what (the link, the image path, the heading text), so `output-check.csv` sorts and filters into work lists: every image without alt text goes to `image-alt.csv`, every table without headers to the table sidecars.

## Contrast

No checker here measures color contrast on the rendered page; Ace, axe, and Panorama do. What the pipeline controls is its own stylesheet and the colors it highlights code in, and those are checked where they're decided. A unit test computes the ratio of every text color `page.css` sets against Pandoc's page background and against white, and fails below 4.5:1 (the caption color is held to 7:1), and the ratio of each color it gives dark mode against a page's background there, `#1a1a1a`, and an EPUB's, `#232629`. Code is highlighted in `bin/highlighting.theme`, which every writer is given: Pandoc's pygments style, each of its colors under 4.5:1 darkened to 4.6:1 or more (a comment's `#60a0b0` was 2.89:1, and is `#3c7c8c`), so a page, an EPUB, a PDF, a Word file, a PowerPoint file, and a reveal.js presentation have the same colors. The unit suite holds the theme to 4.5:1 on Pandoc's background and on white, and `page.css`'s light colors for code to the theme's; the convert suite holds `page.css`'s colors to the backgrounds the stylesheets Pandoc writes give, light and dark, so a Pandoc that changes them fails there. A PowerPoint reference document of your own with a dark background (`slides.reference_doc`) would put the code's colors on it, which isn't checked.

## The full validators

The checks above are what the standard library can do. [epubcheck](https://github.com/w3c/epubcheck) and the [Nu HTML checker](https://validator.github.io/validator/) know their specifications in full, and when they're installed the run uses them too: epubcheck on each EPUB, the Nu checker on every page. Their findings land in the same report in the same shape, with the tool's own message as the check (`epubcheck:RSC-012`, `vnu:error`, `vnu:warning`), and the run says which ran. The Nu checker's informational messages (Pandoc's trailing slashes on void elements, mostly) are counted and not listed, since they change nothing for a reader.

A PDF gets what the [audit](auditing.md) reports about one: what the file claims, whether it's tagged, and, from its structure tree, each figure whose alternative text is a file name (`pdf-figure-alt-is-file-name`), which is what LaTeX writes for an image with none and a validator accepts, and each whose alternative text is the placeholder LaTeX writes for a drawing with none, `picture environment` or `Alternative text missing!`, or says nothing otherwise, as a page's alt text can (`pdf-figure-alt-is-placeholder`), and as warnings, each whose alternative text Office generated (`pdf-figure-alt-auto-generated`), looks copied from a web page with the picture (`pdf-figure-alt-page-title`), or is only a credit (`pdf-figure-alt-credit`); and, as a note, each header cell holding only a formula (`pdf-table-header-is-formula`), which NVDA in Acrobat doesn't announce as a column's header, as on a page ([its Acrobat support](https://github.com/nvaccess/nvda/blob/release-2026.2/nvdaHelper/vbufBackends/adobeAcrobat/adobeAcrobat.cpp#L456-L460)), whatever alternative text the formula has. The detail is the cell's page, its table's number, and its own among the table's header cells, in the structure tree's order. Content beside a formula counts if it shows anything at all, a space glyph included. When [veraPDF](https://verapdf.org) is installed, each rule it finds failed is a finding (`verapdf:<clause>-<test>`, with the standard's clause in the Standard column), and once it has run and found nothing, the note that the file's claims are unverified is dropped.

All three are Java, which is why they're optional. [Installation](installation.md#optional-the-full-validators) says how to set up the first two, and [veraPDF](installation.md#optional-verapdf) the third; the run finds them through `EPUBCHECK_JAR`, `VNU_JAR`, and `VERAPDF`, or as `epubcheck`, `vnu`, and `verapdf` commands on the path. When a fast turn is wanted, `convert.py --quick` checks the run's output without them, as `check-output.py --quick` does on its own; the checks above still run, and the summary says the validators didn't.

The first thing the Nu checker found in this project's own output was a rule the built-in check couldn't know: an `img` with `alt=""` already has the presentation role and may not carry a `role` attribute, which the filter had been adding to every decorative image. It now uses `aria-hidden="true"`, which the checker accepts and which does the same job. That's the argument for running the real thing.

A PDF/UA-2 file this pipeline makes also claims the PDF Association's [Well-Tagged PDF](https://pdfa.org/resource/well-tagged-pdf/), at both its levels (accessibility and reuse; LaTeX writes the declarations), and veraPDF validates what a file claims: its WTPDF 1.0 profiles run on every such PDF, beside PDF/UA-2 and Tagged PDF, and a finding names the profile. A PDF/UA-1 file, PDF 1.7, is outside WTPDF, which is PDF 2.0. A PDF's validators and readers have their own limits. When a screen reader says something a tagged PDF doesn't, the viewer may be at fault rather than the file: the PDF Association's technical notes say that a viewer which announces a figure for an image tagged with the text it shows ([TN-PDFUA1-001](https://pdfa.org/resource/tn-pdfua1-001)), or announces "link" twice for a contents entry, whose `Reference` encloses a `Link` as it should ([TN-PDFUA1-002](https://pdfa.org/resource/tn-pdfua1-002)), has a defect to report to the viewer's publisher. Few checkers know PDF 2.0, and one that applies PDF 1.7's rules to a PDF/UA-2 file reports problems a valid file doesn't have; the LaTeX tagging project keeps a [list of such false reports](https://github.com/latex3/tagging-project/discussions/categories/issues-with-accessibility-checkers-and-other-at-software) to check a finding against. [PDFix](https://pdfix.net/) runs veraPDF's checks but shows where in the page each problem is, which veraPDF's paths into the structure tree don't. veraPDF's [other profiles](https://github.com/veraPDF/veraPDF-validation-profiles) can be run on the same file, but its WCAG 2.2 profiles' own checks, the ones [PDF4WCAG](https://pdf4wcag.com/) reports (a span with nothing in it, spaces used for layout, a link described only by its address), need veraPDF's WCAG modules ([`wcag-validation`](https://github.com/veraPDF/veraPDF-validation) and [`veraPDF-wcag-algs`](https://github.com/veraPDF/veraPDF-wcag-algs)), which its release doesn't include: given such a profile with `-p`, veraPDF 1.30.3 checks the PDF/UA rules in it and passes the rest without checking them. `--wcag` runs one with them ([below](#verapdfs-wcag-22-checks)). Blackboard Ally, in many learning management systems, checks against PDF 1.7: it wants alt text on every formula, which a PDF/UA-1 build has and a PDF/UA-2 build doesn't (`pdf.standard`), and headings in anything over two pages. For hearing a tagged PDF 2.0 file, Acrobat, Foxit, and Firefox expose its tags, to NVDA or JAWS on Windows and Orca on Linux. Only NVDA, mostly in Acrobat, has been tried here.

DAISY's [Ace](https://daisy.github.io/ace/) applies the accessibility rules to an EPUB the way a reading system would; it needs Node with a bundled browser and isn't wired in. Worth running on a book before distributing it.

## veraPDF's WCAG 2.2 checks

`--wcag`, given to `convert.py`, `check-output.py`, or `audit.py`, checks each PDF against veraPDF's WCAG 2.2 machine profile as well, with the WCAG modules veraPDF's release doesn't include ([Installation](installation.md#optional-verapdfs-wcag-modules)): `WCAG-2-2-Machine-PDF20.xml` for a file whose header says PDF 2.0, as a PDF/UA-2 build's does, and `WCAG-2-2-Machine.xml` for any other. The PDF 2.0 profile is 86 of PDF/UA-2's 92 rules and eleven of its own (veraPDF 1.30), and the other has the same eleven: text with five or more of one character in a row, or three or more spaces ([1.3.1](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html)); text outside a figure whose contrast with what's behind it is under 4.5:1, or 3:1 for large text ([1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)); text outside a figure under 4.5 points ([1.4.4](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)); a figure on one page with no bounding box ([1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)); a link described by nothing, or by nothing but its address ([2.4.9](https://www.w3.org/WAI/WCAG22/Understanding/link-purpose-link-only.html)); and a paragraph, span, heading, or numbered heading with nothing in it (veraPDF's "redundant", [PDF4WCAG](https://pdf4wcag.com/)'s "empty"), and a contents entry with no line of text ([4.1.2](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html)). Only those eleven are reported, PDF/UA's rules being veraPDF's usual run's. The profiles repository's `Complete` profiles add 47 rules tagged `human`, the algorithms' guesses at what the structure should be (a paragraph that should be a heading, a table whose rows don't match what's drawn), each for a person to judge; they aren't run.

What the profile finds is information, not a verdict. Its rules are heuristics, and some misread a book: in _Instrumental Analysis_ (LibreTexts), it reads the first four cells of Table 25.7.1's Groups row, I, II, III, and IV, as one run of seven I's. Others are judgments a book has made: in _Introduction to Sociology 3e_ (OpenStax), it fails 106 of the 107 fill-in blanks in the quizzes, each a run of five or more underscores (1.3.1-1; the other has four), and would with ActualText on them too, since the rule reads the glyphs (measured), and every link whose text is its own address, as a reference list's are (2.4.9-1, 789), which conform at AA by their citations ([Bare links](bare-links.md#why-this-and-not-something-else)). And WCAG 2.2 isn't what everyone is held to. The U.S. Department of Justice's [rule for state and local governments](https://www.ada.gov/resources/2024-03-08-web-rule/) names WCAG 2.1 AA, and the [Section 508 standards](https://www.section508.gov/develop/applicability-conformance/) name 2.0 AA; 2.4.9 is beyond both, at AAA, and 1.4.10, which came with 2.1, beyond 2.0's. So what the profile finds is a `note`, never an error. The run's summary counts the other findings as it always has, saying "nothing found" when there are none, and lists the profile's after them, under a line saying they're experimental and may be wrong; an audit's exit status stays its other findings'.

Each finding is one rule a PDF failed. Its check is `verapdf-wcag:<clause>-<test>` (`verapdf-wcag:2.4.9-1`); its where, the PDF; and its detail, the rule, how many of its checks failed and on which pages, where veraPDF gives them (the first 20, and how many more), the criterion's number, name, and level, its Understanding document, and the caveat. The Standard column names the criterion as the output check's own findings do (`WCAG 2.0 SC 2.4.9 (AAA)`), and the summary marks one WCAG 2.0 didn't have with the version that brought it (`1.4.10 Reflow (AA, WCAG 2.1)`). The summary has a line for each rule a PDF failed, then one saying `--verbose` lists the checks:

```
  veraPDF 1.30.3's WCAG 2.2 machine checks ran on 1 PDF(s), with its WCAG modules from /home/you/tools/verapdf-wcag: veraPDF's WCAG checks are experimental and may be wrong, so what they find is a note, never a failure.
  book.pdf: verapdf-wcag:1.3.1-1, 1.3.1 Info and Relationships (A): 1 failed check(s), page 653: Text should not contain repeated non space characters. https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html
  Each rule's failed checks are counted, not listed: run again with --verbose for each one, with what the PDF has there (a link's address, the line repeated characters are on), or check one PDF so with check-output.py --wcag --verbose --pdf.
```

With `--verbose`, given to `convert.py`, `check-output.py`, or `audit.py` beside `--wcag` (without it, `--verbose` changes nothing, and says so), each failed check is a finding instead, at its page (`book.pdf#page=66`; a span with nothing in it has none), and its detail says what veraPDF found (its message, with the text it was about and the structure element when it names them) and what the PDF has there that veraPDF's report doesn't say: for a link, its address, and its description when that isn't the address; for repeated characters, the line of text they're on, read with pypdf. The summary lists each under its rule's line, as the audit's report does under its rule's item. On _Introduction to Sociology 3e_:

```
  book.pdf: verapdf-wcag:1.3.1-1, 1.3.1 Info and Relationships (A): 106 failed check(s), pages 66, 106, 107, 149, 150, 151, 186, 187, and 41 more: Text should not contain repeated non space characters. https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html
    book.pdf#page=66: Text contains 10 repeated non space characters (on the line "__________ to study how society affects individuals.")
    book.pdf#page=106: Text contains 8 repeated non space characters (on the line "2. A measurement is considered ________ if it actually measures what it is")
  ...
  book.pdf: verapdf-wcag:2.4.9-1, 2.4.9 Link Purpose (Link Only) (AAA): 789 failed check(s), pages 70, 71, 72, 73, 74, 110, 111, 112, and 113 more: Links shall contain an alternate description via their Contents or Alt keys or in the text value. https://www.w3.org/WAI/WCAG22/Understanding/link-purpose-link-only.html
    book.pdf#page=70: A link annotation does not include an alternate description in the Contents or Alt Keys or in the text value (the link to https://www.flickr.com/photos/mariachily/3334450816/in/photostream/#/photos/mariachily/3334450816/in/photostream/lightbox/)
  ...
```

veraPDF is asked to list a rule's first 10,000 failed checks (it lists 100 unless told). It lists about 10,000 of a PDF's failed checks in all, though, PDF/UA's rules' among them, and past that only a rule's first (veraPDF 1.30.3, measured), so a rule's pages are those of the checks veraPDF listed, which its finding and its line say when it listed fewer than failed, and with `--verbose` one more finding says how many it didn't list. A book stays well under that: _Introduction to Sociology 3e_ fails 895.

Without the modules, veraPDF passes the profile's own rules unchecked and says nothing of it. So `--wcag` looks for them first, then checks a probe in the same run, a one-page PDF of its own made to fail rule 1.3.1-1. When the folder or a module's jar is missing, or the probe passes because the modules didn't load, a warning in the summary says so, and nothing from the profile is reported. When the profile a PDF needs is missing, the warning names the PDFs the checks didn't run on, and the others are checked; so it is with a profile without the rule the probe fails (veraPDF's 1.30 profiles have it), since the probe would pass it whether the modules loaded or not. veraPDF leaves other things unsaid that a warning says too: a `wcag-validation` of another version than veraPDF's, or two versions of a module in the folder; a run that ended without a report, with the exception veraPDF printed or the signal that stopped it; a PDF it left out of its report, as it does one it can't open by its name (a name outside ASCII where the locale isn't UTF-8, say); and an error it printed as it went, as its contrast check does when PDFBox can't draw a page, which may have left some checks undone. With nothing to check, `check-output.py --wcag` runs the probe alone, which checks the setup, and says which PDFs the checks run on: a PDF 2.0 file, a PDF 1.x file, or both, as the folder has their profiles; `convert.py --wcag` in a run that made no PDF says so, and `--quick` leaves the profile out with the other validators, saying so.
