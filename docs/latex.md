# LaTeX sources

A LaTeX book is read through its master file, the one with `\documentclass` and `\begin{document}`, and every target makes its output from it as from any other source; a book that is a set of documents, each built on its own, is read through each of them. Tested on the suite's own book, on Joseph Fields's [*A Gentle Introduction to the Art of Mathematics*](https://github.com/osj1961/giam) (GIAM), a book of nine chapters that is the test case for this work, on a set of calculus note templates in one file, already tagged by its author, which has to keep converting cleanly as the rest grows, on the notes for a financial planning course (FINC 308), 18 documents, one a topic, and on [*OpenIntro Statistics*](https://github.com/OpenIntroStat/openintro-statistics), a book its authors built their own way, macros, environments, and all.

**LaTeX as a source is new, and needs more testing.** Every path from it is rated NEEDS MORE TESTING on [the formats page](formats.md#at-a-glance): each of the books above turned up something the others hadn't, from the numbers its references print to a bibliography that never reached the pages, and more books will turn up more. Check a book's pages against its own PDF before relying on them.

There are two ways to an accessible PDF of a LaTeX book, and a book can take either:

- **From the book's own LaTeX** ([The PDF target](#the-pdf-target)): a copy of the author's files made to build with LaTeX's own tagging, as a `source` target with `tagging: "on"` writes it, and built with LuaLaTeX. The PDF is the author's book, its layout, index, and bibliography; the copy is a version of the author's files that the author can keep building. This is the default.
- **From the converted pages** (`pdf.from: pages`): Pandoc's LaTeX writer makes a new LaTeX book of the pages, as for any source, and LaTeX builds that. The layout is the pipeline's, not the author's, and the index is lost ([What is lost](#what-is-lost)), but it builds whatever the author's LaTeX does, and it can claim PDF/UA-1 as well.

## How a book is read

The master is the `.tex` file in the book's directory that is a whole document. When there's more than one, as when one set of chapters makes a textbook, a workbook, and a solutions manual, `latex.main` names the book's (GIAM's is `GIAM.tex`), and the run stops and says so until it does.

A document that `\include`s nothing is one page, named after its file; its sections can be split into pages of their own ([Splitting pages](splitting.md)). A division command after its first words (FINC 308's `\appendix` before a topic's last practice set) doesn't make the whole page an appendix, and the reader drops it, so the sections after it aren't lettered; one the document opens with gives the page its role.

**A book of documents each built on its own**, as a course's notes often are, a document a topic, names them all in `latex.main`, as a list, a path (below the book's directory if they're in a folder), or a pattern (`src/*.tex`, in sorted order):

```yaml
defaults:
  latex:
    main:
      - "src/Topic 01 Introduction to Financial Planning and the CFP Profession.tex"
      - "src/Topic 01 Supplement CFP Board Code of Ethics and Standards of Conduct.tex"
      - "src/Topic 02 CFP Financial Planning Process.tex"
```

Each is read on its own, with its own preamble, and is a page (or a page for each file it `\include`s), in the order the list gives, which is the order of `contents-sample.yaml`. Two documents that `\include` the same file would make it a page twice, so the run stops and names them. A document is built from its own folder, as its author builds it there. A master that only gathers documents' PDFs with `\includepdf` (FINC 308's "Combined" file, a section and a PDF per topic) has nothing of its own to convert: when it's the only master, or the one `latex.main` names, the run stops and prints the `latex.main` list to paste, the whole documents named as its PDFs are, anywhere in the book's directory, in its order, and names the PDFs with no LaTeX beside them. With no master in the book's directory at all, a run that finds whole documents in a folder below says where they are.

Pandoc reads the whole book through the master, following `\include` and `\input` from the book's directory, so the preamble's macros apply everywhere, a `\ref` gets the number LaTeX would give it, and a reference into another chapter resolves. The result is cut into pages where each `\include`-d file begins, each page named after its file (`\include{intro/intro}` is `intro`), as every other source's pages are. What the master holds itself before its first `\include` (a copyright page, acknowledgments) is a page named after the master. What it holds between its `\include`s goes on with the page before (OpenIntro's review exercises, `\input` after each chapter), until a part or a chapter the master sets itself, which begins a page of its own, named for the master and numbered (`book-1`), with the role the division commands before it give it, its bibliography's heading among them: a `\part` set between two `\include`s had ended the chapter before and titled its page. A `\ref` whose label is on another page links to that page.

A heading inside a box or another environment the reader keeps as a division (OpenIntro sets each chapter's title in a framed box, its `chapterpage`, mdframed in a minipage) is taken out to the page's own level, the box's text after it, since a page's title and its sections are found only there: every one of OpenIntro's chapter pages was titled with its file's name (`ch_intro_to_data`), its EPUB chapter was cut before the heading into a part of its own, and its sections were out of the chapter's nesting in the EPUB's contents. One taken out of a passage in another language (babel's `otherlanguage`) keeps the language, and one in a theorem or a proof (an example's `\paragraph{Solution.}`) stays where it is. A file that continues a chapter, its headings all below the top level, as OpenIntro's t-table and chi-square table each add a section to its distribution tables' chapter, has them raised until its first is the page's H1 and title, which it otherwise lacks. A page's title holds a formula in its heading as text (`Tables of t`), since a title, an entry in the contents, and a cartridge's name for a page hold no MathML, and Pandoc writes a formula there as its TeX. And a file `\include`-d inside an environment, as the appendix package's `appendices` holds the appendices, is a page of its own, an appendix, its chapters lettered: the reader kept the environment as a division with the cut's marker inside, so the file ran on in the page before, the marker shown as text.

A chapter can be `\include`-d by a macro of the book's own, as OpenIntro's `\includechapter{1}{ch_intro_to_data}` `\include`-s `ch_intro_to_data/TeX/ch_intro_to_data` and `\input`-s its review exercises after it: the macro is found wherever the book defines it, a style file the preamble reads after the master calls it included, and each call is followed, and written out in the copy, so the page begins where the chapter does. A file the master `\include`-s that has nothing to read, definitions or an index the pages don't have (OpenIntro's `headers.tex`), is no page, and the run names it. An unnumbered heading with nothing in it, which a book sets to start a page (`\chapter*{}`), is left out, and a page with no heading after that (OpenIntro's copyright page) is titled by its file's name as words, `copyright` as "Copyright", or by the title `project.yaml`'s contents give it, its title and its H1, and the run says which; the HTML's title had been the bare name. So is a page with several headings at its top level and none to be its title, as a document's sections are when it has no `\title` (the calculus notes' 22), unless the document gives hyperref a PDF title (`pdftitle`), which titles it then, its LaTeX the characters it makes (`\&` as &, `\"i` as ï). A page whose one numbered chapter comes first, a `\chapter*` after it (the chapter's exercises), is titled by the chapter. A bibliography's heading, which an article's page gets beside its own (References), isn't counted against the page's title.

With no `contents` declared, the run writes `contents-sample.yaml`: the pages in the master's order, each with the role `\frontmatter`, `\appendix`, or `\backmatter` before it gives it, each part's pages grouped under it, the part's own page first, as the EPUB's contents and the cartridge's modules then nest them, and the title, authors, and language the preamble declares (babel's or polyglossia's main language, or `\DocumentMetadata`'s `lang`). Copy it into `project.yaml` to use it. An `\author` that sets each name's affiliation on lines beneath it, set apart from the name (`David Diez \\ \small\emph{Data Scientist} \\[6mm] Mine \c{C}etinkaya-Rundel ...`, as OpenIntro's does, with no `\and` between the authors), gives the names alone; with every line set alike, each line is given, an affiliation as a name, so that no author is left out of a list a person checks.

A `README.md` beside the master is the repository's, not a page, and so are a `LICENSE.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, `CODE_OF_CONDUCT.md`, and `SECURITY.md`.

**A brace the book never closes** stops Pandoc's reader at the end of the book ("unexpected end of input"), so when the reader stops, the run looks for one and names its file and line: OpenIntro's `style.tex` opens a group on line 346 that nothing closes. LaTeX 2026-06-01 can't build such a book either, if the brace is in the preamble: it stops at `\begin{document}` with "Loading a class or package in a group". Match it in the book's file, or a copy of it, and run again.

## What is put right before reading

Pandoc's LaTeX reader (3.12) can't take some of what plain LaTeX books do, so the book is copied and the copy put right; the author's files are never written. Each of these was read in Pandoc's source and measured, and is described in `PANDOC-NOTES.md` in the repository, "The LaTeX reader":

- **ifthen's booleans** (`\newboolean`, `\setboolean`, `\ifthenelse{\boolean{...}}`) become etoolbox's toggles, which the reader evaluates. It drops `\ifthenelse`, both branches with it ([jgm/pandoc#11008](https://github.com/jgm/pandoc/issues/11008)). An `\ifthenelse` with any other condition is still dropped, and the run counts them.
- **`\input file`**, TeX's own form without braces, is braced. The reader stops on it.
- **`\centerline`** is read as a center environment. The reader takes its argument as inline text and stops on a table inside it.
- **`\cline{2-3}` and `\cmidrule{2-3}`** become whole rules. The reader leaves their column range in the next cell as text.
- **A table's header declaration for LaTeX's tagging**, `\tagpdfsetup{table/header-rows={1}}` or `table/header-columns={1}` (or both) just before the table, is the table's declaration here too, as a `table-headers.csv` row or a Markdown marker would be; the reader drops `\tagpdfsetup`. A declaration naming more than the first row or column is counted and left for `table-headers.csv`.
- **An image named without its extension** is resolved the way graphicx resolves it (`.pdf`, then `.png`, `.jpg`, and the rest, then `.eps`), in the book's directory and `\graphicspath`. The reader looks in the copy, where it isn't. A name that differs from its file only in case is that file, as macOS and Windows find it, where the book was likely built: OpenIntro's solutions name `GRE_intro.pdf`, and the file is `gre_intro.pdf`. LaTeX on Linux doesn't find it, so the run counts each.
- **An image behind one of the book's own macros**, a macro whose body holds one `\includegraphics` with its file made from an argument (`\newcommand{\fig}[2]{\includegraphics[width=#2]{#1}}`, or `\def` with plain arguments), is written out at each call, the body with the call's arguments, as the reader expands it, so its file is resolved as above. Otherwise the reader would find an image named without its extension, which the run stops on. The file's name can be made of several arguments, and of a macro without arguments, which is written as its value at the call, as the book defines it there: OpenIntro's `\Figures[...]{0.46}{county_pop_transformed}{county_pop_transformed_i}` is `\chapterfolder/figures/#3/#4`, `\chapterfolder` set with `\renewcommand` at each chapter's start. A call inside another definition and a body that also holds a table or a drawing are left to the reader.
- **An environment the book defines** with `\newenvironment` is written as the commands LaTeX makes of it, `\var` for its opening code and `\endvar` for its closing, and `\begin{var}` and `\end{var}` as them. LaTeX lets a book call the opening command alone, as OpenIntro calls `\var{height}`, `\resp`, `\data`, and `\eoce` about 1,700 times. The reader puts a group around the codes and stops where that group meets the book's own: after the command called alone, since nothing closes it, and at `{\raggedright\begin{parts}...\end{parts}}`, an environment holding a list in braces after another command. One defined in another environment's codes, and one of LaTeX's own that the book redefines with `\renewenvironment` (`enumerate`), are left to the reader, since the commands would hold from the start of the book.
- **`\begingroup` and the `\endgroup` that closes it** are braces, the opening one after an italic correction, `\/`, which the reader reads as nothing: the next item says why. The reader takes `\endgroup` for a closing brace but `\begingroup` for a group only at a group's start or in a paragraph, so `{\Large \begingroup ... \par \endgroup}`, OpenIntro's chapter openings, stopped it. A `\begingroup` one macro opens and another closes is left, and so is one in a formula, which is a brace after the reading, as texmath reads it (it stops on `\begingroup`, and on `\bgroup`); in the PDF from the pages, that makes a group of what it held.
- **A group, or a number, after a command the reader takes whole.** The reader takes every braced group after a command it doesn't know, or knows only to skip, as that command's arguments, and drops them; and a number right after one as its dimension. LaTeX takes only the command's own. So `\hspace{2mm}{\small#1}` lost the group, which in OpenIntro's `\eocesol` is an exercise's whole solution, and `{\fontfamily{phv}\selectfont 1.1}` lost its number: its appendix of solutions came out with neither. GIAM lost its defined terms the same way, `\index{conjunction}{\em conjunction}` ("The of two sentences is..."), and its exercises' headings, `\noindent{\large \bf Exercises --- \thesection\ }`: 181 words in all. After `\hspace`, `\vspace`, `\noindent`, `\centering`, `\selectfont`, `\hypersetup`, `\color`, `\setlength`, `\index`, `\makebox`, `\raisebox`, and about fifty others, each measured, with each one's arguments as LaTeX takes them, the copy puts `\/` before such a group or number, outside formulas, since texmath doesn't read `\/`.
- **A box** the reader drops with all it holds, `\fbox`, `\framebox`, `\makebox`, `\raisebox`, `\smash`, `\fcolorbox`, `\scalebox`, `\resizebox`, `\rotatebox`, fancybox's frames, `\boxed` and `\text` in running text, and `\adjustbox` (each measured), is read as a group of what it holds; the box, a frame or a size, is the page's layout. A table a book sets in `\resizebox{\textwidth}{!}{...}` to fit the page was lost whole, and OpenIntro's solutions keep the label for each exercise without one in a `\makebox` of no width.
- **LaTeX's counters.** A label or reference whose key LaTeX makes of its counters, as OpenIntro links each exercise and its solution (`\label{eoce_\arabic{chapter}_\arabic{eoce}}`), is LaTeX's work at the moment it gets there, which the reader doesn't do: it keeps the key as written, every exercise's the same, and drops `\arabic{eocesolch}` and `\thesection` in the text. The copy marks where the book steps, sets, and shows a counter (`\refstepcounter`, `\stepcounter`, `\setcounter` and `\addtocounter` with a number, a macro's argument, or `\value`, the division commands, and `\arabic` and its kin and `\thesection` and its kin), through the book's macros as the reader expands them; after the reading, the marks are counted in the document's order, as LaTeX counts, a numbered heading stepping its counter, and each such key and counter is written as LaTeX would have it, by the book's `\newcounter{eoce}[chapter]` and `\renewcommand{\theeoce}{...}` and the standard classes' own. A reference to a label in running text, which the reader shows as `[key]`, gets the number LaTeX gives it, the value the last `\refstepcounter` or numbered heading set; one to a label in a list item or a footnote is left, since those count with counters of their own here.
- **The number a `\ref` prints.** The reader numbers what a `\ref` names itself, and not as LaTeX does: a numbered `\chapter` in the front matter counted, so every chapter after it was one more; `\appendix` didn't letter; each `\part` started the chapters again, and a reference to a part was empty; a figure or a table without a label didn't count, so each after it in its chapter was one less; a subfigure counted as a figure; and a theorem was numbered within its chapter whatever the book said, so GIAM's Theorem 1.4.1 (`\newtheorem{thm}{Theorem}[section]`) was Theorem 1.1, in its title and in each reference to it. The counting above counts these too, as LaTeX does: headings to the depth `secnumdepth` gives (a `\label` after the book class's subsubsection records its subsection's number), a figure or a table with a caption (`\caption*` numbers nothing), a subfigure by its figure's number and a letter, `1.3a` (`1.3(a)` with the obsolete subfigure package), a float in the front matter without a chapter's number, a section in the front or back matter numbered as the book class numbers it (`0.1` before the first chapter), and a theorem with the counter `\newtheorem` gives it, within a section or shared with another, and with none for `\newtheorem*`'s, which the reader numbers; and every reference gets LaTeX's number, each theorem's title too. A class's own numbers count, as measured with LaTeX 2026-06-01: memoir numbers to the section (or the depth `\setsecnumdepth` gives) and nothing in the front or back matter; amsbook numbers sections, figures, tables, and equations without the chapter's number; and KOMA's scrbook and amsbook number a section in the front or back matter from 1 again at each chapter, scrbook a figure, a table, and an equation there without the chapter's number (`Figure 1`). A reference to a label LaTeX numbers nothing for, a chapter's in the front matter, is the chapter's title, where LaTeX prints nothing.
- **A display formula LaTeX numbers** (`equation`, `align`, `gather`, `multline`, `alignat`, `flalign`, `eqnarray`, and breqn's `dmath`, not starred) is numbered as LaTeX numbers it, in the same count: a row at a time where the environment numbers each, `\nonumber` and `\notag` skipped, a `\tag` as given, a last `\\` making a row of its own as it does in LaTeX, and `subequations`' rows by letter, `2.4a`. The reader keeps the formula's TeX, environment and all, and texmath leaves its `\label`, `\tag`, and `\nonumber` out of the MathML, so a formula had no number and a reference to it read `[eq:energy]`. Now each label is an anchor before the formula, each number is set beside it, a row's under the row before's, at the right of the page as the page's stylesheet sets it, and a reference has the number, `\eqref`'s in parentheses, `(2.1)`; a reference inside a formula (`\text{by \eqref{eq:def}}`, which texmath stopped on) is the number as text. Every environment `subequations` holds is numbered, and a label anywhere in it outside them is the whole system's; a display formula with a `\tag` (`\[ x \tag{$\ast$} \]`) shows its tag; and breqn's `dmath`, whose environment the reader drops, is marked in the copy and numbered once. A Word file sets the formula as a display formula of its own, its number on the line after it, and a PDF from the pages has LaTeX set the same numbers, each written into its row as a `\tag`, the formula's labels kept for a reference inside another formula. An `eqnarray` takes no `\tag` ("\tag not allowed here"), so the PDF sets LaTeX's count before it, with the number's form (`2.\arabic{equation}`), and puts the form back after.
- **`\autoref` and cleveref's references** (`\cref`, `\Cref`, `\crefrange`, `\namecref`, `\labelcref`) print a name before the number, which the reader left out; it read `\cref{a,b}` as one link to a label named `a,b`, and dropped `\crefrange` and `\namecref`, text and all. Each is written as LaTeX prints it, measured with LaTeX 2026-06-01: hyperref's names in the link (`Figure 1.2`, `section 1.1`, `Appendix A`), and cleveref's before it (`fig. 1.2`, `Equation (1.1)`), several labels grouped by type, a run of three or more a range (`figs. 1.2 to 1.5`), each number its own link; the book's own names (`\crefname`, `\Crefname`, `\renewcommand{\sectionautorefname}`) and cleveref's `capitalise` and `noabbrev` count. hyperref names a theorem by its environment, not a counter it shares (`\newtheorem{lemma}[theorem]{Lemma}` with `\lemmaautorefname` gives Lemma 2), and one it has no name for by none. A label of a type cleveref has no name for, which LaTeX prints as ??, has its number alone.
- **titlesec's settings**, `\titleformat` (and its starred form, with only two arguments), `\titlespacing`, and `\titlelabel`, are left out with their arguments, which say how a heading looks. The reader stops on a `\titleformat` whose arguments are on lines of their own, and prints a `\titlespacing`'s.
- **A color the book defines** with `\definecolor` (a `[named]` one too), `\providecolor`, or `\colorlet` is written as CSS, `rgb(86, 155, 189)`, where the reader made a span of a `\textcolor` or `\colorbox` in it (or a division, for paragraphs), after the reading; the reader drops `\color`. The reader writes the name as the span's CSS color, and a name only the book defines isn't one: the Nu checker found 785 on OpenIntro's pages. The definitions are read in LaTeX's order, the last of a name's winning, as OpenIntro's `main.tex` would set its blue to black after the file of colors it `\include`s; one in a macro's body defines nothing, `\providecolor` changes no color already defined, and `\colorlet` takes the color as it is then. A mix, as xcolor reads one (`red!30` with white, `red!70!black`, a chain of them, `-red` the complement), is CSS too, and so is a name of xcolor's own or of its `dvipsnames` that CSS lacks (`BrickRed`), and a mix with a color of `svgnames` or `x11names`, when the book loads them (`NavyBlue!50`), from the installed xcolor's own files (`svgnam.def` and `x11nam.def`, found with `kpsewhich`), the last set the book loads winning a name two sets have, as xcolor loads them in the order its options are given; each with xcolor's value; a name CSS has (`red`, `Orchid`) is left as it is, with CSS's value, and a color none of these is is taken out, since a browser would ignore it. A color given in a model (`\textcolor[rgb]{.5,.5,.5}`), whose model the reader drops, is written as CSS in the copy, but not in a formula, a drawing, or a definition, all of which LaTeX may read, and which get the color as the book wrote it. Whether a color has the contrast WCAG asks for against the page isn't checked.
- **`\nameref`**, hyperref's reference by a section's title, is a link to the label, on whichever page that is, its text what LaTeX prints: a figure's or a table's caption for its label, a heading's title for a label in or after the heading (`\section{Data basics\label{sec:data}}` too), and otherwise the title of the section the label is in. The reader drops it, text and all; OpenIntro's data appendix titles its sections with it, and a `\nameref` to such a heading gets the title the heading's own gives it.
- **`\subfigure`**, from the obsolete subfigure package, and subfig's `\subfloat` are subcaption's subfigure environment, which the reader makes a figure of its own, so its label is an id and a reference to it goes there (25 in OpenIntro). The reader drops the command, its caption, and the label in it, and what a `\subfloat` holds. In a table float, it's a subtable, numbered by the table's number and a letter (`1.1a`), as subcaption's `subtable` is.
- **A caption the reader drops**, and the figure or table with it: the caption package's `\captionof{figure}{...}`, a caption outside a float, is the caption of a figure or a table around the box it's in (a minipage, a center), or around its paragraph, which begins after a blank line, an environment's edge, `\par`, an `\item`, or a heading and the label after it, two in one box each a figure of its own; an environment that ends a paragraph (a tabular, a center) right before it, nothing but space between, is what it captions, and one in a macro's definition is read as the macro sets it where it's used; wrapfig's `wrapfigure` and `wraptable`, whose arguments the reader also showed as text ("r 0.4"), are a figure and a table, set in the column where the text wrapped around them. A table float the reader can't take as one table is a figure numbered as the table it is: one holding no table (an image of one, a box), whose caption the reader keeps only for a table; one holding two tables, each of which the reader gave the caption and the label; and one holding subtables, whose captions gave way to the float's. A float holding two captions of its own, two figures side by side in minipages, say, is a float for each, as LaTeX numbers them, where the reader made one of them with the last caption and label: each in a minipage, a `\parbox`, or one of floatrow's boxes (`\ffigbox`, `\ttabbox`, `\fcapside`), minipages a tabular lays out in a row and nothing else, or the float cut after each caption, a center or a flush environment around them ended and begun again there, unless nothing is left in it. subcaption's `\subcaptionbox` is a subfigure, with its caption and label, and a float's own caption above its subfigures or subtables is still the float's, which the reader gave the last one's place. A table float whose only caption is a `\caption*` note is a figure, as one with no table is, and one whose table an environment of the book's own makes is left a table. A label inside a caption (`\caption{A\label{a}}`), whose name the reader gives the float and an empty span in the caption both, is the float's alone; and a table in a table's cell no longer takes its container's id, so a reference to the table goes to it (in a PDF from the pages, it went nowhere: GIAM's rules of inference).
- **An environment's arguments the reader prints as text**: one of a package the reader doesn't know, multicols's (`\begin{multicols}{2}`, its column count a 2 before the columns' text), setspace's `spacing`, changepage's `adjustwidth`, KOMA's `addmargin`, paracol's, and a few more, is begun without them, and multicols's preface (`[\section{...}]`) is set before the columns, as LaTeX sets it.
- **A bibliography and its citations.** The reader drops `\bibliography`, runs a `thebibliography`'s entries together in one paragraph, their labels and some of their text lost, and keeps a `\cite` as a citation no writer but LaTeX's prints, so GIAM's 16 were empty on the pages ("a finite projective plane of order 10[10]" read "order 10"). BibTeX, run on the book's citations with its own `\bibliographystyle` and databases, makes the `.bbl` LaTeX would read, its lines broken at 79 characters as TeX Live's and MiKTeX's BibTeX breaks them by default, which decides whether a URL after a comment in a database is printed (GIAM's Wikipedia entries'). The bibliography is written out where `\bibliography` stands, under the heading LaTeX gives it (Bibliography in a book, References in an article), a page of its own after the master's last `\include`: each entry with its label, `[1]` or the style's own (alpha's `[Str87]`), and each citation as LaTeX prints it, linked to its entry, its note after it (`[1, 2, p. 3]`). natbib's citations are as natbib prints them, its own code for them followed step by step, and checked, with the cite package's and LaTeX's own, against LaTeX 2026-06-01's output on 49 setups: its defaults, round brackets and semicolons, its preset for the book's style (plainnat's square brackets and commas), which applies only when no option, `\bibpunct`, `\setcitestyle`, or `\citestyle` has set anything before `\begin{document}`, so `[round]` with plainnat separates by semicolons, and one of them in the text sets them from where it stands; author and year from the entries' labels (`Knuth [1984]`, `[Knuth, 1984, Lamport, 1994]`), an author cited again in a row named once and a year again given its letter alone (`[Knuth, 1984, 1986a,b]`), or `?` when it has none, as natbib prints it, the long names for a starred command, every name capitalized by `\Citet` and the rest, and `\cite` as `\citet`, or as `\citep` with a note; numbers for `numbers` or a numeric style, sorted and compressed when the book asks (`[1–3]`), with the author for `\citet` (`Knuth [1]`), a name as the entry gives it and a year without its letter, which natbib prints only with author and year (in the bibliography too); superscripts for `super`, set against the word before them, as natbib takes away the space, a tie, or a line's end there, and `\citeyearpar` printed as `\citeyear`; and labels natbib reads besides `Name(Year)`, `\citeauthoryear`'s, `\harvarditem`'s, and apalike's. Every command is sorted when the book asks, `\citeauthor` and `\citeyear` too. LaTeX's own `\cite` with the cite package is sorted and compressed too, unless its `nosort` or `nocompress` says not, and without natbib a label of author and year is printed as it is (`[Knuth, 1984]`). A year's letter (natbib's `\natexlab`) and a DOI (`\doi`, linked) in an entry are written as the style's `.bbl` defines them. A key with no entry is ?, as LaTeX prints it, and the run names it; with natbib, where natbib prints it, which with numbers is without the separator before it (`[1?, 3]`), and with author and year without the one after it (`[?Knuth, 1984]`). A `thebibliography` the book writes itself is read the same way, and a call of a macro of the book's own that cites (`\newcommand{\see}[1]{see \cite{#1}}`) is written out first, so its citation is BibTeX's too, in LaTeX's order. A database or a style of the book's own named with a folder (`\bibliography{../refs}`, from a master in `src/`) is found from the master's folder, as LaTeX's build finds it; when BibTeX fails, the run says why, and a `.bbl` it writes despite an error (a repeated entry, which it skips) is read, as LaTeX's build reads it, the error given. Without BibTeX, the `.bbl` a build of the book left is read; without either, and for a book under biblatex, Pandoc's citeproc makes the citations and the bibliography from the book's databases, in Pandoc's own style (author and date), not the book's, and the run says so. biblatex's `\fullcite` and `\footfullcite`, which the reader drops with their keys (OpenIntro gives the source of each of its data sets so, 111 times), are written out as the entry in full, from BibTeX's `.bbl` in plain's style, which is close to biblatex's standard one: a footnote's ended with a period, as biblatex ends one, several entries joined by semicolons, a page's number after them as `p. 5`, a title as the database gives it, without plain's change of its case, and a macro of the book's own in a database (OpenIntro's `\oiRedirect`, a link) made as the book makes it, since the entry is read with the book's macros. Without BibTeX, each is a citation for citeproc.
- **A label's key** with whitespace in it (`\label{US Airports}`), or the `{}` that ends a macro in it (`\label{edwardSatBelow\edwardsat{}}`), is written without, in the id it becomes and each link to it, after the reading, so that a reference through the book's own macro (`\secref{US Airports}` for `Section~\ref{#1}`) has been matched to its label, as LaTeX matches it; an empty label is no id.
- **A PDF or EPS image**, which no browser shows, is made an SVG of its first page with `pdftocairo` (EPS through `epstopdf` first).
- **A drawing**, a `picture`, `tikzpicture`, or `pspicture` environment, which the reader drops whole, is rendered by LaTeX with the book's own preamble and made an SVG; the copy includes the SVG in its place, so a figure keeps its caption and label. A run of drawings with nothing between them but comments and a `\setlength{\unitlength}`, which is what fig2dev's `pstex_t` output is, makes one image. The engine is pdfLaTeX unless the preamble needs LuaLaTeX (fontspec, unicode-math, polyglossia, `\DocumentMetadata`). A `tikzpicture` drawn as an `overlay`, a rule down every page from `\AddToShipoutPictureBG` say, belongs to the page and not the text, and is left alone.
- **The `artifact` key** on `\includegraphics` makes the image decorative, as latex-lab does; the reader ignores the key.
- **A title set as large type**, as a document without `\title` often sets one: the brace group in a `center` (or `titlepage`) environment that opens the body, set larger than any other group there and at `\large` or more (`{\LARGE Topic 1: ...}` under `{\large FINC 308: ...}`), is read as the page's title, and the document's sections go under it, a level down. What the environment holds besides it, the course's name, stays where it was. The reader would take the title for a paragraph and the sections for the page's top level, and the page would be titled by its file name.
- **A box**, a `tabular` of one paragraph column (`p`, `m`, `b`, or `X`) with a cell of a dozen words or more, as an author frames an example between rules, is read as a box around its rows' paragraphs, a `<div class="box">` in HTML: a passage, not a table of one column, which a screen reader would announce as a table. A table in a box is a table of its own. FINC 308 has 28.
- **A column type the book defines** with array's `\newcolumntype` (`R{2.3in}`, a right-aligned paragraph column) is written out where a table uses it, its arguments in place, and the definition taken out. The reader doesn't know it and takes the table's column specification as text, so the table falls apart, and it stops on a definition in the body.
- **A `\ref` to a label on an enumerated item** is written as the number LaTeX gives the item: `1b` for the second item of a list in the first item of another, as article's `\theenumi` and `\p@enumii` make it, `(b)` for a list enumitem labels `(\alph*)`, and a `start` or `resume` counted in. The reader can't resolve one and writes the label's name in brackets, `[Topic2Q1]`, where FINC 308's answer keys (70 references) have `1b 2b 3b`.
- **Alt text** in an `alt` key is read as LaTeX (`50\%` is "50%"); the reader keeps it as typed. An image without one is reported in `image-alt-missing.csv` like any other; the reader would describe it as "image".
- **Formulas** texmath can't read, which then appear as their TeX: a size command in text inside math (`\mbox{\tiny noneg}`), a text command inside `\mbox` (`\mbox{\textsf R}`, `\mbox{{\bf c}}`), a length in millimeters (`\hspace{40mm}`; texmath knows em, pt, in, and cm), a length set inside a formula (`\setlength\tabcolsep` in an `array`), and a rule with no width (a strut) or no height (a space) are written as texmath reads them. A rule that shows is left when it's tall, since it draws something only a person can name (see the next section); a flat one, no taller than a point, is a blank to fill in and becomes an underlined space. An `\hspace` inside an `\mbox` moves out of it, and `\raisebox` is dropped, since a raised box is the same symbol. A text command inside `\text` comes out of it, `\text{rolling a \texttt{1}}` as `\text{rolling a }\texttt{1}`, an `\underline` and a color in it too; space inside a text command's argument is a space, or nothing in a name (OpenIntro's `\texttt{income\_\hspace{0.03cm}{}ver}`); `\textcolor` is `\color`, which texmath reads and whose color, like `\color`'s, MathML doesn't keep; `\hfill` is a quad; `\MakeLowercase`, which keeps a formula lowercase in a heading set in capitals, is what it holds, and `\copyright` its sign; and `\vspace` and `\index` go. On OpenIntro, each of the 83 distinct formulas texmath stopped on is read. The book's macros a formula uses, and those their bodies use, are left as the book defines them by the repairs for text above, since texmath reads them there.
- **A rule outside a formula** with no height is a space and with no width nothing; the reader takes any rule with a width for a line across the page.
- **What Pandoc's own LaTeX writer adds**, so the `latex` target's output, or any LaTeX Pandoc wrote, reads back: an image inside `\pandocbounded` is unwrapped; a `longtable`'s head is read once, not again as a row for its copy repeated on later pages, and declared as the table's header row when it's one row; a header declaration before Pandoc's `{\def\LTcaptype{none}` group around a table counts; `@{...}` comes out of a `\multicolumn`'s spec, which lost the whole table; a cell's lines stacked in `\vtop` or broken with `\\` in a minipage are read as lines, not dropped or taken for the row's end; the PDF target's own link commands are dropped; a head-only table's empty body row is dropped; and a table in a table's cell doesn't take its container's caption, which the reader gives it, in a book written by hand too.

The rendered images go in `rendered/` in the book's directory, at the path of the file they came from (`figures/Venn.tex` is `rendered/figures/Venn.svg`; a drawing in a chapter is `rendered/sets/sets-3.svg`). `rendered/.rendered.json` records what each was made from, so an unchanged drawing isn't made again. An image's alt text comes from `image-alt.csv` by that path, like any image's.

Drawings and PDF images need a LaTeX engine and `pdftocairo` (`sudo apt install poppler-utils`). Without them the run says so, and they're left out of the pages. When LaTeX can't make one drawing, the others are made one at a time, so it costs only itself.

## A book with a build of its own

Some books make part of their LaTeX with another program first: GIAM draws its figures in xfig, and its Makefile has fig2dev write each as a `.tex` file and a PDF. The conversion reads LaTeX, so that build runs first, and what it makes is the conversion's input. When the master reaches a file that isn't there, the run stops before converting anything, names the files, and points at any `Makefile` beside the master or the missing files.

## What the book's macros mean: `latex-conversion-macros.tex`

The book's own definitions are always read, a file of them it `\input`-s included (GIAM's `my_latex_definitions.tex`), and this file is read after the whole preamble, so what it defines wins. It works as a sidecar for macros. Some macros draw what they mean. GIAM's "such that" is a bar drawn with `\rule`, and so is its restriction of a function to a set, and its blank to fill in is three rules. Read as written, each is a formula texmath can't read, or one a screen reader reads as nothing. Only a person can say what each means, once, in `latex-conversion-macros.tex` beside the master: LaTeX definitions read after the book's own preamble. The book's own files never change; a `source` target writes the definitions into its copy, after the copy's preamble, so the book's PDF says what the pages say (`latex_definitions: "off"` keeps them to the conversion, for a file that only helps Pandoc read). GIAM's:

```latex
% "Such that", drawn as a bar with \rule.
\renewcommand{\suchthat}{\mid}
% A function restricted to a set, drawn as a bar with \rule.
\renewcommand{\restrict}[2]{#1|_{#2}}
% A blank to fill in, drawn as three rules.
\renewcommand{\blnk}{\underline{\quad}}
```

The file's name is the `latex.macros` setting.

**The run writes a starting point**, `latex-conversion-macros-sample.tex`, whenever any of the book's macros (defined with `\newcommand` and its kin, and used in a formula) still gives a formula texmath can't make MathML of, once the repairs above and the definitions file are applied. Each is listed with how often formulas use it and the book's own definition. Where its drawing has one reading, the sample suggests a definition, kept only if texmath then reads it: a thin tall rule is a vertical bar (`\mid` when only spacing surrounds it, so GIAM's `\suchthat`), and flat rules with nothing but ticks and spacing beside them are a blank to fill in (`\underline{\quad}`). The rest are left as a commented-out `\renewcommand` for a person to fill in, as GIAM's `\nrelR`, an R struck through with a raised `\not`, is. A macro the book defines in its text, where a section uses it (OpenIntro sets `\actmean` to 21 there), is tried with its definition. Each macro is shown as the book defines it, not as the copy the reader reads has it, and the commands the copy makes of the book's environments aren't listed, since they aren't the book's. Check the sample, then save it as `latex-conversion-macros.tex` or merge it into yours; it's never read as it stands. With nothing left to list, a stale sample is removed.

**Alt text an author wrote for another build.** The sample also lists each of the book's macros for an image that takes an argument it never uses, which at least half its calls give a phrase in, as alt text might be, with a definition, every line of it commented out, that passes the argument on as the image's `alt` key. OpenIntro's `\Figure[alt text]{width}{name}` and its three kin take the description first and drop it; only the book's screen-reader build (`style_simple.tex`) passes it on, to `\pdftooltip`. Only a person can say that the phrase is alt text, so the definition is a person's to adopt. Adopted, OpenIntro's:

```latex
\renewcommand{\Figure}[3][]{\includegraphics[alt={#1},width=#2\textwidth]{\chapterfolder/figures/#3/#3}}
```

gives all but 8 of the 322 images behind its macros the authors' descriptions on the pages, and, since a `source` target writes the definitions into its copy, in the PDF the copy builds. A decision in `image-alt.csv` for an image behind such a macro goes into that argument at the call. A call that gives none leaves its image without alt text, and reported, as before.

## The source target

`format: source` writes the book's own `.tex` files back, every one the master reaches, at the same paths under the target's folder, so the folder can be laid over the author's tree. The book's other masters beside it go in too, each with the files only it reaches, as GIAM's workbook and solutions manual do with their exercise files; a file the main master reaches is as its copy has it. What it writes into them is only what a person decided, in the sidecars and in `latex-conversion-macros.tex`, at the element each decision was made about, and the rest is as the author wrote it, comments and all: alt text, the definitions file (below), and, in a tagged copy, table headers. **Alt text:** each image and drawing in the image-alt sidecar gets the `alt` key LaTeX's tagging reads, or `artifact` for `[decorative]`, beside the author's own keys (`\includegraphics[alt={A gray square},width=1cm]{sq}`, `\begin{picture}[alt={Two boxes}](40,20)`, `\begin{tikzpicture}[alt={...},scale=2]`). A drawing is found as the conversion named it (its file, and its place among the file's drawings), an image by the file graphicx would include; anything in a comment or verbatim text is left alone. fig2dev's pair of picture environments is one drawing: the first gets the alt text, and the second, which holds its labels, is marked `artifact` so it isn't a figure of its own. A `pspicture` has no such key; it's counted and left alone.

**An image behind one of the book's own macros**, found as the read finds it (above), gets its key at each call, set just before the call and set back just after it, so the macro stays as the author wrote it: `\setkeys{Gin}{alt={A gray square}}\fig{sq}{1cm}\setkeys{Gin}{alt={}}`. A group around the call would end what the call starts: a `\centering` in the macro before its paragraph ends, and the number its `\caption` gives a `\label` after it. `alt={}` is how LaTeX's tagging starts each image, with no description. A macro whose own `alt` key takes an argument (`alt={#3}`) gets the text in that argument instead, braced so a comma in it doesn't end the key. One that passes an argument to `\includegraphics` as keys (`\includegraphics[#1]{#2}`) gets `alt` among the keys the call gives, since a key there wins over one set before; a call that gives none gets them written in, when the macro's default is empty or has alt text of its own. The book's definitions are read in the order LaTeX reads them, each file where it's `\input`, so a later definition replaces an earlier one, and `\providecommand` defines only a name nothing has defined yet.

Some can't be written, and the run names each by the image's key, since its pages have the alt text and its PDF would have a placeholder:

- A call in an argument LaTeX writes to a file and reads back, or keeps to set elsewhere, where `\setkeys` stops the build (measured, with pdfLaTeX and LuaLaTeX): a caption, `\captionof`'s and `\subcaption`'s too, a heading, either one's short form, `\index`, `\thanks`, `\title`, `\author`, `\markboth`, `\markright`, and `\addcontentsline`'s entry.
- A macro that sets alt text or `artifact` of its own, which wins over a key set before it.
- A macro whose alt argument the body uses elsewhere too, as its caption, say, which a description there would change; and a decorative image behind a macro whose `alt` key takes an argument, which can't say `artifact`.
- An image the copy doesn't find at all, behind a macro that calls another, say, found by checking the images the pages show.

The keys don't change an untagged build. With TeX Live 2026, `pdflatex` builds a document using `alt`, `artifact`, and `\setkeys{Gin}` with no error or warning (TeX Live 2023's graphicx knows `alt` but stops at `artifact`), and with `\DocumentMetadata{tagging=on}` and LuaLaTeX each becomes its figure's `/Alt` in the PDF's structure and the artifact image isn't a figure at all (checked in the structure tree). On GIAM, with a placeholder description for each of its 102 images and drawings, 99 of its 154 files change, and the copy laid over the author's tree builds with the book's own `pdflatex GIAM` to the same 424 pages as the original.

**A file the book's build makes** can be written into, but building again writes over it: 93 of GIAM's drawings are in files fig2dev makes from xfig sources. A file beside a same-named `.fig` is counted as one, and the run says how many of its changes are in such files. Until the book's own build carries the alt text (an xfig comment it passes through, say), the copy is a version whose build is this one.

**`tagging: "on"`** makes the copy build with LaTeX's own tagging, for an accessible PDF. It's a change to the author's build, so it's off by default: a tagged book is built with LuaLaTeX, since pdfLaTeX keeps the structure in TeX's main memory and GIAM's run out of it. Each change was needed on GIAM and found with a document of a few lines, and each keeps the untagged build working:

- `\DocumentMetadata{lang=..., pdfstandard=ua-2, tagging=on}` first, when the book has none, its language the book's declared one or babel's or polyglossia's. First, not just before `\documentclass`, since a master can choose its class inside a conditional. A book's own `\DocumentMetadata` is kept, with `tagging=on` added when it lacks it (one that only sets the PDF's version builds untagged), and the language and standard when it names none.
- `luatex85`, loaded for LuaLaTeX just after `\DocumentMetadata`, when the book uses one of pdfTeX's own commands (`\pdfinfo`, `\pdfcatalog`, and the rest) or tests for pdfTeX by `\pdfoutput`, as GIAM's workbook and solutions manual do to choose their class options (`\ifx\pdfoutput\undefined`), and one of its chapters to choose `.eps` or `.pdf` figures. LuaTeX has neither: the commands stop the build, and the test took LuaLaTeX for LaTeX with dvips. The LaTeX team's package for such documents gives LuaTeX each of them, so the test takes the branch meant for pdfTeX and what's in that branch works (checked tagged, with `\pdfinfo` and `\pdfcatalog`: veraPDF passes, and the PDF has the author `\pdfinfo` gives). It's in TeX Live's `collection-luatex`; TinyTeX installs it with `tlmgr install luatex85`. pdfLaTeX doesn't load it.
- The `pdftex` option taken out of `\documentclass`, `\usepackage`, and `\RequirePackage`, and pdfTeX's own settings (`\pdfcompresslevel=9`) out of the text.
- A starred theorem the book defines beside its numbered one (`\newtheorem*{thm*}{Theorem}` with `\newtheorem{thm}`) defined only when it isn't yet: tagging's `\newtheorem{thm}` defines `thm*` too, and the second definition stops the build.
- `\centerline` on a line of its own made a centered paragraph, by a definition before `\begin{document}`; inside a paragraph it's as before. As an `\hbox` between paragraphs it put every later paragraph inside a P (53 of GIAM's warnings).
- `\leavevmode` before a display formula that opens a paragraph in a `center`, `flushleft`, or `flushright` environment: right after its `\begin`, or after a blank line, as in a paragraph column of a table there (FINC 308's boxes). In LaTeX 2026-06-01 such a formula leaves a paragraph open (`Text. \begin{center} \[ 1! = 1 \] \end{center} After.` is enough), and in a list item the items after it nest in it; in a table's cell it stops the build ("the number of automatic begin and end text para hooks differ").
- enumitem's settings that LaTeX's tagging can't take, let through. With tagging on, LaTeX lays lists out with an emulation of enumitem (`latex-lab-enumitem`, loaded in place of `enumitem.sty`), which stops on `leftmargin=*` and `labelwidth=*` ("Missing number"), as FINC 308's 96 lists have them, and on a setting it doesn't have (`labelindent`, `widest`, `left`, `ref`, `label*`, `before`, `after`, `series`, `style` and others: "Some keys specified on the itemize environment are unused"). A block before `\begin{document}` defines each: a width to compute or a label's indent is left to the emulation's defaults, so such a list has its default margin, `resume` continues the numbering, `nolistsep` is `nosep`, and code to run around a list, a nested label, and `\ref`'s form are left out. The run names the settings the book uses, and how each is taken. It does nothing with enumitem itself, without tagging.
- Packages LaTeX's tagging can't build a tagged PDF with, or can't tag what they make, replaced: the copy doesn't load them, by LaTeX's own way of skipping a package (`\disable@package@load`, written before `\documentclass`, since a class can load one too), and defines their commands where the book would have loaded each, to keep what the book says and not how they made it look. A tagged PDF that doesn't look like the author's is better than none, and the run warns, for a `source` target and for the PDF target's own copy, naming each package and what replacing it changes. Each was built tagged with the commands as books write them, the text checked, and veraPDF's PDF/UA-2 profile passed. A package the tagging status list installed with TeX (below) rates compatible, or partially, is loaded as the book has it, so a package the tagging project comes to support is no longer replaced.
  - **titlesec**, which stopped OpenIntro Statistics' build at its first heading ("No format for this command"; rated currently incompatible): `\titleformat`, `\titlespacing`, `\titlelabel`, `\assignpagestyle` do nothing, so headings are set as the class sets them, titles and numbers and all; `\titlerule` still draws its rule; a heading level `\titleclass` makes is the class's next level down; its page styles (`\newpagestyle`, `\sethead`) are titleps's, which the tagging project rates compatible, loaded when the book defines its first, as titlesec loads it: loaded at once, it clashed with fancyhdr's `\headrule` in OpenIntro, which sets its page styles with fancyhdr.
  - **mdframed** (never to be supported): `mdframed`, and each environment `\newmdenv`, `\surroundwithmdframed`, `\newmdtheoremenv`, and `\mdtheorem` make, are the text around them set apart by space, without frame or background, a `frametitle` (given, from `\mdfsetup`, or from a style) and a `\mdfsubtitle` a line in bold.
  - **framed** (currently incompatible): `framed`, `shaded`, `snugshade`, `leftbar`, and `titled-frame`, the same, a titled frame's title a line in bold.
  - **soul** and **soulutf8**, and **ulem** (currently incompatible; soulutf8 never to be supported): underlined and highlighted text emphasized (italic), letter-spaced and struck-out text plain, the text `\soulomit` and `\sloppyword` hold as it is, and a style of the book's own made the way ulem's documentation shows (`\bgroup\markoverwith{...}\ULon`) its text. A strike-out's meaning has no tag in LaTeX's tagging either way.
  - **tabto** (currently incompatible): a tab stop is a space.
  - **wrapfig** (currently incompatible): a figure or table the text wrapped around is set in the column where it was, not floating, its `\caption` numbered as a figure's or a table's, and tagged as LaTeX's tagging tags a float, the caption first in it (in a `Div`, which veraPDF sees through, the caption was among the section's children: PDF/UA-2's 8.2.5.27). A float there stopped the build in a minipage ("Not in outer par mode") and was dropped in `multicols`.
  - **enumerate** (currently incompatible): with tagging on, LaTeX's own lists take a list's optional argument as keys, and stopped on the package's label pattern ("Some keys specified on the enumerate environment are unknown" at OpenIntro's first `\begin{enumerate}[(a)]`). At `\begin{document}`, after the tagging code defines its lists, `enumerate` is made a wrapper around them that reads an argument naming none of their keys as the package does, with the package's own loop: each `A`, `a`, `I`, `i`, or `1` outside braces is the counter, styled as the last of them is, and the rest is as written, so `(a)` is the label `(\alph*)` and `{Task} 1a` "Task aa". It's read where LaTeX reads it, so a pattern a macro passes (`\begin{enumerate}[#1]`) or a style file of the book's own holds is read too; the book's text is left as it is.
- An alt-text argument of paragraphs run on, at a call of an image macro whose `alt` key takes it (OpenIntro's `\Figure[...]`, with the sample's definitions adopted): `\includegraphics` can't take a paragraph break in its keys ("Paragraph ended before \Gin@ii was complete"), and two of OpenIntro's authors' descriptions have one. The break is a line end, so a comment before it ends where it did.
- A PDF figure that draws text with fonts it doesn't embed, as R's `pdf()` device draws a plot's labels in Helvetica, written beside the copy with them embedded: PDF/UA requires every font embedded and each glyph mapped to Unicode, and veraPDF failed OpenIntro's PDF on both for 546 of its 563 figures. The book's own figure is left as it is; the copy holds the new one at the same path, so laid over the author's tree it's the one LaTeX includes. A figure in a folder the book links to (`figs -> ../shared/figs`) is found too, and the copy never writes through a link: a linked folder in the PDF target's copy is made a folder of its own, of links to what it holds, before a figure in it is replaced. - A `\title` for the PDF's title, which PDF/UA-2 requires (veraPDF's 8.11.1), when the book names none, by `\title` or hyperref's `pdftitle`, and has no `\maketitle` to print one: the title its large type sets (above), or its file's name. - hyperref, for the PDF's bookmarks (PDF/UA-1 recommends them), when the book doesn't load it, nor a package that must come after it (cleveref, glossaries, hypcap, bookmark): `\usepackage[hidelinks]{hyperref}`, so its links look as the text around them, as they did.
- A box (above) tagged as a division of paragraphs, not a table, by `{\tagpdfsetup{table/tagging=div}` before it and `}` after; a table inside one set back to a table, as LaTeX's `table/tagging=on` alone doesn't. veraPDF passes both, and the next table is a table again.
- `float/here`, so a figure's or table's tags are where the text has it. By default LaTeX's tagging gathers every float's tags at the end of the document, where a screen reader reaches them after everything else, and veraPDF can't tell: the 91 of GIAM's 195 figures that are in floats were all there. Where each is printed doesn't change. The key came in latex-lab's float module of 2025-12-04, after the oldest LaTeX release the run takes for tagging (2025-11-01); a release without it leaves the floats' tags at the end, as before.
- `unicode-math`, with the OpenType Latin Modern fonts (TeX's own design) and a fallback for a character they lack, and `math/setup={mathml-SE,mathml-AF}`, so each formula carries its MathML, as structure and as an attached file. Latin Modern's metrics differ a little from those of TeX's own fonts, so pages can break differently: the calculus notes take 84 pages instead of 85, while GIAM keeps its 434. `latex_mathml: "off"` leaves it out. It's inside `\ifdefined\directlua`, so pdfLaTeX builds as before. LaTeX makes MathML only from an OpenType math font: with TeX's own fonts it makes none, and when forced to (`math/mathml/luamml/load=true`), a symbol TeX builds from pieces comes out as the pieces. `\implies` becomes "=" and "⇒", `\neq` "=" and a combining stroke, `\cong` nothing, and ℕ a plain N; 536 of GIAM's 4,521 formulas differ from unicode-math's that way. The fallback matters too: GIAM's flowchart has a `\vdots` in a typewriter label, which Latin Modern Mono lacks, and a missing glyph fails PDF/UA-2. A book that loads `unicode-math` itself gets only the `math/setup`, unless it sets one of its own. A book that sets its fonts or math symbols with a package (`mathptmx`, `fontspec`, `esint`, and others) keeps them, and the run says its formulas get no MathML; that's checked in the preamble, the files it `\input`s there, and a package or class of the book's own beside it, with what that loads (a `bookstyle.sty` loading `newtxmath`, say). `wasysym` is the exception: its symbols come from a font of its own, which gives them no Unicode (veraPDF fails each glyph, and `\Box` reads as "2"), so with LuaLaTeX it isn't loaded, and each of its commands is the Unicode character it draws (`\CIRCLE` is ●, `\lhd` ⊲), from the OpenType fonts and their fallback; the few no font here has are the nearest one that is (APL's symbols) or named in brackets (`[bell]`), and the integrals are left to amsmath, which unicode-math loads. OpenIntro loads it for one symbol, and its formulas get their MathML. A book with no formula that uses its symbols in its text gets the same, with the OpenType fonts and their fallback but not unicode-math. A PostScript font's NFSS family the book names itself, `\fontfamily{phv}` as OpenIntro's headings ask for Helvetica (or `\usefont`, or `\sfdefault` and its kin set to one), isn't in the OpenType fonts' encoding, TU, so LuaLaTeX set it in Latin Modern with a warning each time (425 in OpenIntro); it's declared as TeX Gyre's OpenType clone of it under its own name (`phv` as TeX Gyre Heros, `ptm` Termes, `pcr` Cursor, `ppl` Pagella, and the rest), where that font is installed, and a book with no formula gets the OpenType fonts for it too. And amssymb's names that unicode-math has no command for (`\square`, `\blacksquare`, `\lozenge`, `\Box`, `\lhd`, `\leadsto`, and about 40 more), which amssymb, loaded before it, leaves drawn from TeX's own symbol fonts as control characters (GIAM's eight `\square`s read as U+0003, which veraPDF passes), are each the character it is, from Latin Modern Math, or as a box from the text's fonts for the few it lacks (`\Diamond`, `\blacklozenge`, the dashed arrows); a name the book defines itself is left alone. A bold from `bm` or amsmath's `\boldsymbol` becomes unicode-math's bold italic (`\symbfit`): under unicode-math, `bm` draws a formula's letters from TeX's own bold font, which lacks them ("There is no 𝑥 (U+1D465) in font rm-lmbx10", a missing glyph that fails PDF/UA-2), and `\boldsymbol` puts the formula it makes bold inside the MathML's text. amsbsy's `\pmb` becomes the same: LuaTeX stopped on its overprinting while tagging took a formula's MathML (`\pmb{\hat{p}_1 - b}`: "(nodes): trying to set an attribute fails, case 2"; OpenIntro's boxes have such headings).

For a book of several documents, each `latex.main` names is written, and made to build with tagging the same way; a file two of them reach is written once.

On GIAM, the target's copy laid over the author's tree, built from clean as its Makefile does (LuaLaTeX, BibTeX, makeindex, LuaLaTeX twice), has no error and no tagging warning but the missing alt text, and passes veraPDF's PDF/UA-2 profile, with MathML for each of its 4,521 formulas (434 pages, about eight minutes with latexmk; four without the MathML); without `\DocumentMetadata` it builds with `pdflatex`. Its workbook and solutions manual, built after it from the same copy, pass too, at the 197 and 160 pages they have with pdfLaTeX. That pass says less than it seems: with no description in the image-alt sidecar, LaTeX gives each figure a placeholder (`picture environment`, or the image's file name), which veraPDF can't tell from a description. The run's tagging warnings (`Alternative text for graphic is missing`) say which, and the output check finds each in a PDF the run makes ([The PDF target](#the-pdf-target)).

**Table headers.** A LaTeX book's tables go through the header pre-pass as any other source's do: the census guesses each one's headers, `table-headers-new.csv` gets a row for each (its source the page, `intro.tex`), and what's in effect, a person's row or the guess, reaches the pages. Each table is followed from its file to the page by its place in the files the master reaches, which the read marks and the pages never show. In a copy that is tagged, by `tagging: "on"` or the book's own `\DocumentMetadata`, each table a person decided gets its declaration just before it, in a group of its own, since `\tagpdfsetup` holds until it's changed, and only where tagging defines it: `{\ifdefined\tagpdfsetup\tagpdfsetup{table/header-rows={1}}\fi\begin{tabular}...\end{tabular}}`. A guess is never written, and a table the author declared already is left. An untagged copy gets no declaration, since without tagging it means nothing; the run counts the decisions it couldn't write. Reading the copy again takes each declaration as the pipeline's own. On GIAM, the census found 94 data tables: 47 with a header row, 9 with both a header row and column, 2 with a column, 4 with none, and 32 it couldn't tell.

**The tagging status of the book's packages.** When the copy is made for tagging, by `tagging: "on"` or the book's own `\DocumentMetadata`, the run checks the class and packages the preamble loads (and the files it `\input`s there) against the LaTeX tagging project's [status list](https://latex3.github.io/tagging-project/tagging-status/), and names those not rated compatible: never to be supported, currently incompatible, partially compatible, unchecked, or not in the list. The list comes from TeX's own `latex-tagging-status` package, which LaTeX reads for `\DocumentMetadata`'s `check-tagging-status` key; the run finds it with `kpsewhich`, says how to install it if it isn't there, and says when it's older than the LaTeX it checks, since the distribution's updater keeps the two together. The check only advises and never stops a run: the calculus notes pass PDF/UA-2 with a class (`extarticle`) and a package (`selectp`) the list calls currently incompatible, and a package's own use of the tagging interfaces is no surer guide (the KOMA-Script classes use them and are rated currently incompatible). On GIAM, with the list of 2026-09-27: `hyperref`, `amssymb`, `amsmath`, and `amsthm` partially compatible, `babel` unchecked, the rest compatible.

**Definitions.** Unless `latex_definitions` is `"off"`, the copy gets `latex-conversion-macros.tex` as written, after its preamble, under a comment naming the file, so its definitions replace the book's in the copy as they do in the conversion. On GIAM, `\suchthat` is then `\mid` in the PDF too, a relation LaTeX's tagging writes as MathML, not a drawn bar.

## The PDF target

A `pdf` target builds a LaTeX book's PDF from the book's own LaTeX, so the PDF is the author's book: its pages, index, bibliography, and typography. The book's folder is copied, leaving out what the run writes there and a version control folder (`.git`, `.hg`, `.svn`); a `.latexmkrc` goes with it, and a link to something beside the book still points where the book's did. The files its master reaches are written over the copy as a `source` target with `tagging: "on"` writes them: alt text, the definitions file, MathML, and figures tagged where the text has them, all as described above. Every table's headers are declared as the pages have them, a person's decision or the census's guess, where a `source` target writes only a person's. Then `latexmk -lualatex` builds it, running BibTeX, makeindex, and as many LuaLaTeX passes as the book needs, with the PDF and its log in the document's own folder whatever the book's `.latexmkrc` sets. The PDF claims PDF/UA-2, and the output check runs veraPDF on it as on any other PDF. A reference or citation LaTeX couldn't resolve, which the PDF prints as ?? or [?], is named: a label the book doesn't define, or a bibliography file that isn't beside it, does that in the book's own build too. It needs `latexmk`, which comes with TeX Live.

A book of several documents gets a PDF of each, named as its page is (`Topic-03-Financial-Statements-and-Net-Worth.pdf`), built side by side, up to four at a time; `filename` names only a single document's PDF. A book can need changes of its own to build with LaTeX's tagging; the list above is what GIAM and FINC 308 needed. When LaTeX stops, the run shows its first errors, for each document it stopped on once all have been tried, and stops. `pdf.from: pages` then builds the PDF from the converted pages through Pandoc's LaTeX writer instead, as for any other source; for a book of several documents, that's one PDF of the whole book. That PDF has no index (below), and the `pdf` settings that shape Pandoc's LaTeX (`metadata`, `figures`, `toc_depth`, and the rest) apply only to it, as does any `pdf.standard` but PDF/UA-2. A book that loads a package that must come after hyperref, without hyperref, gets no bookmarks, which the output check notes.

**The PDF from the pages takes the book's layout** from its master's preamble (the first master's, for a book of several documents), read in LaTeX's order up to `\begin{document}`, a style file it `\input`s included, comments left out and a setting an environment, a command, or a hook makes not counted, though one at `\begin{document}` is: the type size and paper its class options give (`11pt`, `a4paper`, a KOMA class's `fontsize=` and `paper=`), `oneside`, `twoside`, `openany`, and `openright`, geometry's options from `\usepackage[...]{geometry}` and `\geometry{...}`, its line spacing (`\setstretch`, `\linespread`, setspace's `\onehalfspacing` and `\doublespacing`), indented paragraphs, as LaTeX's are, unless it loads parskip or sets `\parindent` to zero, and xcolor's sets of named colors the book loads (`dvipsnames`, `svgnames`, `x11names`, from xcolor's options, the class's, or `\PassOptionsToPackage`), as class options xcolor takes, since a formula keeps its TeX and can name one (`\color{BrickRed}`), which LaTeX stopped on as undefined. The book's color definitions go in its preamble too, a `\colorlet` only once each color it's made of is defined, since one a style file of the book's own defines isn't among them. Pandoc's defaults would be 10pt type in the book class's margins with parskip's spacing: FINC 308's whole book had 10pt type in a block five and a half inches wide, where its author set 11pt with inch margins, and now has the author's, on 164 pages instead of 186. The run says what it took; a `pdf.metadata` file's settings win over it.

On GIAM, the run with an HTML target and this one takes about eight minutes. The PDF has the book's 434 pages, index and bibliography included, and passes veraPDF's PDF/UA-2 profile, with MathML for each of its 4,521 formulas, 57 tables declared with a header row and 13 with a header column, and each figure tagged where the text has it. Until `image-alt.csv` describes them, its 195 figures carry the placeholders LaTeX gives a figure with no alt text, which veraPDF accepts and the output check reports: 186 `picture environment` and 9 file names. Built from the pages instead, the PDF has 279 pages and also passes, without the index or bibliography.

## What is lost

In the pages, the EPUB, and a PDF built from the pages:

- **Index entries.** `\index` is dropped; the pages have no index.
- **A bibliography in the book's own style, without BibTeX** or a `.bbl` a build of the book left, and **under biblatex**: Pandoc's citeproc makes the citations and the bibliography, in its own style (author and date), and a full citation is in BibTeX's plain style, all its authors named where biblatex's `maxnames` shortens the list with "et al."
- **Macros defined in a package file beside the book.** The copy holds the `.tex` files the master reaches and no `.sty`, since Pandoc reading a drawing package's definitions (DraTex's) stopped it; a macro the book's own package defines is unknown to the reader, and its text is skipped.
- **Manual formatting**, `\vspace` and `\newpage`, is dropped, and a tall rule drawn in a formula is left as TeX until the definitions file says what it means.
