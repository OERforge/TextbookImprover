# LaTeX sources

A LaTeX book is read through its master file, the one with `\documentclass` and `\begin{document}`, and every target makes its output from it as from any other source; a book that is a set of documents, each built on its own, is read through each of them. Tested on the suite's own book, on Joseph Fields's [*A Gentle Introduction to the Art of Mathematics*](https://github.com/osj1961/giam) (GIAM), a book of nine chapters that is the test case for this work, on a set of calculus note templates in one file, already tagged by its author, which has to keep converting cleanly as the rest grows, and on the notes for a financial planning course (FINC 308), 18 documents, one a topic.

There are two ways to an accessible PDF of a LaTeX book, and a book can take either:

- **From the book's own LaTeX** ([The PDF target](#the-pdf-target)): a copy of the author's files made to build with LaTeX's own tagging, as a `source` target with `tagging: "on"` writes it, and built with LuaLaTeX. The PDF is the author's book, its layout, index, and bibliography; the copy is a version of the author's files that the author can keep building. This is the default.
- **From the converted pages** (`pdf.from: pages`): Pandoc's LaTeX writer makes a new LaTeX book of the pages, as for any source, and LaTeX builds that. The layout is the pipeline's, not the author's, and the index and bibliography are lost ([What is lost](#what-is-lost)), but it builds whatever the author's LaTeX does, and it can claim PDF/UA-1 as well.

## How a book is read

The master is the `.tex` file in the book's directory that is a whole document. When there's more than one, as when one set of chapters makes a textbook, a workbook, and a solutions manual, `latex.main` names the book's (GIAM's is `GIAM.tex`), and the run stops and says so until it does.

A document that `\include`s nothing is one page, named after its file; its sections can be split into pages of their own ([Splitting pages](splitting.md)). A division command after its first words (FINC 308's `\appendix` before a topic's last practice set) doesn't make the whole page an appendix, and the reader drops it, so the sections after it aren't lettered; one the document opens with gives the page its role.

**A book of documents each built on its own**, as a course's notes often are, a document a topic, names them all in `latex.main`, as a list, a path (below the book's directory if they're in a folder), or a pattern (`src/*.tex`, in sorted order):

```yaml
defaults:
  latex:
    main:
      - "src/Topic 01 Introduction to Financial Planning and the CFP Profession.tex"
      - "src/Topic 01 Supplement CFP Board Code of Ethics and Standards of Conduct.tex"
      - "src/Topic 02 CFP Financial Planning Process.tex"
```

Each is read on its own, with its own preamble, and is a page (or a page for each file it `\include`s), in the order the list gives, which is the order of `contents-sample.yaml`. Two documents that `\include` the same file would make it a page twice, so the run stops and names them. A document is built from its own folder, as its author builds it there. A master that only gathers documents' PDFs with `\includepdf` (FINC 308's "Combined" file, a section and a PDF per topic) has nothing of its own to convert: when it's the only master, or the one `latex.main` names, the run stops and prints the `latex.main` list to paste, the whole documents named as its PDFs are, anywhere in the book's directory, in its order, and names the PDFs with no LaTeX beside them. With no master in the book's directory at all, a run that finds whole documents in a folder below says where they are.

Pandoc reads the whole book through the master, following `\include` and `\input` from the book's directory, so the preamble's macros apply everywhere, a `\ref` gets the number LaTeX would give it, and a reference into another chapter resolves. The result is cut into pages where each `\include`-d file begins, each page named after its file (`\include{intro/intro}` is `intro`), as every other source's pages are. What the master holds itself before its first `\include` (a copyright page, acknowledgments) is a page named after the master. A `\ref` whose label is on another page links to that page.

With no `contents` declared, the run writes `contents-sample.yaml`: the pages in the master's order, each with the role `\frontmatter`, `\appendix`, or `\backmatter` before it gives it, and the title, authors, and language the preamble declares (babel's or polyglossia's main language, or `\DocumentMetadata`'s `lang`). Copy it into `project.yaml` to use it.

A `README.md` beside the master is the repository's, not a page.

## What is put right before reading

Pandoc's LaTeX reader (3.12) can't take some of what plain LaTeX books do, so the book is copied and the copy put right; the author's files are never written. Each of these was read in Pandoc's source and measured, and is described in `PANDOC-NOTES.md` in the repository, "The LaTeX reader":

- **ifthen's booleans** (`\newboolean`, `\setboolean`, `\ifthenelse{\boolean{...}}`) become etoolbox's toggles, which the reader evaluates. It drops `\ifthenelse`, both branches with it ([jgm/pandoc#11008](https://github.com/jgm/pandoc/issues/11008)). An `\ifthenelse` with any other condition is still dropped, and the run counts them.
- **`\input file`**, TeX's own form without braces, is braced. The reader stops on it.
- **`\centerline`** is read as a center environment. The reader takes its argument as inline text and stops on a table inside it.
- **`\cline{2-3}` and `\cmidrule{2-3}`** become whole rules. The reader leaves their column range in the next cell as text.
- **A table's header declaration for LaTeX's tagging**, `\tagpdfsetup{table/header-rows={1}}` or `table/header-columns={1}` (or both) just before the table, is the table's declaration here too, as a `table-headers.csv` row or a Markdown marker would be; the reader drops `\tagpdfsetup`. A declaration naming more than the first row or column is counted and left for `table-headers.csv`.
- **An image named without its extension** is resolved the way graphicx resolves it (`.pdf`, then `.png`, `.jpg`, and the rest, then `.eps`), in the book's directory and `\graphicspath`. The reader looks in the copy, where it isn't.
- **An image behind one of the book's own macros**, a macro whose body holds one `\includegraphics` with its file made from an argument (`\newcommand{\fig}[2]{\includegraphics[width=#2]{#1}}`, or `\def` with plain arguments), is written out at each call, the body with the call's arguments, as the reader expands it, so its file is resolved as above. Otherwise the reader would find an image named without its extension, which the run stops on. A call inside another definition, a body that also holds a table or a drawing, and a file name built with another macro (`\chapterfolder/figures/#1`) are left to the reader.
- **A PDF or EPS image**, which no browser shows, is made an SVG of its first page with `pdftocairo` (EPS through `epstopdf` first).
- **A drawing**, a `picture`, `tikzpicture`, or `pspicture` environment, which the reader drops whole, is rendered by LaTeX with the book's own preamble and made an SVG; the copy includes the SVG in its place, so a figure keeps its caption and label. A run of drawings with nothing between them but comments and a `\setlength{\unitlength}`, which is what fig2dev's `pstex_t` output is, makes one image. The engine is pdfLaTeX unless the preamble needs LuaLaTeX (fontspec, unicode-math, polyglossia, `\DocumentMetadata`). A `tikzpicture` drawn as an `overlay`, a rule down every page from `\AddToShipoutPictureBG` say, belongs to the page and not the text, and is left alone.
- **The `artifact` key** on `\includegraphics` makes the image decorative, as latex-lab does; the reader ignores the key.
- **A title set as large type**, as a document without `\title` often sets one: the brace group in a `center` (or `titlepage`) environment that opens the body, set larger than any other group there and at `\large` or more (`{\LARGE Topic 1: ...}` under `{\large FINC 308: ...}`), is read as the page's title, and the document's sections go under it, a level down. What the environment holds besides it, the course's name, stays where it was. The reader would take the title for a paragraph and the sections for the page's top level, and the page would be titled by its file name.
- **A box**, a `tabular` of one paragraph column (`p`, `m`, `b`, or `X`) with a cell of a dozen words or more, as an author frames an example between rules, is read as a box around its rows' paragraphs, a `<div class="box">` in HTML: a passage, not a table of one column, which a screen reader would announce as a table. A table in a box is a table of its own. FINC 308 has 28.
- **A column type the book defines** with array's `\newcolumntype` (`R{2.3in}`, a right-aligned paragraph column) is written out where a table uses it, its arguments in place, and the definition taken out. The reader doesn't know it and takes the table's column specification as text, so the table falls apart, and it stops on a definition in the body.
- **A `\ref` to a label on an enumerated item** is written as the number LaTeX gives the item: `1b` for the second item of a list in the first item of another, as article's `\theenumi` and `\p@enumii` make it, `(b)` for a list enumitem labels `(\alph*)`, and a `start` or `resume` counted in. The reader can't resolve one and writes the label's name in brackets, `[Topic2Q1]`, where FINC 308's answer keys (70 references) have `1b 2b 3b`.
- **Alt text** in an `alt` key is read as LaTeX (`50\%` is "50%"); the reader keeps it as typed. An image without one is reported in `image-alt-missing.csv` like any other; the reader would describe it as "image".
- **Formulas** texmath can't read, which then appear as their TeX: a size command in text inside math (`\mbox{\tiny noneg}`), a text command inside `\mbox` (`\mbox{\textsf R}`, `\mbox{{\bf c}}`), a length in millimeters (`\hspace{40mm}`; texmath knows em, pt, in, and cm), a length set inside a formula (`\setlength\tabcolsep` in an `array`), and a rule with no width (a strut) or no height (a space) are written as texmath reads them. A rule that shows is left when it's tall, since it draws something only a person can name (see the next section); a flat one, no taller than a point, is a blank to fill in and becomes an underlined space. An `\hspace` inside an `\mbox` moves out of it, and `\raisebox` is dropped, since a raised box is the same symbol.
- **A rule outside a formula** with no height is a space and with no width nothing; the reader takes any rule with a width for a line across the page.
- **What Pandoc's own LaTeX writer adds**, so the `latex` target's output, or any LaTeX Pandoc wrote, reads back: an image inside `\pandocbounded` is unwrapped; a `longtable`'s head is read once, not again as a row for its copy repeated on later pages, and declared as the table's header row when it's one row; a header declaration before Pandoc's `{\def\LTcaptype{none}` group around a table counts; `@{...}` comes out of a `\multicolumn`'s spec, which lost the whole table; a cell's lines stacked in `\vtop` or broken with `\\` in a minipage are read as lines, not dropped or taken for the row's end; the PDF target's own link commands are dropped; a head-only table's empty body row is dropped; and a table in a table's cell doesn't take its container's caption, which the reader gives it, in a book written by hand too.

The rendered images go in `rendered/` in the book's directory, at the path of the file they came from (`figures/Venn.tex` is `rendered/figures/Venn.svg`; a drawing in a chapter is `rendered/sets/sets-3.svg`). `rendered/.rendered.json` records what each was made from, so an unchanged drawing isn't made again. An image's alt text comes from `image-alt.csv` by that path, like any image's.

Drawings and PDF images need a LaTeX engine and `pdftocairo` (`sudo apt install poppler-utils`). Without them the run says so, and they're left out of the pages. When LaTeX can't make one drawing, the others are made one at a time, so it costs only itself.

## A book with a build of its own

Some books make part of their LaTeX with another program first: GIAM draws its figures in xfig, and its Makefile has fig2dev write each as a `.tex` file and a PDF. The conversion reads LaTeX, so that build runs first, and what it makes is the conversion's input. When the master reaches a file that isn't there, the run stops before converting anything, names the files, and points at any `Makefile` beside the master or the missing files.

## What the book's macros mean: `latex-conversion-macros.tex`

The book's own definitions are always read, a file of them it `\input`-s included (GIAM's `my_latex_definitions.tex`), and this file is read after the whole preamble, so what it defines wins. It works as a sidecar for macros. Some macros draw what they mean. GIAM's "such that" is a bar drawn with `\rule`, and so is its restriction of a function to a set, and its blank to fill in is three rules. Read as written, each is a formula texmath can't read, or one a screen reader reads as nothing. Only a person can say what each means, once, in `latex-conversion-macros.tex` beside the master: LaTeX definitions read after the book's own preamble. The book's own files never change; a `source` target writes the definitions into its copy, after the copy's preamble, so the book's PDF says what the pages say (`latex_definitions: "off"` keeps them to the conversion, for a file that only helps Pandoc read). GIAM's:

```latex
% "Such that", drawn as a bar with \rule.
\renewcommand{\suchthat}{\mid}
% A function restricted to a set, drawn as a bar with \rule.
\renewcommand{\restrict}[2]{#1|_{#2}}
% A blank to fill in, drawn as three rules.
\renewcommand{\blnk}{\underline{\quad}}
```

The file's name is the `latex.macros` setting.

**The run writes a starting point**, `latex-conversion-macros-sample.tex`, whenever any of the book's macros (defined with `\newcommand` and its kin, and used in a formula) still gives a formula texmath can't make MathML of, once the repairs above and the definitions file are applied. Each is listed with how often formulas use it and the book's own definition. Where its drawing has one reading, the sample suggests a definition, kept only if texmath then reads it: a thin tall rule is a vertical bar (`\mid` when only spacing surrounds it, so GIAM's `\suchthat`), and flat rules with nothing but ticks and spacing beside them are a blank to fill in (`\underline{\quad}`). The rest are left as a commented-out `\renewcommand` for a person to fill in, as GIAM's `\nrelR`, an R struck through with a raised `\not`, is. Check the sample, then save it as `latex-conversion-macros.tex` or merge it into yours; it's never read as it stands. With nothing left to list, a stale sample is removed.

## The source target

`format: source` writes the book's own `.tex` files back, every one the master reaches, at the same paths under the target's folder, so the folder can be laid over the author's tree. The book's other masters beside it go in too, each with the files only it reaches, as GIAM's workbook and solutions manual do with their exercise files; a file the main master reaches is as its copy has it. What it writes into them is only what a person decided, in the sidecars and in `latex-conversion-macros.tex`, at the element each decision was made about, and the rest is as the author wrote it, comments and all: alt text, the definitions file (below), and, in a tagged copy, table headers. **Alt text:** each image and drawing in the image-alt sidecar gets the `alt` key LaTeX's tagging reads, or `artifact` for `[decorative]`, beside the author's own keys (`\includegraphics[alt={A gray square},width=1cm]{sq}`, `\begin{picture}[alt={Two boxes}](40,20)`, `\begin{tikzpicture}[alt={...},scale=2]`). A drawing is found as the conversion named it (its file, and its place among the file's drawings), an image by the file graphicx would include; anything in a comment or verbatim text is left alone. fig2dev's pair of picture environments is one drawing: the first gets the alt text, and the second, which holds its labels, is marked `artifact` so it isn't a figure of its own. A `pspicture` has no such key; it's counted and left alone.

**An image behind one of the book's own macros**, found as the read finds it (above), gets its key at each call, set just before the call and set back just after it, so the macro stays as the author wrote it: `\setkeys{Gin}{alt={A gray square}}\fig{sq}{1cm}\setkeys{Gin}{alt={}}`. A group around the call would end what the call starts: a `\centering` in the macro before its paragraph ends, and the number its `\caption` gives a `\label` after it. `alt={}` is how LaTeX's tagging starts each image, with no description. A macro whose own `alt` key takes an argument (`alt={#3}`) gets the text in that argument instead, braced so a comma in it doesn't end the key. One that passes an argument to `\includegraphics` as keys (`\includegraphics[#1]{#2}`) gets `alt` among the keys the call gives, since a key there wins over one set before; a call that gives none gets them written in, when the macro's default is empty or has alt text of its own. The book's definitions are read in the order LaTeX reads them, each file where it's `\input`, so a later definition replaces an earlier one, and `\providecommand` defines only a name nothing has defined yet.

Some can't be written, and the run names each by the image's key, since its pages have the alt text and its PDF would have a placeholder:

- A call in an argument LaTeX writes to a file and reads back, or keeps to set elsewhere, where `\setkeys` stops the build (measured, with pdfLaTeX and LuaLaTeX): a caption, `\captionof`'s and `\subcaption`'s too, a heading, either one's short form, `\index`, `\thanks`, `\title`, `\author`, `\markboth`, `\markright`, and `\addcontentsline`'s entry.
- A macro that sets alt text or `artifact` of its own, which wins over a key set before it.
- A macro whose alt argument the body uses elsewhere too, as its caption, say, which a description there would change; and a decorative image behind a macro whose `alt` key takes an argument, which can't say `artifact`.
- An image the copy doesn't find at all, behind a macro that calls another, say, found by checking the images the pages show.

The keys don't change an untagged build. With TeX Live 2026, `pdflatex` builds a document using `alt`, `artifact`, and `\setkeys{Gin}` with no error or warning (TeX Live 2023's graphicx knows `alt` but stops at `artifact`), and with `\DocumentMetadata{tagging=on}` and LuaLaTeX each becomes its figure's `/Alt` in the PDF's structure and the artifact image isn't a figure at all (checked in the structure tree). On GIAM, with a placeholder description for each of its 102 images and drawings, 99 of its 154 files change, and the copy laid over the author's tree builds with the book's own `pdflatex GIAM` to the same 424 pages as the original.

**A file the book's build makes** can be written into, but building again writes over it: 93 of GIAM's drawings are in files fig2dev makes from xfig sources. A file beside a same-named `.fig` is counted as one, and the run says how many of its changes are in such files. Until the book's own build carries the alt text (an xfig comment it passes through, say), the copy is a version whose build is this one.

**`tagging: "on"`** makes the copy build with LaTeX's own tagging, for an accessible PDF. It's a change to the author's build, so it's off by default: a tagged book is built with LuaLaTeX, since pdfLaTeX keeps the structure in TeX's main memory and GIAM's run out of it. Each change was needed on GIAM and found with a document of a few lines, and each keeps the untagged build working:

- `\DocumentMetadata{lang=..., pdfstandard=ua-2, tagging=on}` first, when the book has none, its language the book's declared one or babel's or polyglossia's. First, not just before `\documentclass`, since a master can choose its class inside a conditional. A book's own `\DocumentMetadata` is kept, with `tagging=on` added when it lacks it (one that only sets the PDF's version builds untagged), and the language and standard when it names none.
- `luatex85`, loaded for LuaLaTeX just after `\DocumentMetadata`, when the book uses one of pdfTeX's own commands (`\pdfinfo`, `\pdfcatalog`, and the rest) or tests for pdfTeX by `\pdfoutput`, as GIAM's workbook and solutions manual do to choose their class options (`\ifx\pdfoutput\undefined`), and one of its chapters to choose `.eps` or `.pdf` figures. LuaTeX has neither: the commands stop the build, and the test took LuaLaTeX for LaTeX with dvips. The LaTeX team's package for such documents gives LuaTeX each of them, so the test takes the branch meant for pdfTeX and what's in that branch works (checked tagged, with `\pdfinfo` and `\pdfcatalog`: veraPDF passes, and the PDF has the author `\pdfinfo` gives). It's in TeX Live's `collection-luatex`; TinyTeX installs it with `tlmgr install luatex85`. pdfLaTeX doesn't load it.
- The `pdftex` option taken out of `\documentclass`, `\usepackage`, and `\RequirePackage`, and pdfTeX's own settings (`\pdfcompresslevel=9`) out of the text.
- A starred theorem the book defines beside its numbered one (`\newtheorem*{thm*}{Theorem}` with `\newtheorem{thm}`) defined only when it isn't yet: tagging's `\newtheorem{thm}` defines `thm*` too, and the second definition stops the build.
- `\centerline` on a line of its own made a centered paragraph, by a definition before `\begin{document}`; inside a paragraph it's as before. As an `\hbox` between paragraphs it put every later paragraph inside a P (53 of GIAM's warnings).
- `\leavevmode` before a display formula that opens a paragraph in a `center`, `flushleft`, or `flushright` environment: right after its `\begin`, or after a blank line, as in a paragraph column of a table there (FINC 308's boxes). In LaTeX 2026-06-01 such a formula leaves a paragraph open (`Text. \begin{center} \[ 1! = 1 \] \end{center} After.` is enough), and in a list item the items after it nest in it; in a table's cell it stops the build ("the number of automatic begin and end text para hooks differ").
- enumitem's settings that LaTeX's tagging can't take, let through. With tagging on, LaTeX lays lists out with an emulation of enumitem (`latex-lab-enumitem`, loaded in place of `enumitem.sty`), which stops on `leftmargin=*` and `labelwidth=*` ("Missing number"), as FINC 308's 96 lists have them, and on a setting it doesn't have (`labelindent`, `widest`, `left`, `ref`, `label*`, `before`, `after`, `series`, `style` and others: "Some keys specified on the itemize environment are unused"). A block before `\begin{document}` defines each: a width to compute or a label's indent is left to the emulation's defaults, so such a list has its default margin, `resume` continues the numbering, `nolistsep` is `nosep`, and code to run around a list, a nested label, and `\ref`'s form are left out. The run names the settings the book uses, and how each is taken. It does nothing with enumitem itself, without tagging.
- titlesec taken out, when the book uses none of its commands (`\titleformat`, `\titlespacing`, and the rest), as six of FINC 308's topics load it. LaTeX's tagging can't build with it ("No format for this command" at the first `\section`; the tagging project rates it currently incompatible). A book that does set its headings with it is left as it is, and the build stops there; the run says why.
- A `\title` for the PDF's title, which PDF/UA-2 requires (veraPDF's 8.11.1), when the book names none, by `\title` or hyperref's `pdftitle`, and has no `\maketitle` to print one: the title its large type sets (above), or its file's name. LaTeX's tagging puts it in the PDF's metadata; nothing prints it.
- hyperref, for the PDF's bookmarks (PDF/UA-1 recommends them), when the book doesn't load it, nor a package that must come after it (cleveref, glossaries, hypcap, bookmark): `\usepackage[hidelinks]{hyperref}`, so its links look as the text around them, as they did.
- A box (above) tagged as a division of paragraphs, not a table, by `{\tagpdfsetup{table/tagging=div}` before it and `}` after; a table inside one set back to a table, as LaTeX's `table/tagging=on` alone doesn't. veraPDF passes both, and the next table is a table again.
- `float/here`, so a figure's or table's tags are where the text has it. By default LaTeX's tagging gathers every float's tags at the end of the document, where a screen reader reaches them after everything else, and veraPDF can't tell: the 91 of GIAM's 195 figures that are in floats were all there. Where each is printed doesn't change. The key came in latex-lab's float module of 2025-12-04, after the oldest LaTeX release the run takes for tagging (2025-11-01); a release without it leaves the floats' tags at the end, as before.
- `unicode-math`, with the OpenType Latin Modern fonts (TeX's own design) and a fallback for a character they lack, and `math/setup={mathml-SE,mathml-AF}`, so each formula carries its MathML, as structure and as an attached file. Latin Modern's metrics differ a little from those of TeX's own fonts, so pages can break differently: the calculus notes take 84 pages instead of 85, while GIAM keeps its 434. `latex_mathml: "off"` leaves it out. It's inside `\ifdefined\directlua`, so pdfLaTeX builds as before. LaTeX makes MathML only from an OpenType math font: with TeX's own fonts it makes none, and when forced to (`math/mathml/luamml/load=true`), a symbol TeX builds from pieces comes out as the pieces. `\implies` becomes "=" and "⇒", `\neq` "=" and a combining stroke, `\cong` nothing, and ℕ a plain N; 536 of GIAM's 4,521 formulas differ from unicode-math's that way. The fallback matters too: GIAM's flowchart has a `\vdots` in a typewriter label, which Latin Modern Mono lacks, and a missing glyph fails PDF/UA-2. A book that loads `unicode-math` itself gets only the `math/setup`, unless it sets one of its own. A book that sets its fonts or math symbols with a package (`mathptmx`, `fontspec`, `wasysym`, and others) keeps them, and the run says its formulas get no MathML; that's checked in the preamble, the files it `\input`s there, and a package or class of the book's own beside it, with what that loads (a `bookstyle.sty` loading `newtxmath`, say). A bold from `bm` or amsmath's `\boldsymbol` becomes unicode-math's bold italic (`\symbfit`): under unicode-math, `bm` draws a formula's letters from TeX's own bold font, which lacks them ("There is no 𝑥 (U+1D465) in font rm-lmbx10", a missing glyph that fails PDF/UA-2), and `\boldsymbol` puts the formula it makes bold inside the MathML's text.

For a book of several documents, each `latex.main` names is written, and made to build with tagging the same way; a file two of them reach is written once.

On GIAM, the target's copy laid over the author's tree, built from clean as its Makefile does (LuaLaTeX, BibTeX, makeindex, LuaLaTeX twice), has no error and no tagging warning but the missing alt text, and passes veraPDF's PDF/UA-2 profile, with MathML for each of its 4,521 formulas (434 pages, about eight minutes with latexmk; four without the MathML); without `\DocumentMetadata` it builds with `pdflatex`. Its workbook and solutions manual, built after it from the same copy, pass too, at the 197 and 160 pages they have with pdfLaTeX. That pass says less than it seems: with no description in the image-alt sidecar, LaTeX gives each figure a placeholder (`picture environment`, or the image's file name), which veraPDF can't tell from a description. The run's tagging warnings (`Alternative text for graphic is missing`) say which, and the output check finds each in a PDF the run makes ([The PDF target](#the-pdf-target)).

**Table headers.** A LaTeX book's tables go through the header pre-pass as any other source's do: the census guesses each one's headers, `table-headers-new.csv` gets a row for each (its source the page, `intro.tex`), and what's in effect, a person's row or the guess, reaches the pages. Each table is followed from its file to the page by its place in the files the master reaches, which the read marks and the pages never show. In a copy that is tagged, by `tagging: "on"` or the book's own `\DocumentMetadata`, each table a person decided gets its declaration just before it, in a group of its own, since `\tagpdfsetup` holds until it's changed, and only where tagging defines it: `{\ifdefined\tagpdfsetup\tagpdfsetup{table/header-rows={1}}\fi\begin{tabular}...\end{tabular}}`. A guess is never written, and a table the author declared already is left. An untagged copy gets no declaration, since without tagging it means nothing; the run counts the decisions it couldn't write. Reading the copy again takes each declaration as the pipeline's own. On GIAM, the census found 94 data tables: 47 with a header row, 9 with both a header row and column, 2 with a column, 4 with none, and 32 it couldn't tell.

**The tagging status of the book's packages.** When the copy is made for tagging, by `tagging: "on"` or the book's own `\DocumentMetadata`, the run checks the class and packages the preamble loads (and the files it `\input`s there) against the LaTeX tagging project's [status list](https://latex3.github.io/tagging-project/tagging-status/), and names those not rated compatible: never to be supported, currently incompatible, partially compatible, unchecked, or not in the list. The list comes from TeX's own `latex-tagging-status` package, which LaTeX reads for `\DocumentMetadata`'s `check-tagging-status` key; the run finds it with `kpsewhich`, says how to install it if it isn't there, and says when it's older than the LaTeX it checks, since the distribution's updater keeps the two together. The check only advises and never stops a run: the calculus notes pass PDF/UA-2 with a class (`extarticle`) and a package (`selectp`) the list calls currently incompatible, and a package's own use of the tagging interfaces is no surer guide (the KOMA-Script classes use them and are rated currently incompatible). On GIAM, with the list of 2026-09-27: `hyperref`, `amssymb`, `amsmath`, and `amsthm` partially compatible, `babel` unchecked, the rest compatible.

**Definitions.** Unless `latex_definitions` is `"off"`, the copy gets `latex-conversion-macros.tex` as written, after its preamble, under a comment naming the file, so its definitions replace the book's in the copy as they do in the conversion. On GIAM, `\suchthat` is then `\mid` in the PDF too, a relation LaTeX's tagging writes as MathML, not a drawn bar.

## The PDF target

A `pdf` target builds a LaTeX book's PDF from the book's own LaTeX, so the PDF is the author's book: its pages, index, bibliography, and typography. The book's folder is copied, leaving out what the run writes there and a version control folder (`.git`, `.hg`, `.svn`); a `.latexmkrc` goes with it, and a link to something beside the book still points where the book's did. The files its master reaches are written over the copy as a `source` target with `tagging: "on"` writes them: alt text, the definitions file, MathML, and figures tagged where the text has them, all as described above. Every table's headers are declared as the pages have them, a person's decision or the census's guess, where a `source` target writes only a person's. Then `latexmk -lualatex` builds it, running BibTeX, makeindex, and as many LuaLaTeX passes as the book needs, with the PDF and its log in the document's own folder whatever the book's `.latexmkrc` sets. The PDF claims PDF/UA-2, and the output check runs veraPDF on it as on any other PDF. A reference or citation LaTeX couldn't resolve, which the PDF prints as ?? or [?], is named: a label the book doesn't define, or a bibliography file that isn't beside it, does that in the book's own build too. It needs `latexmk`, which comes with TeX Live.

A book of several documents gets a PDF of each, named as its page is (`Topic-03-Financial-Statements-and-Net-Worth.pdf`), built side by side, up to four at a time; `filename` names only a single document's PDF. A book can need changes of its own to build with LaTeX's tagging; the list above is what GIAM and FINC 308 needed. When LaTeX stops, the run shows its first errors, for each document it stopped on once all have been tried, and stops. `pdf.from: pages` then builds the PDF from the converted pages through Pandoc's LaTeX writer instead, as for any other source; for a book of several documents, that's one PDF of the whole book. That PDF has no index or bibliography (below), and the `pdf` settings that shape Pandoc's LaTeX (`metadata`, `figures`, `toc_depth`, and the rest) apply only to it, as does any `pdf.standard` but PDF/UA-2. A book that loads a package that must come after hyperref, without hyperref, gets no bookmarks, which the output check notes.

On GIAM, the run with an HTML target and this one takes about eight minutes. The PDF has the book's 434 pages, index and bibliography included, and passes veraPDF's PDF/UA-2 profile, with MathML for each of its 4,521 formulas, 57 tables declared with a header row and 13 with a header column, and each figure tagged where the text has it. Until `image-alt.csv` describes them, its 195 figures carry the placeholders LaTeX gives a figure with no alt text, which veraPDF accepts and the output check reports: 186 `picture environment` and 9 file names. Built from the pages instead, the PDF has 279 pages and also passes, without the index or bibliography.

## What is lost

In the pages, the EPUB, and a PDF built from the pages:

- **Index entries.** `\index` is dropped; the pages have no index.
- **A bibliography.** `\bibliography` names the `.bib` file, but no references list is made, and a `\cite` stays a citation key.
- **Macros defined in a package file beside the book.** The copy holds the `.tex` files the master reaches and no `.sty`, since Pandoc reading a drawing package's definitions (DraTex's) stopped it; a macro the book's own package defines is unknown to the reader, and its text is skipped.
- **Manual formatting**, `\vspace` and `\newpage`, is dropped, and a tall rule drawn in a formula is left as TeX until the definitions file says what it means.
