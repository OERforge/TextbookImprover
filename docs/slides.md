# Slides

A folder of PowerPoint decks is slides. Each deck is checked as PowerPoint's own Accessibility Checker checks it, and for more besides; what needs a person's decision goes into the reports, as a book's does, keyed so one decision covers every place it applies; and a `source` target writes the decisions made so far into a copy of each deck, changing nothing else. The run never guesses into a deck: a copy holds only what a person decided in the sidecars and the settings, apart from two things it takes from the project and the deck, and two repairs of XML PowerPoint can't read, below.

So is a folder of decks written in Markdown, when `project.yaml` says so: each deck becomes a page and a tagged PDF of its own, by way of the filter that does a book's pages ([Decks written in Markdown](#decks-written-in-markdown)).

Converting a PowerPoint deck to a page, a PDF, or Markdown, writing a Markdown deck as PowerPoint or as a reveal.js presentation, and packaging decks beside a book come later ([ROADMAP.md](../ROADMAP.md#3-slides-and-test-banks)).

## A first run

Put the decks in a folder of their own and run `convert.py` there:

```bash
cd stats-slides
python3 $T/bin/convert.py
```

A slides run needs Python and PyYAML from the [requirements](installation.md#requirements), and not Pandoc, which a book's run reads its sources with.

On OpenStax's 13 decks for _Introductory Business Statistics 2e_, the run begins:

```
Slides: 13 PowerPoint deck(s), each checked and remediated on its own, since they're all this folder holds.
Checked 13 deck(s): 165 finding(s): 21 errors, 144 warnings.
  - `pptx-alt-too-long` ×144: alt text longer than images.alt_max_chars
  - `pptx-alt-placeholder` ×21: alt text that says nothing about the image: punctuation, a word such as "image", a default name, a clip-art id, or a pattern from images.alt_placeholders
Written to slides-check.csv.
Wrote image-alt-missing.csv (165 picture(s) and object(s) needing alt text).
Fill in the second column, then append the rows to image-alt.csv.
```

It then writes a copy of each deck to `remediated/` and checks the copies (`output-check.csv`). On the first run, nothing has been decided yet, so the copies match their originals. The 21 placeholders are `...` and `..`, 12 of them on the regression deck's scatter plots.

A folder holding `.pptx` files and nothing a book is read from (a `README.md` aside) is slides without being told. In a folder with other files, `project.kind: slides` in `project.yaml` says so; the other files are then left out, and the run names them. A deck in a book's folder is left out of the book, and the run says so too. Decks can come in a zip or a tar (`.tar.gz`, `.tgz`, `.tar`), which the first run unpacks as it unpacks a book's archive: a folder that wraps everything is dropped, and what macOS adds (`__MACOSX`, `._` files) is left out. An entry that would land outside the folder, or a link, is refused and listed in `unpack-report.csv`. With no target in `conversion.yaml`, the run implies one, `remediated`, with format `source`. A deck that can't be read, such as one saved with a password, is named with the reason, and the rest go on.

## What's checked

The findings go to `slides-check.csv`, in the format every check here shares ([Auditing](auditing.md#the-findings-format)). `audit.py` writes the same findings as a report to read. They start with what PowerPoint's Accessibility Checker reports, as [WebAIM's guide to it](https://webaim.org/resources/evaloffice/2019) lists them:

- **Errors**: a slide with no title (`pptx-slide-no-title`); a picture, chart, SmartArt graphic, embedded object, or video with no alt text that isn't marked decorative (`pptx-object-no-alt`), or whose alt text holds a file name or extension, which PowerPoint counts as missing (`pptx-alt-is-file-name`: its rule is that alt text "doesn't contain image names or file extensions," [Microsoft says](https://support.microsoft.com/office/rules-for-the-accessibility-checker-651e08f2-0fc3-4e10-aaca-74b4a67101c1)); a table with no header row (`pptx-table-no-header`); and a section that still has PowerPoint's default name (`pptx-section-default-name`).
- **Warnings**: a table with merged cells (`pptx-merged-cells`); a slide whose shapes are read in a different order from how they're laid out, top to bottom and left to right, its title not first, or two shapes that don't overlap read in the opposite order (`pptx-reading-order`); and audio or video with no captions (`pptx-media-no-captions`). Captions count when they're PowerPoint's own, added with Insert Captions: a caption track, a WebVTT file kept in the deck and listed with the clip ([MS-PPTX](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/efd8bb2d-d888-4e2e-af25-cad476730c9f), 2.1.3), that holds at least one cue. A track whose file is missing, empty, or not WebVTT is reported, and the detail says so.
- **Notes**: slides with the same title (`pptx-duplicate-title`) and sections with the same name (`pptx-duplicate-section`).

What the pipeline checks elsewhere, and what older decks are made of, is checked as well:

- Alt text that says nothing: punctuation alone, a word such as "image" or "picture," a clip-art id (`j0309720`), a camera's file name (`IMG_2041`), a shape's default name (`Picture 9`), or a pattern the project lists in `images.alt_placeholders` (`pptx-alt-placeholder`, an error). Alt text that Office generated (`pptx-alt-auto-generated`, PowerPoint's "Review Auto-Generated Description"), which ends "Description automatically generated" in older versions of Office and "AI-generated content may be incorrect." in newer ones ([Clemson University's guide](https://www.clemson.edu/accessibility/digital/guides/powerpoint/images.html) quotes it), or that's longer than `images.alt_max_chars` (`pptx-alt-too-long`).
- Alt text copied from a web page with the picture, the page's title or a stock site's caption (`pptx-alt-page-title`, a warning), found by its form: a site's name after a pipe at the end (`Marketing Mix Explained | Quizlet`), or a domain after a dash, or a one-word name after a dash and a title of three words or more (`Why Do Supply Chains Fail? - Examplepedia`; Creative Commons' `Attribution - By` is a label), a stock or clip-art site's name or its words (Shutterstock, royalty-free, a vector illustration isolated on white), a title cut off with an ellipsis, a search engine's title (`Opportunity Cost - What Is It`), or a numbered section's title followed by its book's. It's a guess made to miss a title rather than name a description: none of the 2,478 alt texts in eight of OpenStax's book repositories matches, nor any of the 167 in its statistics decks. A page's title it misses can go in `images.alt_placeholders` as a pattern.
- One alt text on copies of a picture cropped to show different parts of its image (`pptx-alt-same-for-crops`, a warning). A picture copied and cropped again keeps its alt text, so an image holding a row of icons, cropped to a different icon on each slide, can have the same description on every slide, right for one icon at most.
- A group, or a shape with no text, with no alt text (`pptx-shape-no-alt`, a warning). PowerPoint asks for alt text on these too. A group's pieces without text are the group's to describe, so only the group is named, but a picture inside a group still needs alt text of its own.
- A decorative shape that still has alt text (`pptx-decorative-with-alt`), which a converter may read.
- A picture on a layout or master with no alt text (`pptx-master-image-no-alt`, a note). PowerPoint's checker doesn't look there, but every slide using the layout shows the picture.
- A deck that declares no language (`pptx-no-language`), and a deck whose properties have no title (`pptx-no-core-title`), which a PDF exported from it takes as its own.
- A hidden slide (`pptx-hidden-slide`), and a link whose text is its own address (`pptx-link-bare-url`).
- A diagram drawn from eight or more loose shapes, lines, and one- or two-word labels (`pptx-drawn-diagram`). A screen reader reads each piece on its own. Group it and describe the group, or replace it with a picture that has alt text.
- Columns of text laid out with tabs (`pptx-tab-table`), which a screen reader reads as a run of words, not as a table.
- A font whose license keeps the deck from being edited where the font isn't installed (`pptx-font-restricted`, a warning): one the deck embeds for preview and print only, as the license asks, or that its license forbids embedding. And a deck that uses such a font without embedding it, set to embed its fonts, which PowerPoint won't save where the font isn't installed (`pptx-font-unembedded`, a warning). [Fonts](#fonts) says more.
- XML that PowerPoint can't read as written (`pptx-malformed`, an error): a shape with nothing in it, which stops PowerPoint opening the deck ("Sorry, PowerPoint can't read" it), and a prefix used without its namespace declared, which PowerPoint repairs by removing content. Pandoc's PowerPoint writer writes both: an empty shape for a date when the reference document's title layout has no date placeholder, and `a14` undeclared in a table holding a formula. A copy has both put right ([The copy](#the-copy)).

`images.alt_placeholders` is the project's own list, for junk alt text a corpus turns out to have: each entry is matched against the whole alt text, ignoring case, surrounding spaces, and closing punctuation. An entry starting `re:` is a regular expression that the whole alt text must match:

```yaml
defaults:
  images:
    alt_placeholders: ["slide image", "re:fig\\. ?\\d+"]
```

It's read for a book's images too, whose alt text is judged by the same rules (`lib/alttext.py`): each that needs a person is a row of `image-alt-missing.csv`, with why ([Sidecars](sidecars.md#sidecar-files)). Each check's meaning, severity, and standard are listed in `lib/findings.py`.

## The reports and the sidecars

Each report is written only when it has rows, and a stale one is removed. A report being there means there's something to decide. A row is adopted the way a book's is: fill in the second column and append the row to the sidecar. A header row pasted in again, anywhere, is skipped. The sidecars are read by position, key first and value second, so a sidecar written by hand needs no header row ([Sidecars and reports](sidecars.md)). An `Alt` left blank means what it means for a book's image: checked, and fine as it is. The picture keeps what it has, and the row isn't reported again, which is how a long description someone means to keep stops coming back.

**`image-alt-missing.csv`**, for `image-alt.csv`, has a row for each picture or object whose alt text is missing or says nothing. A picture is keyed on its image's content: `media/` and the first 16 characters of the image's SHA-256, with its extension. The run writes the image at that path in the folder, so the file the row names can be opened. A row covers every copy of the image, on every slide of every deck, and on the layouts and masters too. A logo or a flourish pasted onto 50 slides in 12 decks is one row, marked `[decorative]` once. Since the decision is every copy's, a picture's row names every copy in `Source`, including any whose own alt text was fine, and `CurrentAlt` gives what the copies have now: their alt text, `(none)`, or `(decorative)`. `Reason` says why the row is there: `missing (picture)`, `says nothing (a clip-art id)`, or `too long (227 characters)`. An object with no image of its own (a chart, a SmartArt graphic, a group, a shape) is keyed on `deck/slide-N/shape-M`, where `deck` is the deck's file name without `.pptx`, `N` is the id PowerPoint gave the slide, and `M` the shape's. Those ids last until the slide or the shape is deleted, so moving a slide doesn't break its rows. `deck/media/...` applies a picture's row to one deck's copies alone. The most particular row wins: a shape's own, then its image's in its deck, then its image's anywhere. Two decks whose names are one key (`Deck.pptx` and `Deck.PPTX`) stop the run, since their rows would be applied to both.

A picture cropped to show a different part of its image in different places is a different picture in each, since a crop can show anything from a sliver of the image to all of it. Each copy of one that needs a decision has a row of its own, keyed on its shape as an object is, whose `Reason` names its image (`too long (180 characters); a crop of media/0123456789abcdef.png, which other copies crop differently`), and the image is written where that key points, so the whole of it can be opened. Copies cropped alike, to within a twentieth of the image on every side, show the same part. A picture with a copy on a layout or master keeps its one row, since only its image's key can name that copy. A picture's row in `image-alt.csv` that gives copies showing different parts one alt text is named in a note.

**`table-headers-new.csv`**, for `table-headers.csv`, has a row for each table with no header row. The row has the same columns as a book's table, and the table is keyed on its content the same way ([the header pre-pass](sidecars.md)). The `headers` value is the table census's guess, marked `TI` in `drafted-by`, or empty when the census can't say. A value states the table's headers whole, so each one sets both of PowerPoint's checkboxes, Header Row and First Column. `first-row` checks Header Row and clears First Column, and `none` clears both, which also changes how a table styled with First Column looks. A row left blank, or `manual`, leaves the table as it is. Like any row, it takes the table off the report. `split-at` and `caption-rows` aren't read for a deck, since PowerPoint can't split a table or caption it. Its header row is the first row, whatever that holds.

**`slide-titles-new.csv`**, for `slide-titles.csv`, has a row for each slide with no title, and for each slide whose title an earlier slide in its deck has (`pptx-duplicate-title`), keyed on `deck/slide-N`, with `Slide`, `Title`, `Source`, `Drafted by`, and `Reviewed` columns. A slide with no title is drafted from the heading it shows, when it shows one, marked `TI`: the text of its topmost shape holding words, when that's a shape at the top of the slide's tree (not in a group, not a picture or a table, not styled by the theme), its id no other shape's, and its text a title's length (150 characters and three paragraphs at most), and `Source` names the shape. A slide with an empty title placeholder isn't drafted, since its title goes there. A repeated title's row is drafted too: the title with its number among the slides that share it, `Market Demand (2)` for the second, and `Source` names the slide whose title it repeats. A heading an earlier slide has, or is to have, is numbered so too, `Introduction (2)`. A title for a slide whose title another slide in its deck has takes the old one's place on the slide, where it's seen, so slides titled alike are told apart on the screen and in a screen reader's list of slides alike. A title given as it is keeps it. A row for a slide with a title of its own, that no other slide has, isn't used, and the run names it: the author has given the slide a title since the row was written, and the author's stands.

**`reading-order-new.csv`**, for `reading-order.csv`, has a row for each slide whose shapes are read in another order than they're laid out (`pptx-reading-order`), keyed on `deck/slide-N`. `Order` is a draft, marked `TI`: the ids of the shapes a screen reader reads, the title first, then each shape after every shape wholly above it and every shape beside it and wholly to its left, as the check judges them, shapes the layout leaves in either order kept in the order they're read now; or as near to that as the slide can come without looking any different. A slide with more than 200 shapes to read gets no draft. A slide's shape tree is its reading order and its stacking order at once. A screen reader reads the shapes in the tree's order, and PowerPoint draws them in that order, each over the ones before it, so "changing the order of objects can affect how the slide looks when there are overlapping objects," as [Microsoft says of PowerPoint's own Reading Order pane](https://support.microsoft.com/powerpoint/make-slides-easier-to-read-by-using-the-reading-order-pane). Two shapes whose boxes overlap therefore keep their order, and `Note` says which pairs kept the draft from the layout's order. `Shapes` says what each id is, in the order the shapes are read now: the id, the shape's name, and its text or alt text. A slide where no order nearer the layout keeps what's drawn over what gets no draft, and `Note` says so. Often that's a picture behind the text, read before the title: marked `[decorative]` in `image-alt.csv`, it isn't read at all, and the slide's row leaves the report on the next run. Shapes laid out in a circle, one above the next and that one beside the first, get no draft either, since no order reads each after those above it and to its left.

An `Order` is ids separated by spaces or commas. Only the shapes it names move, each into a place one of them had in the tree, so a shape it leaves out stays where it was. A blank `Order` leaves the slide as it is, and, like any row, takes it off the report.

**`bare-links-new.csv`**, for `bare-links.csv`, has a row for each address a deck's link shows as its text (`pptx-link-bare-url`), in the columns a book's report has ([Bare links](bare-links.md)): `Source` names the slides, `Context` is the text before the link in its paragraph, and `Title` the ScreenTip it has now. A `Replacement` that's an address replaces the link's address and its text, any other `Replacement` its text alone, and a `Title` becomes its ScreenTip. A row left blank keeps the link as it is.

**`math-repaired.csv`** has a row for each equation the copies give the characters it means (`math.repair_equations`), in the columns a book's report has: `Kind` is `equation`, `Page` the deck's file name without `.pptx`, and `Before` and `After` the equation written out in one line, much as PowerPoint's linear format writes it, where a book's are Pandoc's TeX, since a slides run reads a deck without Pandoc. So `z=(x–µ)/σ` before is `z=(x−μ)/σ` after, with a fraction's `/`, a script's `_` or `^`, a root's `√`, a limit over x as `x┴–`, and parentheses round a part of more than one piece. The micro sign and mu look alike in most fonts, as do the increment sign and Delta, so a row repairing only one of them shows `Before` and `After` alike. It records what was done, with nothing to fill in. A row copied from it into `math-keep.csv` keeps that equation as it was, in that deck, or in every deck with a blank `Page` ([Sidecars](sidecars.md#math-kept-as-it-was)). A row that keeps nothing, since no deck it names has that equation as written there, or the repairs wouldn't change it, is warned about.

**`output-check.csv`** has the copies' findings, written once a `source` target has written them, with `Kind` `pptx`. A table that the sidecar says has no headers (`none`) isn't counted against a copy, nor is a slide whose shapes are in the order the reading-order sidecar gives, whatever order a person chose, nor a bare link the bare-links sidecar decided, bare or not.

A sidecar row whose key matches nothing in the decks is named in a note. A deck that changed since the row was written will have its new row in this run's report.

## The copy

A `source` target writes a copy of each deck to its folder, under the deck's own name, and the originals are never touched:

- **Alt text**: each decision goes into the picture's or object's description. For `[decorative]`, PowerPoint's decorative mark is added and the description removed. A shape that was marked decorative and is given alt text loses the mark.
- **Table headers**: each table gets the header row and first column the sidecar decides.
- **Slide titles**: a slide with no title whose title is the text of the heading it shows, as drafted, or that text with a number added, gets that heading as its title, in place, as PowerPoint's Set as Slide Title makes one ([Microsoft](https://support.microsoft.com/en-us/powerpoint/title-a-slide)): the shape keeps its id, its place in the slide's tree, its position, and its text, and becomes a title placeholder, a number added going after its last run in its formatting. A title inherits the master's title style, where the heading inherited its layout's and the master's body style, so what the heading's text inherited is written into the shape's own list style, which its paragraphs and runs inherit before anything else, and its position and text body properties go on the shape as they were, with a default for anything a title would otherwise take from the master. Checked against what PowerPoint's own Set as Slide Title wrote on five slides, three headings in body placeholders and two in text boxes, every paragraph and run came out with the formatting PowerPoint gave it, and the shape with the same position and text body. In LibreOffice, 204 of the 214 slides of ten decks given their headings as titles rendered pixel for pixel as they had: the rest were those whose title had a number added, and one whose text box LibreOffice reads differently as a title, which moved some glyphs by a fraction of a pixel. Any other title for a slide that has none goes above the slide, where a screen reader reads it and the slide doesn't show it, as PowerPoint's Add Hidden Slide Title does, and so does a title for a heading that's in a group, styled by the theme, or on a slide with a title placeholder. An empty title placeholder takes the text and moves above the slide. Otherwise, a title placeholder is added first in the slide's shapes, so it's read first. A slide whose title another slide in its deck has gets the new one in its place: what the new title adds to the old, as ` (2)` does, goes after the old title's last run or equation, in the last run's formatting, and a new title that doesn't begin with the old one takes the place of all its text, in the formatting of its first run and paragraph. Opened in PowerPoint, a deck with a title so numbered looked as it had, the number added in the title's own formatting, and Check Accessibility found no duplicate title.
- **Reading order**: the shapes an order names are put in its order, in the places they had in the slide's tree. A group moves with everything in it, as the Reading Order pane lists a group as one item, and a shape in `mc:AlternateContent` moves with its Fallback. An order isn't written if it would draw two overlapping shapes the other way round, or if it names a shape that isn't at the top of the slide's tree (one in a group moves with the group, by the group's id), an id two shapes share, or one id twice; the run says which order and why. Overlap is judged by the boxes the shapes are drawn in, a rotated shape's box turned with it, stretched to where its geometry reaches past it (a callout's tail or line, a connector's bend, a freeform's points, as the preset shapes' definitions in ECMA-376 place them), a group's to hold its pieces, and each widened on every side by four points, or by the reach of its outline when that's more (its width, or three times it for a line with an arrowhead), since outlines, arrowheads, and the smoothing of edges reach past a box. A shape whose box can't be known, or a freeform whose points can't be read, counts as overlapping everything, and a hidden shape or an empty placeholder, which draws nothing, as overlapping nothing. Text that runs further past its box, and a shadow or a glow, aren't counted. Measured with LibreOffice on real decks, every slide put in order was drawn pixel for pixel as it had been; with boxes widened by one point or two, a few weren't. Since then, one of 18 slides put in order in ten more decks wasn't: LibreOffice fits text that shrinks to fit its box (`normAutofit`) anew as it draws it, and that slide's body text, moved after its title and a table, wrapped and was spaced a little differently. With its autofit taken out, the slide drew pixel for pixel as it had. The fit PowerPoint saved with the text (`fontScale`, `lnSpcReduction`) is in the copy as it was. In PowerPoint, a slide whose title had been moved to the end of its tree was read title last, by NVDA and in Check Accessibility's reading order, and its copy from the drafted order title first, with nothing found.
- **Bare links**: a link the bare-links sidecar decides gets its `Title` as its ScreenTip, and its `Replacement` as its text, and as its address too when the replacement is an address. The new address goes in the link's own relationship, so another link to the old address keeps it, as a named link does on a book's pages, unless PowerPoint wrote the two with one relationship. A link whose text PowerPoint split over several runs is one link: the replacement goes in the first run, in its formatting, and the others go. The ScreenTip is written as PowerPoint writes one from its own dialog, and PowerPoint shows it on hovering over the link, but it's for a mouse: NVDA reads a link's text, and its ScreenTip only when the mouse is over the link in PowerPoint's normal view and NVDA's Report tooltips is on, which it isn't by default ([its settings](https://github.com/nvaccess/nvda/blob/release-2026.2/source/config/configSpec.py#L136)), and never in Slide Show. So the text is what a screen reader gets, and a `Replacement` matters more than a `Title`.
- **Equations**, with `math.repair_equations` (on by default), get the characters they mean, as a Word file's do ([Math](configuration.md#math)), since PowerPoint's equations are the same Office math, except the bar. A bar written as an upper limit, a macron or an en dash set over a letter (x̄ for the sample mean), stays a limit, with a macron in place of an en dash. In PowerPoint, NVDA read an equation by its characters alone, as its source says it would (it takes math from PowerPoint only for [MathType's equations](https://github.com/nvaccess/nvda/blob/release-2026.2/source/appModules/powerpnt.py#L596-L597)): of six ways of writing x̄, the limit with a macron was the only one whose bar it read ("X macron"), and Narrator read that one too ("cap X upper limit overbar"). On OpenStax's decks, 2 of the 73 equations change, each an en dash set over a letter; the other 11 bars are macrons already. Each repair is a row of `math-repaired.csv`, and a row copied from there into `math-keep.csv` keeps its equation as it was ([The reports and the sidecars](#the-reports-and-the-sidecars)).
- **The language**, when the project declares one (`project.language`): it goes where PowerPoint declares a deck's language, in the default text style and the masters' text styles, which every run that names no language of its own inherits. It's written only into a deck with no default language, and a run that names a language keeps it.
- **The title in the file's properties**, when they have none, is the first slide's title (the sidecar's, if that slide has none of its own), since a PDF exported from the deck takes the properties' title as its own.
- **Fonts**, with `fonts.restricted: replace` or `fonts.replacements` ([Fonts](#fonts)): another font in place of one a license restricts, or one named for replacing, in the text, bullets, and themes, with its PANOSE, pitch, and character set where the deck gives them, and the restricted font's embedded files taken out.
- **The file's lists of fonts and slide titles**, where the fonts or the titles change. PowerPoint keeps a list of the fonts a deck uses and one of its slides' titles in the file's extended properties (`docProps/app.xml`), and writes both afresh when it saves. A copy's lists name the replacement in place of the font it replaced, and each title the copy wrote, so what reads them before PowerPoint saves the copy finds what it holds. Lists named in another language, as PowerPoint in another language writes them, or that don't add up, are left as they are.
- **What PowerPoint can't read as written** (`pptx-malformed`), where putting it right loses nothing: an empty shape is taken out, and a prefix used without its namespace declared is declared on the part's root. A deck Pandoc wrote with each, which PowerPoint wouldn't open or repaired by removing content, opened in PowerPoint with only that repair made. A part with something else wrong is left as it is, and its copy's check names it.

The language and the title come from the project and the deck, and the repairs from the file itself, not from a sidecar. Everything else in a copy is what a person decided, in a sidecar or a setting.

Each part of the deck is copied byte for byte unless a decision changes it, and the XML of the parts that change is edited as text, never parsed and written again. A shape in `mc:AlternateContent` is edited in both its Choice and its Fallback, which carry the same id. A decision about a shape whose id its slide repeats, which PowerPoint repairs when it opens the file, is skipped, and the run says how many were.

On the OpenStax decks, with every row of `image-alt-missing.csv` decided (155 described and 10 marked decorative), the copies' check finds nothing. Their changed parts are well-formed XML, the rest is byte for byte, and LibreOffice opens them and exports them to PDF.

A target's `archive` setting packs its folder into one file once the folder is written: `zip` or `tar.gz`, beside the folder and named after it (`remediated.zip`), holding the folder. Nothing is archived in a run where a deck couldn't be read or a copy couldn't be read back, so an archive is never part of the set. Later runs don't read the archive as a source to unpack:

```yaml
targets:
  remediated:
    format: source
    archive: zip
```

## Fonts

PowerPoint can embed the fonts a deck uses in the file (Embed fonts in the file, in PowerPoint's options), so the deck looks the same on a computer without them, and a font's license says how it may be embedded: installable, editable, preview and print only, or not at all ([the OpenType specification](https://learn.microsoft.com/en-us/typography/opentype/spec/os2#fstype)). A deck that embeds a font for preview and print only opens read-only on a computer that doesn't have the font, as the license asks, and a deck that uses such a font without embedding it, set to embed its fonts, won't save on one: PowerPoint says the font isn't available. Both were seen in ten decks made with Avenir Next, which macOS has and Windows doesn't: six embedded it for preview and print only, and the other four used it without embedding it, one of which PowerPoint opened for editing and then wouldn't save. An embedded font can be a subset, too: with "Embed only the characters used in the presentation" chosen, it holds only those, and PowerPoint's options give "Embed all characters" as "best for editing by other people".

A font is known to be restricted when any deck of the run embeds it so, and the run says how many decks use it and how:

```
WARNING: 10 of 10 deck(s) use the restricted font Avenir Next, whose license lets a deck embed it for preview and print only: 6 embed it, so PowerPoint opens them read-only where Avenir Next isn't installed; 4 use it without embedding it, set to embed their fonts, so PowerPoint won't save them there. Set fonts.restricted: replace for the copies to use another font in its place: the nearest each deck uses (Arial), or the one fonts.replacements names.
```

By default (`fonts.restricted: keep`), a copy keeps the font, and its check names it again. With `fonts.restricted: replace`, a copy uses another font in its place: the one `fonts.replacements` names, else the font the deck already uses whose PANOSE is nearest, the ten digits a deck writes beside a typeface to say how it looks (the kind of font, its serif style, weight, proportion, and so on). Nearest is the same kind of font, then the same serif style, then the fewest digits apart. The restricted font's embedded files go, with the presentation's list entry and relationships for them, so the copy opens for editing anywhere. A deck that embeds the font with a license that lets it be edited keeps it, and a deck with no font near it keeps it too, and the run says to name one. `fonts.replacements` replaces whatever it names, restricted or not:

```yaml
defaults:
  fonts:
    restricted: replace
    replacements:
      Avenir Next: Arial
```

Text set in another font can take more room or less, so a copy's slides are worth a look.

## What a person still does

Some findings ask for work in PowerPoint itself, and the copy doesn't change them:

- **Reading order on a slide where nothing can move** without changing how it looks, which the report's row says. A picture behind the text that carries no meaning can be marked decorative, which takes it out of what's read, or made the slide's background in PowerPoint, where it isn't a shape at all. Otherwise it's the author's to lay out again, or to put in order with PowerPoint's Reading Order pane and accept the change in how it looks.
- **Drawn diagrams and tab tables** are the author's to rebuild: a group with alt text or a picture for the one, a table for the other.
- **Media captions**, for a clip reported as having none, go in through PowerPoint's Insert Captions, from a WebVTT file. Captions burned into the video's picture can't be seen in the file, so a clip that has only those is reported too.
- **An old Equation Editor object** (`Equation.3`) is a picture of a formula to a screen reader. It needs alt text now, and retyping in PowerPoint's own equation editor later.

## Decks written in Markdown

A deck written in Pandoc's slide Markdown, a slide at each heading of the slide level and its speaker notes in `::: notes` divs, is read, filtered, and reported on as a page of a book is: the same sidecars decide its pictures' alt text, its tables' headers and captions, and its bare links, and the same reports ask for them. Nothing in a Markdown file says it's a deck rather than a page, so the folder has to: `project.kind: slides`.

```yaml
# project.yaml
project:
  identifier: edu.example.econ205.slides
  title: Principles of Economics, the slides
  language: en-US
  kind: slides
```

Each `.md` file there is a deck, but for a repository's own (`README.md` and the rest), named as a book's page would be (`S05 Value and Demand.md` is `S05-Value-and-Demand`). A deck can be written as an `html` target, a `pdf` target, a `pptx` target, a `revealjs` target, a `markdown` target, or a `source` target; with none declared, the run implies `html`, as a book's does. A target of another format is skipped, and the run says so. A folder holding both PowerPoint decks and Markdown ones stops the run, since one run reads one kind for now, and so does one holding no deck at all. Word, HTML, and AsciiDoc files beside the decks are left out, and the run names them. Slides aren't packaged yet.

```yaml
# conversion.yaml
targets:
  pages:
    format: html
  pdf:
    format: pdf
  powerpoint:
    format: pptx
```

The slide level is Pandoc's: the shallowest heading level that something other than a heading follows somewhere in the deck, or the deck's own `slide-level` in its YAML. It's worked out once, when the deck is read, and the page's headings and the PDF's slides follow it. A heading above it begins a section, as Pandoc's slide writers take one. A title, subtitle, date, or language the YAML gives as a list of one (`title:` and `- The Title` on the next line), which Pandoc's writers lose, is read as the value, for a book's Markdown pages too.

### The page

A deck's page opens with its title block, which plays its title slide's part: the deck's title, as the page's one H1, and its subtitle, authors, and date. A deck's authors stay on its page whatever `author_byline` says, as they're on its title slide. Its sections and slides are headings below that, each at its level among the sections around it: a section's heading is an H2, one in a section an H3, and a slide's heading one below the sections it's in, so a slide before the first section, as an agenda often is, is an H2, as a section is, and one in a section an H3. A heading in a slide, which beamer makes a block, is one below the slide's, with no level skipped whatever levels the deck gives it, and so is one in a slide's notes, a quotation, a list, a table, or a figure, whatever its level, since Pandoc's slide writers find no section there; one with nothing in it, as a block with no title has, is no heading. A deck with no title has no H1 above them, so its headings start at H1. A pause (`. . .`, a slide's next step) is left out. With `pages.split_level`, a deck is cut into a page per section or per slide, as a book's file is cut into pages, each headed by its section's or slide's title, its footnote with it, the headings under it placed as the whole deck's page places them, from H2, none skipped. A section or slide in a div, as a passage in another language holds one, is cut there too, its title in the passage's language, and a section with nothing of its own but a footnote in its title is a page, as it's a slide in the PDF.

A slide's notes go under its content, as `slides.notes` says: `collapsed`, the default, in a `<details>` element a reader opens, its control labeled `slides.notes_label` ("Speaker notes"); `visible`, the same element open; or `omitted`, left off. Browsers give a screen reader a disclosure's control as a button with its state, open or closed, and leave what it holds out while it's closed; an `<aside>` per slide would have made every slide's notes a landmark of the same name for a screen reader to list. The label is in English unless the setting gives it in the page's language:

```yaml
targets:
  handouts:
    format: html
    slides:
      notes: visible
      notes_label: Notas del orador
```

### The PDF

A `pdf` target writes a PDF of each deck, through [ltx-talk](https://ctan.org/pkg/ltx-talk), a presentation class built for LaTeX's tagging: Pandoc's beamer writer, a template of ours (`bin/ltx-talk.latex`), and LuaLaTeX, run until the cross-references settle, four times at most: a deck whose cross-references are still changing after the fourth is named in a warning, since a footnote's link or a link within it may go to the wrong page. Each PDF claims the standards `pdf.standard` names (PDF/UA-2 by default), and its formulas carry their MathML as a book's PDF's do. A deck's PDF is the whole deck, whatever `pages.split_level` cuts its pages into.

- **Headings**: a slide's title is tagged as a heading at the level of the sections around it, where ltx-talk's own default is H4 for every one: H1 for a slide in no section, as on a deck without sections or an agenda before the first, H2 in a section, H3 in a subsection: a level above where a titled deck's page has it, under the page's H1, the deck's title, since PDF/UA-2 tags a document's title as a title and never as a heading (ISO 14289-2, 8.2.5.13), H1 being a PDF's top heading level (ISO 32000-2, 14.8.4.5), as a book's PDF has its chapters' headings at H1 under its title. NVDA in Acrobat counts only H1 to H6 as headings, so it reads the deck's title as text. A block's title (a heading below the slide level), and a heading in a quotation, a list, or a table, is a heading at the level the deck's page gives it: one below the slide's title, and one more for each block's title or heading before it, in reading order, that it's under by the levels the deck gives them: ltx-talk set a block's title as a paragraph, and the writer's `\section` in a quotation was lost. A block with no title has no heading, as on the page. A section has a slide of its own, as in beamer and PowerPoint, its title the slide's heading, H1 for a section and H2 for a subsection; ltx-talk would have tagged it as a heading of no content, its title as actual text, shown on no slide. Sections are numbered for LaTeX in the order of their levels, so a deck whose sections are `##` and slides `###` has the same headings as one at `#` and `##`, and none is skipped. Every slide with a title is bookmarked, under the section it's in.
- **The title slide** shows the deck's title, subtitle, authors, institute, and date, from its YAML, and no date when the YAML gives none.
- **The slide's shape** is `slides.aspect_ratio`: `auto`, the default, takes the deck's own `aspectratio` as beamer reads it (`169`, `43`, `1610`, and the rest), else 4:3 for a deck that names a theme or another of beamer's variables, since that's what its author saw (a theme of reveal.js's own, `white` or `black`, doesn't count), else 16:9, PowerPoint's default. A ratio given (`16:9`, `4:3`) is every deck's. A picture as wide as a 16:9 slide can be taller than a 4:3 slide has room for, and the other way round.
- **Links** are colored, where ltx-talk hides them: `#0066CC`, which has 3.8:1 against black text and 5.6:1 against white, as WCAG's G183 asks of a link told apart by its color alone, unless the deck's YAML sets `linkcolor` or `urlcolor`.
- **Speaker notes** are left out, since ltx-talk has no notes yet.
- **Footnotes**: a footnote in a slide's title keeps its mark in the title and its text at the foot of the slide, where ltx-talk lost it. One in any other heading keeps its mark there and has its text after the heading, where it had been inside the heading and a screen reader read the note as part of it: on a section's slide after its heading, at the head of a block, and after a heading in a quotation or a list. A note set after its heading is in the heading's language, or the language of a passage its mark is in. One in a table, which the writer gives as a mark and its text apart, is set, where ltx-talk 0.6.9 never finished, its text after the table, and a caption's after its figure, where LaTeX would count its mark twice, so a reader meets each note after what it's about. Those are numbered in order with the deck's others, and each mark is a link to its note, the two tied by a `/Ref` each way, as PDF/UA-2 asks of a footnote (8.2.5.14) and as LaTeX ties its own footnotes; in PDF/UA-1 a footnote's mark is no link, as a book's isn't. A footnote in an image's description is left out, as the writer leaves it out.
- **A passage in another language**, a span, a link, or a div with `lang`, is tagged with its language, which a screen reader speaks it in: a passage that begins a paragraph or a list item as part of it, a slide's title by its words, and a div holding slides a block at a time, so it spans none of them. A book's PDF, built through babel, doesn't mark one.
- **beamer's commands** in a deck's `header-includes` that ltx-talk hasn't, for its themes, colors, fonts, templates, and options (`\usetheme`, `\setbeamercolor*`, `\setbeamertemplate`, `\setbeameroption`, `\AtBeginSection`, `\logo`), do nothing, and the run names them, where LaTeX had stopped on them. beamer's modes are ltx-talk's: what `\mode<...>` would show in beamer's presentation is `projector`, the mode the PDF is built in, anything else is `article`, which it doesn't show, and `\mode*` goes.
- **Code**: highlighted code's spaces are characters in the PDF's text, which a screen reader reads, each one, as in a book's PDF: under LuaLaTeX a space beside a colored word had been none at all (`return12-2* p >0`), and a run of them, as an indentation is, one. A code block in a footnote is set in the note, as in a book's PDF, where LaTeX had stopped on it, and so is highlighted code in a section's footnote.
- **A slide shown in steps**, one with a pause (`. . .`), is a page per step, each showing a little more, and ltx-talk tags only the last, the whole slide, so a screen reader reads the slide once. The earlier steps' links are taken out, those in what a step hasn't shown yet too: left untagged, a screen reader in Acrobat read them as links saying "artifact", and keyboard focus landed on links no one could see. The last step keeps every link, so presenting from the PDF, a link on such a slide works on its last step and not before. The run notes how many it took out, and from which decks.
- **What ltx-talk takes differently from beamer** is put right in the writer's LaTeX: a slide holding code is set with ltx-talk's `frame*`, which can read a verbatim body, and code is left as written, a slide's `\end{frame}` in it too; a slide's `{.allowframebreaks}` becomes ltx-talk's `auto-break` (`allowframebreaks=0.8` its coverage too), `{.t}`, `{.c}`, and `{.b}` its alignment, and `{label=...}` stays, while options ltx-talk has no key for (`{.plain}`, `{shrink=10}`) are left out and named; columns' alignment and `totalwidth` become ltx-talk's; a footnote loses beamer's overlay; a numbered list's style (`a.`, `(i)`, `1)`) is LaTeX's label, where ltx-talk set beamer's template as text and stopped; a section's title can hold an `=` (`Profit: MR = MC`), which ltx-talk would have read as a setting; a link to a slide, a block, a heading, or anything else with an id goes there, where the writer's `\hyperlink` names a destination beamer makes of a `\label` and ltx-talk's `\label` doesn't, and every such link went to the PDF's last page; and a slide with no title, one a horizontal rule begins, gets an empty one, which ltx-talk neither shows nor tags. Example and alert blocks are plain blocks. Struck, underlined, and highlighted text, a table's cell spanning rows, and the colors xcolor names (`NavyBlue`) are loaded as Pandoc's own templates load them.
- **Fonts**: ltx-talk's New Computer Modern Sans, whose bold face, the one a slide's title is set in, has no `<` or `>`; a character a face lacks comes from the regular face, then Latin Modern Math, then DejaVu Sans where it's installed.
- **After LaTeX**, a table's caption is retagged as its caption and the empty paragraph elements LaTeX leaves are taken out, as in a book's PDF (`pdf.repair_captions`, `pdf.remove_empty_paragraphs`), and the links of earlier steps go, and so does a footnote's `/Ref` to the mark in a table's head that LaTeX sets again to repeat it, an artifact the captions' repair takes out; all of it needs pikepdf. An SVG picture is made a PDF first, with `rsvg-convert`, as for a book: without `rsvg-convert` a run whose decks show one stops before LaTeX, saying what to install, and an SVG it can't read stops its deck's PDF, saying which and why, since LaTeX can't show an SVG. A LuaLaTeX run that hasn't finished in five minutes is stopped, and its deck's PDF isn't built. `pdf.metadata` isn't read: the template and the deck's YAML are all there is.

A deck's PDF needs LuaLaTeX with LaTeX 2026-06-01 or later, and the `ltx-talk`, `lua-unicode-math`, and `newcomputermodern` packages, which TinyTeX doesn't install with LaTeX ([Installation](installation.md)); the run stops, saying what's missing, without them. Built from a course's 25 decks written for beamer, a conference talk written for PowerPoint, and a lecture with speaker notes, every PDF passed veraPDF's PDF/UA-2 profile; the eight decks that named a theme had as many pages as beamer gave them, 152. So did 27 small decks made to hold what the code has to handle (an agenda before the first section, sections at `##`, footnotes in a table and in titles, lettered lists, passages in other languages, code that shows a frame), and 13 of them built as PDF/UA-1 passed that profile too.

### The PowerPoint file

A `pptx` target writes a PowerPoint file of each deck, through Pandoc's PowerPoint writer, with what the writer leaves out or gets wrong put right before it writes (`bin/deck-pptx.lua`) and after (`lib/pptxtarget.py`), each found by reading the writer's code (Pandoc 3.12.1) and its output. It needs Pandoc 3.10.1 or later, whose writer keeps a table and the text around it on one slide; with an older one the run stops, saying so. A book's `pptx` target writes nothing, and the run says so.

- **The look and the slide's shape**: Pandoc's own reference document, its master and layouts in Office's theme, its slides the shape `slides.aspect_ratio` gives, as the PDF's are, at the size PowerPoint gives that shape. 16:9 is PowerPoint's Widescreen, 13.333 inches by 7.5, a new deck's size in PowerPoint since 2013. Pandoc's document is PowerPoint's older On-screen Show (16:9), ten inches by 5.625, the same shape a quarter smaller, so its layouts, and their text, are made a third larger, as PowerPoint scales a deck's when its size changes: a slide's title is 44 points and its text 32, where Pandoc's are 33 and 24, and a slide holds about what it would at Pandoc's size. `slides.size: on-screen-show` keeps Pandoc's size. A 4:3 or 16:10 deck is ten inches wide, as PowerPoint makes one, its layouts Pandoc's scaled down the slide, so a 4:3 deck's placeholders are where PowerPoint's own 4:3 template has them, in Pandoc's sizes. A table takes PowerPoint's Light Style 1 - Accent 1, its text the theme's dark color, its header row in bold over a rule in the theme's blue, and its rows banded in a pale blue: Pandoc's document gives Medium Style 2 - Accent 1, whose header row of white on that blue, in its theme's colors (Office 2007's), has a contrast of 4.0:1, under the 4.5:1 PowerPoint's Accessibility Checker asks for, and the checker reported the tables. `slides.reference_doc` names a PowerPoint file of your own instead, whose size, master, layouts, fonts, colors, and default table style the files take, as Pandoc's `--reference-doc` takes them; `slides.aspect_ratio` and `slides.size` aren't read then, as the run notes, and the file isn't taken for a deck when it's in the decks' folder. When the file's default table style, which the writer gives every table, is one of PowerPoint's whose header row hasn't 4.5:1 in the file's colors, the run warns of it: another style set as the default (in PowerPoint, right-click one in Table Design's gallery and choose Set as Default), or a darker color in the file's theme, is the fix. The writer finds its layouts by name, as [Pandoc's manual](https://pandoc.org/MANUAL.html#option--reference-doc) says (Title Slide, Title and Content, Section Header, Two Content, Comparison, Content with Caption, and Blank), so a layout renamed or deleted in the file is one the writer takes from its own reference document instead, which may not match the file's look or size, and the run warns of it. Renaming a layout back, in PowerPoint's Slide Master view (View, then Slide Master), is the fix.

```yaml
targets:
  powerpoint:
    format: pptx
    slides:
      reference_doc: department-template.pptx
```

- **Pictures**: a picture's description is its alt text (the sidecar's, the image's `alt` attribute, or its description), or PowerPoint's decorative mark for an image marked decorative, where the writer gives every picture its file's path, which PowerPoint's checker counts as no alt text. A figure's caption shows under its picture, as on the page and in the PDF, and an image that isn't a figure has none, where the writer showed every picture's alt text as its caption and left a figure's own out. A figure of more than one picture, a `::: figure` div, shows each picture, its caption under the last, where the writer wrote each as its alt text; a picture's own caption in it that repeats its alt text, which the page hides from a screen reader, gives way to the figure's. A caption that repeats its picture's alt text has the decorative mark, as the page hides such a caption from a screen reader, so the words are read once. NVDA doesn't heed the mark on a text box, and reads such a caption after the alt text, the words twice; leaving the caption off would take it from every sighted reader, so it stays. A caption longer than a line gets the room it needs, its picture made smaller above it. An SVG is a PNG made with `rsvg-convert`, the SVG beside it, as PowerPoint inserts one: PowerPoint shows the SVG, and a program that can't shows the PNG; without `rsvg-convert` a run whose decks show one stops, saying what to install. An image in a line of text, a list, or a table is written as its alt text, since the writer makes a picture only of an image that begins a paragraph, and the run counts them.
- **A slide cut in two**: the writer puts a slide's pictures where its other content goes, over the text or table before or after them or over each other, and begins a slide with no title at a slide's second table, at a table after a picture, and after a slide's columns. So such a slide is cut where the writer would draw one shape over another or begin a slide with no title, each part after the first titled as the slide is with its number after it, `Supply (2)`, as a second title is given in a PowerPoint deck's copy ([The copy](#the-copy)). Text and then a picture stay on one slide, the text beside the picture, the writer's own layout. A link to something on a part goes to that part, and the slide's speaker notes go with the part they're on. The run says how many slides were added, and to which decks.
- **Tables**: a table's header row is PowerPoint's Header Row, as the writer marks it, and its header column, which the writer doesn't mark, is its First Column. Its caption is read before it, as on the page and in the PDF, and shown above it, as in the PDF, where the writer put it under the table and read it after. A table taller than the room it has, down to the slide's foot or to the text the writer puts under it, is set smaller, to three quarters of the master's size at least (10 points of Pandoc's 13.5, 13.33 of a Widescreen slide's 18), to fit, where the writer sets every table at the master's size and PowerPoint doesn't shrink a table: a table of twelve rows doesn't fit a 16:9 slide at the master's size. The writer shares a slide out between a table and the text around it by their rows and paragraphs, not by the room each needs, so a table with text under it is often set smaller than one alone.
- **Text** too much for its box is shrunk as PowerPoint's "Shrink text on overflow" shrinks it, which the master asks of its placeholders and PowerPoint does only once the text is edited: the scale it would record is worked out from the text's size and length and written, so the slide opens fitted, as such slides did in PowerPoint. It's an estimate, a character taken as half its size wide on average, so text can still come out a little short of its box or over it, and editing the text has PowerPoint fit it again. The run names the slides whose text is shrunk below half its size, and warns of any too much for its slide even at a quarter of its size, as it does of a table too long for its slide at three quarters of its size; cutting the slide in two in the deck is the fix for either.
- **Equations** are PowerPoint's own, as Pandoc's writer makes them, with a bar over a letter (`\bar{x}`) an accent of the macron, as a Word file's is ([Word output](formats.md#word-output)), where the writer's is an accent of the overline: in PowerPoint's normal view Narrator reads it "overbar", where it read nothing for the overline, and LibreOffice draws it as a bar, where it drew the overline as an acute accent. NVDA reads no accent's character in PowerPoint, a bar's or a hat's (`\bar{x}` is "x" to it, `\hat{y}` "y"), and an equation by its characters alone. Each shape or table holding an equation has a fallback, shown by a program that reads no PowerPoint equation: the shape, with each equation written as a line of text (`x̄ = 1/n∑xᵢ`). Without one, LibreOffice showed nothing of such a shape, a slide's title or its other words included. PowerPoint itself gives such a shape a picture of each equation instead.
- **A display equation** is set off from the text around it by half a line's space above it and below it, as on the page and in the PDF, where Pandoc's master gives it a fifth of a line, as it gives every paragraph; the writer makes each a paragraph of its own, the deck's text before and after it in the same paragraph one each. PowerPoint showed no space before a paragraph holding an equation, though the file gave it some, so the space above an equation is given after the paragraph above it, in that paragraph's lines (more of them where its text is smaller, as a list's second level's is), and the equation's own is none. Where the deck gives it space of its own, an empty paragraph (one holding only `&nbsp;`) or a line break (a `\` at the end of a line) before or after it, none is added there, and none is added above an equation at the top of a slide's text, since there's no text above it. A `\vspace` before or after an equation adds to its space, as below.
- **Vertical space** the deck gives in raw LaTeX, which the writer leaves out, is given before the text after it, as LaTeX gives it in the deck's PDF: `\vspace{...}` and `\vspace*{...}`, `\addvspace{...}`, `\vskip`, and `\smallskip`, `\medskip`, and `\bigskip`, alone on a line, or at the start or the end of a paragraph. It's in proportion to the slide's text as it is to the PDF's, where 11-point text is set on lines 13.6 points apart, so a line of space there is a line on the slide: `\bigskip` (12 points) is nearly a line, `\medskip` nearly half, and `\vspace{1em}` four fifths, whatever the slide's text size. It's added to the space the text has already, as LaTeX adds it: a paragraph's usual fifth of a line, a display equation's half line, or a heading's 30 points. Space less than none, `\vspace{-1em}` say, leaves none, as close as PowerPoint comes; space at the top of a slide's text, which PowerPoint leaves out of a text box's first paragraph, is kept there by asking the text box to respect it (which LibreOffice doesn't). Space that stretches to fill the slide (`\vfill`, `\vspace{\fill}`) has no counterpart in PowerPoint, and space with no text after it on its slide, or before a picture or a table, which are shapes of their own, is left out, as the writer leaves it out, and the run warns of it with the rest. The run counts the spaces given.
- **Speaker notes** are the slides' notes in PowerPoint, unless `slides.notes` is `omitted`, which leaves them out of the files too. A notes div with another class too (`::: {.notes .private}`) is its slide's notes, where the writer showed it on the slide, and notes between a slide's heading and its columns stay with the slide, where the writer left the heading a slide of its own.
- **Footnotes** are on a slide of their own at the end, titled Notes (a deck's `notes-title` names it otherwise), each mark a link to it, as Pandoc's writer makes them.
- **A pause** shows nothing: its slide shows all at once, since Pandoc's writer shows only an incremental list's items one at a time, and the run counts them. A `::: incremental` list is shown an item at a time, as in the PDF, its animation tied to the shape holding the list, where the writer, on a slide with a table's caption or text around a table, tied it to another shape.
- **Links**: a link to a heading goes to its slide; one to anything else with an id, a figure, a table, or a div, goes to the slide it's on, where the writer took the link out; one to a place on a slide with no heading isn't a link in the file, its words kept, and the run counts them.
- **The title slide** shows the deck's title, subtitle, authors, its institute under them, where beamer puts it, and its date.
- **The file**: the deck's language on its text and on the styles all its text inherits, in place of the reference document's US English, since the writer writes none; its title in its properties (the deck's `title-meta`, else its title, else its file's name), its authors as its creator, and its custom properties the deck's own fields alone, where the writer wrote every metadata field there, beamer's and the pipeline's included; its slides' titles in the list PowerPoint keeps of them, where the writer copied the reference document's; each shape's id its own on its slide, where the writer gives every picture 0 and every table 6; and what PowerPoint can't read as written put right, as in a PowerPoint deck's copy: an empty shape taken out, and the prefix of an equation in a table's cell, which the writer doesn't declare, declared.
- **What the writer leaves out**, which the run names from its log: a slide's columns past the second, what follows a slide's columns inside its columns div, raw HTML or LaTeX, as a block or in a line of text (but the vertical space above), a table or a horizontal rule in a list or a quotation, and, in a column, what follows a second table, a table after a picture, or a horizontal rule. A comparison slide, whose columns each hold text and then a picture or a table, the writer shows whole. A column holding two pictures, or a picture and text, or a comparison's picture and table, the writer draws in one place, and the run names the slide. The writer's own warnings, as of an equation it can't read, which it writes as its TeX, the run passes on.
- **A passage in another language** is in the deck's language, since the writer writes no language of a passage's own, and the run counts them.

Each file is checked as a PowerPoint deck is ([What's checked](#whats-checked)), into `output-check.csv`. Written from a course's 25 decks written for beamer, a conference talk, a lecture with notes, and the 27 small decks made to hold what the code has to handle, the check finds only what the decks themselves hold: pictures with no alt text, alt text over `images.alt_max_chars`, slides that share a title, bare links, and a slide a rule begins with no title; LibreOffice draws them with no shape over another and no table off its slide.

Small decks made to hold what the code handles, and three of the course's, were opened in PowerPoint for Windows, and the small decks read with NVDA and Narrator. PowerPoint showed them as written, their links, a list's steps, an SVG, the tables and text set to fit, a bar over a letter, and the deck's vertical space, at the top of a slide's text too, working as meant, but no space before a display equation, which is why it's given after the paragraph above (not yet tried in PowerPoint). Its Accessibility Checker found too little contrast in Pandoc's tables, and with the table style above, only a slide the deck gives no title. NVDA read each slide's title, text, and pictures' alt text, and passed over a decorative picture. It reads a caption marked decorative ([above](#the-powerpoint-file)) and an equation by its characters, and it announces no table's header row or column and says nothing as a list's steps appear, neither of which its PowerPoint support has ([its source](https://github.com/nvaccess/nvda/blob/release-2026.2/source/appModules/powerpnt.py)). Narrator, in Slide Show, read only each slide's title, and reads a slide's text in PowerPoint's normal view. Microsoft documents the same of PowerPoint for the web: Narrator doesn't read a slide's content in Reading view, Slide Show, or the Notes pane, and File, Help, Accessibility Mode shows a deck as an outline a screen reader reads ([Using Windows Narrator in Office for the web](https://support.microsoft.com/en-us/accessibility/office-accessibility/using-windows-narrator-in-office-for-the-web)).

### The reveal.js presentation

A `revealjs` target writes each deck as a [reveal.js](https://revealjs.com) presentation, a page named as the deck's page is, for presenting in a browser, through Pandoc's reveal.js writer and what `lib/revealtarget.py` puts right in what it writes. The deck's page is the one to read: the presentation shows one slide at a time, as a projector does. It loads reveal.js from a copy beside it, which the run takes from `REVEALJS_DIR`, the folder of reveal.js 6 (its package from the npm registry, unpacked, or `npm install reveal.js@6`'s `node_modules/reveal.js`; [Installation](installation.md#for-a-revealjs-target-revealjs) has the commands): without one, or with another version, the run stops, saying so. It needs Pandoc 3.12 or later, whose template loads reveal.js 6's plugins.

```yaml
targets:
  present:
    format: revealjs
```

- **What it loads** is the copy beside it, its license with it: Pandoc's template loads reveal.js from unpkg.com, with `^6` in each address, which the Nu checker calls an illegal character, and which an LMS or a reader offline may not reach. Each picture's address is `src`, where the writer gives reveal.js's `data-src` for it to load later: without the script there was no picture, and the Nu checker reported each as missing its address. A picture the deck has load lazily (`{loading=lazy}`) loads with the page too, since a slide reveal.js hides is never near enough to load it, and the slides are fitted once their pictures are in.
- **For a screen reader**, reveal.js's `role="application"` on the whole presentation goes, so a screen reader reads the slide shown as a page, where NVDA treated it as an application and read a slide's formulas as their letters and its tables cell by cell. reveal.js's live region, which announced each slide as its text run together, is silenced, and as a slide is shown its title takes focus, the slide itself where it has none, and as a step of a slide appears, what it shows, so a screen reader reads it and reads on from there. A link within the presentation takes focus to its place: a footnote's mark to its note, the note's way back to the mark, and a link to a slide to the slide's title, where reveal.js did nothing for a place on the slide shown. reveal.js hides the other slides from a screen reader, as before. Each heading is at the level the deck's page gives it, the deck's title the one H1, and a block with no title is no heading, as on the page.
- **Zooming**: a reader on a phone or a tablet can zoom, where the template's viewport stopped it. reveal.js scales a slide to its window, so zooming a laptop's browser doesn't enlarge a slide's text, and a narrow window makes it small; so a window 1000 pixels wide or less (a phone's, a tablet's held upright, or a laptop's zoomed past about 130 percent) shows the slide as a page instead, its text the size it has on the slide, which zooming enlarges, reflowing to the window's width, and scrolling, the up and down keys, the page keys, Home and End, and space scrolling the page, and the left and right keys going from slide to slide. A slide's page starts at its top, and scrolls to a step as it appears and to a link's place as it's followed. On a phone or a tablet that page's text is a page's size. reveal.js's overview of the slides (Escape) isn't offered there, where it showed nothing. reveal.js's own scroll view, which scales each slide to a narrow window's width, is off.
- **The slides** are the deck's shape, as in its PDF and PowerPoint file (`slides.aspect_ratio`), 720 of reveal.js's pixels high: 16:9 is 1280 wide, 4:3 960. A section's slides follow it in one row, where the writer stacks them under the section's slide, so the right arrow went past them. The look is reveal.js's white theme (`#222` text on white), whatever theme the deck's YAML names, with the PowerPoint file's proportions: text 42 pixels, as the theme has it and as the PowerPoint file's 32 points are on a slide 7.5 inches high, a slide's title 1.375 times that, in its own case, where the theme sets headings in capitals; links in `#0066CC`, as in the PDF, and underlined. The controls' arrow back is as plain as the arrow on, where reveal.js fades it to three tenths, too faint to make out well. Code is highlighted in Pandoc's colors, as on the page.
- **A slide too tall** for its frame is fitted: its pictures are kept to three fifths of its height, and what's under its title is set closer, then smaller, in the steps PowerPoint's "Shrink text on overflow" takes, as in the PowerPoint file, to a quarter of its size; a slide too tall even then scrolls, its keys the narrow window's page's. reveal.js would have run it off the bottom of the window: 154 of the 339 slides of a course's 17 decks, a conference talk, and a lecture did. Fitted, none runs off, and 26 are set smaller or closer, one to under half its size.
- **Footnotes** are at the foot of their slides, as in the PDF, where the writer gathered them on a slide at the end. Formulas are MathML, as on the page.
- **Speaker notes** are in reveal.js's speaker view (press S), shown under each slide to everyone with `slides.notes: visible`, and left out with `omitted`. A pause shows the rest of its slide as its next step, and an incremental list an item at a time.
- `slides.reference_doc` and `slides.size` aren't read for a presentation, and the run says so when they're set.

Each presentation gets the output check a page gets ([What's checked](#whats-checked)), the Nu checker's among them, which reads a link within it as reveal.js's route to the slide, `#/` and an id. Written from the course's 17 decks, the conference talk, and the lecture, it finds only what their pages have: pictures with no alt text, header cells holding only a formula, and alt text that repeats a file's name. A slide with no title, which the run names, is a section with no heading in the presentation, as reveal.js needs a section for each slide, and the Nu checker warns of it; on the deck's page it's a rule and what follows it. Fitting, focus, and the narrow window's page were tried in Chromium, from a phone's width to a laptop's. The presentations haven't yet been read with NVDA, which found the most in reveal.js's own; whether that's enough to make reveal.js accessible is for that to say.

### Markdown again, and the source

### What the run says about the decks

- Slides with no title: one a horizontal rule begins without a heading after it, and text before the first slide's heading, which Pandoc's slide writers make a slide with no title. A heading of the slide level gives one, and a screen reader moves through a deck by its titles.
- A deck that names its language `language:`, which Pandoc doesn't read (its name is `lang`). The run writes the project's language either way.
- A deck with no title: its page is named by its file's name, and its PDF has no title slide.
- A heading in a deck's speaker notes that sets its slide level, as a cue written `# Cue` in the notes does: Pandoc takes the shallowest heading that something follows, in the notes too, so the deck's sections become slides and its slides their contents. The run says what the level would be without it; bold text in the notes, or `slide-level` in the deck's YAML, keeps the deck's own.
- beamer's commands in a deck's `header-includes`, which do nothing in its PDF, and frame options ltx-talk has no key for, which are left out.
- A note of the links taken out of the earlier steps of slides shown in steps, and the decks they were in: presenting from the PDF, such a slide's links work on its last step ([above](#the-pdf)).
- A warning when ltx-talk's code for a slide's title or a block, or LaTeX's for a footnote, isn't the code the template was written for (ltx-talk 0.6.9, LaTeX 2026-06-01), and the PDF falls back: every slide's title at one level, a block's title a paragraph, a footnote's mark in a heading, a caption, or a table a number, not a link. And one when a footnote's mark isn't tied to its note by a `/Ref` each way, as one in a slide's title isn't then.
- An image a deck names in another case than its file's (`assets/cs168-layers.png` for `CS168-layers.png`), which macOS and Windows find and Pandoc doesn't, is read as the file and named in a warning, for every Markdown, HTML, and AsciiDoc source.
- For a `revealjs` target: no copy of reveal.js 6 in `REVEALJS_DIR`, or a Pandoc older than 3.12, which stops the run before any presentation is written; `slides.reference_doc` and `slides.size` unread; and the warnings of Pandoc's reveal.js writer.
- For a `pptx` target: the slides cut in two and the slides added, the pauses left out, the images written as their alt text, the passages in other languages, the links that aren't links in the file, the speaker notes `slides.notes: omitted` leaves out, the slides whose text is shrunk below half its size, `slides.aspect_ratio` and `slides.size` unread beside `slides.reference_doc`, and warnings of a reference document's default table style with too little contrast, a table or text too much for its slide, what Pandoc's writer leaves out, shapes it draws in one place, the layouts a reference document lacks, and the writer's own warnings ([above](#the-powerpoint-file)).
