# Troubleshooting and known limits

## Links to "Table 1.11" and the like

OpenStax's DOCX export bookmarks a paragraph, heading, list, or table by putting the bookmark *between* blocks, and Pandoc's reader keeps a bookmark only inside a paragraph, so in v0.4 and earlier every cross-reference to one of these was a dead link (104 of them in *Introductory Business Statistics 2e*, 4,231 bookmarks in all). The conversion now reads a repaired copy of each `.docx` with those bookmarks moved into the block that follows, and the table-headers pre-pass hands the filter the ones that stood before a table, a box of one cell or a table of pictures alone among them, which it doesn't list. The source file isn't changed. Running the filter by hand on a `.docx`, as [How it works](architecture.md#running-the-pandoc-filter-on-its-own) describes, doesn't get the repair, so links to tables stay dead that way.

## "These files would each be the same page"

A page is named after its file, without the extension and made safe for a link, so `ch1.md` and `ch1.adoc` would both be the page `ch1`, and so would `Chapter 1.docx` and `Chapter-1.html`, or `about.docx` and `_pt/about.md`. The run stops before reading either, naming both, rather than let one overwrite the other and every sidecar keyed on the page describe whichever won. Rename one, or move the one that isn't a source out of the book's directory. Two leftovers are recognized and skipped instead: an `.md` beside the `.docx` of the same name (what v0.1 wrote) and an `.html` named after another source (what a target writing beside the sources wrote). Two variants of one page for one target (`ch1.print.md` and `ch1.print.adoc`) stop the run the same way.

## Converting on a cloud-synced drive

A folder that Google Drive, OneDrive, or Dropbox syncs, reached from WSL under `/mnt/...`, can list a file whose contents haven't been downloaded yet. The run skips an empty `.docx` by name, saying that on a cloud-synced drive it's usually such a placeholder, and converts the book without that page, so look for the line. Such a drive can also be slow to show one program what another just wrote, and the symptoms are erratic: a run fails, the next run fails differently, the third succeeds. Version 0.1 checked each file it renamed and retried for that reason; the versions since write their files another way and have no such check.

**Convert on the Linux filesystem** (a folder under your home directory, not `/mnt/...`) and copy the finished files back. A large book also converts noticeably faster there ([Installation](installation.md#on-windows-wsl-first)).

## Troubleshooting

**`import: command not found`, then syntax errors** — a Python script was run with `bash` or `sh` (where ImageMagick is installed, the first error is its `import` program's instead). Everything in `bin/` and `util/` is Python: `python3 $T/bin/convert.py`.

**`/usr/bin/env: 'python3\r': No such file or directory`** — the script has Windows line endings (CRLF), as a file saved by a Windows editor has, or one checked out by Git for Windows with `core.autocrlf` on, and it was run by its own name. `python3 $T/bin/convert.py` runs it all the same. To put the file right, `sed -i 's/\r$//' convert.py`, and `git config --global core.autocrlf input` keeps a later checkout as the repository has it.

**`couldn't unpack docx container`** — Pandoc was given a file that isn't a Word file. Three kinds are skipped before Pandoc sees them, each with a line saying so: the lock file Word writes while a document is open (`~$Name.docx`), an empty file (often a cloud drive's placeholder), and a file that isn't a zip, as an older `.doc` renamed to `.docx` isn't. Anything else that reaches Pandoc and fails this way is damaged.

**`Stopping: N media reference(s) could not be resolved`** — a page shows an image that isn't on disk or isn't in a format the run can identify; `media-unresolved.csv` names each one. Usually it's an EMF or WMF, Word's own vector formats, which no browser shows: [replace it in Word or convert it](architecture.md#what-conversion-does-to-your-pages).

**A page is in the wrong place in the book** — check `project-sample.yaml`. When a run worked out the book's order itself, the sample holds what it decided, for you to correct.

**Keys like `page#table-3` don't match what you see** — in a table report or `table-captions.csv`, the number counts the page's data tables only, in reading order; a table that only holds an image becomes a figure and isn't counted. The `Excerpt` column identifies the table.

**Reports keep listing things you fixed** — check the key in the sidecar's first column, which has to match the report's. A table's description is keyed on its label (`Table 2.1`), or on its position where it has none (`page#table-3`); an image's alt text is keyed on the image's path without its extension.

**`WARNING: image-alt.csv wasn't UTF-8`** — Excel saved the sidecar as plain "CSV", in a code page, and the run rewrote it as UTF-8, keeping the file as it was beside it (`image-alt.csv.windows-1252`, say). Check the lines the warning shows: a character that isn't the one written means the code page was another. A run that stops instead, saying the sidecar `doesn't read as Windows-1252 (…) or as Mac OS Roman (…)`, has found one that was. Either way, you can save the file as "CSV UTF-8 (Comma delimited)" yourself; [A sidecar that isn't UTF-8](sidecars.md#a-sidecar-that-isnt-utf-8) has the steps. ("The mark", below, is the byte-order mark: three bytes at the start of a UTF-8 file that tell Excel it is one.)

**`WARNING: image-alt.csv isn't UTF-8: … but it can't be rewritten as UTF-8`** — the same, but the run couldn't rewrite the file, for the reason it gives: it belongs to another user, it's read-only or the user running the conversion may not write it, another name links to it, its folder can't be written, or it couldn't be written at all, as when Excel has it open on Windows. If it says `isn't rewritten` instead, the file belongs to another user, and that alone keeps the run from rewriting it, as nothing would were it yours: rewritten, it would be yours, not its owner's. Either way, the run read it in its code page all the same and left it as it was. Do what the warning's last line says and run again: make it writable, give that user permission to write it, close Excel, or, for another user's file, replace it with a copy of your own that keeps its mode (`cp -p image-alt.csv mine.csv`, then `mv -f mine.csv image-alt.csv`) or ask its owner to save it as UTF-8 with the mark ([One the run can't change, or can't read](sidecars.md#sidecar-files)); in a folder with the sticky bit that isn't yours, which won't let you replace another user's file, the warning says only to ask its owner. Don't have its owner, or root, run the conversion instead: the book's outputs would be theirs. Or save the file as "CSV UTF-8 (Comma delimited)" yourself. A file in UTF-8 that only lacks the mark gets the same treatment, `has no byte-order mark, … and can't be given one` (or `isn't given one`), as a note when it holds nothing outside ASCII, which reads the same either way, but for another user's that nothing but whose it is keeps from the mark, which is a warning whatever it holds.

**`WARNING: image-alt.csv can't be read`** — the user running the conversion may not read the sidecar, so the run went on without it, as though it weren't there, and left it as it was; the warning names the file's owner when it's someone else. Give that user permission to read it (on Linux or macOS, `chmod a+r image-alt.csv`, say, or ask its owner), and run again. The run goes on without a sidecar, saying so, when its name is a link to a file that isn't there (`is a link to …, which isn't there`) or a pipe (`isn't a file but a pipe or a device`) too; put the sidecar itself there instead.

**`ERROR: image-alt.csv can't be read (Input/output error), so the run stops`** — the sidecar couldn't be read for another reason than permission, a disk's error or a network share gone stale, and the run stopped rather than make the book without what the sidecar holds. Run it again once the file can be read; if the disk is failing, copy the sidecar somewhere else first.

## Known limits

- **Header row text can't be invented.** A table whose cells hold nothing that could be a header—a grid of measurements—is reported as `needs-source` in `table-headers-report.csv`, not fixed. Add the header in the source (in Word, or as `<th>` cells in an HTML page), where it benefits every downstream format. Where the header text is there and only unmarked, a value in `table-headers.csv` is enough.
- **Equation images stay images.** A formula that's a picture is read by its alt text, however good. Where that alt text spells a name out a letter at a time ("upper C u s t o m e r", as alt text written in MathSpeak does), the conversion joins the letters again, which is a mitigation. The real fix is writing the formula as an equation in the source (a Word equation, TeX math in LaTeX or Markdown, MathML in an HTML page), which converts to MathML.
- **Identical files in different media directories are separate files.** Each page gets its own copy of an image from its Word file. Keeping one copy for all would mean the packager rewriting the pages' references, and it's built never to change a page ([Building the cartridge](packaging.md)).
- **Cross-page links aren't rewritten** for the LMS's internal link format, so links between sections may not resolve after import.
- **Strikethrough conveys meaning visually.** A screen reader may not announce `<del>`, so a before-and-after table should say so in its column heading or caption.
- **Complex tables are reported, not fixed.** A table with stacked column headers, or with a header row and a header column, needs `headers`/`id` associations that no current setting can express. See the [roadmap](../ROADMAP.md).
- **Word's "Mark as layout table" doesn't mark anything.** Word's Accessibility Checker flags a table with no header row and offers "Mark as layout table" as the fix. Taking that offer removes the table's `w:tblStyle` reference and resets `w:tblLook`, and writes no record of the claim: no `w:tblCaption`, no `w:tblDescription`, no element in any namespace, nothing in `settings.xml`. So the conversion can't see the declaration, can't honor it, and can't warn about it. What it can do is lose the evidence: a header row whose shading came from the table style rather than from direct formatting stops looking like a header row, and the table converts as though it never had one. If a table genuinely presents data with nothing to relate—a grid of measurements laid out to fit the page—it needs no header cells to conform, and the useful thing to add is a caption, not a layout marking. A table that only lines things up, with no data in it at all, is a layout table by a row of `table-headers.csv` saying `layout` ([Sidecars](sidecars.md)), which every target honors; a remediated copy of the Word file can't hold it either. A box of one cell with no caption is a layout table already.
- **Two PAC errors on a tagged PDF are the validator's, not the file's.** [PAC](https://pac.pdf-accessibility.org), the PDF Accessibility Checker, is a free Windows program from axes4 that checks a PDF against PDF/UA-1. The two are worth recognizing rather than chasing. *Table header cell has no associated subcells* is raised because `latex-lab` sets `Scope` through an attribute class and PAC doesn't resolve `/ClassMap` references: rewriting the same value as an inline `/A` dictionary makes PAC pass with no change to the content, veraPDF never raises it, and [tagging-project discussion #930](https://github.com/latex3/tagging-project/discussions/930) has the maintainers declining to change the implementation, since the class is what makes `TH-both` expressible for a cell that heads both a row and a column. *Invalid use of a TR structure element* is raised because PAC rejects `Artifact` as a child of `Table`, which is how a repeated `longtable` header row is represented; ISO 32000-2 Annex L, Table L.2 permits it, so the file conforms, and [tagging-project issue #1583](https://github.com/latex3/tagging-project/issues/1583) says the same. It has been reported to PAC; there's no public ticket to watch. A PDF this pipeline makes takes that empty repeated head out of the table (`pdf.repair_captions`), so it may not show the second error at all.
- **One package, from one target.** The configuration is shaped for several packages, each holding several targets, and the tools resolve them correctly, but the packager builds from the first `html` target's pages alone: a package whose `includes` name another target, an EPUB or a PDF beside the pages, or decks, is on the roadmap.
- **`cartridge-files.txt` can't build a prefixed package.** `zip -@` names each member after the path it read, so it can't place files under a directory. Use `--zip`; the file list says so in its header when a prefix is in effect.
- **`util/compare-output.py` matches tables by position**, so inserting one table reports every later table on that page as changed. It also flags a `.docx` and its `.json` intermediate as a duplicated filename, which is noise rather than a finding.
