# Web notes

What browsers, Chromium under Playwright, MathJax, reveal.js, web archives, and publishers' sites do, as read from their source or documentation or established by test, for the questions TextbookImprover keeps asking. What Pandoc's HTML and EPUB readers and writers do is in [PANDOC-NOTES.md](PANDOC-NOTES.md); what a screen reader says of a page, and what axe-core and the other checkers report, is in [ACCESSIBILITY-NOTES.md](ACCESSIBILITY-NOTES.md); why TextbookImprover's own pages and decks are built as they are is in [DESIGN-NOTES.md](DESIGN-NOTES.md). Each entry says how its fact is known and when, as [README.md](README.md) describes.

## Browsers, Chromium, and Playwright

**The measurements here dated 2026-11-01 are one prototype's.** It ran Playwright 1.63 with its Chromium 153 headless shell and axe-core 4.14.0 on Ubuntu 24.04, in a container with two processors and no AppArmor, as root and as a normal user, with Pandoc 3.13 building real pages and presentations through `convert.py`. Where an entry with that date says "measured", it was measured there; the rest of what it says rests on the documentation it links.

### Installing and starting

**Playwright's Chromium takes about 570 MB installed as the headless shell alone, against about 1.2 GB in full.** Measured 2026-10-12 with Playwright 1.56 and its Chromium 141 on Ubuntu 24.04: Playwright 134 MB, the headless shell 323 MB, and Chromium in full 597 MB more, `install chromium` taking both; the packages `--with-deps` names are about 110 MB (their `Installed-Size` summed, before their own dependencies). The suites' checks in a browser pass with only the headless shell installed (`PLAYWRIGHT_BROWSERS_PATH` holding it alone), so `docs/installation.md` installs it alone, with `--only-shell`.

**Playwright and Chromium start in about a second** (measured 2026-11-01, with two processors and 8 GB).

**Playwright 1.64's `page.title()` gives a canceled navigation's address, not the document's title.** Once a page's refresh to `https://elsewhere.invalid/` has been canceled with a 204, 1.64's `page.title()` gives "Loading https://elsewhere.invalid/", where 1.63's gave the document's title. The probe `--wcag` checks first compared titles to see whether the probe page's script had run, so the first run with 1.64 failed every axe-core check, the probe saying its script had run when it hadn't (2026-11-06). The probe in `lib/axecheck.py` reads `document.title` now.

**Playwright 1.48 brought `route_web_socket`.** `--wcag` takes a page's WebSockets with it (Requests, navigations, and WebSockets, below), so it needs Playwright 1.48 or later, and names an older one in a line.

### Namespaces and Chromium's sandbox

**A process can take itself off the network without root, in a user namespace that maps its user to itself, with a network namespace inside it.** None of it needs root, the `unshare` command, or a particular util-linux. Measured 2026-11-01 as a normal user: afterward, the only interface was the loopback; a direct connection failed with "Network is unreachable", where the same connection outside the namespace succeeded; a request let through to the network failed; and Chromium still started with its sandbox and served pages from the folder. Python's `os.unshare` arrived in 3.12 and the project supports 3.9, so `lib/lockedbrowser.py`'s `leave_network` makes the namespaces with a few lines of `ctypes`, before Playwright starts. Where the system refuses the namespaces, a run on a person's own machine carries on without this layer and says so, and the other layers still keep the browser off the network.

**Plain `unshare --user --net` maps the user to `nobody`, and Chromium then can't start its sandbox** (measured 2026-11-01, Chromium 153). That's why `leave_network` writes the maps itself, the user to itself.

**A process with a second thread can't make a user namespace.** A thread that watches the worker's parent, added so that a worker couldn't outlive its run, at first kept the worker on the network, since it was started before the namespaces were made; the run's head line said so (found before the check was merged on 2026-11-06). `leave_network` runs before any thread is started, and a check now holds the run off the network wherever a process can leave it.

**Playwright starts Chromium without its sandbox unless asked.** [`chromium_sandbox`](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch) defaults to false, and measured, Chromium's processes had `--no-sandbox` (2026-11-01, Playwright 1.63). Asked for, as root it can't start ("Chromium sandboxing failed!"), and [Playwright's Docker page](https://playwright.dev/docs/docker) says the same, that the sandbox isn't available with root; as a normal user it worked, Chromium's child processes in their own user and network namespaces, with seccomp filtering on in one of them (`Seccomp: 2` in `/proc/<pid>/status`); and it still worked inside the worker's own namespaces. `lib/lockedbrowser.py`'s `launch` asks for it, and `sandbox_state` reads `/proc` to say whether it's on.

**Ubuntu 24.04 restricts unprivileged user namespaces with AppArmor** ([its release notes](https://documentation.ubuntu.com/release-notes/24.04/)). [Chromium's own notes](https://chromium.googlesource.com/chromium/src/+/main/docs/security/apparmor-userns-restrictions.md) describe the restriction stopping the namespace sandbox for builds that no AppArmor profile covers, and Playwright's download probably isn't covered, so it's the likeliest obstacle to the sandbox, and to the worker's own namespaces, on an Ubuntu 24.04 machine. That wasn't tried on 2026-11-01, where there was no AppArmor. Under WSL 2, a probe run as a user was sandboxed and off the network, with Playwright 1.64.1's Chromium 156 (Rob, 2026-11-07). Ubuntu 24.04 outside WSL, where AppArmor is on, was still untried then, and `docs/installation.md` still says so on 2026-11-11.

**Chromium won't start under a `ulimit -v` of 2 GB or of 8 GB** (measured 2026-11-01), since it reserves far more address space than it uses. Its memory has to be limited by a cgroup, a container's or `systemd-run`'s.

**A context whose evaluation hangs can be closed, and the browser goes on.** Measured 2026-11-01: a hung evaluation was abandoned at its deadline, its context closed in 0.01 s, and the browser was still usable. `docs/checking.md` has the time a page is given.

**In a container, Chromium's sandbox wants a user other than root and Playwright's seccomp profile.** [Playwright's Docker page](https://playwright.dev/docs/docker) recommends a separate user and that profile for untrusted sites, and says its own image is for testing and development, not for visiting untrusted sites. It suggests `--ipc=host`, which shares the host's IPC namespace. The container a web front end would check strangers' pages in (`ROADMAP.md`, not built) is designed to run as a non-root user with that profile, so Chromium's sandbox can start, and to use `--shm-size` rather than `--ipc=host`.

### Requests, navigations, and WebSockets

**A navigation refused outright leaves Chromium's error page in the page's place, and an empty 204 cancels it.** Measured 2026-11-01: when a page's own navigation to another site, such as a `<meta http-equiv="refresh">`, was refused by the route that answers its requests, Chromium's error page replaced the page, and axe-core then checked the error page, reporting its missing title and language as the book's. Answered with an empty 204, the page stayed put and axe-core reported the refresh itself (`meta-refresh`, 2.2.1). So `lib/lockedbrowser.py` answers such a navigation with a 204; its context also blocks service workers and downloads, and grants no permissions.

**A route on the context is given every request a page makes that Chromium doesn't refuse itself, except a WebSocket.** Measured 2026-11-01 on a page written to reach out, behind a Playwright [route](https://playwright.dev/python/docs/network) that serves the page's folder and refuses the rest. Without a Content Security Policy, every request it made came to the route and was refused: stylesheets, an `@import`, a font, a background image, a tracking pixel, a video, a script, a `fetch()`, a prefetch, and a frame at the cloud metadata address 169.254.169.254. With the policy (Scripts and Content Security Policy, below), most were stopped before they were made. Chromium refused `file:///etc/passwd` in a frame and `file:///etc/hostname` in an image itself ("Not allowed to load local resource"), and nothing from either reached axe-core's results. The page's `dns-prefetch` and `preconnect` hints never showed up in the net log.

**A WebSocket doesn't go through a route.** Measured 2026-11-01 on the same page: with the page's scripts allowed, a WebSocket opened, and Chromium's net log shows it stopped only at name resolution (`-105`, `ERR_NAME_NOT_RESOLVED`), by the rule Chromium was started with, `--host-resolver-rules=MAP * ~NOTFOUND`, under which no name resolves. The Content Security Policy kept the socket from opening at all, and Playwright's `route_web_socket`, given a handler that never connects it, kept a socket out of Chromium's network stack; a handler that called `close()` on the socket instead left the page's load unfinished (with the sync API). That's why the route isn't the only layer: `lib/lockedbrowser.py` starts Chromium with that rule and with no proxy settings in its environment, and takes every WebSocket with `route_web_socket` and never connects it.

### Scripts and Content Security Policy

**A Content Security Policy sent with every response blocks a page's own scripts, and what Playwright evaluates isn't subject to it.** Measured 2026-11-01 with the policy below: none of these ran, the page's inline script and its `onload` handler, a script in a `srcdoc` frame, which inherits the policy, and a script from another site; and a `data:` frame wasn't loaded. axe-core, injected by Playwright, ran normally. Inline styles are allowed because every TextbookImprover page carries `page.css` in a `<style>` element. The policy is `POLICY` in `lib/lockedbrowser.py`:

```
default-src 'none'; script-src 'none'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; media-src 'self'; frame-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; connect-src 'none'; worker-src 'none'; manifest-src 'none'
```

**Turning JavaScript off stops axe-core too.** With Playwright's `java_script_enabled=False`, code Playwright evaluates still runs, but no timer, animation frame, or message ever fires for it, so `axe.run()` never finished. Measured 2026-11-01: synchronous code and promise callbacks ran; `setTimeout`, `requestAnimationFrame`, and `MessageChannel` callbacks never did. CSP's `sandbox` directive without `allow-scripts` didn't finish either (measured, not looked into further). Blocking the page's scripts by policy, with scripting itself on, is what works. The cost is that a page's `<noscript>` content isn't shown or checked (measured).

## MathJax, and MathML in browsers

**A MathJax rendering holds its formula in several forms, and no version draws a formula's parts in MathML's order.** MathJax 2 and 3 put a superscript before its subscript, an upper limit before its base, and a root's index first; MathJax 4's SVG puts the root sign first and breaks a long formula into one `<svg>` per line; and MathJax 3's `mjx-munder` is a layout wrapper inside an `munderover`. So the unpacker reads each rendering from the best thing it still holds: the TeX script after it, the MathML hidden for screen readers, the TeX it carries, then its structure, where a part's role comes from the wrapper that names it, or in SVG from its position and size; with nothing to read, it leaves a marker, which is reported. The fixtures are MathJax's own renderings, generated with each version in Node (`tests/fixtures/mathjax/make.js`) and compared by the TeX Pandoc reads from MathJax's own MathML; the `mjx-munder` wrapper and the SVG split by line surfaced only in cases added beyond the first harness. No real page saved from a MathJax 3 or 4 book had been read as of 0.8 (2026-10-03), and `docs/formats.md` still says so on 2026-11-11.

**A MathJax 2 rendering names each MathML element in a span's class, and numbers its spans in the formula's tree order.** The spans MathJax 2 draws carry `MathJax-Span-N` ids, so ordering by id rather than layout gives the MathML. Two things the rendering leaves out are recovered from its layout: MathJax draws `msup` and `msub` with `msubsup` (and `mover` and `munder` with `munderover`), so a lone script is named by whether it sits above its base; and a table is drawn by columns with no span for a row, so rows are found from cells' heights. The unpacker rebuilds the MathML so rather than flattening the rendering to text, which would read ¾ as "34" (as of 0.8, 2026-10-03). A check of the result on Pandoc's native output looked for `Math ` with a space and missed real math where the pretty-printer breaks the line; the JSON is what to check.

**MathJax's FindTeX reads a formula across `<br>`, `<wbr>`, and comments.** A formula split by one of them in a page's HTML is still one formula to MathJax. `sitesource.py`'s `_join_breaks` joins it as MathJax does (2026-10-17, with the LibreTexts profile).

**Chromium draws `\bar` and `\overline` alike on a page.** On a page the HTML target wrote, a screenshot showed the two drawn alike (2026-10-10), where LaTeX draws `\overline` as a longer, higher rule over the whole base, a subscript included.

## reveal.js

### What it does for a screen reader

**reveal.js 6.0.2 gives the whole presentation `role="application"` and announces each slide through a live region.** `setupDOM` sets the role once, whatever the view, and `configure` doesn't run it again, so the scroll view has it too; `announceStatus` writes `getStatusText()`, the slide's text nodes run together, into the polite, atomic `.aria-status` on each slide change and step, so a screen reader hears the whole slide on arrival (read in its source, 2026-10-12). NVDA then treats the presentation as an application rather than a page to read, and the text run together loses MathML and table structure alike: in Chrome and Firefox, on Pandoc's reveal.js output, NVDA read formulas as their letters ("q d") and tables cell by cell with no headers, and many slides overran the viewport (Rob, 2026-10-09). The overruns are probably slides with more on them than reveal.js's 960 by 700 frame holds. `oer-reveal.js` takes the role off and silences the live region (`docs/slides.md`; ACCESSIBILITY-NOTES, NVDA in a browser, has what NVDA read afterward).

**Every slide but the one shown is `aria-hidden` and `inert`** (read in reveal.js 6.0.2's source, 2026-10-12; measured 2026-11-01 on a deck of 11 slides, 10 of 11 `inert`). So axe-core, run as each slide is shown, sees each slide once.

### Layout, links, and keys

**`layout` always scales the slides to the window, the scroll view too.** It runs again on the window's `load`, on a resize, from `slide()`, and from `configure` (through `sync`), so a change of setting lays the slides out (read in reveal.js 6.0.2's source, 2026-10-12).

**A link to a place on the slide shown changes nothing.** `onSlidesClicked` routes a click on any `a[href^="#"]` inside the slides with `getIndicesFromHash`, which takes `#id` and `#/id` and finds the slide holding the element, and prevents the browser's own jump (read in reveal.js 6.0.2's source, 2026-10-12).

**`keyboardCondition` returning false leaves a key to the browser, where a `null` binding still prevents its default.** With no vertical slides, navigation is linear, Up and Down going back and on, Home and End to the first and last slides. The overview opens only when `config.overview` allows, and closes whatever it says. `setupScrollPrevention` resets the wrapper's scroll every second (all read in reveal.js 6.0.2's source, 2026-10-12).

**reveal.js's right arrow goes past the slides of a vertical stack.** Pandoc's writer wraps a section's slides in a stack (PANDOC-NOTES, The HTML writer), and the right arrow went past them (reveal.js 6.0.2, 2026-10-12). `revealtarget.py`'s `flatten` takes the writer's stacks apart, so a section's slides are in one row.

**reveal.js's theme lets a slide's code scroll, and nothing makes it focusable.** `white.css` sets `.reveal pre code` to `max-height: 400px; overflow: auto` and its `pre` to break words where `code` doesn't (`word-wrap: normal`), so a program of more than about 14 lines (the theme's 0.55em of 42 pixels, lines 1.2 apart), or a line too long for the slide, scrolls inside its slide (reveal.js 6.0.2, read 2026-11-12). axe-core 4.14.0's `scrollable-region-focusable` (WCAG 2.1.1) found two such blocks in a course's eight decks (BADM 338), a program of 17 lines and a line of 77 characters no space breaks, measured 2026-11-12. Which scroll is known only once a slide is laid out, so `oer-reveal.js` gives focus to those that do as the slides are fitted and as one is shown; on a page and in an EPUB, which have no script, every code block takes focus (`target-blocks.lua`), Pandoc's stylesheets letting a plain `pre` and highlighted code's `div.sourceCode` scroll.

**reveal.js fades its back arrow to three tenths of its strength**, about 1.6:1 against white, too faint for a control (WCAG 1.4.11; reveal.js 6.0.2, 2026-10-12). `revealtarget.py` sets `controlsBackArrows` so the arrow back is as plain as the arrow on.

### Fades and reduced motion

**reveal.js fades a slide's background in over 0.8 s, and a step's text fades in too, so a contrast check can catch either partway.** Measured 2026-11-01 on a deck `convert.py` built: without reduced motion emulated, axe-core caught a step's text mid-fade and reported its contrast. With it emulated, which turns `oer-reveal.css`'s transitions off, the background's fade still ran, since `oer-reveal.css`'s reduced-motion rule didn't stop it, and axe-core measured a gray slide's white title and text against a background still near white: two findings that were artifacts. Since then `oer-reveal.css`'s reduced-motion rule stops that fade too, and the `--wcag` check both emulates reduced motion and finishes whatever is still animating (`document.getAnimations()`) before axe-core runs on a slide. The suite's deck has a slide on #777 instead of the gray one, where the large title passes and 16-pixel text fails (white on #777 is 4.48:1).

### Without its scripts

**With its scripts blocked, `reveal.css` keeps every slide `display: none`.** Measured 2026-11-01 on a deck built with `convert.py` and Pandoc 3.13: 11 slides, with a picture without alt text, another in a step, faint text, a slide with a gray background, and a picture as a link. The presentation with its scripts blocked gave axe-core no findings, not even the picture without alt text. The deck's page gave five: the three pictures, the faint text, and the link. The presentation with TextbookImprover's scripts gave seven, those five and the gray slide's title and text, the last two measured against the slide's background partway through its fade (Fades and reduced motion, above). So a presentation TextbookImprover wrote is checked with TextbookImprover's own scripts allowed, and no others, one slide at a time.

### Getting it

**reveal.js's npm package can be used without Node.js.** The npm registry's package (`https://registry.npmjs.org/reveal.js/-/reveal.js-6.0.2.tgz`, 6.0.2 being npm's `latest` on 2026-10-12), fetched with curl and unpacked with `--strip-components=1`, is a folder `revealjs_problem` takes. Its `package.json` has no `engines`, only `devEngines` (Node 22.12, for working on reveal.js itself), and no dependencies, so `npm install reveal.js@6` works with Ubuntu's older Node too.

## Web archives and saved pages

### An archive against a save

**An archive of a site holds what a browser's save loses.** DCIC's crawl had the TeX of 397 formulas between MathJax's delimiters, where its `.mhtml` save had only the rendering; the unpacker writes those delimiters as math Pandoc reads, never inside code. CS168's three routes (a browser save, a wget WARC, and the Jekyll source) agree on 62 pages and the same 772 images without alt text; where they differ, the book itself changed between the captures ("there are $p$ nodes" became "$D$"), or the theme generated the difference (as of 0.8, 2026-10-03).

**wget stays on its starting host**, which is why the crawl of CS168 lacks its license badge (as of 0.8, 2026-10-03).

**A site that answers wget with a 403 is refusing crawlers.** The answer is the publisher's export or a browser, not a disguised user agent. The _Information Systems for Business and Beyond_ site does that, and OER Commons blocks automated requests too, which is presumably why the business communication book's EPUB exporter got a `403 Forbidden` page for every image (as of 0.8, 2026-10-03).

**A browser's archive differs from a crawl in three ways.** A WACZ lists the pages that were recorded, and the first of them names the book's site, where the first HTML fetched was a Google sign-in relay. ArchiveWeb.page stores a redirect, and a response it already holds, as a revisit record, which is how every image of the OER Commons book reached `img.oercommons.org`. And a site that draws pages by script fetches them as data: OER Commons returns `?section=3` of a lesson as JSON with the section's HTML in it, which is a page only when it's part of a page the archive holds, or its 63 oEmbed answers become pages too. The unpacker names pages told apart only by a query by it (`section-3`) (as of 0.8, 2026-10-03).

### ArchiveWeb.page's WACZ

**ArchiveWeb.page writes each record as its own gzip member, and indexes them in CDXJ.** Read and measured on its WACZ of _Instrumental Analysis_ (LibreTexts) while cleaning it, 2026-10-17. A record can be copied by its byte range, and its digests stand. The index is CDXJ in gzip blocks of 1,024 lines, with `index.idx` naming each block's first key and the sha256 of its compressed bytes (a small archive gets a plain `indexes/index.cdx`); GET requests aren't indexed, and a POST is, under its URL with `__wb_method=post&…` in the key, while the record's own URI ends `&__wb_method=POST&`. Revisits' digests are written `sha-256:`, responses' `sha256:`. Each page has a `urn:thumbnail:` and a `urn:view:` resource, screenshots of the viewport.

**A payload ArchiveWeb.page already holds is written as a revisit, often of another URL, and its original can belong to a page visited later.** A revisit points at the original by `WARC-Refers-To-Target-URI` and `-Date`: in the WACZ of _Instrumental Analysis_, all 870 of the 302s' revisits point at one redirect, Harvey.png's, and the book's subpages at `pages/332621/subpages`; 495 revisits are dated before their originals, though in the file an original always comes first (2026-10-17). So dropping a page from a WACZ has to keep any response a kept revisit points at: 7 records in the archive's first cleaning, and 138 once four recaptured pages were merged in.

**A cleaned WACZ can be verified by its index, its revisits, the unpacker, and a replay.** On the cleaned archive of _Instrumental Analysis_ (2026-10-17): every index line names a record of that URI and date, every revisit has its original, the unpacker's output from the cleaned archive was byte for byte the original's until the recapture went in, and ReplayWeb.page 2.5.3 replayed sampled pages, the three scripted ones and the four recaptured ones with their answers' figures among them. ReplayWeb.page ran from its npm package, served locally in headless Chromium with the locale set, since `en-US@posix` stops its UI.

**py-wacz 0.6.0 doesn't install with pip under Ubuntu's setuptools until `surt` is built with PEP 517.** `pip install wacz` (for `wacz validate`) failed building `surt` (`AttributeError: install_layout`); `pip install surt --use-pep517` first, then `wacz`, works (2026-10-17).

### What a capture records about the person

**A browser's capture records no IP address and no login, but it keeps the browser's headers, every cookie, and the analytics beacons.** Searched in every header and text payload of ArchiveWeb.page's two WACZs of _Instrumental Analysis_ (2026-10-17). No IP address: none in any WARC header (ArchiveWeb.page writes no `WARC-IP-Address`), and none echoed by any response. No login: LibreTexts answered "Anonymous User" and Hypothesis's profile `userid: null`. But every request record keeps the browser's headers (user agent, client hints, `Accept-Language`, `DNT`, and Chrome's `X-Client-Data` to Google Fonts), and every cookie is kept twice, in each request's `Cookie` and in ArchiveWeb.page's `x-wabac-preset-cookie` on responses: the site's anonymous session cookies, and Google Analytics' client ID and session cookies, whose timestamps date earlier visits. The analytics beacons are recorded whole (Google Analytics with screen and viewport sizes, Cloudflare's with the OS version, Sentry's from Hypothesis), the CDN edges that served the requests are named in the response headers (`cf-ray`, `x-amz-cf-pop`), which place the browser roughly, and the WARC dates say when. `docs/making-warcs.md` says the same for someone about to share an archive.

**`datapackage-digest.json` signs a WACZ with a key per ArchiveWeb.page installation.** The two WACZs, made with one installation, carry the same public key, which links them (2026-10-17). An edited archive is unsigned, since any edit invalidates the signature.

## Site generators and publishers' pages

**Generators are recognized from what their pages say about themselves.** just-the-docs names itself in a Jekyll generator meta and its theme's name; Scribble never names itself, but its `navsettop` bar is unmistakable. A profile in the unpacker says where the content is, what inside it is chrome, and, for Scribble, what it lays out as a table that isn't one: REPL interactions, local contents, and verbatim and Racket blocks. 256 of DCIC's 335 tables were those. The REPL tables nest, which is how copying DOM cells instead of moving them left the inner ones unrewritten (as of 0.8, 2026-10-03).

### LibreTexts

**A browser's archive of a LibreTexts book can hold the whole book, its tree included.** In ArchiveWeb.page's WACZ of _Instrumental Analysis_ (2026-10-17) there were no stray pages: all 204 were on chem.libretexts.org and inside the book, the only other HTML being Hypothesis's frame and a Tag Manager frame. Five pages were recorded twice (the home page, Licensing, About the Author, 34.5, 35), each pair's HTML identical but for per-visit tokens (the CSP nonce, and `apiToken` and `pageViewId` in `mt-global-settings`) and their loads the same, so the earlier capture of each was kept; a third copy of the home page was recorded under the Detailed Licensing page, the navigation caught by the page before it. The book's whole tree is in the archive as the site's own `@api/deki/pages/…/subpages` answers (every node's children, 199 pages, all public), and every page in it was recorded.

**An exercise's Answer is hidden until clicked, and its image is lazy, so a browser recording the page never fetches it.** Five figures were missing from the WACZ of _Instrumental Analysis_, each inside an Answer (`section.box-exercise > dl > dd`, its image `loading="lazy"`). Pages 14.3, 14.4, 27.4, and 28.4 were recaptured with the answers open, and the recaptures' HTML matched the first captures' but for the per-visit tokens (2026-10-17).

**Every page asks for a Back Matter `20: Glossary`, and a book without one answers 403.** _Instrumental Analysis_ has none: the answer is a 403 with a stub of page id 0 (2026-10-17).

**Table of Contents, Index, and Detailed Licensing are drawn by script.** They're drawn from `@api/deki/pages/332621/tree`, the `Template:MindTouch/IDF3/Views/Tag_directory` contents, and `api.libretexts.org/endpoint/licensereport/…`; all three answers were in the archive of _Instrumental Analysis_ and replay, but to the unpacker those pages are empty shells, and the text in `pages.jsonl` is taken at load, so it says "Loading..." for two of them whatever the archive holds (2026-10-17). `lib/libretexts.py`'s `Book` makes Index from the tag directory's JSON (dynamicIndexMaker.js's filter and sort, read from the archived script) and Detailed Licensing from the license report.

**A LibreTexts book's order is in its listings**: the home page's `ul.mt-sortable-listings-container` and a chapter's `ul.mt-guide-listings`, which `lib/libretexts.py`'s `Book` reads the order from (2026-10-17).

**CKEditor's magic line can be left in a page.** It's spans `contenteditable="false"` whose style names `magicline`, in a paragraph otherwise empty: _Instrumental Analysis_'s 11.4 had one, its "↵" in every target and its icon a remote resource epubcheck rejected (RSC-006 and OPF-014). `lib/libretexts.py` drops the spans and the paragraph left empty (2026-10-17).

**A LibreTexts page numbers its formulas through its MathJax configuration.** `\PageIndex` is the page's number, and display formulas are numbered as the page's configuration says: `tags: "all"`, the front of the number from `PageNum` or `PageName`, and `InitialOffset`. `lib/libretexts.py` does the same as it reads a page: a taggable environment's rows are tagged, `\nonumber` and `\notag` honored, and unstarred environments starred so LaTeX doesn't number again (2026-10-17; `docs/site-input.md`).
